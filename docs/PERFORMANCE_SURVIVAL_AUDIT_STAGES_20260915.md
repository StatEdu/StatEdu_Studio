# 제외 사유 문자열·행 감사표·분석 자료 생성 비용 분리

제품 코드는 변경하지 않았다. 사유 기록 최적화 이후의 다섯 단계를 별도 함수 사본에서 계측했다. 다음 후보는 단일 제외 사유에도 반복하는 문자열 결합이다.

## 방법과 검증

`scripts/profile_survival_audit_stages.R`가 현재 preflight 본문의 최상위 대입문 위치를 AST로 찾아 계측 구간을 삽입한다. 기존 문장 순서와 마지막 반환식을 유지한다.

| 구간 | 포함 연산 |
|---|---|
| exclusion_mask | 사유 목록 길이로 제외 마스크 계산 |
| labels | 빈 문자열 준비, 제외 행의 paste/vapply, 결과 대입 |
| audit_frame | source_row/included/exclusion_reasons 데이터프레임 생성 |
| analysis_data | 분석 행 추출, 조건부 정렬, 집단 수준 정리, 측정수준/공변량 형식 처리 |
| counts_issues | 사건/중도절단 수, 안내 이슈와 대상자 수 계산 |

번들 R 4.5.3, 실제 앱 모듈·환경설정 초기화, 동일 시드, 양쪽 preflight 컴파일. 두 독립 프로세스에서 조건 순서를 반대로 실행했다. 각 조건 원래 함수는 준비 후 5회 전체 시간, 계측 사본은 준비 후 3회 단계별 시간을 측정했다. 단계별 값은 별도 계측 실행이므로 원래 전체 시간의 정확한 구성 비율이나 최적화 예상 단축률로 해석하지 않는다. 짧은 구간은 시계 해상도와 계측 오버헤드의 영향을 받는다.

20,000/100,000행, 공변량 6개, 집단 3수준. 정상, 사건 5%·집단 5%의 서로 다른 결측(sparse), 같은 절반의 행에 사건·집단·공변량 전체 결측(overlap), 공변량별 서로 다른 결측(disjoint) 조건이다. 모두 단일 기록 자료이며 시작–종료 정렬 구간의 성능까지 대표하지 않는다.

성공 결과와 complete.cases에 따른 예상 분석 행 수를 확인했다. 프로세스마다 72개, 합계 144개 전체 반환값·속성·진단·stdout·RNG 비교가 `identical(..., num.eq=FALSE)`로 통과했다. 프로세스 간 저장 결과 8쌍도 일치했다. 환경 정규화나 수치 허용오차는 사용하지 않았다.

## 100,000행 단계별 시간

단위 ms, 독립 실행 1 / 2 중앙값.

| 조건 | 제외 마스크 | 사유 문자열 | 행 감사표 | 분석 자료 | 건수·이슈 |

행 감사표 생성 자체보다 사유 문자열 준비 비용이 컸다. disjoint는 제외된 50,002행이 각각 missing_covariate 하나만 가지는데도, 현재 구현은 각 행에서 `paste(..., collapse=';')`를 호출한다. overlap은 제외된 50,000행마다 세 사유를 결합한다. 이 차이를 구분해 다음 후보를 설계한다.

## 다음 후보와 범위

사유가 하나인 행은 원래 단일 문자열을 사용하고 여러 개인 행만 기존 결합을 수행하는 후보를 검토한다. 사유가 없는 행의 빈 문자열, 순서·인코딩·속성, 여러 사유의 구분자를 유지해야 한다. 후보가 실제로 빠른지는 전체 전처리와 정상/중첩/분산 조건에서 별도 검증한다. 이번에는 해당 변경을 적용하지 않았다.
