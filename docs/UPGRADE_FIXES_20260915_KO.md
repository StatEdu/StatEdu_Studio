# 이력 저장 및 모델 이관 보완

## 변경

- 데스크톱에서는 `STATEDU_USER_DATA_DIR/data/StatEdu_Studio_results.json`을 기본 이력 경로로 사용한다. 명시적 `STATEDU_RESULT_STORE`가 최우선이며, 사용자 데이터 디렉터리가 없는 소스 실행은 기존 상대 경로를 유지한다.
- 새 기본 파일이 없으면 현재 작업 디렉터리의 `data/StatEdu_Studio_results.json`, 다음으로 `data/EasyFlow_Statistics_results.json`을 검사한다. 정상 구조를 확인한 후 원본 바이트를 새 경로에 복사하고 원본을 보존한다. 손상된 파일은 자동 복사하거나 덮어쓰지 않고 기존 복원 오류 안내로 전달한다.
- 새 이력이 빈 목록이어도 존재하면 구 이력을 다시 가져오지 않는다. 명시적으로 지정한 저장 경로에는 다른 경로의 이력을 자동으로 가져오지 않는다.
- 구형 모델의 명시적 `constructType=unspecified`를 그대로 보존한다. 유형이 없는 구형 모델에만 기존 추론을 적용한다. 새 노드의 공통요인 기본값은 유지한다.
- 모델 이관 검사의 기대 스키마를 현재 7로 갱신하고, CFA UI 검사의 자동 변환 요구를 보존 정책에 맞췄다. 첫 빌드가 해당 충돌 때문에 중단된 기록도 남겼다.

수치 계산식이나 분석 표/그림/내보내기 표현을 바꾸는 작업은 아니다. 기존 저장된 결과 HTML을 그대로 유지한다.

## 검증

`validate_result_profile_migration.R`, `validate_result_history.R`, `validate_result_autorestore.R`, `validate_sem_construct_migration.js` 통과. 새 검사에서는 프로필 경로, 원본/복사본 바이트 동일성, 명시적 비우기 유지, 지정 경로 격리, 손상 원본 보존을 확인했다.

전체 설치 회귀 검사 통과. CFA 1,000회 9.442초, SEM 5,000회 131.911초, PLS 1,000회 1.594초이며 A/B 성능 비교 수치는 아니다. 번들 준비 단계와 최종 패키지 각각 PLS/PLSc 19개 검사 및 최종 R 모듈 로딩 통과.

새 패키지에서 `STATEDU_RESULT_STORE` 없이 격리 사용자 프로필의 저장 이력을 복원했다. ID·HTML 정확 일치 및 파일 바이트 불변을 확인했다. 첫 GUI 실행은 자동화 도구의 대화상자 처리 오류로 중단되어 기존 대화상자 처리 방식을 적용한 뒤 재실행했고 통과했다. 해당 시험의 Electron 프로세스가 남아 있지 않음을 확인했다. 로그 디렉터리는 `output/upgrade-fixes-20260915/`, GUI 증거는 `tmp/default-history-nh2GPF/result.json`이다.

R/web/HWPX helper 337개 현재 소스와 패키지 해시 일치. 새 설치 파일 `dist/electron/StatEdu_Studio_Setup_1.3.0.exe`: 324,298,451 bytes, SHA256 `0BB609C4BAF5CE755AD772479886CB84651458C426100FC26779778E5520B17F`. 기존 보고서의 설치 파일 해시는 이전 빌드의 이력이다.

## 구버전에서 업데이트할 때

이 수정은 새 버전 실행 시 아직 남아 있는 구 이력을 가져온다. 이전 설치 제거 과정에서 이미 삭제된 파일을 복구하지 않는다. 구버전 앱의 **결과 → 결과 저장** 기능으로 `.efs-result` 또는 `.json` 이력을 설치 폴더 밖에 저장한 뒤 업데이트하고, 필요하면 새 앱의 **결과 불러오기**로 복원한다. 일반 HTML/PDF 내보내기와 이력 저장은 다르다. 모델 파일과 설정 파일도 설치 폴더 밖에 보존한다.

개발판과 정식판의 사용자 프로필을 자동으로 합치지 않는다. 실제 이전 정식판 설치→업데이트 시험은 별도 Windows 환경이 필요하며, 이 코드 검증만으로 완료 처리하지 않는다.
