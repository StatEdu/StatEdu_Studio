# Cox 완전한 설계 행렬의 행 선택 생략 — 2026-09-14

> 검증 범위 정정 (2026-09-14): 아래의 경쟁위험/Fine–Gray 전체 결과 검증 표현은 당시 `integration.R`이 `regression`을 지정하지 않아 기본 CIF/Gray 경로만 실행한 것을 잘못 기술한 것이다. 그 검증은 원인별 Cox 또는 Fine–Gray 회귀 검증으로 볼 수 없다. 직접 함수 및 Cox 검증 결과는 별개다. 이후 `regression="both"`를 명시한 600행·20공변량 자료에서 초기 Cox 최적화 전과 현재 모듈 전체의 결과·진단·난수 상태를 비교해 통과했다. 상세 내용은 [원인별 Cox 저장·통합 검증](COMPETING_PH_EXPORT_VALIDATION_20260914.md)을 참고한다.

## 변경

`R/analysis_survival.R`의 `survival_cox_collinearity()`에서 모든 행이 유한하고 클래스 및 dim/dimnames 이외의 속성이 없는 행렬은 전체 행 선택을 생략하도록 변경했다. 결측·무한값으로 제외할 행이 있거나 특수 클래스/속성이 있으면 기존 부분 행렬 생성 경로를 사용한다.

유한값 판정, 분산, 회귀 함수, 열 순서, VIF 및 조건수 계산은 변경하지 않았다. 직전의 절편 행렬 재사용 변경은 그대로 유지했다.

## 실행 시간

동봉 R 4.5.3, 정규 합성 자료, 시드 42. 공변량 수별 기존/후보를 각각 새 프로세스에서 3회 실행했고 두 번째 쌍은 후보부터 실행했다. 각 프로세스는 1천 행 다음 10만 행 순서로 진단 함수 전체를 측정했다. 자료 생성과 결과 저장은 제외하고 동일한 결과/진단 수집 래퍼는 포함했다. 프로파일러 및 별도 검증은 시간 측정 중 실행하지 않았다.

| 행 수 | 공변량 | 기존 3회(초) | 변경 후 3회(초) | 중앙값 기존 → 변경 후 |
|---|---:|---|---|---|
| 1,000 | 5 | 0.03 / 0.02 / 0.03 | 0.03 / 0.01 / 0.01 | 0.03 → 0.01 |
| 100,000 | 5 | 0.17 / 0.17 / 0.17 | 0.18 / 0.15 / 0.17 | 0.17 → 0.17 |
| 1,000 | 20 | 0.03 / 0.03 / 0.03 | 0.03 / 0.01 / 0.03 | 0.03 → 0.03 |
| 100,000 | 20 | 1.66 / 1.66 / 1.68 | 1.43 / 1.45 / 1.47 | 1.66 → 1.45 |

10万 행·20공변량은 세 쌍 모두 단축됐으며 중앙값 기준 약 12.7% 감소했다. 작은 입력의 0.01초 수준 차이는 측정 해상도와 변동을 고려해야 한다. 전체 Cox 적합·로딩·화면 대기 시간의 단축률을 뜻하지 않는다.

## 검증

- 기본 36조건: 0/1/2/40행과 일반 입력, NA, Inf, 상수열, 중복열, 행 이름, 데이터 프레임, 단일 열, 사용자 클래스 행렬.

- 속성과 입력 보존 24조건: 0/1/30행 × 일반 입력, note 속성, assign 속성, 사용자 클래스, 이름 있는 dimnames, 정수 행렬, NA, Inf. 기존/후보 호출 전후 입력의 직렬화 바이트가 일치했다.
- 시간 측정 전체 결과·진단·난수 상태 12쌍.
- 600행 전체 Cox 및 경쟁위험/Fine–Gray 결과와 각 HTML/의존성 비교 2건.
