# Excel 저장의 불필요한 Word 표 변환 생략 — 2026-09-14

`result_entry_tables()`에 기본값이 TRUE인 `include_docx` 인자를 추가했다. Excel 저장 호출만 FALSE를 전달하여 사용하지 않는 Word용 정규화 데이터를 만들지 않는다. Excel은 기존처럼 캡처된 `screen` 셀을 사용한다. Word 저장과 기존 기본 호출은 전체 데이터를 계속 생성한다.

인쇄 방향 판단은 명시적 방향, 표 종류, 제목과 열 수를 사용하며 Word용 정규화 데이터에 의존하지 않는다. 분석 계산, 표시 문자열, 서식, 병합, 주석과 인쇄 설정을 변경하지 않았다.

## 전체 저장 시간

저장된 30변수 상관분석 HTML, Excel 3개 시트, 번들 R 4.5.3을 사용했다. 이전 최적화는 비교 양쪽에 포함된다. 새 프로세스에서 모듈과 설정을 로드한 뒤 전체 저장을 측정하고 파일 비교는 측정 밖에서 수행했다. 프로파일러 없이 3쌍을 순차 실행하고 두 번째 쌍의 순서를 뒤집었다. 변경 전후 함수의 전역 도우미 환경은 동일하다.

| 반복 | 변경 전(초) | 변경 후(초) |
| --- | ---: | ---: |
| 1 | 2.50 | 2.30 |
| 2 | 2.49 | 2.28 |
| 3 | 2.50 | 2.28 |
| 중앙값 | 2.50 | 2.28 |

이 파일의 전체 저장 시간은 **약 9% 감소**했다. 이전 개선율과 합산하지 않으며 시작 시간이나 통계 계산의 개선을 의미하지 않는다.

## 검증

- `scripts/validate_excel_skip_docx.R`: 개별 표 9개 및 누적 결과 1개 통과. 문자열, 빈 셀, 병합, 다양한 서식과 연속 구간을 포함한다.
- 모든 시트 이름과 읽어 들인 값이 동일하다. core 메타데이터 이외의 내부 파일은 바이트 단위로 동일하며 core도 생성·수정 시각만 정규화하면 동일하다.
- 개별 검증의 경고 순서와 RNG 상태가 동일했다. 측정 파일 6개도 기준 파일과 같은 내부 비교를 통과했고 저장 중 경고가 없었다.
- 각 표의 기본 호출 반환값은 변경 전후 정확히 동일했다. Excel용 반환값은 `docx = NULL` 외 모든 필드가 기본 호출과 동일했고 방향 판단도 같았다.
- `verify_orientation.R`: 상관행렬 9/10변수 경계, 명시적 세로/가로, 가로 패널, 그룹 표 클래스와 위첨자 각주를 포함한 6개 추가 사례에서 전체 Excel 내부 파일 비교 통과.
- Word용 표 변환 호출을 계수하여 기본 호출은 1회, Excel 저장은 0회임을 확인했다.
- `git diff --check -- R/result_saved_ui.R` 통과. 변경 전 스냅샷과의 차이는 선택 인자와 Excel 호출부로 제한된다.

Excel에서 생략한 Word 전용 변환은 실행되지 않으므로 그 변환 자체에서만 발생할 수 있는 진단도 실행되지 않는다. 검증 입력에서 진단 차이는 없었으나 임의의 모든 잘못된 입력에 대한 진단 동일성을 보장하는 검사는 아니다. 기본 Word 변환 경로는 유지한다.

출력 내용 변경이 없는 저장 경로 최적화다. HTML/PDF/Word/HWPX 작성기는 변경하지 않았고 해당 완성 파일은 이번에 재생성하지 않았다. 설치 파일도 재빌드하지 않았다.
