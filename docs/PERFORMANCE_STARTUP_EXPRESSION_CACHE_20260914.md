# 파싱된 모듈 식 캐시 적용 — 2026-09-14

## 적용 결과

`R/app_bootstrap.R`에 파싱된 R 식을 압축 RDS로 보관하는 캐시를 추가했다. 유효한 캐시가 있으면 합쳐진 소스를 매번 파싱하는 대신 식을 읽어 같은 전역 환경에서 평가한다. 수치 분석 코드는 변경하지 않았다.

새 프로세스 3회의 단계별 중앙값:

| 조건 | 기존 모듈 로딩(초) | 적용 후(초) |
|---|---:|---:|
| 유효한 캐시 | 0.67 | 0.28 |
| 캐시 최초 생성 | 0.73 | 0.93 |

반복 로딩은 **약 58% 단축**됐지만 캐시 최초 생성에는 **약 0.20초 추가**된다. 원본 소스 변경 또는 R 버전 변경으로 재생성이 필요할 때도 생성 비용이 생긴다. 프로그램 전체 시작 시간이 58% 줄었다는 의미는 아니다.

## 첫 분석까지 확인한 최종 모의 흐름

현재 UI 가시성 모델을 사용하는 MockShinySession에서 모듈 로딩, 서버 초기화, 업로드, 상관분석 및 Kaplan–Meier 분석과 동일 입력 재실행을 수행했다. 각 버전 새 프로세스 3개, 순차 실행, 두 번째 세트는 후보부터 실행했다.

| 단계 | 기존 중앙값(초) | 적용 후 중앙값(초) |
|---|---:|---:|
| 모듈 로딩 | 0.67 | 0.28 |
| 서버 초기화 및 첫 flush | 0.75 | 0.73 |
| 첫 상관분석 | 0.48 | 0.47 |
| 첫 KM 분석 | 2.13 | 2.06 |
| 모듈 로딩을 제외한 작업 흐름 | 5.64 | 5.50 |
| 모듈 로딩을 포함한 작업 흐름 | **6.32** | **5.78** |

마지막 행의 원자료는 기존 6.32/6.32/6.29초, 적용 후 5.81/5.76/5.78초다. 중앙값 기준 약 8.5% 감소했다. 후속 첫 분석으로 비용이 이동하는 징후는 이 실험에서 관측되지 않았다. 각 단계 중앙값을 더한 값과 전체 중앙값은 다를 수 있다.

이 흐름에는 업로드와 분석이 포함된다. 실제 설치된 Electron 앱의 시작 시간, 브라우저 DOM 가시성/렌더링, 콜드 디스크, R 프로세스 시작 및 패키지 로딩을 모두 포함한 측정은 아니다. 별도 초기 UI 구성 실험과 이 값을 합산하지 않는다. 운영체제 파일 캐시도 비우지 않았다.

## 구현과 복구 동작

- 기존 합친 소스 및 원본 파일 경로·크기·mtime 매니페스트 검증을 유지했다. 식 캐시에도 같은 매니페스트와 전체 `R.version.string`을 저장해 비교한다.
- 캐시 파일은 기존 캐시 디렉터리의 `app-expressions-r4.5.rds` 형식이다. gzip 압축을 사용한다. `STATEDU_MODULE_CACHE=false/0` 및 사용자 지정 파일 선택은 기존 개별 소스 경로를 유지한다.
- RDS를 읽을 수 없거나 버전·매니페스트·식 형식이 맞지 않으면 기존 합친 소스에서 다시 파싱한다. 성공적으로 평가한 뒤 임시 파일을 거쳐 캐시를 기록한다. 기록 실패는 모듈 로딩을 막거나 새 경고를 발생시키지 않는다.
- 평가 자체가 실패하면 기존 경고와 개별 소스 로딩 경로로 돌아간다. 유효한 형식의 RDS에 실행 오류를 내는 식이 들어 있는 경우까지 자동 파일 복구를 보장하는 것은 아니다.
- `keep.source` 또는 `verbose`가 기본 FALSE 이외의 값이면 기존 `source()` 경로를 사용해 소스 참조 및 출력 동작을 보존한다.
- 서버 초기화 JIT 조정과 기존 분석 캐시는 그대로다. 최초 캐시 생성을 다음 분석으로 미루는 방식은 사용하지 않았다.

## 형식 선택 실험

통합 전 실험에서 소스 파일은 7,438,033 bytes였다. 식만 저장한 gzip RDS는 1,592,621 bytes, 무압축은 10,470,680 bytes였다. 최초 파싱 0.31초, gzip 저장 0.36초, 무압축 저장 0.19초는 각각 단일 생성 실행의 값이다. 생성 시간의 3회 중앙값으로 해석하지 않는다.

유효 캐시의 모듈 로딩 중앙값은 소스 0.67초, gzip 식 0.27초, 무압축 식 0.25초였다. 약 0.02초의 추가 이득에 비해 무압축 파일이 훨씬 커서 gzip을 선택했다. 실제 통합 캐시는 버전·매니페스트도 포함하므로 식만 저장한 파일과 크기가 다르다. 최고 메모리는 이번에 측정하지 않았다.

## 검증

- 형식 비교 실험 9개 초기 스냅샷 및 최종 hit/miss 실험 12개 초기 스냅샷이 각각 정확히 일치했다. 초기 HTML의 자동 생성 숫자 탭 ID만 정규화했고, HTML 의존성·전체 Pearson/생명표 결과·난수 상태·서버 함수 본문/인자를 비교했다.
- 모의 전체 세션은 형식 후보 6개와 최종 구현 6개의 스냅샷을 각각 비교했다. 상관/KM 전체 분석 객체, 결과 HTML/의존성, 경고 및 알림이 일치했다. 각 실행에서 첫 결과와 동일 입력 재실행 결과도 일치했다. 경고는 모두 0건이다. 콘솔에는 기존 ggplot 좌표계 교체 메시지가 출력됐으며 세션 스냅샷이 모든 콘솔 메시지나 난수 상태를 비교한 것은 아니다.
- `scripts/validate_expression_module_cache.R` 통과: miss/hit, 소스 변경, 깨진 RDS, 버전/매니페스트/식 형식 불일치, 쓰기 실패, keep.source/verbose, 평가 실패 후 개별 소스 복구, 캐시 비활성/사용자 지정 선택, 선택 모듈 추가.
- `scripts/validate_module_manifest_metadata.R` 통과: 7개 매니페스트 조건, 크기/mtime 무효화, 합친 소스 바이트 동일성.
- 모든 수치 비교는 `identical(..., num.eq=FALSE)`를 사용했으며 수치 허용오차를 사용하지 않았다. 소스 참조·출력 옵션의 기본 FALSE 판정을 보수적으로 제한한 뒤 복구 검사를 재실행했다. 기본 FALSE에서의 측정 경로는 유지된다.

초기 UI 및 서버 세션 측정은 번들 R 4.5.3, JIT 3, UTF-8 및 패키지 자동 설치 비활성 환경에서 수행했다. 각 cache miss에는 새 디렉터리를 썼으며 hit 캐시는 측정 전에 준비했다. 타 R 검증과 성능 측정을 동시에 실행하지 않았다.
