# 기본 인접행렬 처리 비용 검토

## 결론

Pesaran CD 검정의 기본 인접행렬 생성과 대칭성 검사를 생략하는 내부 함수 시제품은 성능 이득을 보였다. 그러나 이 방식은 plm 내부 함수 복사와 호출 경로 대체가 필요하다. 공개 인자만 사용하는 대안도 비교했으나 RE가 세 번 중 두 번 느려지고 중앙값도 증가했다. 두 후보 모두 이번 제품에는 적용하지 않았다. 내부 시제품의 개선율을 제품 개선율로 간주하지 않는다.

제품 `R/analysis_longitudinal.R`은 변경하지 않았으며 시작 스냅샷과 확인한 해시는 `1A57B5CB6E504ED5A8A1392FF0B1C86485A1107D4357BCF50598302CBBCA45B8`이다. 기존 선택 모형·Hausman·HC1 재사용을 유지한다.

## 후보 구분

1. **내부 함수 시제품**: w가 NULL이고 개체 수가 2 이상일 때 값이 모두 TRUE인 선택 행렬을 직접 만든다. 기존 numeric 인접행렬, 논리 변환 및 항상 대칭인 행렬에 대한 검사를 생략한다. 그 외에는 기존 분기를 사용한다. 공통 시점 부족 경고와 이후 삼각 선택, 상관·통계량·p값 계산은 그대로다. 설치된 pcdres/pcdtest.panelmodel 복사본만 지역 환경에서 변경하며 namespace는 수정하지 않았다.
2. **공개 인자 대안**: 모든 개체 쌍을 포함하는 하삼각 논리 행렬을 `plm::pcdtest(..., w=...)`에 전달한다. 상삼각 정보가 없으므로 패키지가 대칭성 확인을 생략한다. 패키지가 붙이는 method 필드의 `local` 표현은 원래 기본 검정의 문자열로 되돌린다. 명시적 w와 개체 수 1의 경우 기존 경로로 실행한다. 제품 호출 후보는 공개 pcdtest를 사용하고, 원시 검증용 어댑터에서만 pcdres에 직접 같은 w를 전달한다.

이전 턴의 선택 원소 산술 변경은 어느 후보에도 합치지 않았다. 내부 함수 후보는 추가 호환성 검토 없이 제품의 일반 S3 호출을 대체할 수 있는 구현으로 취급하지 않는다.

## 전체 실행 시간

번들 R 4.5.3, seed 939, 2,000명 × 6시점(12,000행), 두 공변량과 시간 항, 비가중 gaussian FE/RE의 기본 민감도·가정 검사를 사용했다. 후보별 독립 프로세스 3개를 순차 실행했다. 워밍업 후 두 번째 프로세스는 후보를 먼저 측정했다. 로딩을 제외하고 결과 캡처와 정규화를 포함한다. 두 후보는 각각 같은 실행 내 현재 제품과 비교했으며 서로 다른 실행의 시간으로 후보 간 차이를 직접 추정하지 않는다.

| 후보 | 모형 | 현재 1 / 2 / 3 (초) | 후보 1 / 2 / 3 (초) | 중앙값 |
|---|---|---|---|---|
| 내부 함수 | FE | 3.39 / 2.99 / 3.26 | 2.80 / 2.98 / 2.30 | 3.26 → 2.80 |
| 내부 함수 | RE | 2.87 / 3.08 / 2.53 | 2.34 / 2.47 / 2.45 | 2.87 → 2.45 |
| 공개 인자 | FE | 3.05 / 2.96 / 3.03 | 2.37 / 2.83 / 2.36 | 3.03 → 2.37 |
| 공개 인자 | RE | 2.33 / 2.80 / 2.34 | 2.53 / 2.53 / 2.55 | 2.34 → 2.53 |

내부 함수 시제품은 두 모형 모두 세 번 빨라졌다(FE 두 번째는 0.01초 차이). 공개 인자 대안은 FE 세 번 개선, RE 한 번 개선·두 번 증가였다. RE 중앙값 증가가 관찰된 공개 대안을 공통 경로에 적용하지 않았다. 내부 시제품은 효과가 있지만 패키지 내부 코드에 대한 의존과 유지보수 비용이 남는다. 이번 결과로 모든 자료의 성능이나 차이의 내부 원인을 단정하지 않는다.

각 후보의 워밍업 6건과 측정 6건에서 정규화한 전체 반환 결과, 조건 클래스·본문·순서, 표준 출력 및 RNG가 `identical(..., num.eq = FALSE)`로 일치했다. formula/terms 환경과 함수 표현을 정규화하며 원시 환경 객체 동일성까지 주장하지 않는다. 같은 정상 자료의 반복 비교이고 실제 모형 반환도 확인했다.

## 원시 검정 및 경계 조건

각 후보에 대해 개체 수 2/5/30 × 균형/일부 행 제외/한 개체가 한 시점만 존재/상수 잔차 × 인접행렬 NULL/대칭/하삼각/전부 0/잘못된 차원의 60개 조건을 비교했다. 개체 수 1에서도 같은 자료·인접행렬 조합 20개를 별도 검사했다.

각 후보 80건, 합계 160건에서 원시 htest 전체 필드·속성, 조건 클래스·본문·순서, 표준 출력 및 RNG가 수치 허용오차 없이 일치했다. 오류 사례는 오류 보존 비교이며 성공 검정 건수로 해석하지 않는다. 2,000개체 자료의 원시 결과 및 메모리 계측 실행 결과도 각각 일치했다. 모든 임의 사용자 클래스·S3 확장을 검증한 것은 아니다.

## 메모리 할당

별도 원시 검정 실행에서 2,000명 × 6시점 잔차 자료로 워밍업 후 Rprofmem을 사용했다. 수치는 검정과 캡처에서 관측된 누적 할당이다.

| 경로 | 누적 할당 바이트 | 가장 큰 단일 할당 바이트 |
|---|---|---|
| 기존 | 597,534,664 | 32,000,048 |
| 내부 함수 시제품 | 277,227,720 | 32,000,048 |
| 공개 인자 대안 | 517,212,552 | 32,000,048 |

내부 함수 시제품은 약 53.6%, 공개 대안은 약 13.4% 감소했다. 최대 상주 메모리나 peak heap 측정은 아니며 가장 큰 단일 할당도 최대 동시 메모리가 아니다. 전체 상관행렬은 그대로 남는다.
