# 데이터 화면 첫 생성과 UI JIT 후보 검토 — 2026-09-14

## 판단

제품 코드는 변경하지 않았다. 초기 데이터 화면의 주요 비용은 DT 출력 생성보다 첫 번역 라벨 호출 경로에 있었다. UI 생성 동안만 JIT를 끄고 반환 시 복원하는 후보는 UI 생성 시간을 줄였지만, 첫 상관·생존분석까지의 전체 흐름에서 일관된 이득이 없어서 적용하지 않았다.

## 세부 측정

번들 R 4.5.3, JIT 3, 유효한 모듈 캐시를 사용했다. 패키지·모듈 로드와 환경설정 이후 UI를 생성했다. 각 조건은 새 프로세스에서 3회 순차 실행했고 두 번째 비교는 실행 순서를 뒤집었다.

`data_tab_panel()` 복사본의 환경에만 함수 래퍼를 넣었다. 래퍼는 인수를 평가한 뒤 대상 함수 시간을 측정한다. 제품이나 패키지 네임스페이스는 수정하지 않았다.

| 구간 | 1회 | 2회 | 3회 |
| --- | ---: | ---: | ---: |
| 첫 `statedu_ui_label()` 호출 | 0.12 | 0.11 | 0.11 |
| DTOutput 5개 호출 합계 | 0.02 | 0.00 | 0.01 |
| 계측 없는 전체 UI | 0.36 | 0.34 | 0.34 |
| 데이터 화면 내부 계측 전체 UI | 0.34 | 0.34 | 0.34 |
| UI 호출 전 JIT를 끈 탐색 조건 | 0.18 | 0.19 | 0.20 |

단위는 초다. 번역 라벨 시간은 `statedu_t()`와 `statedu_translate()` 등 하위 호출을 포함한다. 래퍼의 직접 `statedu_t()` 측정값은 이 중첩 호출을 별도로 포착하지 않는다. 따라서 0.11초 전부를 특정 번역 함수의 계산이나 컴파일이라고 단정하지 않는다. 0.00초는 비용이 없다는 의미가 아니다.

탐색 조건 9개 실행의 HTML, 의존성, 난수 상태, 경고·메시지가 동일했다. 자동 숫자 탭 ID만 정규화했다.

## 범위를 제한한 후보와 후속 분석

후보는 `app_ui()` 본문 첫 부분에서 이전 JIT 수준을 저장하고 0으로 설정하며, `on.exit()`에서 복원한다. 전역 JIT를 계속 끈 탐색 조건과 구별하여 별도 측정했다. 기존 서버 초기화 최적화는 양쪽 모두 그대로 사용했다.

가시성을 설정한 MockShinySession으로 UI 생성·HTML 렌더링, 서버 초기화, 데이터 업로드·변수 선택, 상관분석, KM 생존분석 및 동일 입력 재실행을 수행했다. 다음은 각각 3회 중앙값이다.

| 단계 | 기존 | 후보 |
| --- | ---: | ---: |
| UI 생성 | 0.36 | 0.22 |
| UI HTML 렌더링 | 0.07 | 0.06 |
| 서버 초기화 및 첫 flush | 0.71 | 0.64 |
| 업로드·변수 선택 | 0.78 | 0.67 |
| 상관분석 설정 | 0.82 | 0.74 |
| 첫 상관분석 | 0.75 | 0.77 |
| 생존분석 설정 | 1.75 | 1.86 |
| 첫 KM 분석 | 3.00 | 3.06 |
| 상관분석 재실행 | 0.01 | 0.01 |
| KM 재실행 | 0.03 | 0.03 |
| 전체 흐름 | 8.24 | 8.30 |

전체 흐름 원자료는 기존 8.14/8.39/8.24초, 후보 8.55/8.30/7.76초다. UI 생성 중앙값은 약 39% 줄었지만 전체 중앙값은 약 0.7% 늘었고 쌍별 개선 방향도 달랐다. 측정 변동과 후속 초기화 비용을 분리할 수 없어 전체 성능 개선으로 채택하지 않았다. 단계별 중앙값의 합은 전체 중앙값과 다를 수 있다.

이 측정은 Electron 기동, 브라우저 DOM 렌더링, 콜드 디스크 시작을 포함하지 않는다. 재실행은 동일 입력의 기존 분석 캐시를 포함한다.

## 검증과 재현

- 최종 3쌍의 초기 UI, 상관·KM 분석 객체, 결과 HTML·의존성, 경고, 알림이 `identical(..., num.eq=FALSE)`로 일치했다. 초기 UI의 자동 숫자 탭 ID만 정규화했다.
- 각 프로세스에서 첫 분석과 재실행의 분석 객체도 동일했다.
- 후보의 JIT 수준 0·1·2·3에서 정상, 오류, 인증 거부, 경고 경로 총 16개가 원래 수준을 복원했다. 난수 상태와 조건 전달도 검증했다.
- 제품 `R/ui_helpers.R` SHA256은 `7D82C5AB8707320AF2D9596B41ACD0A8AE94B8B9E28B3074C7C9BDECE7815E5D`로 이전 검토와 동일하다.
- 탐색 자료: `output/startup-data-widget-profile-20260914/`.
- 후보·전체 흐름·복원 검증 자료: `output/startup-ui-jit-20260914/`의 `baseline.R`, `candidate.R`, `measure.R`, `compare.R`, `verify_restore.R`, CSV와 RDS. 파일명의 `current`는 실험 후보를 뜻하며 제품 적용을 뜻하지 않는다.
- 제품 코드와 분석 출력 변경이 없어 내보내기 변환과 설치 파일 빌드는 실행하지 않았다.

다음 후보는 번역 라벨 첫 호출 경로의 초기화 구성이다. JIT 전체를 끄는 대신 반복 자료 구성 여부를 먼저 확인한다.
