# 벌점 회귀 예측 경로의 보간 필요성 검토

## 결론

교차검증 fold 예측은 단순한 기존 계수 열 선택으로 대체할 수 없었다. 관측된 450회 모두 요청한 lambda 중 해당 fold 모형의 경로에 없는 값이 포함되어 있었다. 반면 선택된 lambda의 계수 추출 90회는 경로에 있는 값만 사용했으나 누적 시간이 0.05–0.07초였다. 이번에는 보간 생략이나 패키지 예측 함수 대체를 적용하지 않았다.

제품 `R/analysis_penalized.R`은 변경하지 않았다. 제품과 시작 스냅샷 SHA256은 `502C3EC1E0A2D9C2F8E6932A9E255B195D8E86618DD702837D2DC7EADCE1BAD2`로 일치했다.

## 확인한 구현

설치된 glmnet의 buildPredmat.default는 fold별 모형에 전체 모형의 lambda 경로를 전달한다. predict.glmnet은 lambda.interp로 위치와 가중치를 구하고 두 계수 행렬을 Diagonal 가중치로 곱해 더한다. 이후 입력 행렬과 곱해 예측한다.

fold 모형들은 훈련 자료가 달라 lambda 경로도 다를 수 있다. 측정에서는 450회 예측 모두 요청 lambda 전체가 fold 경로에 포함되는 조건을 만족하지 않았다. 모든 개별 lambda가 경로 밖이라는 뜻은 아니며, 일부 값은 기존 열과 일치할 수 있다. 보간을 완전히 생략할 근거는 없다.

## 측정

번들 R 4.5.3, 자료 seed 939, 분석 seed 7731, 1,000행·설명변수 20개, gaussian, Ridge/LASSO/Elastic Net, alpha_grid 0.25/0.5/0.75, 방법별 부트스트랩 20회, 워커 1개다. 독립 프로세스 3개를 순차 실행했다. 워밍업 후 비계측 전체 실행과 별도 예측 계측을 수행했다. 로딩은 제외하고 캡처를 포함한다.

| 항목 | 호출 수(각 실행) | 1 / 2 / 3회 시간(초) |
|---|---:|---|
| 전체 분석, 비계측 | 해당 없음 | 1.48 / 1.50 / 1.48 |
| 경로 밖 lambda를 포함하는 link 예측 | 450 | 0.32 / 0.38 / 0.35 |
| 경로 내 lambda의 계수 추출 | 90 | 0.05 / 0.07 / 0.06 |
| 경로 내 lambda의 link 예측 | 6 | 0.00 / 0.00 / 0.00 |

0.00초는 타이머 해상도에서 잡히지 않은 값이지 계산 비용이 없다는 뜻이 아니다. 전체 glmnet 객체 predict 호출은 각 실행 594회였다. 표의 546회 외에 s가 NULL인 호출 48회가 있다. lambda 포함 여부가 NA인 이 호출은 경로 내/밖 집계에서 제외했다. 시간은 계측 실행의 함수 구간 누적이며 비계측 전체 시간과 직접 더하거나 빼지 않는다.

계수 추출의 작은 비용만으로 전체 성능 개선을 주장하지 않는다. fold 예측의 희소행렬 생성 비용은 후속 검토 후보지만 연산 순서와 보간 결과를 보존하는 별도 후보 검증이 필요하다. 이번 작업은 그 후보의 구현·속도 개선을 입증한 것이 아니다.

## 계측의 동일성

각 프로세스에서 워밍업, 비계측, 최종 계측 실행의 전체 반환 객체·조건 클래스/본문/순서·표준 출력·RNG가 `identical(..., num.eq=FALSE)`로 일치했다. 허용오차나 반환 객체 정규화는 사용하지 않았다. 정상 자료 반복 검증이며 다양한 오류 조건의 검증은 아니다.

초기 계측은 `list(...)`로 모든 인자를 강제 평가하여, 원래 offset 없는 예측에서는 평가하지 않는 newoffset=off_sub 인자 때문에 중단됐다. 이는 계측 도구가 만든 오류이며 제품 오류가 아니다. 초기 로그를 보관하고, 필요한 s와 type만 선택해 평가하도록 수정한 뒤 3개 프로세스를 모두 실행했다. 최종 동일성 검사는 수정된 계측에 해당한다. trace는 검증 프로세스 안에서만 사용하고 해제했다.
