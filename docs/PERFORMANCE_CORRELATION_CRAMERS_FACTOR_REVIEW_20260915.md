# Cramér’s V 중복 factor 정리 제거 검토

## 결론

제품에는 반영하지 않았다. 명목형 자료에서는 반복 측정 모두 단축됐으나, 연속형·명목형 혼합 자료에서 시간이 증가했다. 자동 컴파일을 비활성화한 추가 측정에서도 같은 문제가 남아, 전체 상관분석에 적용할 근거가 충분하지 않았다. 이 결과만으로 중복 factor 제거 자체가 혼합형에서 느려지는 원인이라고 단정하지 않는다.

## 후보

`correlation_cramers_v_result`의 두 `droplevels(factor(pair$x/y))`를 `factor(pair$x/y)`로 바꾼 후보를 별도 환경에서 시험했다. factor 생성 뒤 수준을 다시 정리하는 중복을 줄이려는 변경이다. 교차표 생성, `chisq.test(correct=FALSE)`, 계수·p값 계산과 결측 처리는 그대로 두었다. 원본 제품 소스는 수정하지 않았다.

## 검증

10종 입력의 모든 조합 100개에서 기존/후보 함수의 반환값·진단·stdout·난수 상태가 `identical(..., num.eq=FALSE)`로 일치했다. 정수, 인접 실수, 문자·빈 문자열·한글, 사용하지 않는 수준이 있는 factor/ordered, NA 수준, 논리형, 무한대/NaN, 빈 입력, 상수를 포함했다. 길이는 조합별 최대 길이로 반복하여 맞췄다. 오류 반환도 비교 대상으로 수집했다.

100개 경계 조건은 각 프로세스에서 반복 확인한 동일한 사례 집합이다. 별도의 원시 `htest` 내부 객체나 사용자 정의 클래스 전체를 검증한 것은 아니다.

전체 결과 준비는 10,000행·20변수·190쌍의 명목형/혼합형, 변수별 무작위 결측 0/10%의 네 조건을 사용했다. 명목형은 여섯 범주, 혼합형은 연속형 10개와 명목형 10개다. Pearson 지정, 정규성 검사 및 잠재상관은 비활성화했다. 자료 생성은 직전 명목형 프로파일과 동일한 시드 33을 사용했다.

두 실험 모두 새 R 프로세스 세 개를 순차 실행하고, 양쪽 예열 후 전체 결과 준비와 진단·stdout·난수 수집 시간을 측정했다. 두 번째 프로세스에서는 조건 및 기존/후보 순서를 뒤집었다. 총 24개 전체 결과 비교가 모두 정확히 일치했다. 결과 수치에 정규화·반올림·허용오차를 적용하지 않았다.

## 시간

첫 실험은 각 환경의 상관분석 소스 함수를 명시적으로 컴파일했다. 두 번째는 동일 준비 후 `compiler::enableJIT(0)`으로 이후 자동 컴파일을 비활성화했다. 이미 컴파일된 코드는 유지되므로 모든 함수를 인터프리터로 실행한 실험은 아니다. 프로세스 메모리나 모든 의존 함수의 상태를 통제한 것은 아니다.

표는 세 실행의 중앙값(초)을 소수 둘째 자리로 표시한 것이다.

| 자료 | 기본 JIT 기존 | 기본 JIT 후보 | JIT 비활성 기존 | JIT 비활성 후보 |
|---|---:|---:|---:|---:|
| 명목형 | 0.25 | 0.17 | 0.24 | 0.17 |
| 명목형, 결측 10% | 0.23 | 0.18 | 0.23 | 0.17 |
| 혼합형 | 0.34 | 0.42 | 0.33 | 0.42 |
| 혼합형, 결측 10% | 0.31 | 0.30 | 0.30 | 0.29 |

명목형 두 조건은 두 실험의 총 12회 모두 단축됐다. 결측 없는 혼합형의 기본 JIT 실행은 0.35→0.42초, 0.32→0.32초, 0.34→0.46초였다. JIT 비활성 실행도 0.33→0.44초, 0.33→0.34초, 0.34→0.42초로 개선되지 않았다. 따라서 명목형의 이득만을 근거로 공통 함수 변경을 적용하지 않았다. 혼합형 증가의 구체적 원인은 분리하지 않았다.
