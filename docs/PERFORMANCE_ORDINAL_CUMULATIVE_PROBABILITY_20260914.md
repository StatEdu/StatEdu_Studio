# 큰 순서형 확률 행렬의 누적확률 계산 개선 — 2026-09-14

## 적용

`R/analysis_logistic.R`에 `logistic_cumulative_probability()`를 추가하고 순서형 로지스틱 회귀의 apparent ranked probability score 계산에 연결했다. 일반 double 행렬이면서 **5만 행 이상·20열 이상**일 때 행별 `cumsum()`을 `vapply()`로 모아 기존 `apply()`의 중간 행렬 재배열을 줄인다. 나머지 입력은 기존 `t(apply(..., cumsum))` 경로를 사용한다.

각 행의 cumsum 순서, 마지막 범주 제외, 관측 누적확률 구성, 제곱·rowSums·mean 순서를 유지했다. 행렬 dimnames도 복원한다. 모형 적합, 계수·표준오차·검정, 출력 문구·형식은 변경하지 않았다.

## 후보 선정 근거

3·6범주에서는 직접 행 접근 후보가 더 느려 일반 입력에 적용하지 않았다. 5만 행에서 5회 누적확률 계산의 중앙값은 3범주 0.12→0.18초, 6범주 0.15→0.20초였다.

반면 큰 범주 수에서는 속도와 할당량이 함께 줄었다. 새 프로세스 3개를 순차 실행하고 두 번째 쌍은 후보부터 실행했다. 입력과 준비 실행은 시간 밖이다.

| 입력 | 기존 5회 시간 중앙값 | 후보 5회 시간 중앙값 | 기존 1회 총 할당 | 후보 1회 총 할당 |
| --- | ---: | ---: | ---: | ---: |
| 50,000 × 20 | 0.34초 | 0.28초 | 61,400,432B | 44,600,400B |
| 50,000 × 50 | 0.54초 | 0.47초 | 157,801,184B | 117,001,392B |

5,000행의 20·50범주에서는 명확한 시간 이득이 없어서 적용 조건에 포함하지 않았다. Rprofmem 값은 누적 할당량이며 최대 메모리나 RSS가 아니다. 20범주에서 해당 구간의 총 할당량은 약 27.4% 줄었다.

## 실제 순서형 모형의 성능 지표 계산

두 예측변수·20수준 순서형 자료에서 MASS::polr 모형을 2,000행으로 적합한 뒤 50,000행의 `logistic_apparent_performance()` 전체를 측정했다. 예측, clipping, 정확도·log loss·ranked probability score 계산을 포함한다. 모형 적합 시간은 제외했다.

각 값은 같은 지표 계산 5회 합계(초)다.

| 반복 | 기존 | 후보 |
| --- | ---: | ---: |
| 1 | 3.49 | 3.22 |
| 2 | 3.26 | 2.42 |
| 3 | 3.04 | 2.87 |
| 중앙값 | 3.26 | 2.87 |

중앙값 약 12% 감소이며 세 쌍 모두 빨랐다. 모델 적합이나 프로그램 전체가 12% 빨라졌다는 의미는 아니다. 각 쌍의 전체 지표 벡터와 난수 상태가 `identical(..., num.eq=FALSE)`로 일치했다.
