# 공분산분석 저장 성능 측정 — 2026-09-14

## 결론

공분산분석의 다음 최적화 대상은 저장용 그림의 반복 생성이다. 결과 변수 4개, 그림 20개 조건에서 반복 HTML 생성 중앙값은 4.33초였다. 별도 프로파일 실행에서는 전체 4.44초 중 `plot_data_uri`가 3.90초(약 88%)를 차지했다. 보정평균 계산은 합계 0.01초로, 먼저 수정할 병목은 아니었다.

이번 단계는 측정과 후보 선정이며 운영 R 코드를 변경하지 않았다. 속도 향상을 구현했다는 의미는 아니다.

## 방법과 측정값

- Windows, 번들 R 4.5.3, 기존 앱 부트스트랩과 사용자 설정 사용.
- 관측치 2,000개, 집단 4개, 연속 공변량 2개, 결과 변수 1개 또는 4개.
- 자동 방법 변경을 경고 모드로 설정하고 정규성 검사는 비활성화. 분석은 측정 전에 완료했다.
- 결과 변수마다 보정평균, 원자료 중첩, 회귀선, 공변량별 선형성 진단 2개: 총 5개 또는 20개 PNG.
- 실제 PNG 크기 3,400 × 2,500, 사용자 그림 설정에 따른 600 DPI.
- 조건별 독립 프로세스 3회, 두 번째 쌍은 실행 순서를 반대로 했다. 프로파일은 추가 독립 프로세스로 실행했다. 측정 작업끼리 동시에 실행하지 않았다.
- CSS는 `benchmark.css`로 고정하여 외부 편집으로 인한 출력 차이를 방지했다.
- 최초 값은 해당 프로세스에서 첫 저장용 HTML 생성이며, 앱 시작·분석·파일 변환 시간은 포함하지 않는다.

## 동일성 검증

각 프로세스의 최초·반복 출력과 조건별 4개 프로세스(일반 3회, 프로파일 1회)의 HTML 전체, 내장 PNG, 경고·메시지, 표준 출력, 난수 상태가 정확히 일치했다. PNG 서명과 크기, 5개·20개 개수를 확인했다. 렌더링 전후 분석 결과 스냅샷도 동일했다.

스냅샷 검증은 복제본의 lm 잔차·적합값 이름을 일반 문자열로 정규화한 뒤 직렬화한다. R의 지연 문자열 표현 차이와 환경 객체의 복제에 따른 거짓 실패를 피하기 위한 검증 처리이며, 원본 수치·이름 또는 운영 코드를 변경하지 않는다. 초기 단순 복제 객체 `identical` 검사는 실패하여 측정 결과에 포함하지 않았고, 위 스냅샷 검증을 적용해 전 회차를 다시 실행했다.

출력을 변경하지 않은 조사 단계이므로 PDF·Word·HWPX·Excel 변환 성능이나 실제 메모리 사용량은 이번에 측정하지 않았다.
