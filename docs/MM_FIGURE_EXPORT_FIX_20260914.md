# 그림 저장 base64 오류 수정

- 재현: R의 `base64_enc()` 줄바꿈이 로드된 Chrome 이미지의 `currentSrc`에서 `%0A`로 표현된다. 이를 바로 `base64_dec()`에 넘기면 `Error in base64 decode`가 발생한다.
- 브라우저 전송 전에 URL 이스케이프와 base64 공백을 정상화한다. 서버도 기존 브라우저 URL을 받을 수 있도록 같은 처리를 지원한다. 큰 PNG의 처리 지연을 피하도록 URL 이스케이프는 한 번에 치환한다.
- 모형, 조절효과, J-N 그래프의 원본 PNG 바이트를 유지한다. 손상된 데이터는 파일을 쓰기 전에 거부한다. 분석 결과의 표시 내용과 문서 내보내기 경로는 변경하지 않는다.
- 검증: `scripts/validate_mm_figure_snapshot.cjs`에서 이미지 로딩 완료 후 `%0A`가 포함된 URL로 실제 저장 동작을 실행했다. `scripts/validate_mm_figure_snapshot.R --check`에서 정상화된 전송과 기존 브라우저 URL 모두 3개 PNG의 바이트 일치 및 손상 데이터 거부를 확인했다.
- 설치본은 이 수정에서 다시 생성하지 않았다.

## 후속 공통 수정

- 네 분석의 그림 저장 수신기를 `register_canvas_report_exports()`로 통일했다. 모형 PNG와 현재 결과의 PNG를 분석별 새 폴더에 저장한다. 모형 파일 저장은 기존 공통 `dialogs.save()`를 유지한다.
- Windows 폴더 선택은 `FolderBrowserDialog`를 사용한다. 파일 이름 `Select this folder` 및 `Open` 버튼을 사용하는 우회 방식을 제거했다.
- PNG는 표준 디코더로 해독한 뒤 재인코딩 결과와 비교한다. 선택적인 끝 패딩이 없는 유효한 base64도 허용하며, 잘못된 문자와 PNG가 아닌 데이터는 거부한다. 사용자 모형에서 발생한 두 번째 오류의 원본 전송 데이터는 확보하지 못했으므로 패딩이 실제 원인이라고 단정하지 않는다.
- 경로/조절 연결/노드를 삭제하면 네 분석 공통으로 결과 상태를 무효화하고 선택 모드로 돌아간다. 배치를 보존하고 이전 계수를 제거하며, 실행 취소 시에도 이전 계수가 되살아나지 않는다.
- `validate_canvas_common_save_edit.cjs`: 네 분석의 결과 상태 해제, 시각적 수정 시 결과 유지, 실행 취소, 그림 저장 전달, 수정된 모형 파일 저장을 검증했다. R 검증은 네 분석 PNG의 원본 바이트 일치, 패딩 유무, URL 이스케이프, 손상 입력 거부, 폴더 선택 스크립트를 확인한다.
