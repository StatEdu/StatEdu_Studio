# 생존분석 저장 HTML·PNG 단계별 비용 — 2026-09-14

## 결론

8개 그림을 포함한 저장 HTML의 큰 비용은 HTML 문자열 조립이 아니라 600dpi PNG 출력이었다. 실제 그림 그리기와 장치를 닫아 PNG를 완성하는 단계가 대부분을 차지했다. 이번에는 제품 코드를 변경하지 않았다. 해상도나 출력 장치를 바꾸지 않았으며, 앞서 픽셀 불일치로 탈락한 PNG 장치 교체도 재적용하지 않았다.

## 측정 범위

번들 R 4.5.3, JIT 3, 유효한 모듈 캐시에서 기존 KM 분석 객체를 사용했다. 분석은 다시 실행하지 않았다. 4가지 곡선 × 색상/흑백으로 총 8개 저장 그림을 만들었다. 기존 그림 함수 내부의 JIT 제어와 지연 평가 순서를 유지했다.

상위 함수 계측 3개 프로세스, PNG 문장별 추가 계측 3개 프로세스를 순차 실행했다. 계측을 끈 기준 HTML은 앞선 저장 실험의 파일을 사용했다. 따라서 최적화 전후 속도 비교가 아니며 실행 시점과 계측 비용의 영향을 포함한다.

## 상위 구간

상위 함수만 계측한 첫 3회 중앙값(초):

| 구간 | 시간 |
| --- | ---: |
| HTML 콘텐츠 전체 | 10.07 |
| 결과 패널 구성 | 0.49 |
| 저장 그림 명세 생성 | 0.01 |
| 그림 삽입 함수 전체 | 9.54 |
| 그 안의 plot_data_uri 8회 합계 | 9.36 |
| 최종 노드 HTML 직렬화 합계 | 0.07 |

시간은 포함 시간이다. 그림 삽입에 plot_data_uri와 노드 직렬화가 포함되므로 합산하면 안 된다. 전체 HTML 시간 원자료는 9.67/10.08/10.07초다. 이전 실험의 8초대 값과의 차이를 제품 성능 악화로 해석하지 않는다.

## PNG 내부 구간

`plot_data_uri()`의 메모리 복사본에 각 문장 전후 시계를 삽입했다. 인수를 미리 강제 평가하거나 새로운 함수 평가 환경으로 옮기지 않았다. 기존 반환값, 장치 정리와 임시 파일 삭제 동작을 유지했다.

추가 계측 3회의 8개 PNG 합계 중앙값(초):

| 구간 | 시간 |
| --- | ---: |
| PNG 장치 열기 | 0.33 |
| plot_function 호출: 그림 구성 및 그리기 | 4.57 |
| dev.off: 장치 종료 및 PNG 완성 | 3.38 |
| PNG 파일 바이트 읽기 | 0.05 |
| base64 변환과 URI 결합 | 0.00 |

0.00초는 측정 분해능에서 작은 값이라는 의미이며 비용이 없다는 의미가 아니다. PNG 장치 종료 시간을 순수 파일 시스템 쓰기 시간으로 단정하지 않는다. PNG 인코딩과 장치 내부 마무리가 포함될 수 있다.

각 실행에서 `analysis_figure_dpi()`는 600이었다. 명세 1000×720, 입력 res=110이 기존 정책에 따라 5455×3927픽셀로 출력된다. 추가 계측의 전체 HTML 시간은 10.41/8.83/9.02초로 변동이 있었으므로 소수점 단위의 개선 추정에 사용하지 않는다.

## 동일성 검증과 후속 판단

- 총 6개 계측 실행의 그림 포함 HTML 문자열, 경고·메시지와 난수 상태가 기존 비계측 기준과 `identical(..., num.eq=FALSE)`로 일치했다. 이미지 URI도 문자열 비교에 포함된다.
- 제품 소스, 분석 공식, 그래프 해상도·장치·축 정렬·캡션을 변경하지 않았다.
- 제품 변경이 없어 현재/누적 PDF·Word·HWPX·Excel 변환과 설치 파일 빌드는 실행하지 않았다.
- PNG 장치 교체는 기존 `PERFORMANCE_SURVIVAL_PNG_BACKEND_REVIEW_20260914.md`에서 픽셀 불일치를 확인했다. 같은 접근을 다시 적용할 근거는 없다.

이 경로에서 HTML 조립이나 base64 처리를 우선 최적화할 근거는 약하다. 동일 그림을 불필요하게 다시 그리는 호출이 확인될 때 기존 PNG를 재사용하는 방향이 가능하지만, 이번 8개 그림은 종류와 버전이 달라 동일 이미지로 합칠 수 없다. 이후에는 다른 분석·저장 경로의 중복 계산이나 중복 렌더링을 우선 조사한다.
