# 현재 로지스틱 회귀 병목 측정 — 2026-09-14

다음 우선 검토 대상은 다항 회귀 표준오차 계산에 쓰이는 `nnet:::multinomHess()`의 반복 작업 행렬 구성이다. 5만 행에서 이 경로가 전체 프로파일 표본의 약 32~34%를 차지했다. 이번 작업은 병목 확인이며 운영 코드는 변경하지 않았다. 개선율을 측정한 결과는 아니다.

## 전체 분석 시간

연속 예측변수 6개를 2개씩 추가하는 3단계 위계적 모형을 사용했다. 아래는 새 프로세스 3회의 비프로파일 경과 시간이다.

| 행 수 | 입력 및 실제 모형 | 3회(초) | 중앙값(초) |
|---|---|---|---|
| 5,000 | 이항 → 이항 | 0.07 / 0.08 / 0.08 | 0.08 |
| 5,000 | 순서형 → 순서형 | 0.17 / 0.19 / 0.18 | 0.18 |
| 5,000 | 명목형 → 다항 | 0.31 / 0.31 / 0.33 | 0.31 |
| 50,000 | 이항 → 이항 | 0.87 / 0.86 / 0.87 | 0.87 |
| 50,000 | 순서형 → 다항 자동 전환 | 3.64 / 3.66 / 3.63 | 3.64 |
| 50,000 | 명목형 → 다항 | 3.09 / 3.11 / 3.11 | 3.11 |

순서형 자료의 기존 평행선 검정 p값은 5천 행에서 약 0.7912001, 5만 행에서 약 0.0418991이다. 따라서 5만 행 순서형 입력의 시간은 평행선 검정과 다항 회귀를 포함하며, 순수 순서형 회귀의 확장 성능으로 해석하면 안 된다. 실제 반환 모형명을 확인해 표에 반영했다.

## 병목 근거

5만 행 프로파일에서 하위 호출을 포함하는 total 비율이다. 서로 포함 관계가 있어 비율을 합산하면 안 된다.

| 경로 | 이항 3회(%) | 명목형 다항 3회(%) | 순서형 입력의 다항 전환 3회(%) |
|---|---|---|---|
| `fit_logistic_model` | 51.35 / 50.67 / 51.32 | 84.48 / 83.69 / 84.48 | 76.86 / 76.26 / 76.56 |
| `nnet::multinom` | 표본 없음 | 52.16 / 51.93 / 52.16 | 43.14 / 42.80 / 42.97 |
| `multinomHess` | 표본 없음 | 32.33 / 31.76 / 32.33 | 33.33 / 33.46 / 33.59 |
| `logistic_vif_diagnostics` | 41.89 / 41.33 / 42.11 | 6.03 / 6.44 / 6.90 | 6.27 / 5.84 / 5.86 |
| `logistic_parallel_odds_test` | 표본 없음 | 표본 없음 | 13.33 / 13.62 / 13.28 |

번들 nnet 구현을 직접 읽어 `installed-multinomHess.R`에 보관했다. 이 함수는 관측 행마다 범주를 순회하며 영행렬에서 작업 행렬을 만들고, 열을 대입·제거하고, 중심화한 뒤 `crossprod` 결과를 누적한다. 계수 표를 만드는 `summary(model)`의 공분산 경로에서 호출된다. `logistic_multinom_coef_table()`는 summary를 한 번 호출하므로 중복 summary 호출 제거 대상으로 보지 않는다.

후속 후보는 행/범주 인덱스와 작업 행렬 준비 비용을 줄이되 `crossprod`, 곱셈, 누적 순서를 유지하는 것이다. 후보 속도와 전체 표준오차·검정값의 정확한 동일성은 아직 확인하지 않았다. 행렬 곱으로 수식을 일괄 대체하면 부동소수점 합산 순서가 달라질 수 있으므로 같은 결과라고 가정하지 않는다.

이항에서는 VIF 보조회귀 비용이 크다. 그러나 기존 `PERFORMANCE_VIF_SUMMARY_REVIEW_20260913.md`의 summary 생략 후보는 이득이 작아 미채택되었고, 현재 로지스틱 VIF 결과 공유도 이미 적용되어 있다. 이를 새로운 개선 성과로 중복 계산하지 않는다.

## 재현 및 결과 확인

- 번들 R 4.5.3, 설치된 패키지와 기존 모듈 캐시를 사용했다. 시드 719의 정규 예측변수와 로지스틱 오차/이항 반응을 생성했다. 입력 생성 과정은 `profile.R`에 고정했다.
- 크기별 새 프로세스 3개를 순차 실행했다. 각 프로세스에서 이항→순서형→명목형 순서로 준비 실행 1회, 비프로파일 측정 1회, 0.01초 간격 Rprof 1회를 수행했다. 다른 R 작업을 동시에 실행하지 않았다.
- 패키지/모듈 로딩과 입력 생성·사전 GC는 시간에서 제외했다. 전체 결과 준비와 진단/표준출력 수집 및 비교용 공식 환경 정규화는 포함했다. 화면, 내보내기, 앱 로딩 시간은 포함하지 않았다.
- 모든 실행에서 3개 모형과 각 단계의 예상 N을 확인했다. 18개 프로세스 내 조건 실행 각각에서 준비/측정/프로파일 결과를 비교했다. 6개 크기·자료 조건 각각에서 새 프로세스 3개 간 저장 결과도 일치했다.
- 전체 반환값·경고/메시지·표준출력·난수 상태를 `identical(..., num.eq=FALSE)`로 비교했다. 공식의 환경 참조만 `.GlobalEnv`로 통일했으며 수치 허용오차를 사용하지 않았다. 최초 검증 보조 함수의 NULL 목록 원소 대입 오류는 실험 코드에서 수정한 후 전체 실행했다.
- 5천 행 이항의 표본은 4~6개에 불과해 세부 병목 판단에 사용하지 않았다. 5만 행은 이항 74~76, 순서형 입력 255~257, 명목형 232~233개 표본이다. 프로파일 표본 시간과 실제 경과 시간은 서로 다르다.
