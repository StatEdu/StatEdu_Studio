# 다항 Brier 점수 중간 행렬 축소 후보 검토 — 2026-09-14

## 결정

제품에는 적용하지 않았다. 관측 범주를 표시하는 큰 0/1 행렬을 생략하는 후보는 메모리 할당을 줄였지만, 실제 다항 모형의 전체 예측 성능 지표 계산에서 실행 시간이 개선되지 않았다. 앞서 적용한 순서형 누적확률 개선은 그대로 유지한다.

## 후보

기존 계산은 `mean(rowSums((probabilities - observed_matrix)^2))`다. 후보는 확률의 제곱 행렬을 만든 뒤 각 행의 실제 관측 범주 위치만 `(p - 1)^2`로 바꾸고 기존과 같은 `rowSums`·`mean`을 수행한다. 행별 합산 순서를 바꾸는 대수적 축약식을 사용하지 않았다.

검증용 helper는 일반 double 행렬, 10만 셀 이상, 3범주 이상, 각 행에 대응하는 유효한 정수 범주 인덱스일 때만 후보를 사용한다. 작은 입력·결측 인덱스·범위 밖 인덱스 등은 기존 경로를 유지한다.

초기 별도 후보는 확률 행렬을 복사한 뒤 관측 위치에서 1을 빼는 방식이었다. 이는 할당이 오히려 늘어 제외했다. 최종 후보는 `square.R`와 `helper.R`에 있다.

## 계산 구간만 측정한 결과

번들 R 4.5.3, JIT 3, 새 프로세스 3개를 순차 실행했고 두 번째 쌍은 후보부터 실행했다. 입력 생성과 준비 실행은 시간 밖이다.

50,000행·20범주에서 Brier 계산 20회 중앙값은 기존 0.10초, 제곱행렬 후보 0.08초였다. 한 번의 누적 할당량은 17,200,288→9,800,336바이트로 약 43% 감소했다. 이 미세 측정은 최종 helper의 입력 가드를 포함하지 않으며 전체 분석 속도 수치가 아니다.
