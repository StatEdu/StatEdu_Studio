# 사후검정 후보의 컴파일 영향 감사 및 정정

## 정정

직전 집단 문자열 재사용 후보의 16집단 연속시간 0.33초 대 2.29초 차이를 후보 연산 자체의 성능 저하로 해석해서는 안 된다. 하위 `survival_weighted_rank_test`를 양쪽 모두 명시적으로 컴파일하자 큰 차이가 사라졌다. 상위 사후검정 함수만 컴파일했던 이전 비교는 불충분했다.

보정한 측정에서는 16집단의 전체 준비 중앙값이 양쪽 모두 약 0.33초로 뚜렷한 이득도 없었다. 후보 미적용 결정은 유지하지만 그 근거는 ‘큰 성능 저하’에서 ‘보정 후 유의미한 이득 미확인’으로 수정한다. 제품 코드는 변경하지 않았다.

## 추적

동일한 5,000행·16집단·연속시간·Breslow 자료를 예열하고 Rprof로 각각 한 번 추적했다. 표본 간격은 0.005초다. 후보에서는 비용 증가가 문자열 선택 함수보다 `survival_weighted_rank_test`에 집중됐다. 이 함수는 수정한 사후검정 밖의 전체 검정에서도 호출되므로 집단 문자열 변환만으로 차이를 설명하기 어려웠다.

Rprof의 전체 표본 시간은 기준 0.110초, 후보 0.795초였다. 이 값은 실제 경과 시간과 다르며 정확한 벽시계 점유율이나 성능 개선율로 사용하지 않는다. `audit.R`과 `audit-*.Rprof`, `audit-*-total.csv`에 원시 자료를 보존했다.

이후 상위 사후검정 함수와 하위 가중 순위검정 함수를 양쪽 모두 `compiler::cmpfun`으로 컴파일하고, 기존과 같은 전체 분석 비교를 새 R 프로세스 3개에서 다시 수행했다. 이는 연구용 조건 통제이며 제품에 강제 컴파일을 추가한 것이 아니다. 이번 감사로 JIT의 모든 내부 상태나 다른 함수의 컴파일 상태를 완전히 통제했다고 주장하지 않는다.

## 보정한 결과

5,000행, 4/16집단, 연속/동점 시간, Breslow/Tarone–Ware, 진입 없음, 그림 제외. 전체 결과 준비와 반환값·진단·stdout·난수 상태 수집을 포함한다. 예열 후 순차 측정하고 두 번째 프로세스는 순서를 뒤집었다.

보정 비교 24개 모두 전체 반환값·경고/메시지/오류·stdout·난수 상태가 `identical(..., num.eq=FALSE)`로 일치했다. 정규화나 허용오차는 사용하지 않았다. 4집단에서는 여전히 큰 실행 변동이 있어, 일부 중앙값 차이를 일반적인 개선율로 삼지 않는다. 후보의 수치 동일성과 실행 속도의 인과 해석은 구분한다.

## 기록과 후속 기준

기존 보고서 `PERFORMANCE_SURVIVAL_POSTHOC_GROUP_REVIEW_20260915.md` 상단에 정정 링크를 추가했다. 과거 측정 파일은 지우지 않았으며 보정 자료는 `output/survival-posthoc-group-review-20260915/kernel-compiled.R`와 `kernel-compiled-timing-1.csv`부터 `kernel-compiled-timing-3.csv`로 분리했다.

앞으로 지역 함수 복사본을 사용하는 R 성능 후보에서 큰 차이가 나타나면 수정한 함수뿐 아니라 실제 비용을 차지하는 하위 함수의 컴파일 영향도 확인한다. 이 감사로 이전의 다른 최적화 측정 전체를 일괄 무효화하거나 재검증했다고 주장하지 않는다.

현재 `R/analysis_survival.R` SHA256은 이전과 동일한 `D32B8EA2305D08BF01CA8E4DF669386C1EF4C2934B3B7471F7D783BCAEE1FFF6`다. 제품·UI·내보내기 변경이나 배포 빌드는 수행하지 않았다.
