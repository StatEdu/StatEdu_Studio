# 단일 제외 사유의 문자열 결합 생략

`survival_preflight`에서 사유 개수를 한 번 계산하고, 사유가 하나인 행과 여러 개인 행을 나눈다. 단일 사유는 `unlist(..., use.names=FALSE)`로 기존 문자열을 추출하고, 여러 사유는 기존 `vapply(..., paste, collapse=';')`로 결합한다. 사유가 없는 행은 빈 문자열을 유지한다.

제외 마스크·행 순서·사유 순서·구분자·수치 연산과 모형은 변경하지 않았다. 내부 사유는 고정된 단일 문자 코드이고 목록에는 사유 문자열만 들어간다. 사유 개수와 인덱스 벡터를 추가로 보관하므로 메모리는 행 수에 비례해 증가한다.

처음 시험한 행별 `if(length(reason)==1)` 후보는 단일 사유에서 빨랐지만 중첩 결측 100,000행에서 약 9% 느려졌다. 최종 코드에는 행별 분기 대신 위의 일괄 추출을 적용했다. 초기 후보와 측정은 `output/survival-reason-label-20260915/branch-candidate.R` 및 상위 폴더 CSV에 보관하고 최종 측정과 구분한다.

## 검증

- `validate_survival_reason_label.R`: 빈 자료·1/30/120행, 정상·중첩·분산·전부 결측, 단일 기록·지연 진입·시작–종료, 변수 순서·중복 역할·집단/공변량 역할 중첩 등 전체 결과 96개 비교. 사용자 정의 결측 검사 2개, 반복 시간 인코딩/집단 사유 4개도 비교한다.
- 기존 사건 매핑 helper 294개와 전처리 36개는 별도 회귀 검사로 함께 실행한다.
- `benchmark_survival_reason_label.R`: 최종 코드로 두 독립 프로세스 각각 네 결측 조건 × 1,000/100,000행의 성공 전처리와 전체 결과 88개 비교.
- `validate_survival_reason_label_cox.R`: 정상/중첩/분산 결측 × Cox 기본/층화/군집/스플라인 12조건의 성공 모형·분석 행 수·유한 계수 및 전체 결과 비교.
- 전체 값/속성·진단·stdout·RNG는 `identical(..., num.eq=FALSE)`로 비교한다. Cox만 call 내부 수식의 `.Environment` 속성을 제외하며 수치 허용오차는 사용하지 않는다.
- 위 검사는 모두 통과했다. 기존 `validate_survival_preflight.R` 종합 검사도 실제 앱 초기화 후 통과했다.

## 측정 방법

번들 R 4.5.3, 실제 앱 모듈·환경설정 초기화, 동일 시드, 양쪽 함수 컴파일. 각 조건 준비 후 기존/변경을 번갈아 5회씩 실행한 중앙값. 전체 전처리와 진단/stdout 수집을 포함하고 동일성 비교는 타이머 밖에서 수행한다.

중첩 조건은 같은 절반의 행에 사건·집단·공변량 6개 모두 결측이다. 분산 조건은 공변량별 결측이 서로 다른 행에 있다. sparse는 사건 5%와 집단 5%가 서로 다른 행에 결측이다. 정상 조건은 결측이 없다. 기준은 직전 추가 사유 기록 개선까지 적용한 코드이며 여러 단계의 누적 개선율이 아니다.

초기 행별 분기 후보의 결과와 최종 결과를 같은 프로세스의 전후 값처럼 비교하지 않았다. 최종 표의 각 실행 안에서 동일 기준 함수와 비교한 값만 사용한다.
