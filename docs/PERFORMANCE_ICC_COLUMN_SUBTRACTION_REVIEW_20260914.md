# ICC 열 평균 차감 검토: 미적용

## 결론

행 평균 차감 개선에 이어 두 번째 잔차 계산을 `sweep(residual, 2L, col_means - grand, "-")`에서 `residual - rep(col_means - grand, each = n)`으로 바꾸는 후보를 시험했다. 수치와 진단 비교는 통과했지만 ICC(2/3) 모두 세 번 중 두 번 느려졌다. 제품에 적용하지 않고 기존 sweep을 유지했다. 이전 행 평균 차감 개선은 그대로다.

반복 벡터도 전체 원소 수만큼 생성하므로 이번 후보가 보조 메모리를 모두 없애는 것은 아니다. 별도 메모리 계측을 하지 않아 할당량이나 최대 메모리 감소를 주장하지 않는다.

## 부트스트랩 CI 계산 성능

번들 R 4.5.3, 자료 seed 939, 2,000행·20평가자·1,000회 재표집, seed 7731, 절대 일치·단일 측정 기준이다. 독립 프로세스 3개를 순차 실행했고 워밍업 후 두 번째 프로세스는 후보를 먼저 측정했다. 로딩을 제외한 CI 함수 및 캡처 시간이다. 화면 생성이나 저장을 포함한 전체 앱 실행 시간은 아니다.

| 모형 | 현재 1 / 2 / 3 (초) | 후보 1 / 2 / 3 (초) | 중앙값 |
|---|---|---|---|
| ICC(2) | 0.56 / 0.66 / 0.56 | 0.69 / 0.58 / 0.67 | 0.56 → 0.67초 |
| ICC(3) | 0.57 / 0.65 / 0.56 | 0.66 / 0.57 / 0.69 | 0.57 → 0.66초 |

두 번째 실행에서는 빨라졌지만 두 모형 모두 나머지 두 실행과 중앙값이 악화됐다. 측정 편차의 원인이나 모든 자료의 성능을 단정하지 않는다.

## 검증

- 워밍업과 측정 각각에서 CI 값, 조건 클래스·본문·순서, 표준 출력과 RNG가 `identical(..., num.eq=FALSE)`로 일치했다.
- 기존 ICC 검증 스크립트를 후보 소스를 로드하는 형태로 별도 복사하고 변경 직전 실제 소스를 참조로 전달했다. 세 모형, 일치/일관성, 단일/평균, 결측·상수·무한대·큰/작은 수치·작은/빈 입력 등을 포함한 156개 ICC/CI/조건/RNG 비교가 통과했다.
- 전체 결과 12개(ICC 3종 × 일치/일관성 × 단일/평균), 정규성 검사 및 결측이 있는 자료의 100회 부트스트랩을 비교했다. 전체 결과·진단·출력·RNG와 점추정/재표집 원시 ICC 값 총 1,212개가 일치했다. 수치 허용오차나 정규화는 사용하지 않았다.

동일성 시험 통과와 성능 개선 여부를 구분하여 판단했다. CI가 같다는 이유만으로 재표집 원값의 일치를 추정하지 않았다.
