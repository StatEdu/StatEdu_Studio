# 순서형 신뢰도 문항쌍 재사용 통합 — 2026-09-14

`R/analysis_reliability.R`에 적용했다. 실제 신뢰도 분석 호출 내부에서만 쌍별 추정 캐시를 만들고, 전체 및 문항 삭제 신뢰도 계산에 명시적인 함수 인수로 전달한다. 전역 분석 함수나 설치 패키지 네임스페이스를 교체하지 않는다. 결과에 캐시를 포함하지 않으며 다른 분석 호출이나 세션과 공유하지 않는다.

## 적용 범위와 보호 장치

- 순서형 계산 방법, 문항 삭제 신뢰도 또는 문항-전체 상관 요청, 64행 이상, 3~16문항, 변환된 모든 문항이 객체 속성 없는 유한 수치 벡터인 경우만 활성화한다. 결측·비유한 값이 있거나 그 밖의 조건이면 원래 `psych::polychoric`을 사용한다. 16문항의 전체 120쌍이 최대 128항목 캐시에 들어가도록 범위를 제한했다.
- psych 2.6.5, mnormt 2.1.2와 psych의 `polychoric`, `polyc`, `polyF`, `polyBinBvn`, `tableFast` 형식 인수/본문 SHA-256을 확인한다. 예상과 다르거나 설정 중 경고/오류가 나면 기존 함수를 선택한다.
- 쌍별 원자료, 임계값, 범주 범위와 계산 옵션을 모두 키에 포함하고 해시 조회 후에도 실제 인수 목록의 정확한 동일성을 확인한다. 경고/메시지가 있거나 난수 상태가 바뀐 결과는 저장하지 않는다. 추정 오류는 재시도하지 않는다.
- 각 행렬의 구성·결측 처리·보정과 alpha/omega 적합을 원래 순서대로 실행한다. 보정한 전체 행렬의 부분행렬을 그대로 반환하는 방식은 사용하지 않는다.

## 통합 후 시간

2,000건·8문항, 공통 정규 성분 0.6과 문항별 독립 정규 성분 0.8, 동일 확률의 5범주 자료를 사용했다. 자료 시드 719, 분석 시드 941, omega·normality·문항 삭제 신뢰도·문항-전체 상관을 요청했다. 결측 조건은 문항별로 독립적으로 200건을 제거했다.

번들 Windows R 4.5.3에서 버전별 새 프로세스 3개를 순차 실행하고 두 번째 쌍은 역순으로 실행했다. 조건별 준비 실행 후 GC하고 전체 분석을 측정했다. 준비 실행의 캐시는 측정 호출로 넘어가지 않는다. 캐시 검사/생성, 결과와 진단·표준출력 수집을 포함하며 앱/패키지 초기화, 자료 생성, UI와 저장은 제외한다.

| 조건 | 기존 3회(초) | 통합 3회(초) | 중앙값 |
| --- | --- | --- | --- |
| 완전 자료 | 1.27 / 1.17 / 1.19 | 0.39 / 0.38 / 0.39 | 1.19 → 0.39초 |
| 결측 자료 | 1.21 / 1.12 / 1.13 | 1.11 / 1.11 / 1.12 | 1.13 → 1.11초 |

완전 자료는 약 **67.2% 단축**됐다. 결측 자료는 캐시를 우회하므로 작은 시간 차이를 새 계산 최적화 효과로 해석하지 않는다. 이는 해당 조건의 국소 측정이며 프로그램 로딩 시간의 개선을 의미하지 않는다.

## 메모리 교환 관계

별도 새 프로세스 각 3개에서 완전 자료를 한 번 분석했다. 실제 R PID의 `PeakWorkingSet64`를 약 20ms 간격으로 관측했으며, 패키지/모듈 초기화·자료 생성·분석·결과 직렬화를 포함했다. 시간 측정과 동시에 실행하지 않았다.

| 반복 | 기존(bytes) | 통합(bytes) |
| --- | ---: | ---: |
| 1 | 277,204,992 | 310,108,160 |
| 2 | 277,348,352 | 308,834,304 |
| 3 | 277,250,048 | 311,152,640 |
| 중앙값 | 277,250,048 | 310,108,160 |

관측 최고 메모리는 **32,858,112 bytes(32.86 MB), 약 11.9% 증가**했다. 캐시 항목 수 제한은 전체 프로세스 메모리 상한을 의미하지 않는다. 이 비용을 함께 기록하고 완전 자료의 큰 시간 이점을 근거로 적용했다. Electron 전체나 동시 분석, 더 큰 자료의 메모리는 측정하지 않았다.

## 수치·우회·수명 검증

- 시간 측정 6쌍, 메모리 측정 3쌍의 전체 반환값·경고/메시지·표준출력·난수 상태가 `identical(..., num.eq = FALSE)`로 일치했다. 시간 측정의 준비/본 실행 결과도 같았다.
- `scripts/validate_reliability_pair_cache.R`: 버전/본문/설정 경고·오류 9개 우회 검사, 경고·메시지·난수 변경·추정 오류의 비저장/비재시도, 새 엔진 간 캐시 분리를 통과했다.
- 동일 스크립트의 행렬 비교 168개 통과. 12/80건, 2/3/5범주, 결측, 서로 다른 문항별 범주 수와 문항 삭제를 포함하며, 양의 정부호가 아닌 행렬의 보정 경로 59회도 유지했다.
- `validate_integration.R`: 순서형/연속형/이항, 결측 유무, 상세 옵션 유무의 전체 분석 12개에서 기준과 정확히 일치했다. 각 조건의 캐시 생성 횟수, 63행/17문항 우회, 128항목 제한과 오래된 항목 제거도 확인했다.
- 적용 소스와 측정 사본의 SHA-256이 동일하다: `8F412C7A5DD4EA8535EF548DB11562A3CA6B9A059FCE807764134907EE81DFEF`. 소스의 `git diff --check`를 통과했다.

## 화면 및 저장

전체 신뢰도 UI 렌더링, 저장 HTML과 현재/누적 HTML 파일이 기준과 정확히 같았다. 현재/누적 Excel도 시트·셀과 패키지 내용이 생성/수정 시각만 정규화하면 동일했다.

현재/누적 HTML·PDF·Word·HWPX·Excel 총 10개 파일을 생성했다. HTML의 비어 있지 않은 표 셀 120개/240개가 Word와 HWPX에서 내용별 빈도와 총수까지 일치했다. PDF는 2쪽/4쪽이며 신뢰도 요약과 문항 분석을 포함한다. 현재 PDF 두 페이지를 렌더링해 육안 확인했다. Word/Hancom 편집 화면의 별도 육안 검수는 수행하지 않았다. 설치 파일은 재빌드하지 않았다.
