# Start-stop 반복 검사의 열 직접 접근 — 2026-09-14

`survival_preflight()`의 대상자별 구간 검사에서 일반 데이터프레임의 `[[.data.frame` 접근을 반복하던 부분을, 같은 열을 담은 리스트의 직접 조회로 변경했다. 정확히 `data.frame` 클래스인 경우만 `unclass(frame)`을 읽기 용도로 사용하고 사용자 정의 하위 클래스나 tibble은 원래 객체로 접근한다.

열 값이나 열의 클래스는 변경하지 않는다. 정렬, 누적 최댓값, 겹침·사건 이후 구간·다중 사건 판단식과 계산 순서를 유지한다. 기존 단일 구간 생략과 대상자 위치 조회 최적화는 양쪽 모두 활성화되어 있다.

## 전체 입력 검증 시간

대상자 1만 명, 대상자당 1개 또는 2개 구간의 합성 자료를 사용했다. 각 구성의 총 행 수는 1만·1만5천·2만이다. 번들 R 4.5.3의 새 프로세스에서 모듈·설정 로딩 후 세 조건을 같은 순서로 측정했다. 프로파일러 없이 3쌍을 순차 실행하고 두 번째 쌍은 변형 순서를 뒤집었다. 비교 함수는 같은 전역 도우미 환경을 사용했다.

| 대상자 구성 | 변경 전 중앙값(초) | 변경 후 중앙값(초) | 해석 |
| --- | ---: | ---: | --- |
| 모두 단일 구간 | 0.17 | 0.16 | 차이 작음 |
| 단일/복수 구간 각 50% | 0.21 | 0.11 | 약 48% 단축 |
| 모두 복수 구간 | 0.40 | 0.19 | 약 53% 단축 |

| 반복 | 모두 단일 전/후 | 혼합 전/후 | 모두 복수 전/후 |
| --- | --- | --- | --- |
| 1 | 0.17 / 0.16 | 0.22 / 0.11 | 0.39 / 0.19 |
| 2 | 0.16 / 0.16 | 0.21 / 0.11 | 0.40 / 0.19 |
| 3 | 0.17 / 0.15 | 0.21 / 0.12 | 0.40 / 0.20 |

모두 단일 구간인 조건은 이미 반복 검사를 생략하므로 이번 변경의 속도 이점을 크게 해석하지 않는다. 위 수치는 입력 검증 전체 시간이며 Cox 적합이나 프로그램 시작 시간의 감소율이 아니다. 이전 개선율과 합산하지 않는다.

## 검증

- `scripts/validate_survival_interval_columns.R`: 48개 기존 입력 검증 사례의 전체 결과/오류, 조건과 RNG 일치.
- `verify_intervals.R`: 구간 구성, 잘못된·겹치는·순서가 뒤섞인 구간과 결측을 포함한 40개 사례 일치.
- `verify_ids.R`: 빈 문자열·공백·다국어·factor ID를 포함한 4개 사례의 결과 또는 기존 오류 일치.
- `verify_classes.R`: 사용자 정의 열 접근 메서드를 가진 데이터프레임 3개와 tibble 1개에서 전체 결과, 접근 메서드 메시지 순서·횟수, RNG 일치.
- 최종 대용량 9쌍의 전체 입력 검증 결과를 `identical(..., num.eq = FALSE)`로 비교하여 통과했다.
- `verify_integrated.R`: 150명 혼합 구간 자료의 실제 start-stop Cox 분석에서 입력 검증, 모든 데이터프레임 결과, 회귀계수·분산·로그우도, 조건 및 RNG가 정확히 같았다.
- 전체 Cox 패널 HTML과 개별·누적 Excel이 동일했다. Excel의 모든 비-core 내부 파일은 바이트 단위로 같았고 core도 생성·수정 시각만 정규화하면 동일했다.
- `git diff --check -- R/analysis_survival.R` 통과.

PDF/Word/HWPX 완성 파일과 설치 파일은 이번에 재생성하지 않았다.
