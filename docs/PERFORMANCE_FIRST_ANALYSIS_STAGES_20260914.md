# 첫 상관·KM 분석 실행 구간 검토 — 2026-09-14

## 결론

현재 코드의 첫 분석 실행을 다시 측정했다. 이번에는 제품 코드를 변경하지 않았다. 작은 검증 데이터의 첫 KM 실행에서는 그림 생성 경로가 가장 큰 측정 구간이었다. 위험집단 수 계산 자체의 병목으로 단정할 수 없으며, 첫 그래픽 의존성 초기화와 표시 준비를 포함한다.

## 범위와 측정값

번들 R 4.5.3, JIT 3, 유효한 모듈 캐시를 사용했다. 초기 UI 생성 후 MockShinySession에서 선택된 지연 출력만 표시하고 기존 `survival_validation.csv`를 업로드했다. Pearson 상관분석 후 KM 분석을 실행하고 동일 입력을 다시 실행했다. 각 프로세스는 순차 실행했다.

계측 없는 3회에서 첫 상관분석 handler/flush는 0.66/0.73/0.67초, 첫 KM handler/flush는 2.67/2.70/3.35초였다. 중앙값은 각각 0.67초와 2.70초다.

최종 계측 3회에서는 첫 상관분석 0.70/0.85/0.83초, 첫 KM 2.91/3.39/3.34초였다. 계측 및 실행 시점에 따른 차이가 있어 계측값을 비계측 실행의 정확한 시간 비율로 환산하지 않는다. 최종 계측값은 다음과 같다(초, 중앙값).

| 구간 | 시간 |
| --- | ---: |
| 상관분석 결과 준비 | 0.20 |
| KM 결과 준비 | 0.92 |
| KM 결과 패널 생성 | 0.78 |
| 위 패널 내부 단순 표 생성 12회 합계 | 0.49 |
| 곡선·위험집단 표 구성 및 그리기 전체 | 1.52 |
| 위 그림 경로 내부 위험집단 표 구성 | 0.95 |
| 위 그림 경로 내부 생존곡선 구성 | 0.06 |

중첩 시간은 합산하지 않는다. 특히 1.52초에는 0.95초와 0.06초가 포함된다. KM 결과 준비 시간은 의존성 초기화와 보고용 계산도 포함하며 순수 생존함수 추정 시간으로 표현하지 않는다. 반복 실행은 기존 캐시를 포함하므로 새로운 데이터의 계산 성능을 뜻하지 않는다.

## 계측 수정과 제한

첫 탐색 래퍼는 인수를 미리 평가했다. 하지만 그림 함수는 진입 후 JIT를 제어하므로 인수의 사전 평가가 원래 컴파일 범위를 벗어나고, 원래 위험집단 표를 먼저 평가하던 순서도 바꿀 수 있었다. 이 탐색값(`current-1..3`)은 최종 결론에서 제외했다. 최종 래퍼는 `original(...)`으로 원래 지연 평가와 순서를 보존하며 포함 시간을 기록한다(`current-final1..3`).

초기 하네스에 존재하지 않는 상관 결과 패널 함수명이 들어가 두 프로파일 실행이 시작 전에 중단됐다. 해당 계측 대상을 제거하고 성공한 최종 실행 3회만 비교했다. 계측 없는 3회는 성공했으며 결과 비교에 사용했다. 최종 계측은 별도 후속 묶음이므로 교차 순서의 최적화 전후 실험이 아니다.

Windows Rprof의 샘플 시간은 경과 시간과 같지 않으며, 이 보고서는 샘플 비율을 병목의 정확한 비중으로 사용하지 않는다. Electron 기동과 브라우저 DOM 표시 시간도 측정 범위 밖이다.

## 검증과 다음 대상

- 비계측/최종 계측 3쌍의 초기 UI, 분석 객체, 결과 HTML·의존성, 경고와 알림이 `identical(..., num.eq=FALSE)`로 일치했다. 초기 UI의 자동 숫자 탭 ID만 정규화했다.
- 각 프로세스에서 첫 실행과 재실행의 분석 객체가 동일했다.
- 그래프 좌표계 교체 안내 메시지는 기존 동작으로 양쪽에 나타났다. 이번에는 별도 PNG 픽셀 비교를 수행하지 않았다.
- 기존 그림 함수의 실제 시간축 범위 계산, 곡선·위험집단 표의 폭 정렬, JIT 제어를 유지했다. 표 스타일 재사용과 PNG 장치 검토 등 이미 수행한 작업도 재적용하지 않았다.
- 다음 조사 대상은 위험집단 표가 첫 그래픽 객체를 만들 때의 의존성 초기화와 객체 구성 비용이다. 패키지 사전 로드만으로 대기 시간을 앞당기는 변경은 전체 흐름 개선으로 간주하지 않는다.

제품 및 분석 출력 변경이 없어 문서 내보내기와 설치 파일 빌드는 수행하지 않았다. 재현 자료는 `output/first-analysis-stages-20260914/`의 `measure.R`, `compare.R`, `final-helper-totals.csv`, `final-helper-medians.csv`, 최종 CSV/RDS 및 프로파일에 있다. 이 폴더의 `baseline`과 `current`는 동일 제품 코드의 비계측/계측 조건을 뜻한다.
