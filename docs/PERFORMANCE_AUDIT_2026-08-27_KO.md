매개·조절의 부트스트랩 작업 자체는 회귀하지 않았다. 실제 앱과 같은 새 백그라운드 작업자 결과를 다시 측정한 결과 HTML 구성은 `2.59초`로 기존 5초 성능 기준을 통과했다. 10,000회 작업자는 첫 실행 `6.60초`, 세 번의 중앙값 `4.89초`였다. 최초 감사의 `8.33초` 렌더 지연은 재현되지 않았다.

CFA 신뢰도 부트스트랩은 격리형 callr 작업자와 lavaan 메타데이터 고속 경로를 실제 앱과 동일하게 활성화해 다시 측정했다. 최초 감사의 `247.50초 / 338.46초`는 이 옵션을 빠뜨려 양쪽 모두 직렬 공개 경로를 측정한 값이므로 폐기했다. 동일 시드·작업자 8개·청크 1,000 조건에서 현재 `11.16초`, 일요일 `15.49초`였으며 유효 적합은 양쪽 모두 997회였다. 현재 자동 청크 250 조건은 `11.79초`로 측정됐다.

일반 SEM의 실제 결측 FIML도 비제품 모형에 한해 데이터 프레임은 작업자에 한 번만 설치하고 이후에는 재표집 행 인덱스만 전송하도록 확장했다. 결측 10%·동일 seed에서 기존 `lavaanList`와 새 경로의 표본 인덱스, 유효 마스크, 원계수, 표준화계수, 최종 요약은 허용오차 0으로 일치했다. 2,000회·12작업자·청크250의 연속 A/B는 `184.44초 -> 129.73초`였다. 프로파일에서 반복별 관측정보행렬/Hessian 계산이 CPU의 약 43%를 차지함을 확인했다. 부트스트랩 추론은 각 반복의 모형기반 표준오차가 아니라 반복 계수 분포를 사용하므로, 실제 결측 비제품 경로의 파라미터 공분산 유효성 검사는 더 빠른 기대정보행렬로 계산한다. 1,000회에서 기존 관측정보 경로와 표본 인덱스·유효 마스크·원계수·표준화계수·최종 요약이 허용오차 0으로 일치했고 `96.45초 -> 30.21초`였다. 실제 앱 방식 5,000회는 `144.66초`, 유효 4,999회, 폴백 0회로 일요일 `234.76초`보다 38.4% 단축됐다. 15작업자는 더 느려 기본 상한 12를 유지한다. 제품지표와 실제 결측이 함께 있는 모형은 기존 보호 경로를 유지하며, 검증 범위를 넘는 5,000회 초과 사용자 지정 반복도 기존 `lavaanList`로 폴백한다.

## 결론 및 우선순위

1. 분석 메뉴 전반은 일요일보다 빨라졌다. 메뉴별 지연 등록 분리가 효과가 있다.
2. 완전자료 SEM 5,000회는 현재 약 31초로 복구·개선됐다. 기본 반복 수 5,000은 유지한다.
3. 실제 결측 FIML의 비제품 SEM에 인덱스 전송과 기대정보 유효성 검사를 적용했다. 기본 5,000회는 144.66초로 일요일보다 38.4% 단축됐다.
4. CFA 신뢰도 부트스트랩은 앱 실행 조건에서 1,000회 약 11~12초로 확인됐고, 일요일보다 약 28% 빠르다.
5. 매개·조절 결과 화면은 재측정에서 2.59초로 성능 기준을 통과했다.
6. 복합표본 회귀는 중복된 숨김 조사설계 UI를 제거해 반복 UI 생성 중앙값을 약 70% 줄였다.
