# Excel 문단 추출 재사용 검토 — 미적용 — 2026-09-14

Excel 저장에서 표 설명 배치와 별도 메모 시트 생성에 쓰이는 문단 추출을 한 번으로 줄이는 후보를 시험했다. 표 수집 함수의 선택 인자와 결과별 지연 평가를 이용해 첫 사용 시 추출하고 같은 결과 안에서만 재사용했다.

결과 동일성 검사는 통과했으나 실제 전체 저장 시간의 개선이 확인되지 않아 **적용하지 않았다**. 실행 소스는 실험 직전 스냅샷과 SHA-256이 동일함을 확인했다. 이전 HTML 문서 재사용 최적화는 그대로 유지한다.

## 전체 저장 측정

같은 30변수 상관분석 HTML, Excel 3개 시트, 번들 R 4.5.3을 사용했다. 각 변형은 새 프로세스에서 모듈과 설정을 로드한 뒤 측정했다. 프로파일러 없이 3쌍을 순차 실행하고 두 번째 쌍의 순서를 뒤집었다. 비교 함수는 같은 전역 도우미 환경을 사용했고 파일 검증은 측정 시간 밖에서 수행했다.

| 반복 | 기존(초) | 후보(초) |
| --- | ---: | ---: |
| 1 | 2.14 | 2.15 |
| 2 | 2.14 | 2.17 |
| 3 | 2.16 | 2.16 |
| 중앙값 | 2.14 | 2.16 |

후보는 중앙값 기준 0.02초 길었다. 이 차이만으로 유의한 성능 저하를 단정하지는 않지만, 추가 복잡성을 정당화할 개선 근거가 없다. 문단 추출 횟수 감소 자체를 전체 저장 속도 개선으로 해석하지 않는다.

## 검증 및 보관

- `scripts/validate_excel_paragraph_reuse.R`: 개별 표 9개와 누적 결과 1개 통과. 기본 표 데이터, 인쇄 방향, 개별 저장의 경고와 RNG 상태가 동일했다.
- `verify_context.R`: 표·그림·앞뒤 문단, 다이어그램 교체, 텍스트 전용 결과 3개와 누적 결과 통과. 다이어그램은 결정적인 PNG 반환 함수로 대체하여 문서 교체와 순서를 검사했다.
- 테스트한 표·그림 혼합 결과의 문단 추출은 실제로 2회에서 1회로 줄었다.
- 시트 이름, 읽어 들인 셀 값, 모든 비-core 내부 파일이 동일했다. core도 생성·수정 시각만 정규화하면 동일했다.
- 측정 파일 6개 모두 기준 파일과 내부 비교를 통과했고 저장 중 경고가 없었다.
- 실험 변경 철회 후 `R/result_saved_ui.R`가 변경 전 파일과 바이트 단위로 동일함을 SHA-256으로 확인했다. `git diff --check -- R/result_saved_ui.R`도 통과했다.

실험 자료는 `output/excel-paragraph-reuse-20260914/`에 보관했다. `baseline.R`는 기존 구현, `candidate.R`는 미적용 후보다. `common.R`는 후보 스냅샷을 명시적으로 읽으므로 이후 실행 소스가 바뀌어도 이 실험의 후보를 다시 비교할 수 있다. CSV에서 `current`는 적용된 코드가 아니라 실험 후보를 뜻한다.

`measure.R baseline|current <반복 ID>`와 `summarize.R`로 재현한다. 번들 Rscript `--vanilla`, English UTF-8 로캘, 번들 라이브러리, 패키지 자동 설치 비활성화, 별도 모듈 캐시를 사용한다. PDF/Word/HWPX 완성 파일과 설치 파일은 재생성하지 않았다.
