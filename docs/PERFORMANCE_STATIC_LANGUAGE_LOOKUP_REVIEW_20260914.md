# 정적 언어 스크립트의 언어 목록 조회 재사용 — 미채택 — 2026-09-14

초기 언어 스크립트 생성에서 지원 언어 목록을 한 번 읽고 내부 고정 문구 및 분석 방법 문구 생성에 공유하는 후보를 시험했다. 첫 생성 시간과 전체 UI 시간에 이점이 없어 운영 코드에 적용하지 않았다. 기존 스크립트 결과 캐시는 유지한다.

## 후보와 측정

`R/ui_helpers.R`의 `app_static_language_labels_script()` 내부에서 `statedu_supported_languages()` 결과를 보관하고, `static_label_row()`와 `method_label_rows()`의 반복 조회 대신 공유하도록 했다. 번역 행 자체의 언어별 대체 문구 처리는 변경하지 않았다.

번들 Windows R 4.5.3, JIT 3, 기존 모듈 캐시, 패키지 자동 설치 비활성 조건이다. 버전/조건별 새 프로세스 3개를 순차 실행했고 두 번째 세트는 후보부터 실행했다. 전체 UI 첫 호출과 스크립트 단독 첫 호출은 서로 다른 프로세스에서 측정했다.

UI 조건은 패키지·모듈 및 비교용 UI 소스를 읽고 서버 함수를 만든 뒤 첫 `app_ui()`를 측정했다. 스크립트 조건은 같은 준비 후 번역표를 먼저 초기화해 번역표 생성 비용을 제외하고, 아직 캐시되지 않은 정적 언어 스크립트의 첫 생성을 측정했다. 두 조건 모두 결과·진단·표준출력 수집을 포함하고, HTML 태그 렌더링은 측정 후 수행했다.

| 조건 | 기존 3회(초) | 후보 3회(초) | 중앙값 |
| --- | --- | --- | --- |
| 전체 첫 UI 구성 | 0.36 / 0.35 / 0.35 | 0.34 / 0.36 / 0.36 | 0.35 → 0.36초 |
| 번역표 초기화 후 스크립트 첫 생성 | 0.03 / 0.03 / 0.05 | 0.03 / 0.05 / 0.03 | 0.03 → 0.03초 |

UI의 작은 차이는 이 짧은 세 번의 측정으로 일반적인 악화라고 단정할 수 없지만, 후보가 더 빠르다는 근거도 아니다. 스크립트 자체의 중앙값도 같아 변경을 추가하지 않았다. 실제 Electron 시작이나 사용자 서버 세션을 측정한 결과는 아니다.

## 동일성 확인

전체 UI 3쌍과 스크립트 3쌍에서 HTML·의존성·경고/메시지·표준출력·난수 상태가 `identical(..., num.eq=FALSE)`로 일치했다. UI의 자동 생성 숫자 탭 ID만 정규화했다. 스크립트 조건에서는 첫 반환 객체와 캐시된 재호출 객체도 같았다. 이는 실제 설정에서의 비교이며 임의로 실행 중 언어 공급 함수를 바꾸는 조건까지 보장하는 검사는 아니다.

운영 파일은 기준 사본과 동일하다. SHA-256: `7D82C5AB8707320AF2D9596B41ACD0A8AE94B8B9E28B3074C7C9BDECE7815E5D`. 직전에 적용한 번역 overlay 값의 정수 위치 조회 최적화는 양쪽에 유지했다.

별도 메모리·분석·내보내기 검증이나 설치 파일 재빌드는 수행하지 않았다. 산출물은 `output/static-language-lookup-20260914/`의 기준/후보 소스, `measure.R`, `compare.R`, 시간 CSV 및 전체 UI/스크립트 스냅샷이다. `current.R`는 미채택 후보를 뜻한다.
