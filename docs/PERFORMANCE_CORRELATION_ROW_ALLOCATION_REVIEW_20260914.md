# 상관 결과표 행 목록 사전 할당 검토 — 2026-09-14

`correlation_pair_rows_and_matrices`의 결과표 행 목록을 쌍 개수만큼 미리 할당하고, 명시적 인덱스로 행과 CI 문자열을 저장하는 후보를 시험했다. 이전의 추정 결과 pair_results 목록 사전 할당 검토와 달리 이번 대상은 표시용 행 목록 rows다.

전체 분석 실행시간 개선이 확인되지 않아 적용하지 않았다. 후보는 output 디렉터리의 current.R에만 보관했으며 실행 모듈은 시작 시점과 SHA256이 일치한다.

## 측정

번들 R 4.5.3, 앱 환경 설정 적용, 자동 설치 비활성화. 100행의 숫자 자료, continuous_method=auto, 정규성 검사 활성화 조건에서 전체 prepare_correlation_results 실행을 측정했다. 새 프로세스에서 변경 전후 3쌍을 순차 실행했으며 두 번째 쌍은 순서를 반대로 했다. 각 프로세스는 10변수 다음 100변수를 실행했다. 기준/후보 함수는 같은 전역 환경에 연결했다. 검증은 시간 측정 종료 후 수행했다.

| 변수 수 | 기존 3회(초) | 후보 3회(초) | 중앙값 기존→후보 |
|---|---|---|---|
| 10 | 0.15 / 0.14 / 0.14 | 0.16 / 0.14 / 0.14 | 0.14→0.14 |
| 100 | 0.64 / 0.59 / 0.59 | 0.61 / 0.59 / 0.59 | 0.59→0.59 |

100변수는 4,950개 쌍이다. 첫 측정의 작은 차이가 후속 측정에서 재현되지 않았다. 사전 할당 자체가 전체 분석의 속도 개선으로 이어진다는 근거를 얻지 못했다. 메모리 할당량은 이번에 측정하지 않았다. 앱 로딩, 렌더링, 내보내기는 측정 범위에 포함하지 않는다.
