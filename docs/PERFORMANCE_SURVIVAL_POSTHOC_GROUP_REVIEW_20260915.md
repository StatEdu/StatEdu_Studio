# 생존분석 사후검정의 집단 문자열 재사용 후보

> 후속 정정: [컴파일 영향 감사](PERFORMANCE_SURVIVAL_POSTHOC_COMPILE_AUDIT_20260915.md)에서 하위 `survival_weighted_rank_test`까지 양쪽을 명시적으로 컴파일하자 큰 시간 차이가 사라졌다. 아래 기존 측정은 당시 실험 기록으로 보존하지만, 문자열 재사용 자체가 크게 느리다는 근거로 사용하지 않는다. 보정 비교에서도 16집단의 뚜렷한 이득은 없어 미적용 결정은 유지한다.

## 결정

후보를 적용하지 않았다. 당시에는 상위 사후검정 함수의 컴파일만 맞춰 비교했으나, 후속 감사로 이 통제가 불충분했음을 확인했다. 최종 판단은 위 후속 정정과 보정 측정을 따른다.

프로그램 코드는 변경하지 않았다. `R/analysis_survival.R`와 보존한 기준 소스의 SHA256은 모두 `D32B8EA2305D08BF01CA8E4DF669386C1EF4C2934B3B7471F7D783BCAEE1FFF6`다.

## 검토 범위

사후검정의 자료 선택은 집단 쌍마다 `data[[group]] %in% pair`를 계산한다. 후보에서는 쌍 순회를 시작하기 전에 `match_groups <- as.character(data[[group]])`를 만들고 `match_groups %in% pair`로 행을 선택했다. 행 순서와 이후 factor 수준 제거·검정·Holm 보정은 유지했다. 후보는 보존한 소스의 지역 복사본에서만 구성했다.

열 선택도 확인했으나 전체 분석 전처리는 이미 `role_variables`만 남긴다. 따라서 일반 전체 분석에서 수백 개의 미사용 열을 매 사후검정에 복사한다고 가정하고 최적화하지 않았다. 기존 생명표의 열 선택 개선은 다른 경로이며 이번에 반복 적용하지 않았다.

## 측정과 동일성

5,000행·4/16집단, 연속시간/동점 시간, Breslow/Tarone–Ware, 지연 진입 없음. 평가 시점 10/20과 기본 표를 사용하고 그림은 제외했다. 전체 결과 준비 및 반환값·진단·stdout·난수 상태 수집을 포함한 경과 시간이다.

1. 지역 복사 후보를 사용해 새 R 프로세스 3개에서 기존/후보를 예열한 뒤 순차 측정했다. 두 번째 실행은 순서를 뒤집었다.
2. 큰 시간 차이가 나와 컴파일 상태 영향을 추가 확인했다. 양쪽 `survival_km_posthoc_table`에 `compiler::cmpfun`을 명시적으로 적용하고 같은 조건을 새 프로세스 3개에서 다시 측정했다.

두 실험의 총 48개 전체 결과 비교에서 원시 반환값·경고/메시지/오류·stdout·난수 상태가 `identical(..., num.eq=FALSE)`로 모두 일치했다. 정규화나 허용오차는 사용하지 않았다. 두 실험의 시간을 섞어 중앙값을 계산하지 않았다.
