# 조절변수 이름 소문자 변환 재사용 — 2026-09-14

`meta_moderator_catalog()`에서 전체 조절변수 이름의 `tolower()` 결과를 한 번 계산해 재사용하도록 적용했다. 이전에는 이름·유형 조합마다 전체 이름 벡터를 다시 변환했다. 기존 대소문자 무시 비교, 출력 이름과 순서, 연구 수 집계는 유지한다. 직전 문자열 해석 캐시도 유지했다.

| 연구 1,000개의 조절변수 수 | 기존 3회(초) | 후보 3회(초) | 중앙값 |
|---|---|---|---|
| 2개 | 0.23 / 0.20 / 0.23 | 0.20 / 0.23 / 0.20 | 0.23 → 0.20 |
| 40개 | 0.66 / 0.69 / 0.66 | 0.30 / 0.25 / 0.31 | 0.66 → 0.30 |

40개 조건에서는 3회 모두 빨라졌으며 중앙값 기준 약 55% 감소했다. 2개에서는 두 번째 실행이 느려져 작은 자료의 일관된 개선은 주장하지 않는다. 각 연구에 같은 `Variable1=A; ...` 문자열을 넣었다. 따라서 직전 캐시가 적용된 상태에서의 추가 효과이며, 조절변수가 많은 합성 자료의 목록 생성 시간이다. 수치 모형 적합·화면·내보내기·전체 앱 시간의 개선율은 아니다.

번들 R 4.5.3의 새 프로세스 3개를 순차 실행했고 두 번째는 기존/후보 순서를 뒤집었다. 각 조건을 준비 실행하고 GC 후 측정했다. 입력 생성·소스 로딩은 제외하고 전체 목록 생성과 조건 수집을 포함했다. 다른 R 작업은 동시에 실행하지 않았다. 메모리는 측정하지 않았다.

두 변수 수 × 세 프로세스에서 전체 반환값·경고/메시지 문자열·난수 상태가 기존 소스와 `identical(..., num.eq=FALSE)`로 일치했다. 적용 후 실제 소스로 기준 결과 6개도 다시 비교했다. 수치 허용오차를 사용하지 않았다.

신규 `validate_meta_moderator_names.R`은 0/1/24행 × 대소문자·한글/악센트 문자·잘못된 문법·빈 값·결측·유형 혼합의 18개 조건에서 값·속성·오류/경고/메시지 클래스와 문자열·표준출력·난수 상태를 비교한다. 조건 객체의 호출 환경 자체는 비교하지 않는다. 이 검증과 기존 문자열 재사용 45개 조건, 모형·UI 검증이 통과했다.
