# 순서형 교차분석 추세 검정의 임시 데이터프레임 제거

2026-09-15. `R/analysis_crosstabs.R`의 순서형×순서형 추세 경로에서 빈도만큼 행을 복제한 임시 데이터프레임을 만들던 부분을 점수 벡터 추출로 바꿨다. 직전 Gamma 누적 합 개선은 그대로 유지했다.

## 변경과 보존 범위

기존에는 빈도표의 셀 인덱스를 관측 수만큼 반복한 뒤 두 점수 열을 데이터프레임으로 추출했다. 계산에는 열 벡터와 행 수만 필요했지만 중복 행 이름을 고유하게 만드는 작업도 수행됐다. 현재는 같은 반복 인덱스로 두 점수 벡터를 직접 추출하고 인덱스 길이를 관측 수로 사용한다.

**빈도 가중 공식으로 상관계수를 다시 계산하지 않는다.** 관측 단위 점수 벡터의 순서와 자료형, stats::cor 호출, `(n - 1) * r^2`, pchisq 및 Gamma 계산을 그대로 유지한다. 관측 단위 벡터와 반복 인덱스 자체는 여전히 생성하므로 빈도표 크기만큼의 메모리로 계산하는 방식은 아니다. 메모리 절감량을 별도로 측정하지 않았다.

## 정확성

`scripts/fixtures/crosstab_trend_reference.R`에 기존 구현을 보존하고 `scripts/validate_crosstab_trend_vectors.R`을 추가했다.

- 124개 비교: 반환값, 조건 클래스/본문/순서, 표준 출력, 최종 RNG가 `identical(..., num.eq=FALSE)`로 일치했다. 1·2·3·8·12차원, 정수/double 빈도, 0·1·2개 관측, NA/NaN/Inf, 음수/소수, 이름 없는 표와 중복 수준 이름, 순서형/범주형 조합을 포함한다. 2차원 이진 추세 등 변경되지 않은 경로도 포함된다.
- 26개 비교: 기존 데이터프레임에서 꺼낸 두 열과 현재 방식의 두 점수 벡터가 값·자료형·속성까지 정확히 일치하고, 기존 행 수와 반복 인덱스 길이가 일치했다.
- 아래 독립 프로세스 비교의 준비·측정 및 결측 추가 조건에서 전체 `prepare_crosstab_results` 반환값과 진단/RNG가 정확히 일치했다.
- 기존 `scripts/validate_crosstabs.R`이 HTML/Excel 저장 helper 검사까지 끝까지 통과했다.

## 전체 분석 시간

번들 R 4.5.3, 행/열 각각 12수준의 순서형 변수, 10,000 / 100,000 / 500,000행 합성자료다. 셀 빈도를 거의 균등하게 배분했으며 추세와 행/열/전체 백분율을 켰다. 충분한 기대빈도로 Monte Carlo Fisher 경로를 사용하지 않는다.

수정 전 기준은 **Gamma 개선까지 포함된 직전 소스**다. 기준/현재 모듈을 별도 환경에 로드하고 양쪽 함수에 동일하게 compiler::cmpfun을 적용했다. 독립 R 프로세스 3개를 순차 실행하고 각 조건의 준비 비교 뒤 3회를 측정했다. 두 번째 프로세스의 측정 순서는 반대로 했다.

|행 수|프로세스별 기준 중앙값(초)|프로세스별 현재 중앙값(초)|
|---|---|---|
|10,000|0.02 / 0.03 / 0.02|0.01 / 0.02 / 0.02|
|100,000|0.04 / 0.05 / 0.04|0.03 / 0.03 / 0.03|
|500,000|0.17 / 0.15 / 0.17|0.09 / 0.09 / 0.09|

50만 행의 중앙값은 약 0.17→0.09초, 약 47% 감소했다. 시간에는 분석과 동일한 진단/출력 캡처를 포함한다. 정확 비교, 초기 자료 생성·로딩, 브라우저 HTML 배치와 저장은 제외한다. 앱 전체 성능이나 모든 자료의 개선율로 일반화하지 않으며 작은 조건의 0.01초 차이를 정밀한 개선율로 해석하지 않는다.

표시·저장 형식을 변경하지 않았고 전체 반환값이 같음을 확인했으므로 모든 문서 형식의 재생성 및 설치 파일 빌드는 수행하지 않았다. 기존 저장 helper 통과를 전체 PDF/Word/HWPX 교차 형식 검증으로 표현하지 않는다.
