# Spearman 고유값 검사 캐시 검토 — 2026-09-14

## 결정

기존 순위 캐시에 고유값 검사 결과를 함께 보관하는 후보를 구현하고 검증했다. 검증 범위에서 결과는 정확히 같았으나 변수별 결측 자료에서 세 번 모두 느려져 제품에는 적용하지 않았다. 기존 상관분석 코드는 유지한다.

후보는 `cor.test.default`를 복사해 사용하는 기존 로컬 실행 환경에 `unique` 래퍼를 추가한다. 속성 없는 integer/double 입력이며 추가 인자가 없을 때만 캐시를 사용하고, 나머지는 `base::unique`로 처리한다. 기존 분석 단위 캐시 항목 수 제한을 공유하며 원래 고유값 벡터와 순위를 보관한다. 고유값 검사가 순위 계산보다 먼저 실행되므로 순위가 없는 항목은 나중에 원래 `base::rank`로 채운다.

## 실행 시간

번들 R 4.5.3, 시드 33, 10,000행·20변수·190쌍의 전체 Spearman 분석을 측정했다. 정규성 검사는 켰다. 동률 자료는 정규 난수를 반올림했으며 결측 자료는 변수마다 서로 다른 무작위 결측 10%를 넣었다.

변경 전후 각각 세 개의 새 R 프로세스를 순차 실행하고 두 번째 비교에서는 후보를 먼저 실행했다. 조건별 준비 실행 후 전체 분석을 10회 반복한 시간을 측정했다. 입력 생성, 프로그램 로딩, 화면 및 내보내기는 제외했다. 시간 측정과 다른 R 검증을 동시에 실행하지 않았다.

| 조건 | 기존 3회(초, 각 10분석) | 후보 3회(초, 각 10분석) | 중앙값 기존→후보 |
| --- | --- | --- | --- |
| 완전 자료 | 1.85 / 2.06 / 1.83 | 1.61 / 1.69 / 1.64 | 1.85→1.64, 약 11% 감소 |
| 동률 자료 | 1.89 / 2.92 / 1.89 | 1.80 / 2.47 / 1.58 | 1.89→1.80, 약 5% 감소 |
| 변수별 결측 10% | 4.46 / 4.97 / 4.42 | 5.77 / 6.33 / 4.77 | 4.46→5.77, 약 29% 증가 |

두 번째 실행 묶음 등에서 시간 변동이 있었다. 감소율은 이 자료와 반복 실행 조건에 한정된다. 특히 결측 조건은 세 비교 모두 후보가 느렸다. 이전 호출 감사에서 확인한 것처럼, 변수마다 결측 위치가 달라지면 쌍별 완전 관측치 입력이 모두 달라 재사용이 되지 않는다. 추가 캐시 탐색과 보관은 이 조건에서 불리했다. 메모리 사용량은 이번 실험에서 별도로 측정하지 않았다.

## 동일성 검증

- 캐시 제한 1·2·20, Spearman/Pearson/Kendall, exact FALSE/TRUE/NULL 조합을 검사했다.
- double, integer, 상수, NA/NaN, 무한대, 양·음의 0, 빈 입력, 길이 1·2, 이름 있는 입력, Date 입력을 반복 호출했다.
- 총 594개 경계·재사용 사례에서 전체 반환값, 오류 메시지, 경고/메시지, 표준 출력, 난수 상태가 `identical(..., num.eq=FALSE)`로 일치했다. 각 실행의 캐시 항목 수 제한도 검사했다.
- 전체 분석 세 조건 × 세 프로세스의 9쌍에서 결과·경고/메시지·표준 출력·난수 상태가 정확히 일치했다. 각 측정 내 준비 실행과 마지막 반복 결과도 일치했다.

제품 및 표시·내보내기 내용은 변경하지 않았고 새 내보내기 검증은 수행하지 않았다. 후속 후보는 결측 처리로 입력이 달라지는 경우를 제외하고 캐시를 제한하는 방식이다. 제한 판단 비용까지 포함한 측정이 필요하며, 이번 결과만으로 해당 방식의 효과를 확정하지 않는다.
