# 생존 부트스트랩 결과 수집 인덱스 검토

2026-09-14. 결과 수집에서 집단별 행 인덱스를 재사용하는 후보를 검토했으며 제품에는 적용하지 않았다.

## 실제 분석 내 계측

600/2,000건, 3집단, 부트스트랩 60회, 선택 시점 0·10·20으로 현재 보정 생존곡선을 준비 실행한 뒤 조건별 3회 분석했다. 각 성공한 부트스트랩에서 다음 행 선택 및 대입 구간만 계측했다.

`boot_values[[level]][iteration, ] <- boot_curve$Survival[boot_curve$Level == level]`

| 데이터 | 계측 포함 전체 시간 | 60회 결과 수집 합계 |
|---|---|---|
| 600건 | 0.97 / 1.18 / 1.15초 | 0.00 / 0.00 / 0.00초 |
| 2,000건 | 5.98 / 5.99 / 6.34초 | 0.00 / 0.00 / 0.01초 |

0.00초는 비용이 없다는 뜻이 아니다. 구간마다 타이머 해상도보다 짧을 수 있어 아래 묶음 측정을 추가했다. 위 시간은 하나의 프로세스에서 수행한 계측 포함 측정이며, 이전의 독립 프로세스 성능 비교와 누적 비교하지 않는다.

계측은 원래 수집 코드를 그대로 실행하며 시간과 호출 수만 추가로 기록했다. 계측 전후 전체 반환값·경고·메시지·표준출력·난수 상태가 `identical(..., num.eq=FALSE)`로 일치했고 각 분석의 성공한 수집 호출은 60회였다.

## 수집 연산 묶음 측정

집단별 2,001행, 3집단의 고정 합성 곡선으로 수집 연산 3,000회를 실행했다. 버전별 3회 순차 실행하고 두 번째 비교 순서를 바꿨다. 기존 방식과 사전 계산 인덱스 방식의 결과 행렬은 정확히 일치했다.

| 수집 방식 | 3,000회 중앙값 | 60회로 비례 환산 |
|---|---:|---:|
| 기존 문자열 비교 | 0.25초 | 0.0050초 |
| 사전 계산 인덱스 | 0.08초 | 0.0016초 |

고정 곡선이 메모리에 있는 미세 측정이며 실제 부트스트랩 개선율을 측정한 것이 아니다. 인덱스 구성 비용도 후보의 측정 구간에서 제외했다. 유리한 조건에서도 환산 절감량은 약 0.0034초/60회로 작았다. 실제 곡선이 매번 달라지는 상황의 상한이나 정확한 예상 절감량으로 해석하지 않는다.
