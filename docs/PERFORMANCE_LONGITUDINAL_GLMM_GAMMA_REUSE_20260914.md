# 무작위 절편 Gamma GLMM 선택 모형 재사용

## 적용 범위

`R/analysis_longitudinal.R`에서 선택 모형 재사용을 `family = "gamma"`, `random_slope = FALSE`인 GLMM까지 확장했다. 같은 분석 안의 동일한 데이터와 적합 옵션으로 만든 선택 모형을 민감도 분석에서 재사용하며, 대안 구조는 새로 적합한다.

경고·메시지가 발생하거나 RNG 상태가 달라진 적합은 재사용하지 않는다. 정상 재사용에서는 앱 적합 함수 호출이 3회에서 2회로 줄어든다. 기존 이항/Poisson 적용 범위와 보호 조건은 유지한다.

Gamma 무작위 기울기 모형은 이번 확장에서 제외했다. 초기에는 두 설정을 검토했으나 추가 검증 자료에서도 기울기 적합에 진단이 발생해 정상 재사용 사례를 확보하지 못했다. 해당 모델의 수치가 틀렸다는 판단은 아니며, 검증한 범위에 맞춰 절편 모형만 적용했다.

## 성능 측정

번들 R 4.5.3, seed 939, 500명 × 6시점 = 3,000행, 두 공변량, Gamma 반응(shape 3), 기본 분석 옵션을 사용했다. 자료 생성에는 무작위 절편과 기울기를 포함했다. 워밍업 후 독립 프로세스 3개를 순차 실행했고 두 번째 프로세스는 후보부터 측정했다. 로딩 시간은 제외했다.

| random_slope | 변경 전 1 / 2 / 3 (초) | 후보 1 / 2 / 3 (초) | 중앙값 |
|---|---|---|---|
| FALSE | 1.72 / 1.47 / 1.72 | 1.11 / 1.31 / 1.13 | 1.72 → 1.13초, 약 34% 감소 |
| TRUE | 1.61 / 1.59 / 1.61 | 1.62 / 1.58 / 1.61 | 1.61 → 1.61초 |

FALSE에서는 세 번 모두 빨라졌다. 대안 모형에서 발생한 진단 조건 2개는 유지했다. TRUE에서는 진단 조건 4개가 유지되어 보호 조건에 따라 재적합했고, 성능 개선을 주장하지 않는다.

이 표는 TRUE도 검토하던 초기 후보 측정이다. 이후 최종 코드에서 TRUE를 명시적으로 제외했다. 측정 자료의 TRUE는 이미 진단으로 재사용하지 않았으며 FALSE 경로는 그대로다. 최종 제한 코드의 동일성은 아래 검증으로 확인했지만 시간 측정은 다시 실행하지 않았다. 위 개선율은 해당 자료·환경의 측정이다.

## 동일성 및 회귀 검증

`scripts/validate_longitudinal_glmm_gamma_reuse.R`의 20개 조건에서 전체 반환 결과, 조건 클래스/본문/순서, 표준 출력, 최종 RNG를 비교했다. 기울기 FALSE/TRUE 각각에서 정상 자료, 경고/메시지/RNG 소비/오류 주입, exponentiate FALSE, sampling 가중치, 결측/역순 자료, 이름 있는 행을 검사하고 LMM 두 설정의 기존 호출 수를 확인한다.

정상 절편 재사용 5개, 재적합 유지 13개, 오류 2개가 통과했다. 반올림 전 AIC/BIC와 특이성 판정, 적합 호출 수도 비교했다. 지속 검증의 참조 경로에서는 Gamma 선택 모형 재사용을 끄며, 변경 전 소스를 직접 로드한 20개 비교도 통과했다.

merMod는 고정/무작위효과, 공분산, 적합값, 잔차, logLik, theta, devcomp, optinfo, call, model frame을 추출한다. formula/terms 환경과 함수 표현만 정규화하며 `identical(..., num.eq = FALSE)`로 수치를 허용오차 없이 비교한다. 모든 내부 슬롯·외부 포인터의 동일성까지 주장하지 않는다.

기존 Poisson 검증 20개와 이항형 검증 20개도 재실행하여 통과했다. Poisson 스크립트의 종전 Gamma 비적용 사례는 새 Gamma 스크립트에서 검증하며, Poisson 스크립트에서는 LMM 기울기 모형의 비적용을 검사하도록 바꿨다.
