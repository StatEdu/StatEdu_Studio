# 혼합 잠재 상관의 변환 캐시 효과 검증 — 2026-09-14

이전 순서형 변환 캐시 변경을 연속형 4개·순서형 4개 혼합 자료에서도 확인했다. 이번에는 실행 코드를 추가로 변경하지 않았다. 비교 기준은 해당 캐시 적용 직전의 모듈과 현재 모듈이며, 이번 측정값은 이전 변경의 효과다.

## 측정 결과

1만 행·8변수, 순서형은 3범주다. latent_correlations=TRUE, continuous_method=auto, normality=TRUE로 전체 prepare_correlation_results 호출을 측정했다. 번들 R 4.5.3과 설치된 polycor를 사용하고 자동 설치는 비활성화했다.

새 프로세스에서 변경 전후 3쌍을 순차 실행했으며 두 번째 쌍은 순서를 바꿨다. 각 프로세스는 완전 자료, 변수별 독립 결측 10%, 모든 변수에 동일한 행의 결측 10% 순서로 실행했다. 각 스냅샷의 함수를 같은 전역 환경으로 연결했다. 테스트·호출 계측을 시간 측정과 동시에 실행하지 않았다.

| 조건 | 변경 전 3회(초) | 변경 후 3회(초) | 중앙값 전→후 |
|---|---|---|---|
| 완전 자료 | 0.82 / 0.82 / 0.82 | 0.67 / 0.67 / 0.69 | 0.82→0.67 |
| 변수별 독립 결측 10% | 0.50 / 0.53 / 0.52 | 0.50 / 0.52 / 0.50 | 0.52→0.50 |
| 같은 행에 결측 10% | 0.56 / 0.55 / 0.54 | 0.42 / 0.42 / 0.42 | 0.55→0.42 |

완전 자료는 약 18%, 결측 행이 같은 자료는 약 24% 단축됐다. 독립 결측 조건의 0.02초 차이는 작고 측정 범위가 겹치므로 뚜렷한 개선으로 해석하지 않는다. 조건마다 실행 순서와 완전 관측치 수가 다르므로 조건 간 절대 시간을 직접 비교해 원인을 추론하지 않는다. 앱 로딩·화면 렌더링·내보내기 시간은 포함하지 않았다.

## 재사용 조건 확인

혼합 자료에는 Pearson 6쌍, polyserial 16쌍, polychoric 6쌍이 있다. 별도의 계측 실행에서 애플리케이션 ordered() 호출은 완전 자료와 동일 행 결측에서 각각 28→4회, 독립 결측에서 28→28회였다. 따라서 결측값의 유무 자체보다 쌍별 완전 관측치 선택 후 같은 순서형 벡터가 반복되는지가 캐시 효과를 결정한다.

입력 벡터와 범주 목록을 정확히 비교하는 기존 캐시 조건을 유지했다. 더 넓은 재사용을 위해 결측 처리나 빈 범주 제거 규칙을 바꾸지 않았다.

## 동일성 및 남은 검토

- 시간 측정 9쌍에서 전체 결과·진단·난수 상태가 identical(..., num.eq=FALSE)로 일치했다.
- 호출 계측 6건에서도 계측하지 않은 각 기준 실행과 전체 결과·진단·난수 상태가 일치했다.
- 세 자료 조건의 HTML 및 의존성 객체가 각각 일치했다.
- 현재 실행 모듈과 보관한 current.R의 SHA256 일치를 확인했다.

설치된 polycor의 polyserial 구현에서는 BFGS 최적화 및 Hessian 계산 중 정규밀도·누적확률과 행렬 연산을 반복한다. 불변 중간값의 재사용은 추가 검토 후보지만, 이를 적용하려면 외부 추정 함수의 내부 구현을 별도로 유지하거나 대체해야 한다. 이번에는 해당 함수를 변경하지 않았다. ML, std.err, 최적화 제어 및 수치 계산 순서도 유지했다. 이번 작업은 혼합 자료에서 기존 개선 효과와 적용 한계를 확인한 것이며 새로운 성능 개선을 적용했다고 주장하지 않는다.
