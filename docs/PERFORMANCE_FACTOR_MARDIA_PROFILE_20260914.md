# 요인분석 Mardia 검사 시간·메모리 확인 — 2026-09-14

다변량 정규성 검사에서 큰 자료의 병목을 확인했다. `factor_analysis_mardia_table()`은 `centered %*% inv_cov %*% t(centered)`로 관측치 수의 제곱 크기 행렬을 생성한 뒤 `mean(distances^3)`를 계산한다. 이번에는 제품 코드를 변경하지 않았다.

## 전체 분석과 검사 시간

| 행 수 / 변수 12개 | 전체 요인분석 3회(초) | 별도 계측 실행의 Mardia 3회(초) |
|---|---|---|
| 750 | 0.08 / 0.07 / 0.07 | 0.02 / 0.03 / 0.03 |
| 1,500 | 0.15 / 0.17 / 0.15 | 0.10 / 0.12 / 0.11 |
| 3,000 | 0.64 / 0.66 / 0.62 | 0.57 / 0.56 / 0.57 |

3,000행에서는 Mardia 검사가 전체 분석의 대부분을 차지했다. 전체 시간과 검사 시간은 별도 호출에서 측정했으므로 둘을 빼서 정확한 나머지 단계 시간이나 비율을 계산하지 않는다. 세 입력 모두 정규성 결정에 따라 ML이 선택됐다.

세 프로세스에서 각 크기의 누적 할당량은 같았다. 3,000행 로그에는 Mardia 함수 본문과 `mean` 아래 각각 72,000,048 bytes 할당이 기록돼 있다. 코드의 거리 행렬과 세제곱 임시 배열에 대응한다.

`Rprofmem`의 누적 할당량은 최대 동시 사용량이나 프로세스 RSS가 아니다. 해제·재사용·공유·외부 라이브러리 메모리를 포함해 실제 최대 메모리를 측정한 결과로 해석하지 않는다. 거리 행렬의 double payload는 이 코드에서 8*n² bytes다. 예를 들어 10,000행이면 행렬 하나의 숫자 데이터만 800MB가 필요하지만, 10,000행을 이번에 실제 실행하지는 않았다.
