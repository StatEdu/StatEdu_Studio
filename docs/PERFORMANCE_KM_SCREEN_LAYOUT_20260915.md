# KM 위험집단 표와 주석 화면 배치 수정

2026-09-15. 좁은 고해상도 화면에서 위험집단 표의 행이 붙고 긴 주석이 잘리는 문제를 수정했다. 계산·분석 옵션은 변경하지 않았다.

## 변경

`R/result_survival_ui.R`의 공통 생존곡선/위험표 그리기 함수가 화면 크기에 비례한 고정 구획만 쓰던 방식을 보완했다. 위험표 제목·축 등 고정 요소와 집단별 최소 14pt 공간을 확보하고, 주석은 실제 장치 폭에서 측정한 글자 폭으로 줄바꿈한다. 주석 내용은 그대로 유지하며 여러 문장의 주석도 모두 표시한다. KM의 3개 이상 집단에는 집단당 36px를 추가해 곡선 공간을 확보한다. 현재 화면과 저장 그림 모두 같은 높이 규칙을 사용한다(기본 높이는 각각 650/720px).

공통 그리기 함수는 경쟁위험 그림에서도 사용된다. 기존 JIT/호출 상태 복구 검사의 경쟁위험 사례를 포함해 확인했으며, 이번 내보내기/시각 검증의 집중 대상은 KM이다.

저장 검사 중 HWPX 변환 완료 후 한글의 Quit와 프로세스 Kill이 경합해 완료된 변환을 오류로 보고하는 문제가 재현됐다. `scripts/convert_result_hwpx.ps1`에서 종료를 다시 확인해 실제 종료된 경우만 허용했다. 전용 프로세스의 ID/시작 시각 확인을 유지하며 실제 종료 실패는 계속 오류로 처리한다. 이 수정 후 현재·누적 HWPX 변환이 모두 통과했다.

## 검증

- 700×650/160dpi, 500×650/160dpi, 저장용 1000×720/110dpi에서 수정 전후 그림 생성. 분석 객체 직렬화 및 RNG 정확 일치.
- 1·2·4·6집단 그림 생성 및 2/6집단 시각 확인. 좁은 장치에서도 위험표 숫자 행과 전체 주석이 표시되고, 6집단은 높이를 확장해 곡선 축 제목 공간을 확보했다.
- 기존 생존 그리기 JIT 검사의 12개 PNG/진단/stdout/RNG 쌍 및 8개 호출자 설정/성공/실패 복구 검사 통과. 이 검사는 수정 전 이미지 일치가 아니라 현재 내부 draw와 공개 wrapper의 일치 검사다.
- 현재(2집단)·누적(2집단+6집단) 각각 HTML/PDF/Word/HWPX/Excel 생성. 화면 표 셀은 수정 전 패널 및 저장 HTML과 정확히 일치했다. HTML/Word/HWPX/Excel의 모든 예상 표 셀·제목·문구 포함 확인, Word/HWPX/Excel에 포함된 PNG SHA256은 원본과 일치했다.
- PDF 현재 12페이지, 누적 23페이지에서 모든 예상 텍스트 추출 비교 통과. 이미지 페이지 렌더링 및 현재 9페이지/누적 23페이지의 KM 그림을 시각 확인했다. PDF 그림에서 위험표와 주석 전체가 표시됐다.
- 수정 소스의 실제 Shiny 화면을 DPR 1.5, 창 너비 1500/1100에서 실행해 그림 로딩·pageerror 0 및 캡처를 확인했다. 앱의 고정 결과 폭 때문에 두 조건의 실제 이미지 크기는 동일한 1089×975였다. 더 좁은 그림 자체는 앞선 500px 장치 검사로 검증했다. 임시 결과·설정 경로를 사용했고 테스트 서버를 종료했다.

## 파일과 범위

검증 스크립트: `validate_km_screen_layout.R`, `validate_km_screen_layout.cjs`, `validate_km_layout_exports.R`, `validate_km_layout_pdf.py`.

증거: `output/km-screen-layout-20260915/`의 수정 전 소스, 장치별 PNG, GUI 캡처/JSON, 분석 RDS, 현재·누적 다섯 형식 산출물, 문서 내부 PNG 및 PDF 렌더링.

첫 내보내기 시도의 HWPX 정리 경합과 PDF 검사 도구 import 실패를 보완한 최종 실행 결과를 기준으로 보고한다. 설치 파일은 이번 소스 수정 이후 재빌드하지 않았으며, 기존 배포용 exe에는 이 화면 수정이 아직 포함되지 않는다.
