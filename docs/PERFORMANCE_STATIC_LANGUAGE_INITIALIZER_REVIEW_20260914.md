# 정적 언어 스크립트 초기화 식 분리 — 미채택 — 2026-09-14

정적 언어 스크립트의 일회성 초기화를 `quote()` 식으로 분리하고, 작은 캐시 접근 함수가 첫 호출에서 `eval()`하도록 하는 후보를 시험했다. 첫 호출 함수의 컴파일 비용을 줄이려는 목적이었으나 실제 실행 이점이 없어 적용하지 않았다. 운영 코드와 JIT 설정은 유지했다.

후보는 `app_static_language_labels_script()` 내부의 초기화 문장과 순서를 그대로 옮겼다. 기존처럼 첫 호출에서 전체 스크립트를 생성하고 캐시하며, 이후 호출은 같은 캐시를 반환한다. 계산을 다음 분석으로 미루지 않고, 직전 미채택 언어 목록 조회 공유 후보도 포함하지 않았다.

## 측정

번들 Windows R 4.5.3, JIT 3, 기존 모듈 캐시, 패키지 자동 설치 비활성 조건이다. 버전/조건별 새 프로세스 3개, 총 12개를 순차 실행하고 두 번째 세트는 후보부터 실행했다. 전체 첫 UI 구성과 스크립트 단독 첫 생성은 별도 프로세스에서 측정했다.

| 조건 | 기존 3회(초) | 후보 3회(초) | 중앙값 |
| --- | --- | --- | --- |
| 첫 UI 구성 | 0.34 / 0.35 / 0.34 | 0.34 / 0.35 / 0.35 | 0.34 → 0.35초 |
| 번역표 초기화 후 스크립트 첫 생성 | 0.03 / 0.03 / 0.03 | 0.03 / 0.04 / 0.05 | 0.03 → 0.04초 |

패키지·모듈·비교용 UI 소스 로딩과 서버 함수 생성 후 측정했다. 스크립트 조건만 번역표를 미리 초기화하여 번역표 생성 비용을 제외했다. 시간에는 조건/표준출력 수집을 포함하고, HTML 태그 렌더링은 측정 후 실행했다. 실제 Electron 시작이나 사용자 서버 세션의 시간이 아니다.

짧은 세 번의 측정으로 일반적인 악화 폭을 단정하지는 않지만, 어떤 비교에서도 후보가 더 빨라지지 않았다. 따라서 이 구간에 추가 복잡성을 도입할 근거가 없다.

## 검증과 보관

전체 UI 3쌍과 스크립트 3쌍의 HTML·의존성·경고/메시지·표준출력·난수 상태가 `identical(..., num.eq=FALSE)`로 일치했다. UI의 자동 생성 숫자 탭 ID만 정규화했다. 단독 스크립트의 초기 반환값과 캐시 재호출 값도 같았다.

운영 `R/ui_helpers.R`는 기준 사본과 동일하다. SHA-256: `7D82C5AB8707320AF2D9596B41ACD0A8AE94B8B9E28B3074C7C9BDECE7815E5D`. 분석·출력 구현은 변경하지 않았으며 별도 메모리나 내보내기 검증, 설치 파일 재빌드는 하지 않았다.

자료는 `output/static-language-initializer-20260914/`의 기준/후보, `build.R`, `measure.R`, `compare.R`, 시간 CSV와 전체 UI/스크립트 스냅샷에 보관했다. `current.R`는 미채택 후보를 뜻한다.
