# 회귀분석 진단 그림 캐시 — 2026-09-14

일반·위계적 회귀의 HTML·PDF·Excel 저장에 세션별 진단 그림 캐시를 적용했다. OLS 4개 모형의 반복 저장용 HTML 생성 중앙값은 1.16초에서 0.15초로 약 87.1% 줄었다. 첫 저장은 1.96→1.92초로 비슷했다.

## 구현

- `saved_plot_result_block`, 일반·위계적 저장용 HTML 함수 및 직접 HTML/PDF/Excel 함수에 선택적 `plot_renderer` 인자를 전달한다. 기본값은 기존 `plot_data_uri`다.
- 일반·위계적 저장 핸들러에 각각 독립적인 공통 캐시를 생성한다. 최대 32항목·`object.size` 추정 합계 16 MiB이며, 모형과 그리기 함수·크기·해상도·표시 문맥을 정확히 비교한다. 항목 크기에 따라 보관 가능한 그림 수는 32개보다 적을 수 있다.
- 결과 조회가 갱신되거나 비워지면 우선순위 100의 관찰자가 캐시를 비운다. 실제 앱의 `create_analysis_result_views()`는 결과가 없을 때 `req()` 검증 예외를 내므로, 이 경우도 NULL 이벤트로 처리해 초기화한다. 세션 종료 시에도 비운다.
- 부트스트랩 완료로 결과 객체의 `boot_table`이 바뀌면 같은 갱신 경로로 초기화한다. 키 자체도 결과 전체를 비교하므로 이전 결과와 다른 항목을 같은 것으로 취급하지 않는다.
- PNG만 재사용하며 표·주석·문서 구성은 매번 기존 경로다. 통계 계산, 진단 그림 내용·해상도·장치와 누적 스냅샷 변환은 변경하지 않았다. 개별 그림 저장과 기존 다운로드 핸들러는 기본 비캐시 경로를 유지한다.
- 기존 공통 캐시의 경고·메시지·RNG 변경 시 우회, 항목·바이트 한도를 유지한다. 이는 전체 프로세스 메모리나 환경 참조 전체의 상한이 아니다. 한도 초과 시 기존 렌더링으로 출력을 완성하며 반복 저장 이득은 줄어들 수 있다.

## 성능

번들 R 4.5.3, Windows, seed 714, 2,000행, 연속 예측변수 2개, 종속변수 4개의 독립 OLS 모형이다. 자동 추정 선택은 끄고 잔차 진단은 켰으며 부트스트랩 작업은 0개였다. 모형당 Q-Q·표준화 잔차 그림 2개, 총 8개를 기본 600 dpi로 저장했다.

각 방식 새 프로세스 3개를 순차 실행하고 두 번째 회차는 순서를 반대로 했다. 로딩·분석 후 HTML 생성만 측정했으며 다른 R 검사·변환·메모리 관측을 동시에 실행하지 않았다.

대화상자와 PDF 등의 변환 시간을 포함하지 않으므로 전체 저장이 87% 빨라진다는 의미는 아니다. 위계적·HC3·부트스트랩 결과는 정확성 검사에 포함했지만 이 성능 수치는 일반 OLS 조건이다.

저장 후 8개 항목의 추정 보관량은 8,029,576 bytes였다. 별도 새 프로세스 3쌍에서 실제 R PID의 `PeakWorkingSet64`를 관측했다. 값은 로딩·분석·첫/반복 저장·검증 자료 기록을 포함하는 프로세스 전체 최고치이며 MB는 1,000,000 bytes다.

최초 메모리 실행 중 공통 `www/style.css`가 변경되어 세 번째 쌍의 전체 HTML 비교가 달랐다. 차이는 스타일 블록 안에만 있었고 보고서 본문·내장 PNG는 같았다. 해당 실행 전체를 제외하고 CSS 사본을 고정해 3쌍 모두 재측정한 값이 위 표다. 제외 수치는 `memory/excluded-css-change.csv`, 비교 HTML은 `memory/before-3.html`, `memory/after-3.html`에 남겼다. 공통 CSS는 이 작업에서 수정하지 않았다.

## 동일성·갱신 검증

- 성능 3쌍과 최종 메모리 3쌍의 HTML 전체(내장 PNG), 경고·메시지·표준 출력·RNG가 `identical(..., num.eq=FALSE)`로 일치했다. 각 실행의 첫·반복 HTML도 같았다.
- 회귀의 잔차·적합값 이름은 렌더링 중 지연 문자열 표현에서 일반 문자열로 바뀔 수 있다. 앞선 조사에서 숫자와 이름 내용이 정확히 같음을 확인했다. 검사용 복사본에서 이 두 이름 표현만 통일한 뒤 전체 결과 직렬화 값이 저장 전후 같음을 검증했다. 실제 프로그램 결과에는 이 정규화를 적용하지 않는다.
- 변경 전 소스와 적용 후 캐시를 13조건에서 비교했다: 일반, 위계적, 부트스트랩 대기, 완료, 반복, 보고서 모드, CSS, 소수점 쉼표 표시, 영어, 변수 라벨, 300 dpi, 넓은 위계적 표, sr²/f²/VIF 표시. 모두 출력과 결과가 일치했다.
- 비정규·이분산 합성 자료를 실제 분석해 HC3 및 부트스트랩 선택을 확인했다. 완료 표는 실제 40회 재표집 계산으로 생성했다. 외부 부트스트랩 작업 프로세스를 실행하거나 폴링하는 테스트는 아니며, 실제 완료 표를 결과 상태에 반영하는 갱신 경로를 검사했다.
- 일반·위계적 저장 핸들러를 MockShinySession에서 실행하고 실제 `create_analysis_result_views`를 연결했다. HTML 두 번·PDF·Excel 저장에 일반 2개, 위계적 4개 PNG를 재사용했다. 대기→완료 결과 갱신 시 캐시가 비워지고 저장 표도 바뀌었다. NULL에 따른 검증 예외·초기화 및 항목이 있는 상태의 세션 종료도 캐시를 비웠다.
- 서버 검사에는 실제 앱처럼 초기 UI 언어를 설정했다. 언어 옵션이 뒤늦게 초기화되는 별도 상황에서는 문맥 키가 달라져 정상적으로 재생성되므로 정확한 문맥 비교를 완화하지 않았다.
- 서버 검사의 PDF 변환은 입력 HTML 기록용 대체 함수였다. 별도 직접 저장에서는 일반·위계적 실제 HTML/PDF/Excel 함수와 실제 PDF 변환기를 실행해 PNG 재사용을 확인했다.
- 기존 공통 캐시의 키·인자·함수·문맥 변경, 독립 객체, 초기화, 기본 2개 제한, 바이트 한도 및 경고·메시지·RNG·오류 우회 검사도 통과했다.
