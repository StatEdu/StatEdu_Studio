# Fine–Gray 선택적 네이티브 로더 구현 — 2026-09-14

## 구현

`R/analysis_survival.R`에 `survival_fine_gray_engine()`을 추가하고 전체 경쟁위험 분석의 Fine–Gray 적합에서 사용한다. 기본값은 설치된 `cmprsk::crr`이다. `STATEDU_FINE_GRAY_NATIVE_DLL`에 검증된 후보 DLL 경로를 지정한 경우에만 다음 조건을 확인한다.

- Windows x86_64, 64비트 포인터, R 4.5.3, cmprsk 2.2-12.
- 검증된 파일의 MD5 식별값 `46ea81bd3b78a1284e7ce4f78654bea5` 일치. 이는 배포 서명이나 보안 인증 수단이 아니라 테스트한 빌드의 식별값이다.
- DLL 로드 및 `crrvvc` 심볼 조회 성공.

조건 불일치, 파일/로드/심볼 오류는 기존 함수로 복귀한다. 적합 자체의 수치 오류를 잡아서 재실행하지는 않는다. 로드는 실제 Fine–Gray 분석 시점에 수행하며 시작 시 DLL을 미리 로드하지 않는다. 패키지 네임스페이스를 수정하지 않고 함수 복사본의 `.Fortran` 호출 중 분산 루틴만 교체한다. 반환 모형의 `$call`은 기존 `cmprsk::crr(...)` 표현을 유지한다. 시간가변 공변량의 원본 복귀는 후보 DLL 내부에 유지된다.

환경 변수를 앱 설정이나 시스템 환경에 등록하지 않았다. DLL은 실험 폴더에 있고 자동 배포하지 않는다. 따라서 일반 실행은 현재도 원본 엔진을 사용한다. 설치 DLL과 설치 파일은 교체·재빌드하지 않았다.

## 검증

`scripts/validate_fine_gray_native_loader.R`을 추가했다. 기본 비활성, 없는 파일, 다른 해시, 강제로 주입한 로드/심볼 실패, 다른 R 버전/운영체제/아키텍처, 활성화, 반복 로드, 패키지 네임스페이스 불변을 검사했다. 로드 실패 등은 테스트 함수의 별도 환경에만 주입했다.

변경 직전 소스, 새 코드의 기본 설정, 후보 활성화의 300행 전체 결과를 비교했다. 일반·동률·범주형·결측·검열 집단 × Fine–Gray 단독/원인별 Cox 포함의 10조건 모두 전체 반환값·진단·표준출력·난수 상태가 `identical(..., num.eq=FALSE)`로 일치했다. 원인별 Cox의 formula/terms 환경 참조만 정규화했으며 수치는 정규화하지 않았다. 실제 모델 계수와 PH 열 수도 검사했다.

화면 HTML, PNG를 포함한 저장 콘텐츠, 현재/누적 HTML 파일이 동일했다. 현재/누적 Excel은 시트/셀과 압축 내부 파일을 비교하여 일치했다. Excel의 생성/수정 시각만 정규화했다. 별도로 기존 `validate_survival_ui_smoke.R`도 통과했다.

후보 결과로 현재/누적 각각 HTML·PDF·Word·HWPX·Excel 총 10개 파일 생성이 통과했다. HTML·Word·HWPX의 PNG 해시가 원본과 일치했고 그림 참조는 4개/8개였다. PDF는 20쪽/40쪽이며 PH 그림은 8쪽/8·28쪽에 있었다. PDF 현재 8쪽을 렌더링해 PH 10개 패널과 하단 주석을 확인했다. PDF·Word·HWPX 파일 전체의 변경 전후 바이트 비교나 Word/한글 앱의 전체 페이지 육안 검사는 하지 않았다.

## 첫 분석 시간

## 남은 배포 작업

검증된 DLL은 명시적으로 선택할 수 있지만, 기본 활성화와 배포 패키지 구성·새 머신 검증은 아직 수행하지 않았다. 새로 빌드한 DLL은 식별값과 호환성 검증을 갱신하기 전에는 선택되지 않는다. 기본 비활성 상태에서는 설치 폴더에 후보 파일이 없어도 원본으로 실행한다.

재현 자료와 내보내기 상태는 `output/fine-gray-loader-20260914/`에 보관했다. 검증 스크립트는 `STATEDU_FINE_GRAY_TEST_DLL`로 후보 경로를 지정할 수 있다. 변경 직전 소스와 추가 비교하려면 `STATEDU_FINE_GRAY_BASELINE`에 보관된 `baseline.R`을 지정한다.
