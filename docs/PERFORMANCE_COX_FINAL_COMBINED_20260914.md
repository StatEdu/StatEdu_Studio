# Cox 누적 개선과 저장 결과 검증 — 2026-09-14

## 전체 분석 시간

번들 R 4.5.3, 앱 설정 및 기존 모듈 캐시, 자동 설치 비활성화. 새 프로세스에서 변경 전후 3쌍을 순차 실행했고 두 번째 쌍은 역순이다. 각 프로세스에서 1천·1만·5만 행을 순서대로 실행했다. 숫자 공변량 10개, 약 70% 사건률의 동일한 합성 자료를 사용했다.

prepare_cox_analysis_result의 적합·진단·결과표 구성을 포함하고, HTML 생성 및 파일 저장은 제외한 시간이다.

| 행 수 | 기준 3회(초) | 최신 3회(초) | 중앙값 기준→최신 |
|---|---|---|---|
| 1,000 | 0.79 / 0.78 / 0.78 | 0.82 / 0.80 / 0.80 | 0.78→0.80 |
| 10,000 | 0.13 / 0.12 / 0.13 | 0.09 / 0.11 / 0.11 | 0.13→0.11 |
| 50,000 | 1.32 / 1.28 / 1.30 | 1.19 / 1.17 / 1.18 | 1.30→1.18 |

5만 행의 누적 효과는 약 9%, 절대 0.12초다. 1천 행은 첫 호출의 초기화·컴파일 비용을 포함하며 중앙값이 0.02초 증가했다. 서로 다른 크기 조건을 같은 준비 상태로 간주하지 않는다. 이전 보고서의 측정값과 단순 차감해 최근 변경만의 추가 효과로 해석하지 않는다. 함수 단독의 큰 감소율을 전체 분석이나 앱 실행 시간으로 확대하지 않는다.

## 계산·화면 검증

- 9개 결과 쌍의 전체 수치·표·진단·난수 상태가 identical(..., num.eq=FALSE)로 일치했다.
- Cox 수식/terms의 네 `.Environment` 참조만 측정 종료 후 정규화했다. 수치 반올림이나 허용오차를 적용하지 않았다.
- 세 크기의 화면 HTML/의존성이 각각 일치했다.
- 분석 행 수와 추정 계수 10개, 영향 진단의 유한 DFBETAS 10개, 다중공선성 진단 10행을 확인했다. 잔차 진단용 자료는 각각 1만/10만/50만 행으로 실제 생성됐다.
- 첫 최신 결과의 진단 메시지·경고는 각 크기에서 0건이었다.
