# 복합표본 계수 요약 후보의 적용 제한 검증

2026-09-15. 무조건 계수 전용 요약으로 대체하면 오류가 누락되던 이전 실험에 이어, 연구용 후보에 조사설계와 분포 함수 검사를 추가했다. 제품에는 아직 반영하지 않았다.

## 연구용 적용 조건

기본 클래스 svyglm 및 단일 단계 survey.design2, 기본 Gaussian 분포 함수, 유한한 입력/계수/공분산과 양의 가중치, 각 관측 층에 적어도 두 PSU가 있는 경우만 계수 전용 경로를 사용한다. 복제 가중치, 다른 분포, na.action이 남은 적합, 유한모집단 보정, PPS 및 post-stratification은 기존 요약으로 복귀한다. 이 조건 전체의 충분성을 전수 증명한 것은 아니다.

최초 제한은 분포 함수의 formals/body만 비교했지만, 동일한 본문의 variance 함수가 별도 환경에서 경고를 내는 rep.int를 참조하는 사례를 잘못 허용했다. 함수의 자유 심벌이 참조하는 실제 바인딩까지 비교하고 활성 바인딩/이름 해석 실패는 적용 제외하는 검사를 추가했다. 이 비용도 아래 측정에 포함한다. 오류나 경고를 무조건 숨겨 통과시키지 않았다.

## 정확성 검증

14개 조건이 원시 계수 표 전체, 조건 클래스/본문/순서, 표준 출력 및 최종 RNG에 대해 `identical(..., num.eq=FALSE)`로 통과했다. Gaussian 완전자료와 하위모집단 2개 조건은 계수 전용 경로, 나머지 12개는 기존 요약 경로다.

기존 경로 조건은 quasibinomial, quasipoisson, Gamma, 단일 PSU adjust 적합, 단일 PSU 요약 정책 fail/remove/certainty/average/adjust, JKn 복제 가중치, 결측 적합, 그리고 사용자 정의 함수 환경이다. 같은 단일 PSU adjust 조건의 반복도 개별 검사에 포함되어 있으므로 14개가 모두 독립적인 설계 유형이라는 뜻은 아니다. fail 정책의 기존 오류 및 사용자 함수의 진단을 보존했다.

계수 표는 허용오차나 반올림 없이 비교했지만 전체 fit 객체나 앱 화면/내보내기를 비교한 검사는 아니다. 분포가 다른 조건의 계수 전용 계산을 검증한 것도 아니다.

## 비용 및 후속 기준

10,000행 Gaussian 적합 하나에서 한 프로세스 내 50회 요약 블록을 3회 측정했다. 두 번째 블록은 순서를 바꿨다. 기본 요약은 호출당 0.0210 / 0.0210 / 0.0206초, 조사설계·함수 바인딩 검사를 포함한 후보는 0.0068 / 0.0066 / 0.0070초였다. 이 실험에서는 검사 비용을 포함해도 계산 생략의 이득이 남았다. 각 블록 전에 준비 호출이 있으며 독립 프로세스 성능 검증이나 전체 앱 속도 개선 수치는 아니다.

따라서 이 후보를 단순 폐기하지 않고 제한된 구현 후보로 유지한다. 다만 현재 연구 코드는 설치된 survey 메서드의 변경/버전을 자동 배제하는 제품용 조건이 없고, 추가 경계·전체 분석 비교 및 독립 프로세스 측정도 끝나지 않았다. 이 조건들을 검증하기 전에는 제품의 기본 계산 경로를 바꾸지 않는다. 같은 14개 검사의 반복만으로 미확인 범위를 통과 처리하지 않는다.

증거는 `output/complex-summary-guard-20260915/inspect.R`, `inspect.log`, `check.R`, `check.log`(초기 함수 환경 경계 실패), `check-final.log`, `checks.csv`, `results.rds`, `times.csv`다. `check.R`은 직전 `output/complex-summary-review-20260915/check.R`에서 시험 적합 준비 부분만 재사용한다. 최종 CSV/RDS는 보완된 검사 결과다. 제품 및 번들 파일, 출력 형식은 수정하지 않았고 빌드/전체 내보내기도 실행하지 않았다.
