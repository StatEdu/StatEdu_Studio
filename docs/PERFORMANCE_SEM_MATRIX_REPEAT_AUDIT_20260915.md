# 결측 SEM 역행렬 갱신 동일 입력 호출 감사

제품 변경 없이 `lavaan:::` 내부의 `lav_mat_sym_inverse_update` 호출을 계측했다. 앞선 결측 FIML 검증의 실제 재표집 행 인덱스 중 첫 3개로 일반 SEM을 다시 적합했다. 동일한 전체 인자 조합이 반복되는 것을 확인했지만 캐시로 결과를 대체하지 않았다.

## 입력과 계측

240행/9지표/3잠재변수, 변수별 10% 결측의 기존 자료에 저장된 재표집 행 인덱스를 적용했다. 원 적합의 파라미터 표와 옵션을 사용하되 기존 fixed-index 경로와 같이 start/est/se 필드를 제거하고 expected information을 사용했다. 각 표본은 비계측 및 계측으로 한 번씩 직접 직렬 적합했다. 이 진단은 200회 병렬 컨트롤러 전체의 호출 감사를 대신하지 않으며, 부모/작업자 메타데이터 고속 경로를 모두 재현한 비교도 아니다.

계측은 s_inv, rm_idx, logdet, s_logdet 전체를 SHA256으로 조회한 뒤 `identical(..., num.eq=FALSE)`로 확인했다. 저장된 원래 인자의 값·자료형·속성을 비교하고 반올림하지 않았다. 매 호출마다 원 함수를 그대로 실행했다. 연구용 R 프로세스의 namespace 바인딩만 잠시 감싼 뒤 종료 경로에서 원 함수로 복구했고 복구 동일성을 확인했다. 패키지 파일과 제품 파일은 수정하지 않았다.

## 호출 수

|재표집|전체 호출|완전 동일 인자 재호출|서로 다른 입력|반복 비율|
|---|---:|---:|---:|---:|
|1|2,812|380|2,432|13.5%|
|2|3,080|400|2,680|13.0%|
|3|2,808|390|2,418|13.9%|

모든 기록된 입력을 보관한 감사에서의 반복 수다. 계측 자체의 해시/저장 비용은 크므로 이 실행 시간을 성능 개선으로 보고하지 않는다.

호출 순서에 대한 별도 LRU 모의계산에서는 16개와 32개 용량은 적중 0회였고, 64개/128개 용량은 각각 위 반복 380/400/390회를 모두 포함했다. 이는 **캐시 구현 성능 측정이 아니라 기록된 순서의 적중 가능성**이다. 향후 다른 표본에서 같은 비율을 보장하지 않는다.

## 결과 확인

3개 적합 모두 수렴했다. 계측 전후 parameterEstimates, standardizedSolution, vcov, 수렴 상태, 적합 중 경고·메시지·표준 출력 및 최종 부모 RNG를 묶어 `identical(..., num.eq=FALSE)`로 비교해 일치했다. 전체 lavaan S4 객체의 환경 참조까지 무변환으로 비교하거나 전체 부트스트랩 요약을 비교한 것은 아니다. 이번 함수는 계산 결과를 재사용하지 않고 항상 원 계산을 실행했다.

## 판단과 다음 단계

동일 입력 중복 계산이라는 구체적인 근거를 얻었다. 다음 후보는 **한 적합 호출 안에서 최대 64개 항목만 보관**하는 제한된 캐시다. 반환값 대신 입력만 계측한 이번 자료만으로 채택하지 않는다. 입력 비교/저장/조회 비용을 포함한 전체 재적합 시간, 원시 출력·경고·오류·RNG 보존, 빈/단일/여러 삭제 인덱스와 logdet 분기 및 특수 값 폴백을 검증해야 한다.

작업자나 다른 재표집 간에 캐시를 공유하지 않고, 수치 행렬의 근사 비교도 하지 않는다. 패키지 버전/함수 계약이 다른 환경에 자동 적용하지 않는다. 실제 캐시가 의미 있는 속도 개선을 보이지 않으면 보류한다.
