# 큰 자료의 Cox 추가 옵션 프로파일

2026-09-15. 제품 코드를 변경하지 않고 20,000행의 기본 Cox, 층화, 군집 보정, 스플라인 옵션을 측정했다. 기존 2,000행 기본 모형 및 보정곡선 부트스트랩 기록을 다른 옵션의 성능으로 일반화하지 않고 별도 조건을 마련했다.

## 조건

`scripts/profile_cox_large_options.R`, 번들 R 4.5.3, 실제 서버와 같은 환경설정 초기화, 시드 778. 생존시간은 rate 0.01 지수분포, 사건은 확률 0.7 Bernoulli, 연속 공변량은 표준정규 6개다. 층화는 3집단, 군집은 10행씩 2,000개, 스플라인은 x1의 자유도 4를 사용했다. 보정 생존곡선은 요청하지 않았으며 부트스트랩을 측정하지 않았다. ties는 기존 기본값 Efron이다.

독립 프로세스 2개에서 옵션 순서를 뒤집었다. 옵션별 사전 실행 후 계측 없는 3회 중앙값을 기록하고, 별도 3회 호출을 10ms Rprof로 기록했다. 시간에는 결과 준비·진단/stdout 수집·모형 성공 검사가 포함된다. 입력 생성, 명시적 GC, 객체 정규화 및 동일성 비교는 최종 시간과 프로파일에서 제외했다.

## 반복성 확인과 비교 범위

모든 결과가 성공한 `coxph` 모형이고 20,000행을 사용하며 계수가 유한함을 확인했다. 사전 실행과 각각의 시간 측정/프로파일 결과를 비교했다. 프로세스 사이의 결과도 비교했다.

수식에 연결된 `.Environment` 속성만 재귀적으로 제외하고, 다른 필드·속성, 수치, 진단의 종류/문구/순서, stdout, RNG를 `identical(..., num.eq=FALSE)`로 비교했다. 따라서 환경 참조를 포함한 원본 객체 전체의 동일성을 주장하지 않는다.

초기 군집 모형 비교가 실패했을 때 기본 `all.equal()`은 TRUE였지만 이를 그대로 통과로 처리하지 않았다. 차이를 추적해 `fit$call` 내부 수식의 `.Environment` 참조임을 확인했다. 기존 정규화가 list 내부는 처리했으나 language/call 내부 수식을 놓치고 있었으므로 call/pairlist도 순회하도록 보완했다. 수치 허용오차를 늘리거나 수치값을 반올림하지 않았다. 차이 추적 자료는 상위 폴더의 `mismatch-cluster.rds`, `inspect-mismatch.R`, `mismatch-details.csv`에 남겼다.

## 프로파일 판단

최종 표본 시간은 옵션별 3회 합계 약 0.49~1.00초로 짧다. 단일 순위의 백분율보다 반복되는 경로를 확인하는 데 사용한다. 기본 모형에서는 적합과 공선성 진단 비용이 보였고, 스플라인에서도 선형 적합/스케일링 관련 진단 비용이 나타났다. 여러 옵션에서 생존시간 전처리의 문자 변환·공백 정리와 factor/table 관련 경로가 반복됐다.

다음 후보는 `survival_coerce_duration()`의 정상 숫자 입력 처리다. 기존 문자 변환 후 숫자 복원이 값의 마지막 비트에 영향을 줄 수 있으므로 단순히 원래 숫자를 반환하는 대체는 동등성 확인 없이 적용하지 않는다. 시간 해석, 결측 사유, 날짜·문자 입력 및 진단을 먼저 검증한다.

초기 프로파일은 동일성 검사나 정규화 비용을 포함했다. 최종 자료는 `analysis-only/`로 분리했고 상위 폴더의 초기 시간은 최종 성능 기준으로 사용하지 않는다.
