# 교차분석 스타일 적용 후 태그 평탄화 검토

## 결과와 결정

후보는 미반영으로 종료한다. 36개 준비 비교와 216개 시간 측정 호출에서 HTML·진단·표준 출력·최종 RNG가 모두 정확히 일치했다. 그러나 처리 시간을 일관되게 줄이지 못해 추가 재귀 코드를 유지할 근거가 부족하다.

## 후보와 검증 범위

이전 행 생성 단계의 평탄화는 머리글 스타일을 바꿔 제외했다. 이번 후보는 기존 `result_table_apply_contract()`를 먼저 실행한 다음, 완성된 표의 일반 리스트 중첩을 재귀적으로 제거한다. 태그 객체·속성은 유지하고, 기존 htmltools 렌더링과 이스케이프 경로를 사용한다. 제품 소스가 아닌 연구 환경에서 함수 바인딩을 교체했다.

번들 R 4.5.3, 독립 프로세스 3개를 순차 실행한다. 한·영 UI × 4/12/40 수준 × 빈도·백분율 분리 여부의 12개 조건을 사용한다. 모든 셀에 8개 관측을 두고 추세와 세 백분율 옵션을 켰다. 변수 라벨에 한국어, 따옴표, &, <script> 형태의 문자열을 포함했다.

기준/후보 UI 모듈 함수를 동일하게 바이트 컴파일한다. 분석 결과는 타이머 밖에서 한 번 계산하고 재사용하며, 조건별 준비 호출 후 각 경로를 3회 실행한다. 프로세스와 반복에 따라 실행 순서를 교대한다. 시간은 UI 객체 생성부터 HTML 문자열 생성 및 진단 캡처까지 포함한다. 후보의 추가 재귀 순회 비용도 포함한다.

비교 항목은 최종 HTML 전체 문자열, 경고/메시지의 클래스·문구·순서, 표준 출력, 최종 RNG이며 `identical(..., num.eq=FALSE)`로 비교한다. 수치 계산 자체나 전체 내부 태그 객체의 새 검증은 아니다. 브라우저 표시·전송, 최초 로딩, 실제 파일 쓰기 및 저장 형식별 검증은 이번 측정에 포함하지 않는다.

증거는 `output/crosstab-post-contract-review-20260915/compare.R`, `summarize.R`, `run-1/2/3.log`, 각 `run-*/checks.csv`, `run-*/times.csv`다.
