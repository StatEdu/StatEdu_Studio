# 정상 생존자료의 제외 사유 처리 단계 계측

2026-09-15. 제품 변경 없음. 직전의 `any(excluded)` 후보는 계속 미적용한다. 정상 자료에서 단일/복수 사유 분류가 약 0.20ms로 작아 이 부분의 추가 분기 최적화는 우선순위를 낮춘다.

## 방법과 결과 보존

현재 `survival_preflight`의 메모리 사본에만 구간 타이머를 삽입했다. 기존 단계 계측과 달리 사유 개수 계산, 제외 마스크, 빈 문자열 할당, 단일 사유, 복수 사유를 각각 구분했다. 원래 코드의 순서와 계산은 유지했다. 제품 소스는 편집하지 않았다.

번들 R 4.5.3과 앱 초기 환경설정을 사용했다. 20,000/100,000행 × 정상/사건·집단 일부 결측/중첩 결측/분산 공변량 결측의 8조건을 두 독립 프로세스에서 순차 실행하고, 두 번째는 조건 순서를 뒤집었다. 연속 생존시간, 숫자 사건, 3수준 집단, 공변량 6개의 단일 기록 자료다. KM 전체 적합이나 지연 진입·시작/종료 정렬의 성능 측정은 아니다.

각 조건의 성공 반환과 예상 분석 행 수를 확인하고, 비계측 원본 5회, 계측 사본 예열 1회 및 기록 7회의 전체 반환값·속성·진단·stdout·RNG를 `identical(..., num.eq=FALSE)`로 비교했다. 프로세스별 104개, 프로세스 간 저장 결과 8쌍, 합계 216개 비교가 통과했다. 환경 속성 제거 및 수치 허용오차는 사용하지 않았다.

원본 전체 시간은 GC 후 별도 호출에서 측정했다. 단계 계측은 별도 호출의 7회 중앙값이며 타이머 비용이 포함된다. 하위 구간 중앙값을 합산해 전체 시간의 정확한 구성비나 예상 개선율로 해석하지 않는다. 결과 캡처는 전체 시간에 포함되고 동일성 비교는 제외된다.

정상 자료에서는 단일/복수 사유 행이 없으므로 마지막 두 사유 구간은 인덱스 준비와 빈 조건 검사 위주다. 둘의 중앙값 합계 약 0.20ms는 직전 후보로 생략하려던 구간의 규모를 보여준다. 사유 개수부터 복수 사유까지의 중앙값 합계도 약 0.74~0.76ms다. 이 수치는 전체 사유 기록 비용을 포함하지 않는다.

분석 자료 준비 구간에는 행 추출, 집단의 factor/droplevels 처리, 변수 측정수준 조회 및 공변량 변환 검사가 함께 포함된다. 8.4ms 전체를 자료 복사 비용으로 단정하지 않는다. 별도 검토가 필요하면 이 구간을 먼저 분리할 수 있으나, 현재 개선 후보로 확정하지 않는다.

대조 조건의 전체 전처리는 100,000행 일부 결측 42.6~44.0ms, 분산 결측 49.6~50.4ms, 중첩 결측 179.6~181.9ms였다. 중첩 자료의 복수 사유 문자열 구간은 62.9~65.7ms로 정상 자료와 성격이 다르다. 정상 자료의 작은 구간을 줄이기 위해 결측 자료에 추가 비용을 넣지 않는다.
