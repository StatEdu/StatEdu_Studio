# Kruskal–Wallis 효과크기 재사용

## 적용 범위

`R/analysis_ttest_anova.R`에서 비모수 분석의 추가 평균·표준편차 표가 같은 epsilon squared 효과크기를 다시 계산하던 작업을 분석 호출 안에서 재사용한다. 기존 `ttest_effect_size`와 `ttest_kruskal_epsilon_squared` 함수의 계산·서식 처리는 그대로 사용한다. 본검정의 htest를 효과크기 계산에 대신 넣거나 수식을 변경하지 않는다.

효과크기 제공 함수를 core와 개별 결과 함수로 전달하고, 비모수·추가 표·중앙값/IQR·효과크기가 모두 활성화된 경우에만 캐시를 준비한다. `kw`만 저장하며 다른 검정은 원래 효과크기 함수를 호출한다. 효과크기 캐시는 기존 본검정 캐시와 별도로 최대 16개 입력 조합을 저장하고 분석 종료 후 재사용하지 않는다. 값·집단·검정 종류를 정확히 비교하며, 경고·메시지·난수 상태 변경이 발생하면 저장하지 않는다. 오류도 기존 경로로 전달한다.

처음 검토한 후보는 Cliff’s delta도 재사용했으나, 두 집단·동점·결측 없음에서 3회 중 2회가 0.06초에서 0.07초로 느려졌다. 해당 후보는 채택하지 않고 Kruskal–Wallis로 범위를 좁힌 뒤 최종 코드를 다시 측정했다. 초기 후보 자료는 `both-effects-timing-*.csv`에 별도로 보존했다.

## 정확성

`scripts/validate_ttest_effect_reuse.R`에서 현재 코드의 효과크기 호출만 원래 직접 호출로 복원한 참조와 비교했다. 모든 비교는 수치 정규화나 허용오차 없이 `identical(..., num.eq=FALSE)`를 사용하며, 결과·경고·메시지·오류·stdout·난수 상태를 함께 검사했다.

- 효과크기 함수와 공통 캐시의 경계 사례 84개: 2/4집단, 표본 크기 0/1/4/20/100/20,000, 일반·동점·상수·아주 가까운 실수·큰 크기의 가까운 실수·결측·무한대.
- 전체 결과 24개: 2/4집단, 6개 자료 유형, 추가 표 켜기/끄기, 종속변수 2개.
- 실제 분석 경로의 원시 숫자 계측 12개: 재사용한 epsilon squared가 기존 두 번의 값과 정확히 일치하고, Cliff’s delta는 재사용하지 않음을 확인했다. 상수 자료에서 효과크기 계산 전에 종료되는 경로도 확인했다.
- 진단 주입 10개: 2/4집단 × 정상·경고·메시지·난수 변경·오류. 정상 KW 효과크기 호출은 2회에서 1회로 감소한다. 다음 분석은 새로 계산하며 다른 경로의 호출 횟수와 관찰 결과는 기존과 같다.
- 기존 z 재사용 검증: 원시 z 42개, 전체 결과 24개, 진단 주입 5개 통과.
- 기존 본검정 재사용 검증: 원시 htest 50개, 전체 결과 48개, 진단 주입 10개 통과.
- 기존 사후검정 재사용 검증: 전체 결과 48개, 원시 행렬, 진단 처리, 캐시 제한 및 분석별 수명 검증 통과.

## 측정 방법과 자료

20,000행, 2/4/8집단, 연속값/반올림한 동점값, 결측률 0/0.1. 값과 집단에 독립적으로 결측을 적용했다. 비모수 분석·사후검정·추가 평균/표준편차 표·효과크기를 활성화했다. 기존 및 변경 코드를 예열한 뒤 새 R 프로세스 3개에서 순차 측정했고, 두 번째 실행은 기존/변경 순서를 뒤집었다. 시간은 전체 분석과 결과·진단·stdout·난수 상태 수집을 포함한 경과 시간이며 함수별 추적은 사용하지 않았다.

변경 전 소스, 재현 스크립트 `check.R`, 최종 측정 `product-timing-1.csv`부터 `product-timing-3.csv`는 `output/ttest-effect-reuse-20260914/`에 있다. 최종 전체 측정에서도 동일성을 검사했다.

적용 대상인 4/8집단은 24개 측정 중 21개 단축, 2개 동일, 1개 증가했다. 증가한 측정은 두 번째 실행의 4집단·동점·결측 자료로 0.12→0.13초였다. 재사용을 제외한 2집단 대조군은 12개 중 4개 단축, 5개 동일, 3개 증가했다. 특히 연속값·결측 자료는 3회 중 2회 0.01초 증가했으므로, 두 집단 경로까지 성능 향상을 주장하지 않는다. 짧은 실행의 타이머 해상도와 변동을 고려해야 하며, 모든 조건에서 더 빠르다고 보장할 수 없다.

UI·표 형식·내보내기 코드는 변경하지 않았다. 별도 UI/내보내기 실행 및 배포 빌드는 수행하지 않았다. 검증 결과는 명시한 자료·옵션 범위에 해당한다.
