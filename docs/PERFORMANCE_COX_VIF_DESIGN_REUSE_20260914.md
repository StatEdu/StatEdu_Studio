# Cox VIF 보조회귀 행렬 재사용 — 2026-09-14

> 검증 범위 정정 (2026-09-14): 아래의 경쟁위험/Fine–Gray 전체 결과 검증 표현은 당시 `integration.R`이 `regression`을 지정하지 않아 기본 CIF/Gray 경로만 실행한 것을 잘못 기술한 것이다. 그 검증은 원인별 Cox 또는 Fine–Gray 회귀 검증으로 볼 수 없다. 직접 함수 및 Cox 검증 결과는 별개다. 이후 `regression="both"`를 명시한 600행·20공변량 자료에서 초기 Cox 최적화 전과 현재 모듈 전체의 결과·진단·난수 상태를 비교해 통과했다. 상세 내용은 [원인별 Cox 저장·통합 검증](COMPETING_PH_EXPORT_VALIDATION_20260914.md)을 참고한다.

## 변경

`R/analysis_survival.R`의 `survival_cox_collinearity()`에 적용했다. 일반 행렬에서는 절편과 추정 가능한 공변량을 결합한 행렬을 한 번 만들고, 각 보조회귀에서 대상 공변량의 열만 제외한다. 기존의 공변량 부분 행렬 생성 후 절편을 붙이는 두 단계 중 중간 행렬 생성을 줄인다. 클래스가 있는 추정 가능 행렬은 기존 구성 경로를 유지한다.

열의 값·순서, `stats::lm.fit()`, 잔차 및 총 제곱합의 계산 순서, VIF 공식, 조건수 계산은 유지했다. 직전 검토에서 미채택한 `.lm.fit()` 변경은 포함하지 않았다. 캐시는 한 번의 진단 함수 호출 안에서만 사용한다.

## 시간 측정

동봉 R 4.5.3, 정규 합성 자료, 시드 42. 공변량 수별 기존/후보를 각각 새 프로세스로 3회 실행했고 두 번째 쌍은 후보부터 실행했다. 각 프로세스는 1천 행 다음 10만 행 순서로 진단 함수 전체를 측정했다. 자료 생성과 결과 저장은 제외하고 동일한 오류/경고/메시지·난수 수집 래퍼는 포함했다. 시간 측정 중 프로파일러나 별도 검증은 실행하지 않았다.

| 행 수 | 공변량 | 기존 3회(초) | 변경 후 3회(초) | 중앙값 기존 → 변경 후 |
|---|---:|---|---|---|
| 1,000 | 5 | 0.03 / 0.01 / 0.03 | 0.03 / 0.01 / 0.01 | 0.03 → 0.01 |
| 100,000 | 5 | 0.16 / 0.17 / 0.17 | 0.16 / 0.17 / 0.15 | 0.17 → 0.16 |
| 1,000 | 20 | 0.04 / 0.03 / 0.03 | 0.03 / 0.02 / 0.03 | 0.03 → 0.03 |
| 100,000 | 20 | 1.72 / 1.75 / 1.75 | 1.67 / 1.67 / 1.68 | 1.75 → 1.67 |

10만 행·20공변량에서는 세 쌍 모두 단축됐고 중앙값 기준 약 4.6% 감소했다. 작은 입력과 0.01초 수준 차이는 변동과 측정 해상도를 고려해야 한다. 전체 Cox 적합·프로그램 로딩·화면 대기 시간의 단축률로 해석하면 안 된다.
