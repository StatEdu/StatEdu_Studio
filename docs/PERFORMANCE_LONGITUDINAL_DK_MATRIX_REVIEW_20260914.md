# DK 공분산 모형행렬 재사용 검토: 미적용

## 결론

한 번의 Driscoll–Kraay 공분산 계산 안에서 모형행렬을 재사용하는 후보를 검토했다. 원시 공분산과 진단 동작 비교는 통과했지만 전체 분석은 FE에서 세 번 중 두 번, RE에서 세 번 모두 느려져 제품에 적용하지 않았다.

제품 `R/analysis_longitudinal.R`의 SHA256은 검토 시작과 확인 시 모두 `1A57B5CB6E504ED5A8A1392FF0B1C86485A1107D4357BCF50598302CBBCA45B8`이다. 앞서 적용한 선택 모형·Hausman·HC1 재사용은 유지한다.

## 후보

설치된 plm의 `vcovSCC.plm`은 시차 0부터 maxlag까지 `vcovG`를 호출한다. 각 호출의 `vcovG.plm`은 같은 모형에 `model.matrix`를 실행한다. 6시점의 기본 maxlag는 1이므로 한 DK 호출에서 행렬 생성이 두 번 일어난다.

시험 코드는 두 패키지 메서드를 지역 환경에 복사하고, 그 환경에서만 `model.matrix`를 감쌌다. 인자가 `identical(..., num.eq = FALSE)`로 같은 경우 첫 행렬을 재사용한다. 첫 계산에 경고·메시지 또는 RNG 변화가 있으면 보관하지 않는다. 오류는 그대로 전파한다. DK 호출마다 별도 환경을 만들며 패키지 namespace나 제품 소스는 수정하지 않았다. 공분산 산식과 연산 순서는 바꾸지 않았다.

이 구현은 패키지 내부 메서드에 의존하는 탐색용 후보이며, 측정 이득이 확인되지 않은 상태에서 제품 유지보수 부담을 추가할 이유가 없다.

## 전체 실행 시간

번들 R 4.5.3, seed 939, 2,000명 × 6시점, 두 공변량과 시간 항, 비가중 gaussian 패널 FE/RE, 기본 민감도·가정 검사를 사용했다. 현재 제품을 기준으로 비교했다. 워밍업 후 독립 프로세스 3개를 순차 실행하고 두 번째는 후보를 먼저 측정했다. 로딩은 제외하고 결과 캡처와 정규화를 포함한다.

| 모형 | 현재 1 / 2 / 3 (초) | 후보 1 / 2 / 3 (초) | 중앙값 |
|---|---|---|---|
| FE | 3.34 / 2.70 / 3.06 | 2.29 / 2.92 / 3.07 | 3.06 → 2.92초 |
| RE | 2.39 / 2.58 / 2.61 | 3.12 / 2.67 / 2.73 | 2.58 → 2.73초 |

FE 중앙값만으로 개선을 판단하지 않았다. FE 두 쌍은 느려졌고 RE는 모두 느려졌다. 이 측정만으로 느려진 내부 원인을 단정하지 않는다.

워밍업과 측정 각각에서 전체 반환 결과·조건 클래스/본문/순서·표준 출력·RNG를 수치 허용오차 없이 비교해 모두 일치했다. 측정 6건과 워밍업 6건은 같은 정상 자료를 반복한 비교다. formula/terms 환경과 함수 표현은 정규화했고 원시 환경의 동일성을 주장하지 않는다.

## 원시 공분산과 진단 검증

100명 × 6시점 자료에서 FE/RE × 균형/일부 행 제외 × maxlag 0/1/2 × 정상/경고/메시지/RNG/오류의 60개 조건을 검증했다. 패키지 `model.matrix.plm` 진입을 별도 검증 프로세스에서 trace하여 호출 횟수를 세고 조건을 주입했다. 종료 전에 trace를 해제했다.

60건 모두 원시 공분산 행렬과 속성, 조건 클래스·본문·순서, 표준 출력, RNG가 `identical(..., num.eq = FALSE)`로 일치했다. 정상 행렬 생성 횟수는 maxlag 0/1/2에서 각각 1/2/3 → 1/1/1이다. 경고·메시지·RNG 조건에서는 기존 횟수를 유지했고 오류 조건은 양쪽 한 번이었다.

초기 원시 검증 자료의 `y ~ time + x1 + x2` RE 적합에서 기존 plm 경로가 특이행렬 오류로 중단됐다. 후보 DK 실행 이전의 모형 적합 오류이며 통과 건수에 포함하지 않았다. 로그를 보존하고, 원시 검증은 `y ~ x1 + x2`로 다시 실행하여 60건을 완료했다. 전체 실행 성능 비교의 시간 항 포함 자료는 그대로 유지했고 정상 모형 반환을 확인했다.
