# 제외 행이 없는 생존분석 사유 분류 생략 검토

2026-09-15. 후보 미적용. 결과는 같지만 정상 자료의 단축이 일관되지 않고 결측 조건에서 시간이 증가하여, 제품 코드를 작업 시작 상태로 복원했다. 이전 Kaplan–Meier 통합 측정에서 발견한 정상 자료의 0.7~1.4% 추가 비용이 해결됐다고 주장하지 않는다.

## 후보와 비교 범위

`survival_preflight`의 사유 개수와 제외 마스크 계산 뒤, 단일/복수 사유 인덱스 생성 및 문자열 준비를 `if (any(excluded))`로 감쌌다. 정상 자료에서는 두 분류를 건너뛰지만 제외 마스크 확인이 추가된다. 그 밖의 제품 변경은 없다.

직전 제품의 preflight를 `scripts/fixtures/survival_reason_empty_reference.R`, 후보를 `scripts/fixtures/survival_reason_empty_candidate.R`에 보관했다. 재현 스크립트는 현재 모듈을 로드한 뒤 각각의 함수 사본으로 덮어쓰므로 제품 복원 뒤에도 후보 비교를 유지한다. 향후 다른 모듈 변경까지 고정하는 독립 배포 스냅샷은 아니다.

번들 R 4.5.3, 실제 초기 환경설정과 앱 모듈을 로드했다. 성능 비교는 두 독립 프로세스를 순차 실행하고 동일 컴파일 조건에서 전후 순서를 번갈아 측정했다. 각 측정 전 GC를 실행하고 벽시계 중앙값을 비교했다. 서로 다른 실행의 절대 시간을 전후 값으로 사용하지 않았다.

## 동일성 검증

- 전처리 96개: 0/1/30/120행, 단일 기록/지연 진입/시작·종료, 정상/중첩/분산/전체 결측, 중복 및 순서 변경 공변량.
- 사용자 정의 결측 검사 2개와 반복 시간 인코딩·집단 사유 4개.
- 성능 측정 중 전처리 기본 88개씩 2회, 정상 집중 62개씩 2회: 전체 결과 비교 300개.
- 100,000행 정상 Kaplan–Meier 표준/지연 진입, 각 조건 15회씩: 두 실행 전체 결과 비교 124개, 측정 적합 120개 모두 진단 0개. 일 단위 동률 자료이며 로그순위·사후 비교·생존 요약·생명표·RMST 등을 포함한다.
- 복원 후 저장 후보로 Cox 기본/층화/군집/스플라인 × 정상/중첩/분산 12개 비교 통과. 예상 분석 행 수와 유한 계수를 확인했다.
- 기존 사건 매핑 helper 294개 및 전처리 36개 검사도 통과했다. 호출 스크립트별 반복 실행은 별개의 신규 사례로 세지 않았다.

전처리는 값·속성·진단·stdout·RNG를 `identical(..., num.eq=FALSE)`로 비교했다. 전체 KM/Cox에서는 재귀적으로 `.Environment` 속성만 제거한 뒤 같은 비교를 했다. 숫자 허용오차는 적용하지 않았다.
