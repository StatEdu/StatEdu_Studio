# 순서형 신뢰도 문항쌍 추정 재사용 후보 — 2026-09-14

운영 코드에는 적용하지 않은 실험 후보다. 완전 자료의 문항 삭제 시 신뢰도 계산에서 동일한 문항쌍 추정을 재사용하면 전체 분석 시간이 크게 줄었다. 결측 자료는 재사용 없이 소폭 느려졌으므로 조건 제한과 패키지 변경 시 원래 경로 선택을 갖춘 통합이 추가로 필요하다.

## 재사용 위치

설치된 psych 2.6.5의 `polychoric`, `polyc`, `cor.smooth`, `polyF` 구현을 직접 확인했다. `polychoric`은 문항 임계값 및 전체 범주 범위를 계산하고, 문항쌍별 `polyc` 결과로 행렬을 만든 뒤 `cor.smooth`를 수행한다. 범주 수가 다른 문항이 있으면 global 옵션이 바뀔 수 있다. 행렬 보정은 행렬 전체에 의존하므로 완성된 행렬의 부분행렬을 그대로 반환하지 않는다.

후보는 로컬로 복제한 `polychoric`의 환경에서만 `polyc` 조회를 바꾼다. 설치된 패키지 네임스페이스나 파일은 수정하지 않는다. 각 전체 신뢰도 분석 호출마다 새 캐시를 만들고, 문항쌍의 두 벡터·두 임계값·global·weight·correct·최소/최대 범위를 포함한 실제 인수 목록을 키로 사용한다. SHA-256 조회 후에도 인수 목록을 `identical(..., num.eq = FALSE)`로 재확인한다.

캐시는 최대 128개 항목을 유지한다. 경고/메시지가 없고 난수 상태가 바뀌지 않은 쌍별 계산만 저장하며, 오류는 저장하지 않는다. 문항쌍의 추정 결과 목록 전체를 반환한다. 이후 행렬 구성·결측 처리·행렬 보정과 alpha/omega 계산은 기존 순서대로 실행한다. 이는 실험 구현이며, 패키지 버전/함수 본문을 확인해 자동 우회하는 운영용 보호 장치는 아직 포함하지 않았다.

## 시간 비교

2,000건·8문항, 공통 정규 성분 0.6과 문항별 정규 성분 0.8, 동일 확률의 5범주 자료를 사용했다. 결측 조건은 각 문항에서 독립적으로 200건을 제거했다. omega·normality·문항 삭제 신뢰도·문항-전체 상관 옵션을 모두 요청했다. 자료 시드 719, 분석 시드 941다.

번들 Windows R 4.5.3에서 버전별 새 프로세스 3개를 순차 실행하고 두 번째 쌍은 역순으로 실행했다. 매 조건에 준비 실행 후 GC와 비프로파일 측정을 수행했다. 준비 실행과 측정 실행은 각각 새 캐시를 만들므로 캐시가 준비 실행에서 넘어오지 않는다. 전체 `prepare_reliability_results()`와 캐시 설치·진단/표준출력 수집을 포함하며 패키지/앱 로딩, 입력 생성, UI 및 내보내기는 제외한다.

| 조건 | 기존 3회 | 후보 3회 | 중앙값 |
| --- | --- | --- | --- |
| 완전 자료 | 1.19 / 1.19 / 1.19초 | 0.37 / 0.37 / 0.39초 | 1.19 → 0.37초 |
| 결측 자료 | 1.13 / 1.11 / 1.13초 | 1.14 / 1.14 / 1.14초 | 1.13 → 1.14초 |

완전 자료의 중앙값 단축률은 약 **68.9%**다. 각 실행에서 재사용 168회, 실제 추정 28회였다. 결측 자료는 재사용 0회, 실제 추정 196회였으며 키 구성 등의 추가 비용만 발생했다. 이 결과를 모든 순서형 신뢰도 자료의 개선율로 일반화하지 않는다.

## 결과 검증

- 여섯 변경 전후 전체 분석 결과·경고/메시지·표준출력·난수 상태가 `identical(..., num.eq = FALSE)`로 일치했다. 각 준비/측정 결과도 같았고 신뢰도 추정치는 모두 유한했다.
- 별도 168개 행렬 결과/조건/표준출력/난수 비교가 정확히 일치했다. 12/80건, 2/3/5범주, 6문항, 결측 유무, 동일/서로 다른 범주 수, 전체/문항 삭제 입력을 포함했다. 오류나 NULL을 포함하는 기존 결과도 비교 대상이다.
- 후보에서 양의 정부호가 아닌 행렬에 대한 보정 경로 59회가 실제 실행됐으며, 이 경우를 포함한 모든 비교가 같았다. 이미 보정된 전체 행렬을 잘라 쓰는 방식과 구별되는 검증이다.
- 최초 실험의 호출식 치환 보조 함수가 NULL 원소를 삭제해 실패했다. 실험 코드의 대입 방식을 수정한 뒤 기준/후보 3쌍 전체를 새로 실행했다. 수정 전 실패 결과는 시간 집계에 포함하지 않았다.
- 운영 `R/analysis_reliability.R`는 기준 사본과 SHA-256이 동일하다: `DA934B2453F8EC05D1A7A2EBD63B2A04E5DFBDFD87AB8F20433E1B54B6F76595`.

## 후속 통합 조건

재사용이 기대되는 입력에 한정해 활성화하고, 예상 패키지/함수 구현이 아닌 경우 기존 함수를 사용하도록 해야 한다. 실제 앱 호출 범위 안에서 캐시 생성·해제가 보장되어야 하며, 다른 분석이나 사용자 세션으로 결과가 넘어가면 안 된다. 별도 최고 메모리 측정과 현재/누적 HTML·PDF·Word·HWPX·Excel 검증도 아직 수행하지 않았다. 따라서 이번 결과는 통합 전 후보의 검증이며 설치 파일을 재빌드하지 않았다.
