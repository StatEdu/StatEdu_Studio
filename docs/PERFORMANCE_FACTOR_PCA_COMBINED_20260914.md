# PCA·요인분석 최근 최적화 통합 검증 — 2026-09-14

PCA 적합성 상관행렬 재사용, 일반 integer 입력의 문자 변환 생략, 전체 척도와 동일한 하위요인 신뢰도 재사용을 함께 적용한 현재 코드와 세 변경 전 코드를 비교했다. 이번에는 제품 소스를 추가로 변경하지 않았다.

## 전체 분석 결과

| 입력 / 분석 | 변경 전 3회(초) | 현재 3회(초) | 중앙값 |
|---|---|---|---|
| 20,000행·60변수 double PCA | 2.94 / 2.77 / 2.95 | 2.70 / 2.85 / 2.67 | 2.94 → 2.70 |
| 20,000행·60변수 integer PCA | 0.76 / 0.81 / 0.80 | 0.28 / 0.29 / 0.28 | 0.80 → 0.28, 약 65% 감소 |
| 2,000행·12문항 integer 단일 요인·신뢰도 켬 | 0.45 / 0.36 / 0.47 | 0.18 / 0.32 / 0.21 | 0.45 → 0.21, 약 53% 감소 |
| 2,000행·12문항 double 두 요인·신뢰도 켬 | 0.92 / 0.89 / 0.90 | 0.89 / 0.90 / 0.89 | 0.90 → 0.89 |

정수형 PCA와 단일 요인 분석은 세 번 모두 빨라졌다. double PCA는 세 번 중 두 번 빨랐고 한 번 느렸다. 두 요인 대조군의 작은 차이는 개선으로 주장하지 않는다. 앞선 개별 보고서의 개선율을 더하거나 곱한 결과가 아니라, 이번 동일 실험에서 전체 분석을 직접 비교한 결과다.

## 비교 기준

- 요인분석 기준: `output/factor-integer-input-20260914/baseline.R`.
- PCA 기준: `output/pca-correlation-reuse-20260914/baseline.R`.
- 현재 소스는 측정 폴더의 `factor-current.R`, `pca-current.R`에 고정했다. 기준/현재를 각각 전용 환경에 요인분석→PCA 순서로 로딩해 공유 숫자 변환 별칭도 해당 버전을 사용하게 했다. 그 외 패키지·공통 모듈은 동일하다.
- 소스 비교상 요인분석 파일의 두 최적화와 PCA의 상관행렬 선택 조건만 달랐다. 네 파일의 SHA256은 측정 폴더의 `source-hashes.json`에 보관했다.

## 재현 조건과 동일성

번들 R 4.5.3, 새 프로세스 3개 순차 실행. 각 입력에서 양쪽 준비 실행 후 GC와 전체 분석 시간을 측정했으며 두 번째 프로세스는 현재 버전을 먼저 실행했다. 다른 R 타이밍 작업은 동시에 실행하지 않았다.

시드 935로 정규 잠재값과 표준편차 0.5의 독립 정규 오차를 더한 자료를 만들었다. 두 요인은 문항 6개씩 다른 잠재값을 사용했다. integer 조건은 원자료를 100,000배해 반올림 후 integer로 저장했다. PCA는 Pearson·고정 3성분·회전 없음이다. 요인분석은 Pearson·주축요인·고정 요인 수·정규성 검사 끔·하위요인 신뢰도 켬이며 단일 요인은 회전 없음, 두 요인은 Varimax다. 매 분석 전 시드 718로 초기화했다.

네 입력 × 세 프로세스의 준비/측정 실행에서 전체 반환 객체, 경고·메시지 클래스와 문자열·순서, 표준 출력 및 난수 상태가 `identical(..., num.eq=FALSE)`로 일치했다. 결과 객체 정규화나 수치 허용오차는 사용하지 않았다. 즉 이 입력 범위에서 세 변경이 함께 있어도 적재량·점수·신뢰도·표와 관련 반환 정보의 정확 동일성을 확인했다.

시간에는 분석·결과표 준비·비교용 스냅샷 구성이 포함된다. 모듈 로딩·입력 생성·그림 렌더링·저장은 제외했다. 메모리는 이번에 측정하지 않았다. 제품 파일 추가 변경이 없으므로 이미 통과한 개별 경계/회귀 검증을 반복하지 않고 이번 통합 비교를 수행했다. 파일 형식 변환을 새로 실행하거나 설치 파일을 재빌드하지 않았다.
