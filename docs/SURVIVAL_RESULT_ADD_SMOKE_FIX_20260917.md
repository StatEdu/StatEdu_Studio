# 생존분석 결과 추가 스모크 실패 원인

실패 원인은 제품의 결과 저장 함수가 아니라 테스트의 실행/정리 범위였다. 이전에는 UTF-8 로딩을 위해 테스트 파일을 `source()`로 실행했다. 파일 최상위의 `on.exit()`가 임시 `STATEDU_RESULT_STORE`를 너무 일찍 해제하여, 기대 경로는 임시 파일이지만 실제 경로는 작업공간의 `data/StatEdu_Studio_results.json`이 됐다. 진단 로그에서 두 경로의 차이와 실제 저장 성공 알림을 확인했다.

공통 브라우저 캡처 응답 누락을 처음 의심했으나 생존 모듈 등록은 `html_fn` 경로여서 해당 원인이 아니었다. 이 가정에 따른 테스트 변경은 제거했다. 제품 저장 경로를 변경하지 않았다.

`scripts/validate_survival_ui_smoke.R`를 함수로 감싸 `on.exit()`가 테스트 종료 시 실행되도록 수정했다. UTF-8 locale을 지정하고 모듈 캐시를 비활성화한다. 파일 검사에 앞서 실제 저장 경로가 지정한 임시 경로와 일치하는지도 확인한다.

검증: 직접 Rscript 실행과 locale 지정 후 source 실행 모두 전체 스모크 통과. KM/Cox/경쟁위험 결과 생성과 저장 컨트롤, Cox 결과 추가 후 파일 생성·1개 항목·제목/내용, 공개/개발판 저장 정책 검사 포함. 실제 Chrome UI 클릭 검사는 이번에 수행하지 않았다.

로그: `tmp/survival-snapshot-smoke.log`, `tmp/survival-smoke-source-fixed.log`. 수정 전 진단은 `tmp/survival-smoke-source-diagnostic.log`에 남겼다. 진단 당시 잘못 사용된 작업공간 기본 결과 파일은 기존 항목과 구분 없이 삭제하지 않았다. 설치본과 사용자 설치 프로필은 변경하지 않았다.

테스트만 수정했으며 분석 출력 및 내보내기는 변경하지 않았다. 기존 생존 설정 저장 보고서의 결과 추가 스모크 미해결 항목은 이 기록으로 해소한다.
