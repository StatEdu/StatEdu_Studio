# 회귀 효과크기의 경량 적합 재사용 — 2026-09-14

## 적용 내용과 판단

`R/analysis_regression.R`의 `coefficient_effect_sizes`에서 변수별 축소모형 적합 한 줄을 기존 `regression_bootstrap_lm_fit` 호출로 바꿨다. 효과크기는 축소모형의 잔차만 사용하므로 `lm.fit`의 추가 반환 정보가 필요하지 않다. 새로운 적합 함수를 추가하지 않고 이미 부트스트랩에서 사용하는 경량 함수를 재사용한다.

해당 함수는 같은 QR 허용오차 `1e-7`의 `.lm.fit`을 사용하고, 빈 행렬·빈 열·행렬 반응은 기존 `lm.fit`으로 처리한다. 잔차제곱합, 전체 R², sr²·f² 계산식 및 연산 순서는 유지했다. 직전 적용한 VIF 재사용도 비교 양쪽에 유지했다.

이번 변경의 확인된 이점은 메모리 할당 감소다. 전체 분석 시간은 조건과 반복에 따라 달라 일관된 속도 개선을 확정하지 않는다.

## 전체 분석 시간

번들 R 4.5.3, 2,000행, 예측변수 12개, 종속변수 4개, 시드 714, 일반 OLS 및 잔차 진단 활성화 조건이다. 자동 강건 추정은 끄고 부트스트랩 작업이 0개인지 확인했다. 단일 모형은 종속변수 하나만 사용한다. 결측은 모든 종속변수의 공통 200행 또는 종속변수별 무작위 200행이다.

버전별 새 프로세스 세 개를 순차 실행하고 두 번째 비교는 후보를 먼저 실행했다. 조건별 준비 실행 후 전체 분석 5회를 측정했다. 로딩·자료 생성·화면·저장은 제외했다. 다른 R 작업을 시간 측정과 동시에 실행하지 않았다.

| 조건 | 기존 3회(초, 각 5분석) | 후보 3회(초, 각 5분석) | 중앙값 기존→후보 |
| --- | --- | --- | --- |
| 완전 자료 | 0.88 / 0.93 / 0.91 | 0.91 / 1.07 / 0.92 | 0.91→0.92 |
| 공통 결측 | 1.20 / 0.93 / 1.00 | 0.89 / 0.93 / 0.89 | 1.00→0.89 |
| 종속변수별 다른 결측 | 1.77 / 1.20 / 1.25 | 1.18 / 1.24 / 1.18 | 1.25→1.18 |
| 단일 종속변수 | 0.31 / 0.33 / 0.32 | 0.33 / 0.33 / 0.28 | 0.32→0.33 |

완전 자료는 세 비교 모두 조금 느렸으며, 결측 자료 일부에서는 시간이 줄었다. 이러한 변동을 합쳐 전체 프로그램이 빨라졌다고 표현하지 않는다.

## 메모리 할당

시간 측정 종료 후 별도 고정 모형(2,000행·예측변수 12개, 시드 7)의 효과크기 함수 1회를 Rprofmem으로 측정했다. 각 함수를 먼저 준비 실행했다.

| 방식 | 누적 할당 바이트 |
| --- | ---: |
| 기존 lm.fit | 6,325,552 |
| 기존 경량 함수 재사용 | 5,748,976 |

누적 할당량은 576,576바이트, 약 9.1% 줄었다. 이는 해당 효과크기 함수 호출의 할당 기록이며 전체 분석의 최대 메모리나 프로세스 RSS가 아니다.

## 수치 검증

- 20/200/2,000행 × 일반·가중·0가중치·결측·na.exclude·특이·완전 적합·offset·절편 없음·범주형·근접 특이·다변량 반응의 36개 모형 사례에서 반환값 또는 오류, 경고/메시지, 표준 출력 및 난수 상태가 정확히 일치했다.
- 영구 검증 `scripts/validate_regression_effect_fit.R`에서도 동일한 36개 사례를 통과했다. 비교용 함수 사본의 한 적합 호출만 기존 `stats::lm.fit`으로 복원한다.
- 전체 분석 네 조건 × 세 쌍의 12개 기존/후보 결과·조건·표준 출력·난수 상태가 일치했다. 수식의 `.Environment` 속성만 테스트 사본에서 제거하고 `identical(..., num.eq=FALSE)`로 비교했다. 제품 결과는 정규화하지 않았다.
- 적용 제품 소스와 측정 후보 소스는 UTF-8 텍스트를 읽어 줄바꿈을 정규화한 비교에서 일치했다.
