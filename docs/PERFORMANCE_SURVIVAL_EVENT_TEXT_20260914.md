# 생존분석 사건 문자열 변환 재사용 — 2026-09-14

`survival_preflight()`의 사건 결측 검사에서 만든 문자열을 사건 역할 조회에 재사용하도록 변경했다. 일반 atomic 벡터이고 클래스와 차원이 없는 경우에만 재사용한다. factor, Date, 사용자 정의 클래스 등은 원래처럼 역할 조회 시 다시 변환하여 메서드 호출을 유지한다.

기존 `is.na()` 평가 뒤 문자열 변환 결과를 저장하여 결측 검사와 변환의 실행 순서를 보존한다. 관측 코드 목록 생성과 사건 매핑의 정규화 처리는 변경하지 않았다. 결측 판정, 사건·검열·경쟁사건 분류, 제외 사유 및 안내 내용은 그대로다.

## 전체 입력 검증 측정

10만 행의 시간·사건·집단·연령 자료를 사용했다. 결측 조건은 연령 10%를 NA로 지정했다. 사건은 정수 코드다. 번들 R 4.5.3의 새 프로세스에서 모듈·설정 로딩 후 정상 자료, 결측 자료 순서로 입력 검증 전체를 측정했다. 프로파일러 없이 3쌍을 순차 실행하고 두 번째 쌍의 순서를 뒤집었다. 함수는 같은 전역 도우미 환경을 사용했다.

| 최종 반복 | 정상 전/후(초) | 결측 전/후(초) |
| --- | --- | --- |
| final1 | 0.38 / 0.38 | 0.28 / 0.25 |
| final2 | 0.36 / 0.36 | 0.28 / 0.27 |
| final3 | 0.37 / 0.36 | 0.28 / 0.27 |
| 중앙값 | 0.37 / 0.36 | 0.28 / 0.27 |

개선 폭은 작다. 일반 사건 벡터의 중복 변환을 한 번 줄였으나 이 측정으로 큰 속도 개선을 주장하지 않는다. 클래스가 있는 사건 벡터는 이 재사용 경로를 사용하지 않는다. 프로그램 시작 및 전체 분석 시간의 개선율을 측정한 결과도 아니다.

초기 반복 1–3은 결측 검사와 변환의 평가 순서를 정리하기 전 후보의 자료다. 최종 성능 기록은 위의 `final1`–`final3`만 사용한다.

## 검증

- `scripts/validate_survival_event_text.R`: 48개 입력 검증 사례의 전체 결과/오류, 경고·메시지 및 RNG 상태가 정확히 동일했다.
- `verify_events.R`: 정수, 실수·NaN·무한대, 논리, 공백·빈 문자열·NA·다국어, factor, ordered factor, Date, 사용자 정의 클래스와 사건 맵을 조합한 24개 사례 통과. 사용자 정의 `is.na()`/`as.character()`가 발생시키는 메시지의 순서와 횟수도 유지했다.
- 최종 대용량 측정 6쌍의 분석 자료, 행별 감사 정보, 건수, 이슈, 매핑 등 전체 결과를 `identical(..., num.eq = FALSE)`로 비교하여 통과했다.
- 실제 서버의 업로드·변수 선택·상관분석·Kaplan–Meier 실행을 완료했다. 직전 기준과 전체 결과 객체, HTML/의존성, 경고 및 알림이 정확히 같았고 분석 실행 경고는 0개였다.
- `git diff --check -- R/analysis_survival.R` 통과.

출력 내용과 분석 결과는 유지한다. 내보내기 완성 파일과 설치 파일은 이번에 재생성하지 않았다.
