# Excel 저장 최적화 후 병목 재측정 — 2026-09-14

이번 작업은 현재 저장 경로의 재측정과 결과 보존 확인이다. 실행 코드는 추가 변경하지 않았다. 앞서 적용한 값 쓰기 묶음, 서식 객체 캐시, 서식 적용 묶음, 표 해석 재사용을 모두 활성화했다.

동일한 30변수 상관분석 HTML과 3개 시트를 대상으로 번들 R 4.5.3의 새 프로세스에서 두 차례 순차 측정했다. 기존 `scripts/profile_excel_export.R`의 함수별 경과 시간과 10ms Rprof 샘플링을 함께 사용했다. 패키지 로딩은 저장 측정 밖에 있다.

| 경로 | 1회(초) | 2회(초) | 중앙값(초) |
| --- | ---: | ---: | ---: |
| 전체 저장 | 2.53 | 2.57 | 2.55 |
| 표 수집·변환 `result_entry_tables` | 1.05 | 1.05 | 1.05 |
| 시트 쓰기 `add_screen_excel_table` | 0.71 | 0.74 | 0.725 |
| HTML 셀 해석 | 0.55 | 0.55 | 0.55 |
| 문서용 표 데이터 변환 | 0.18 | 0.22 | 0.20 |
| HTML 문서 읽기 | 0.28 | 0.31 | 0.295 |
| 주변 문단 추출 | 0.18 | 0.15 | 0.165 |

표 수집·변환은 전체 경과 시간의 약 41%, 시트 쓰기는 약 28%다. 하위 함수 시간은 상위 함수에 포함되므로 표의 시간을 합산하면 안 된다. Rprof 샘플 비율 역시 전체 경과 시간의 비율로 해석하지 않는다. 이번 수치는 프로파일러가 포함된 관찰값이며 이전의 프로파일러 없는 비교 측정을 대체하지 않는다.

이전 프로파일링에서는 시트 쓰기가 중앙값 39.045초로 전체의 약 86%를 차지했다. 현재는 그 병목이 크게 줄어 표 수집·변환의 비중이 가장 크다. 프로그램 시작과 통계 계산은 이번 측정 대상이 아니다.

## 다음 후보 검토

Excel 저장은 `result_entry_tables()`에서 Word용 `docx` 데이터도 준비한다. 확인한 Excel 시트 쓰기는 `screen` 값을 사용하고, 공통 인쇄 방향 판단 함수는 명시적 방향·표 종류·제목·열 수를 사용한다. Word용 데이터 변환은 두 측정에서 0.18–0.22초를 차지했다.

Excel에 한해 이 변환을 생략하는 것이 다음 검토 후보다. 적용 전에는 헤더·본문·각주 처리에서 생기는 경고와 메시지, 명시적/자동 인쇄 방향, 누적 결과 및 기본 Word 호출 경로를 검증해야 한다. 이번에는 이 변환을 생략하지 않았으며, 0.20초가 그대로 절약된다고 확정하지 않는다.

## 결과 보존과 자료

두 저장 파일의 시트 3개와 모든 읽어 들인 셀 값이 기준 파일과 동일했다. 16개 비-core 내부 파일은 바이트 단위로 동일했으며 core 메타데이터도 생성·수정 시각만 정규화하면 동일했다. 경고는 두 실행 모두 0개였다.

- 실행: `scripts/profile_excel_export.R after-parse-1`, `after-parse-2`
- 강화된 파일 비교 및 요약: `scripts/audit_excel_export_after_optimizations.R`
- 원자료: `output/excel-export-profile-20260914/`의 `after-parse-*` ID를 포함한 파일
- 요약: 같은 폴더의 `after-optimizations-measurements.csv`, `after-optimizations-summary.csv`

실행 코드를 변경하지 않았으므로 HTML/PDF/Word/HWPX 파일은 재생성하지 않았다. 설치 파일도 재빌드하지 않았다.
