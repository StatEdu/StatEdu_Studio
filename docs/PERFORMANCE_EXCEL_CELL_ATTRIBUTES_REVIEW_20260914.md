# Excel 셀 속성 일괄 읽기 검토 — 미적용 — 2026-09-14

`result_html_table_cells()`에서 셀마다 읽던 colspan, rowspan, style을 행의 셀 목록에서 먼저 읽는 후보를 시험했다. 셀 순서, 병합 값 해석, 텍스트와 위첨자 처리는 유지했다.

결과 동일성 검사는 통과했지만 전체 저장 시간의 이점이 작고 반복 간 방향이 일관되지 않아 **적용하지 않았다**. 실행 소스는 원래 줄바꿈까지 복원했으며 변경 전 스냅샷과 SHA-256이 동일하다.

## 전체 Excel 저장 측정

같은 30변수 상관분석 HTML, 3개 시트, 번들 R 4.5.3을 사용했다. 새 프로세스에서 모듈과 설정을 로드한 뒤 프로파일러 없이 측정했다. 3쌍을 순차 실행하고 두 번째 쌍은 순서를 뒤집었다. 비교 함수의 전역 도우미 환경은 같고, 파일 비교 시간은 제외했다.

| 반복 | 기존(초) | 후보(초) |
| --- | ---: | ---: |
| 1 | 2.14 | 2.12 |
| 2 | 2.16 | 2.13 |
| 3 | 2.16 | 2.18 |
| 중앙값 | 2.16 | 2.13 |

중앙값 차이는 0.03초(약 1%)이지만 마지막 반복에서는 후보가 느렸다. 이 측정으로 안정적인 개선을 주장하지 않는다. 추가 속성 배열과 인덱스 처리의 복잡성을 도입할 근거가 충분하지 않다고 판단했다.

## 검증

- `scripts/validate_excel_cell_attributes.R`: 개별 표 9개 및 누적 결과 1개 통과. 전체 기본 표 데이터, 인쇄 방향, 개별 저장의 경고와 RNG 상태가 동일했다.
- `verify_cells.R`: 빈 표, 중첩 표, 빈 행, 임의 생성 표, 누락/0/음수/잘못된 문자열/소수/정수 범위 초과 병합 속성, 빈 서식, 여러 위첨자, 다국어 및 잘못된 기하 정보 등 123개 사례에서 전체 셀 데이터와 조건·RNG 상태가 동일했다.
- 검증 Excel의 시트 이름과 읽어 들인 값, 모든 비-core 내부 파일이 동일했다. core도 생성·수정 시각만 정규화하면 동일했다.
- 전체 크기 측정 파일 6개도 기존 기준 파일과 같은 내부 비교를 통과했고 경고가 없었다.
- 철회 후 실행 소스의 SHA-256 동일성과 `git diff --check -- R/result_saved_ui.R` 통과를 확인했다.

실험 자료는 `output/excel-cell-attributes-20260914/`에 보관했다. `baseline.R`는 기존 구현, `candidate.R`는 미적용 후보다. `common.R`는 후보를 명시적으로 읽는다. CSV의 `current`는 실험 후보를 뜻한다. `measure.R baseline|current <반복 ID>` 및 `summarize.R`로 재현한다.

PDF/Word/HWPX 완성 파일과 설치 파일은 재생성하지 않았다. 앞서 적용한 최적화는 유지한다.
