# 보정 생존곡선의 중복 위험값 지수 계산 재사용

2026-09-14. `R/analysis_survival.R`의 `survival_adjusted_curve_once()`에 적용했다. 부트스트랩에서 같은 관측치가 중복 선택되어 같은 위험값이 반복될 때 `exp(-hazard * risk)`를 고유 위험값에 대해서만 계산하고, 원래 인덱스로 다시 펼친다.

평균에 전달되는 값의 순서와 개수, 결측 제거 조건, 곱셈·지수·평균 순서, Cox 재적합, 표본 추출, 난수 복원, 분위수 신뢰구간과 대비 계산은 유지한다. 위험값이 모두 유한하고 중복이 있는 경우에만 적용한다. 무한대·NA·NaN 또는 중복이 없는 경우에는 기존 지수 계산을 사용한다. 부트스트랩 횟수를 줄이거나 근사 평균을 사용하지 않는다.

## 측정

3집단, 사건 확률 0.45, 연속 생존 시간·나이 공변량, 부트스트랩 60회, 선택 시점 0·10·20. 버전별 새 R 프로세스 3개를 순차 실행하고 두 번째 비교 순서를 뒤집었다. 각 데이터 조건을 준비 실행한 뒤 GC하고 전체 `survival_adjusted_curve()`를 측정했다. 자료 생성·최초 Cox 적합·앱 로딩·렌더링·저장은 제외하며, 부트스트랩 재적합·곡선·신뢰구간·대비는 포함한다.

| 데이터 | 기존 3회 | 변경 3회 | 중앙값 | 감소 |
|---|---|---|---|---:|
| 600건 | 1.06 / 1.05 / 1.00초 | 1.00 / 1.00 / 0.99초 | 1.05 → 1.00초 | 약 5% |
| 2,000건 | 7.07 / 6.91 / 7.05초 | 6.25 / 6.24 / 6.48초 | 7.05 → 6.25초 | 약 11% |

모든 변경 후 측정이 대응 기존 측정보다 빨랐다. 이 조건에서의 결과이며 기본 부트스트랩 2,000회 전체 시간, 보정곡선 없는 Cox 분석 또는 앱 로딩 개선율을 뜻하지 않는다. 이전 보고서와 누적 개선율을 계산하지 않는다. 고유 위험값과 인덱스 벡터가 추가되며 실제 최고 메모리 사용량은 측정하지 않았다.

## 검증

- 측정 6개 비교의 전체 반환값, 경고·메시지·표준출력·난수 상태가 `identical(..., num.eq=FALSE)`로 일치. 각 실행에서 부트스트랩 60회 성공 및 CI 사용 가능 확인. 준비 실행과 측정 실행도 동일.
- 60개 보정곡선 조건: 2/3집단, 사건 비율, 동률 시간, 부트스트랩 0/25회, 중복·역순·결측 선택 시점 포함. 기존 오류가 발생하는 빈 시점도 같은 오류를 유지했다.
- 지수 결과 벡터 자체와 그 평균의 경계값 비교 120건 정확히 일치. 빈 벡터, 부호 있는 0, NA/NaN, 무한대, 극소·극대 값, 반복 위험값과 무작위 반복 벡터 포함.
- 지속 검증 `scripts/validate_survival_risk_exp_reuse.R`의 60개 곡선·120개 평균 경계값 검사 통과. 기존 `scripts/validate_survival_adjusted_mean.R`도 통과. 기존 테스트의 함수 변환이 새 `NULL` 리터럴을 삭제하지 않도록 수정하고, 검증 대상을 평균 호출식으로 좁혔다. 이는 제품 계산식 변경이 아니다.

- 관련 파일 `git diff --check` 통과.
- 실제 전체 Cox 분석(180건, 3집단, 부트스트랩 25회)의 결과·조건·표준출력·난수 상태 동일. 비교 시 재귀적으로 `.Environment` 속성만 제외했으며 수치나 다른 속성은 정규화하지 않았다. 영문 결과 패널과 그림 포함 저장 HTML도 정확히 동일했다. 현재·누적 HTML 파일 및 Excel 패키지 내용 동일(Excel 생성 시각 제외). 실행 전 난수 상태가 없던 경우에도 없는 상태로 복원됨을 확인했다.
