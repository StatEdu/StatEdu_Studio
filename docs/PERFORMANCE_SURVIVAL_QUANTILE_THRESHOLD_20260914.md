# 큰 생존 부트스트랩 행렬의 분위수 계산 개선

2026-09-14. `survival_bootstrap_intervals()`를 추가해 일반 숫자 행렬의 행 수가 1,024 이상일 때 열별 `vapply()`를 사용한다. 행 수가 작거나, 빈 열, 특수 클래스, 이름이 붙은 차원 목록이면 기존 `apply()`를 사용한다. 확률 .025/.975, 기본 분위수 type 7, 결측 제거, 열 순서와 이름을 유지한다. 부트스트랩 횟수·표본 추출·모형 적합에는 변경이 없다.

## 적용 기준 측정

표본 수 60/256/512/1,024/2,000, 시점 수 201/2,001의 10조건을 비교했다. 각 열의 처음 5개 값이 결측인 고정 난수 행렬이며, 한 측정은 함수 5회 호출이다. 버전별 3회 순차 측정하고 두 번째 쌍의 순서를 바꿨다. 모든 행렬에서 결과가 정확히 일치했다.

2,001열 조건의 중앙값은 다음과 같다.

| 행 수 | 기존 | 열별 후보 |
|---|---:|---:|
| 60 | 0.28초 | 0.30초 |
| 256 | 0.41초 | 0.44초 |
| 512 | 0.43초 | 0.48초 |
| 1,024 | 0.59초 | 0.55초 |
| 2,000 | 0.87초 | 0.78초 |

201열에서는 1,024행까지 타이머 해상도에서 대체로 같았고, 2,000행은 0.08초에서 0.06초로 줄었다. 이 표본 범위에서 작은 행렬의 느려짐을 피하도록 1,024행 기준을 선택했다. 모든 크기에 대한 최적 경계를 증명한 것은 아니다.

## 메모리 할당

시간 측정과 별도로 준비된 입력 행렬에 함수 1회를 실행하며 Rprofmem을 기록했다.

| 행렬 크기 | 기존 누적 할당 | 후보 누적 할당 | 감소량 |
|---|---:|---:|---:|
| 2,000 × 201 | 22,587,872 B | 19,365,192 B | 3,222,680 B |
| 2,000 × 2,001 | 224,864,672 B | 192,784,392 B | 32,080,280 B |

두 조건 모두 약 14% 감소했다. 이는 함수 실행 중 누적 할당량이며 실제 최고 메모리나 RSS가 아니다. 입력 생성 비용은 포함하지 않는다.

## 실제 전체 부트스트랩 비교

180건, 3집단, 기본 부트스트랩 2,000회, 선택 시점 0·10·20. 각 버전을 새 R 프로세스 3개에서 준비 실행 후 측정하고 두 번째 쌍의 순서를 바꿨다. 전체 보정곡선·부트스트랩 재적합·신뢰구간·대비를 포함하고 최초 Cox 적합·앱 로딩·렌더링은 제외했다.

| 비교 | 기존 | 후보 |
|---|---:|---:|
| 1 | 16.04초 | 11.78초 |
| 2 | 15.00초 | 11.82초 |
| 3 | 15.21초 | 15.17초 |

세 쌍 모두 후보가 느리지는 않았지만, 후보 변동이 크고 함수 단위 측정보다 차이가 훨씬 크다. 전체 속도 차이를 분위수 연산만의 효과로 단정하거나 안정적인 전체 개선율로 제시하지 않는다. 이번 적용의 주된 근거는 큰 행렬의 누적 할당 감소와 수치 동등성이다.

## 검증

- `scripts/validate_survival_bootstrap_intervals.R`: 행 수 0/1/60/1,023/1,024/1,025/2,000, 열 수 0/1/3, 난수·결측·전부 결측·상수·행열 이름·차원 이름·무한대/NaN·정수의 168조건. 수치와 속성·경고·메시지·표준출력·난수 상태가 `identical(..., num.eq=FALSE)`로 일치했다.
- 실제 2,000회 부트스트랩의 3개 전체 비교에서 반환값·곡선·CI·대비·조건·표준출력·난수 상태가 정확히 일치했다. 각 실행에서 2,000회 모두 성공했고 준비/측정 결과도 동일했다.
- 적용 경계인 1,024회 부트스트랩을 사용한 전체 Cox 분석(180건, 3집단) 결과·조건·표준출력·난수 상태도 동일했다. 비교 시 재귀적으로 `.Environment` 속성만 제외했다. 영문 결과 패널과 그림 포함 저장 HTML이 정확히 일치하고, 현재·누적 HTML 및 Excel 패키지 내용도 일치했다(Excel 생성 시각 제외). 사전에 난수 상태가 없었던 경우의 복원도 확인했다.
- 기존 지수 재사용·결측 제거 평균 검증 스크립트가 각각 60개 곡선 및 120개 평균 경계값 검사를 통과했다.
- 적용 소스와 측정 후보의 SHA256 동일: `A0273E0975FA81FD3556E1708B2DEAF082A0601FDFD89A4C1396BD3B4F60BC92`. 관련 파일 `git diff --check` 통과.
