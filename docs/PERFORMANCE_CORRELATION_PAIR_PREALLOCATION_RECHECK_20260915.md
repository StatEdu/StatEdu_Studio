# 상관분석 결과 목록 사전 할당 재검토 — 미반영

이전 `PERFORMANCE_CORRELATION_PAIR_ALLOCATION_REVIEW_20260914.md`에서 보류한 후보를 현재 코드에서 다시 측정했다. 변수 쌍 결과를 동적으로 추가하는 대신 p(p−1)/2 길이의 목록을 만들고 별도 인덱스로 저장하는 후보다. 실행 모듈에는 적용하지 않았다.

## 방법

번들 Windows R 4.5.3, JIT 3. 두 소스 환경의 함수를 모두 `compiler::cmpfun()`으로 컴파일하고, 각 조건을 한 번씩 실행한 후 측정했다. 새 프로세스 3개를 순차 실행했으며 두 번째 프로세스에서는 후보를 먼저 측정했다. 각 블록은 전체 분석과 동일성 검사를 3회 실행한 경과 시간을 3으로 나눈 값이다. 첫 호출이나 앱 로딩 시간을 나타내지 않는다.

입력은 200행 정규 난수, 6/30/60개 연속형 변수, Pearson/Spearman, 정규성 검사 및 잠재 상관분석 비활성화다. 각 조건의 기존 결과를 기준으로 전체 반환값, 경고·메시지, 표준 출력, 난수 상태를 `identical(..., num.eq=FALSE)`로 비교했다. 6조건 × 3프로세스의 사전 비교 18회 및 측정 중 108회 비교가 모두 통과했다. 결측 자료와 잠재 상관분석은 이번 측정에 포함하지 않았다.

## 결과

표는 세 프로세스의 블록 평균 중앙값이며 소수 넷째 자리까지 표시했다. 동일성 비교에는 반올림을 사용하지 않았다.

|변수 수|방법|기존(초)|후보(초)|
|---|---|---:|---:|
|6|Pearson|0.0033|0.0067|
|6|Spearman|0.0033|0.0033|
|30|Pearson|0.0533|0.0500|
|30|Spearman|0.0733|0.0667|
|60|Pearson|0.2133|0.2033|
|60|Spearman|0.3000|0.3033|

60변수 Pearson은 2회 소폭 단축, 1회 동일했다. Spearman은 2회 동일, 1회 소폭 증가했다. 일부 작은 개선이 있으나 반복 순회용 인덱스 코드를 추가할 만큼 유용한 전체 성능 향상으로 판단하지 않았다. 메모리 할당량이나 최대 사용량은 측정하지 않았으므로 메모리 절감도 주장하지 않는다. 이전 보류 결론을 유지한다.

재현 자료: `output/correlation-pair-preallocation-20260915/check.R`, `baseline.R`, `times-1.csv`~`times-3.csv`. check.R은 보관한 기준 소스의 AST를 수정해 후보를 만들므로 현재 실행 모듈을 변경하지 않고 재현할 수 있다.
