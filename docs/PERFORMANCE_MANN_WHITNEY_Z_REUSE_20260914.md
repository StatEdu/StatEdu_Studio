# Mann–Whitney z값 재사용 검증

## 변경

추가 평균·표준편차 표를 만들 때 같은 입력의 Mann–Whitney z값을 다시 계산하던 부분을 기존 분석 단위 캐시로 연결했다. `R/analysis_ttest_anova.R`의 본검정 제공 함수에 `mw_z` 분기를 추가하고 호출부 한 곳을 연결했다. z 계산식, 순위 계산, `table(data$y)`의 동점 처리는 변경하지 않았다. 매우 가까운 실수에서 기존 함수가 NA를 반환하는 동작도 그대로 보존한다.

캐시는 비모수 분석에서 추가 평균·표준편차 표가 필요한 기존 조건에서만 사용한다. 입력 값·집단·검정 종류를 정확히 비교하며, 경고·메시지·난수 상태 변경이 있으면 저장하지 않는다. 오류는 기존 경로로 전달한다. 분석 호출마다 새 캐시를 만들고 최대 16개 항목을 저장한다. 두 집단 조합은 본검정과 z값으로 2개 항목을 쓰므로, 8개 조합을 넘으면 일부 계산은 재사용되지 않을 수 있다. 계산 결과에는 영향을 주지 않는다.

## 성능

20,000행, 2개 집단, 사후검정 및 추가 평균·표준편차 표 활성화. 연속값과 반올림한 동점값, 결측률 0/0.1을 조합했다. 결측은 값과 집단에 각각 독립적으로 적용했다. 기존·변경 코드를 각각 예열하고 새 R 프로세스 3개에서 순차 측정했으며, 두 번째 실행은 측정 순서를 뒤집었다. 시간은 전체 분석 호출에 결과·진단·stdout·RNG 수집을 포함한 경과 시간이다. 함수별 추적은 넣지 않았다.

| 입력 | 결측률 | 기존 중앙값(초) | 변경 중앙값(초) |
|---|---:|---:|---:|
| 연속값 | 0 | 0.18 | 0.12 |
| 연속값 | 0.1 | 0.15 | 0.10 |
| 동점값 | 0 | 0.06 | 0.05 |
| 동점값 | 0.1 | 0.05 | 0.05 |

12개 측정 중 9개 단축, 3개 동일. 짧은 동점 자료 실행은 타이머 해상도와 실행 변동의 영향을 받으므로 일반적인 속도 향상을 보장하지 않는다. 모든 측정에서 기존 결과와 정확히 일치했다.

## 정확성 및 회귀 검증

`scripts/validate_ttest_mw_z_reuse.R`은 현재 코드에서 z값 호출만 원래 직접 호출로 복원한 참조와 비교한다. 수치 정규화나 허용오차 없이 `identical(..., num.eq=FALSE)`로 결과, 진단, stdout, 난수 상태를 확인했다.

- 원시 z값 42개: 표본 크기 0/1/4/20/100/20,000, 일반·동점·상수·아주 가까운 실수·큰 크기의 가까운 실수·결측·무한대.
- 전체 결과 24개: 2/4집단, 6개 자료 유형, 추가 표 켜기/끄기, 종속변수 2개와 효과크기 포함.
- 실제 분석 경로의 진단 주입 5개: 정상·경고·메시지·난수 변경·오류. 정상 z 계산은 2회에서 1회로 감소하며 원시 값도 동일하다. 다음 분석에서는 새로 계산한다. 나머지 경로의 결과와 호출 횟수는 기존과 동일하다.
- `scripts/validate_ttest_main_reuse.R`: 원시 본검정 50개, 전체 결과 48개, 진단 주입 10개 통과. 본검정 호출 횟수 계측에서 새 z 분기는 제외해 기존 검증 목적을 유지했다.
- `scripts/validate_ttest_pairwise_reuse.R`: 전체 결과 48개, 원시 사후검정 행렬, 진단 처리, 16개 제한, 정확한 키, 분석별 수명 검증 통과.

자료: `output/mann-whitney-z-reuse-20260914/`의 변경 전 소스, `check.R`, `product-timing-1.csv`부터 `product-timing-3.csv`. 예비 후보 측정은 `timing-*.csv`로 별도 보존했다.

UI·표 형식·내보내기 코드는 변경하지 않았다. 검증 범위에서 출력이 동일하며 별도 UI/내보내기 실행 및 배포 빌드는 수행하지 않았다.
