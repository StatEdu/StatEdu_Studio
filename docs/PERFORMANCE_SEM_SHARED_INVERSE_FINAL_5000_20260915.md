# SEM 역행렬 공유 후보: 긴 작업 적용 조건과 5,000회 검증

2026-09-15. 연구 후보 검증이며 제품 코드는 아직 변경하지 않았다.

5,000회 전체 조합 DMC의 두 독립 비교에서 재표집 시간이 **9.1~10.6% 단축**됐고, timings만 제외한 전체 결과·표본·계수·부모 진단/stdout/RNG가 정확히 일치했다. 적용 조건 검사까지 완료했다.

기존 28개 범위/호환성/진단/복구 검사와 신규 30개 작업 적용 조건 검사가 통과했다. 신규 검사는 반복 수·작업자 수 경계, 결측/무한값, 일반 SEM, 지원 밖 제품 방식·빈 지표쌍, std.lv, 다집단 및 기타 제외 설정을 다룬다. 짝별 방식 허용 검사는 명세 변경에 대한 정책 검사이며 짝별 5,000회 실행 검사가 아니다. 제외된 작업의 실제 전체 실행·취소 경로를 검사한 것도 아니다.

## 적용 조건

`scripts/fixtures/sem_shared_inverse_eligibility.R`에서 후보 설치 전 조건을 분리했다. 200회 이상, 병렬 작업자 2개 이상, 유한한 일반 수치형 완전자료, 제품지표 명세 하나, 전체 조합 또는 짝별 DMC, 단일 그룹·단일 수준 ML/LISREL, std.lv=FALSE를 요구한다. 범주형·복합체·조건부 x·집단 가중치·단순 등식 제약·무작위 효과 등 지원 밖 설정은 제외한다. 설치 후에도 기존 함수 지문/버전 검사 및 매 기울기 호출의 지원 조건을 유지한다.

200회 기준은 앞선 24회에서 준비 비용으로 느려지고 200회 전체 조합에서 이득이 관찰된 데 따른 보수적인 연구 기준이다. 최적 임계값을 추정한 것은 아니다. 짝별 DMC와 다른 작업자 수의 긴 작업 성능을 이번 전체 조합 측정으로 일반화하지 않는다.

## 비교 방법

- 안정적인 240행 전체 조합 DMC 모형, 제품지표 9개, 기존 ML/FIML 설정과 난수 시드 유지.
- 각 버전 5,000회, 작업자 4개, 청크 100, 편향 보정 신뢰구간, 모든 표본 인덱스·유효 마스크·원계수·표준화계수 반환.
- 독립 부모 프로세스 두 개에서 원본→후보와 후보→원본 순서로 실행.
- 실제 prepared 부트스트랩 엔진과 PSOCK 작업자를 사용한다. 앱의 callr 백그라운드 작업 또는 UI 전체 시간 측정은 아니다.
- 후보 함수 준비는 작업자별 한 번이다. 각 블록 종료 시 원래 namespace 바인딩과 잠금 상태 복구를 검사한다. 역행렬 값은 매 기울기 호출 시작에 초기화하고 같은 호출 안의 완전히 동일한 mlist에서만 공유한다.
- 반환 결과에서 `timings` 속성만 제거하고 `identical(..., num.eq=FALSE)`로 비교한다. 표본 배열과 부모 진단·stdout·RNG를 포함한다. 기존 내부에서 억제되는 자식 진단을 새로 수집한 검사는 아니다.

## 남은 범위

제품 작업자 수명주기와의 통합, 호환성 실패 시 후보 미설치 및 오류/취소 복구의 실제 작업 검사, 통합 후 앱 작업 경로 회귀 검증이 남아 있다. 화면/내보내기 코드를 바꾸거나 이번에 재검증하지 않았다.

통합 지점은 기존 `structural_canvas_effect_bootstrap_prepared`의 fixed-index 문맥 설치 이후와 `structural_canvas_effect_bootstrap_worker_cleanup`이다. 후보 설치 여부는 fixed-index 활성 여부까지 확인해야 한다. 기존 블록/item 실패 주입 경로, 작업 취소, 반복 실행, 호환성 불일치에서 원래 바인딩/잠금과 작업자 상태가 복구되는지 확인한 다음 앱의 callr 작업 경로로 검증한다. 연구 스크립트는 소스 파일을 직접 불러오므로 그대로 제품 코드에 복사하지 않는다.
