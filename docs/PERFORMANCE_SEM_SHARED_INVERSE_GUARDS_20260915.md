# 역행렬 공유 후보의 호환성·지원 범위·복구 검증

2026-09-15. 연구 후보에 보호 조건을 추가하고 인접 모형을 검증했다. 제품에는 아직 반영하지 않았다. 보호 조건을 포함해도 200회 전체 조합 DMC의 재표집 구간에서 약 6.6~8.3% 단축을 확인했지만, 24회 소규모 작업에서는 준비 비용 때문에 느려졌다.

## 보호 조건

`make_guarded_shared_inverse_gradient`는 번들 lavaan 0.7.2와 관련 함수 7개의 formals/body SHA256, namespace 환경을 확인한다. 대상은 기울기, 역행렬, 공분산·평균 및 LISREL 하위 함수다. 구현이 다르면 그 시점의 원래 기울기 함수를 반환한다. 활성 바인딩도 거부하도록 구성했다. 버전 불일치 및 활성 바인딩 분기 자체의 주입 검사는 이번 28개에 포함되지 않는다.

실행 경로는 단일 수준 ML/LISREL, free 기울기, 비범주·비복합·비조건부 모형, 자유 집단 가중치/랜덤 기울기/단순 등식 제약이 없는 경우로 제한했다. 실제 결측 패턴이 있으면 기존 기울기로 복귀한다. 함수 사본은 작업자별 한 번 준비하지만 역행렬 저장값은 기울기 호출 시작마다 초기화한다.

초기 조건은 `missing.flag`만 확인해 FIML 완전자료도 제외했다. 직접 활성화 검사에서 이를 발견했다. 최종 조건은 FIML 플래그가 켜져 있어도 각 그룹에 모든 변수가 관측된 단일 패턴만 있고 빈 사례가 없는지 확인한다. 최초 전체 조합 24회 검사는 결과는 같았지만 공유 활성 검증으로 인정하지 않고, 수정 후 전 조건을 새 `final` 폴더에서 재실행했다.

이는 연구용 지원 조건이다. 모든 추정법·다집단·std_lv 설정·복합/랜덤 모형을 검증한 것은 아니다. 생성 후 의존 함수가 동적으로 바뀌는 상황까지 자동 대응하는 제품 수명주기 통합도 아직 남아 있다.

## 호환성 및 경계 검사 28개

- 5개 직접 호출: 지원 경로, full 기울기, ceq_simple 요청, 결측 패턴 표시 경계, group_weight=FALSE. 지원 경로는 역행렬 요청 3개 중 2개 재사용, 제외 경로는 공유 호출 0개를 확인했다. 결측 패턴 표시 경계는 직접 구성한 분기 검사이고 실제 결측 모형은 아래 통합 검사로 확인했다.
- 7개 함수 × 본문/인자/환경 변경 3종 = 21개: 변경을 감지하고 원래 기울기 함수를 반환하는지 확인했다. 각 주입 후 원래 namespace 함수와 잠금 상태를 정확히 복원했다.
- 역행렬 함수에 경고·메시지·난수 소비를 주입한 경우 및 오류를 주입한 경우 2개: 호환성 거부 후 기존 결과·진단·stdout·RNG가 보존됐다. 경고/메시지 6개 및 오류 문구도 명시적으로 확인했다.

최종 검사 모두 통과했다. 실제 패키지 파일은 편집하지 않았고 주입은 별도 검증 프로세스의 메모리 바인딩에 한정했다.

## 인접 모형의 전체 부트스트랩

일반 완전자료, 일반 10% 결측(216셀), 짝별 DMC(제품지표 3개), 전체 조합 DMC(9개)를 각각 두 독립 프로세스에서 원본/후보 비교했다. 240행, ML/FIML, std_lv=FALSE, 작업자 4개·청크 100개, 24회, return_draws=TRUE다. seed는 일반 20260826, 짝별 20260832, 전체 조합 20260833이다. 두 번째 실행은 조건 및 버전 순서를 뒤집었다.

모든 실행에서 유효 24/24, fixed-index 활성 및 fallback 0이었다. 공유 지원을 점추정 기울기에서 별도로 확인했으며 일반 완전/두 제품지표는 역행렬 요청 3개·재사용 2개, 실제 결측 모형은 공유 호출 0개였다. 이 계수는 모든 작업자 호출을 계측한 합계가 아니다.

각 비교는 timings 속성만 제거한 전체 결과, 표본 행 인덱스·유효 마스크·원계수·표준화계수와 부모 진단/stdout/RNG를 `identical(..., num.eq=FALSE)`로 검사했다. 8개 비교 및 조건별 프로세스 간 4쌍 비교가 통과했다. 후보 블록 종료 때 원래 기울기 함수와 바인딩 잠금 상태 복원도 검사했다. 기존 작업자가 억제한 자식 진단 전체를 새로 수집한 검사는 아니다.

24회에서 관측된 재표집 시간 범위:

| 조건 | 기준(초) | 후보(초) |
|---|---:|---:|
| 일반 완전 | 0.493~0.518 | 0.698~0.707 |
| 일반 결측 | 0.932~0.944 | 1.086~1.118 |
| 짝별 DMC | 0.814~0.815 | 0.955~0.978 |
| 전체 조합 DMC | 1.055~1.083 | 1.163~1.192 |

모든 소규모 조건이 느렸다. 특히 복귀 경로에서도 연구용 설치·확인 비용이 발생했다. 따라서 현재 후보를 모든 작업에 무조건 설치하는 방식은 채택하지 않는다.

## 보호 조건을 포함한 200회 재측정

같은 최종 후보를 전체 조합 DMC에서 200회씩 두 독립 프로세스로 비교했다. 둘 다 전체 반환/표본/계수/부모 진단/stdout/RNG 정확 일치, 유효 200/200, fixed-index 활성·fallback 0, 복원 검사를 통과했다. 프로세스 간 원본 결과도 정확히 일치했다.

| 실행 | 기준 재표집(초) | 후보 재표집(초) | 변화 |
|---|---:|---:|---:|
| 1 | 8.058 | 7.523 | -6.64% |
| 2 | 8.127 | 7.456 | -8.27% |

함수 호환성 검사와 작업자별 함수 준비·설치/복구를 포함한 재표집 구간이다. 전체 앱 대기시간이나 보호 조건 없는 이전 후보의 10~14% 개선율과 혼용하지 않는다. 캐시 준비 전 점추정·엔진 준비·화면·내보내기는 제외한다.
