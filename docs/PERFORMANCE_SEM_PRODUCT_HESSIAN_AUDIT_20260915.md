# 제품지표 SEM Hessian 기울기 입력 중복 감사

2026-09-15. 제품 변경 없음. 현재 전체 조합 제품지표 fixture에서 단일 Hessian 내부의 동일 기울기 입력은 관측되지 않았다. 기울기 결과 전체를 입력별로 캐시하는 후보는 구현하지 않는다.

## 코드와 검사 범위

번들 lavaan의 실제 `lav_model_hessian` 함수를 읽고 해당 함수를 산출물로 보관했다. 이번 fixture는 함수의 `richardson` 분기를 사용했다. 각 모수 j에 대해 기존 x에서 해당 성분을 `-h`, `-2h`, `+h`, `+2h`만큼 바꾼 네 벡터의 기울기를 계산하고 기존 결합식으로 Hessian 열을 만든다. h는 1e-6이었다.

전체 조합 DMC의 기존 240행·관측 지표 9개·제품지표 9개, ML/FIML, std_lv=FALSE, seed 20260833, bias-corrected CI, 작업자 4개·청크 100개를 사용했다. 이번 입력 감사는 24회 재표집으로 제한하고, 표본 인덱스 및 원계수 검증을 위해 return_draws=TRUE로 실행했다. 앞선 5,000회 전체 실행의 모든 Hessian을 감사한 것은 아니다.

연구용 작업자에서만 lavaan namespace의 Hessian 함수 사본을 잠시 설치하고, 블록 종료 시 원래 함수와 바인딩 잠금 상태를 복원했다. 설치 패키지 파일과 제품 함수 파일은 변경하지 않았다. Hessian 내부 `grad_at` 호출 직전에 x_p를 serialize(version=2)로 보관했다. 같은 Hessian 안에서는 다른 입력인 모형·자료·캐시 등이 고정된 채 x_p가 바뀌므로, 이 벡터의 정확한 중복 여부가 기울기 전체 결과 재사용의 우선 조건이다.

직렬화된 raw 벡터 목록의 중복을 검사해 부호 있는 0 등의 비트 차이를 보존하고, 해시 충돌이나 수치 허용오차를 도입하지 않았다. 서로 다른 Hessian/적합 사이의 전체 인자 중복을 검사한 것은 아니다.

이번 감사는 성능 측정이 아니며 기록·직렬화 비용을 실행 성능으로 보고하지 않는다. 앞선 프로파일에서 Hessian이 작업자 표본 시간 약 36~38%를 차지했더라도, 그 비중을 곧바로 제거 가능한 중복 비용으로 볼 수 없다.

## 동일성 및 실행 이력

- 세 독립 프로세스에서 원본과 계측을 순차 실행했으며 두 번째는 순서를 뒤집었다.
- 반환 객체의 timings 속성만 제거하고 전체 결과, 24개 표본 인덱스·유효 마스크·원계수/표준화계수, 부모에서 포착한 조건·stdout·RNG를 묶어 `identical(..., num.eq=FALSE)`로 비교해 세 번 모두 통과했다. 매 실행 유효 24/24, fixed-index/product-aware 활성, fallback 0이었다.
- 원본 결과의 프로세스 간 비교 두 쌍도 통과했다. 반올림·환경 속성 제거·수치 허용오차는 사용하지 않았다. 기존 작업자 내부가 억제한 자식 진단 전체의 비교로 확대하지 않는다.
- 최초 연구 스크립트는 중첩 bquote가 안쪽 표현을 너무 일찍 평가해 준비 단계에서 실패했다. 외부 치환을 substitute로 고친 뒤 최종 세 실행을 완료했다. 이 실패는 제품 수치 오류가 아니며 결과/성능 자료에 포함하지 않았다.

## 판단과 다음 단계

동일 기울기 입력 캐시는 이 fixture의 단일 Hessian 내부에서 적중 근거가 없어 미구현으로 종료한다. 기존 일반 SEM 역행렬 캐시 보류 결정도 유지한다.

다음 검토는 `lav_model_grad` 안에서 x_p에 따라 변하지 않는 구조나 자료 준비가 반복되는지 확인하는 것이다. 모수 벡터가 달라도 모든 내부 계산이 달라지는 것은 아니지만, 아직 재사용 가능한 연산을 발견했다는 뜻은 아니다. 표준오차·추론·유효성 검사와 기존 차분 간격·결합식·호출 순서는 유지한다.
