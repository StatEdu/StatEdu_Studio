# 추가 제외 사유와 행 번호 보관 비용 재계측

제품 코드는 변경하지 않았다. 직전 최초 사유 기록 최적화가 적용된 현재 코드를 기준으로 남은 비용을 분리했다. 다음 후보는 기존 사유가 있는 행에 단일 사유를 추가할 때 전체 목록에 다시 적용하는 `unique` 경로이다.

## 방법

`scripts/profile_survival_reason_remaining.R`에서 현재 모듈 두 사본을 읽고 한쪽의 지역 `add_reason`만 AST로 교체한다. 최종 제품과 같은 연산을 유지하면서 다음 네 구간에 시계를 넣는다.

1. 지연된 mask 인자 평가.
2. `which(!is.na(mask) & mask)` 인덱스 구성.
3. 기록된 공변량 결측 행 확인과 행 번호 목록 보관.
4. 최초 사유 직접 기록 또는 기존 사유에 추가 기록.

번들 R 4.5.3, 실제 앱 모듈·환경설정 초기화, 같은 시드, 20,000/100,000행, 공변량 6개, 집단 3수준. 두 독립 프로세스에서 조건 순서를 반대로 실행했다. 원래 함수는 준비 후 5회 전체 시간, 계측 사본은 준비 후 3회 단계별 시간을 측정했다.

정상/사건 5%·집단 5% 결측(sparse)/같은 절반의 행에 사건·집단·공변량 6개 결측(overlap)/공변량별 결측 행이 서로 다른 조건(disjoint)을 사용했다. 각 결과가 성공이고 분석 행 수가 complete.cases로 계산한 예상값과 일치하는지 확인했다.

각 프로세스 72개, 합계 144개 원래 함수/계측 사본 전체 결과·속성·진단·stdout·RNG 비교가 `identical(..., num.eq=FALSE)`로 통과했다. 저장된 프로세스 간 결과 8쌍도 일치했다. 환경 정규화나 수치 허용오차는 사용하지 않았다.

## 원래 전체 전처리 시간

독립 실행 1 / 2의 중앙값, 단위 ms.

| 조건 | 20,000행 | 100,000행 |
|---|---:|---:|
| 정상 | 9.29 / 11.53 | 42.65 / 46.69 |
| sparse | 17.14 / 13.42 | 70.58 / 67.96 |
| overlap | 96.77 / 103.18 | 508.80 / 531.08 |
| disjoint | 29.31 / 28.98 | 140.09 / 119.79 |

## 100,000행 단계별 시간

각 계측 반복에서 모든 add_reason 호출의 시간을 구간별로 합한 뒤 중앙값을 계산했다. 단위 ms, 실행 1 / 2.

| 조건 | mask 평가 | 인덱스 | 행 번호 확인·보관 | 사유 기록 |
|---|---:|---:|---:|---:|
| 정상 | 16.22 / 16.03 | 8.82 / 1.60 | 0.036 / 0.029 | 0.018 / 0.017 |
| sparse | 16.11 / 13.64 | 5.02 / 3.88 | 0.054 / 0.031 | 2.35 / 1.36 |
| overlap | 10.47 / 15.82 | 2.89 / 12.06 | 25.68 / 24.28 | 372.54 / 396.36 |
| disjoint | 18.62 / 17.76 | 2.14 / 3.95 | 5.15 / 4.91 | 10.32 / 9.53 |

시계 호출 및 계측에 따른 실행 비용 변화가 포함되고 원래 함수의 타이밍과 별도 실행이다. 따라서 이 표를 원래 함수 시간으로 나눠 정확한 비중이나 예상 개선율을 계산하지 않는다. 극히 작은 구간은 시계 해상도·오버헤드의 영향을 크게 받는다.

overlap에서 같은 50,000행에 대한 코드별 기록 시간은 다음과 같다.

| 사유 | 처리 의미 | 실행 1 / 2(ms) |
|---|---|---:|
| missing_event | 첫 사유 직접 기록 | 8.33 / 9.65 |
| missing_group | 기존 사유에 두 번째 사유 추가 | 177.95 / 188.45 |
| missing_covariate | 기존 사유에 세 번째 사유 추가 | 189.48 / 197.78 |

공변량 결측의 인덱스는 여전히 총 300,000행분을 검사하지만 실제 기록은 50,000행으로 줄어 있음을 확인했다. 행 번호 확인·보관은 약 24~26ms로, 추가 사유 기록보다 작았다. 코드별 중앙값과 전체 합의 중앙값은 산출 순서가 달라 단순 합이 정확히 일치하지 않을 수 있다.

## 다음 후보
