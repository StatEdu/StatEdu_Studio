# Cox 진단 자료의 잔차 유한값 검사 재사용 — 2026-09-14

> 검증 범위 정정 (2026-09-14): 아래의 경쟁위험/Fine–Gray 전체 결과 검증 표현은 당시 `integration.R`이 `regression`을 지정하지 않아 기본 CIF/Gray 경로만 실행한 것을 잘못 기술한 것이다. 그 검증은 원인별 Cox 또는 Fine–Gray 회귀 검증으로 볼 수 없다. 직접 함수 및 Cox 검증 결과는 별개다. 이후 `regression="both"`를 명시한 600행·20공변량 자료에서 초기 Cox 최적화 전과 현재 모듈 전체의 결과·진단·난수 상태를 비교해 통과했다. 상세 내용은 [원인별 Cox 저장·통합 검증](COMPETING_PH_EXPORT_VALIDATION_20260914.md)을 참고한다.

`survival_cox_functional_form_data`에서 공변량마다 동일하게 계산하던 마팅게일 잔차의 유한값 여부를 한 번 계산해 재사용하도록 적용했다. 숫자 변환 후 속성 없는 숫자 벡터에만 적용하며 이름/특수 클래스 등 속성이 남아 있으면 기존 검사를 유지한다. 분석 대상 행, 변수 순서, 값 및 결과표 생성 방식은 바꾸지 않았다.

## 측정

번들 R 4.5.3, 앱 설정 적용, 자동 설치 비활성화. 새 프로세스에서 변경 전후 3쌍을 순차 실행하고 두 번째 쌍은 순서를 반대로 했다. 공변량 10개, 각 프로세스에서 1천 행 다음 10만 행을 실행했다. 시간은 진단용 자료 생성 함수 전체이며 모형 적합·나머지 진단·UI·내보내기·앱 로딩은 포함하지 않는다.

시간 측정 후 별도 실행에서 각 함수를 3회 준비 실행하고 gc() 후 1회 호출을 Rprofmem으로 측정했다. 10만 행·10공변량의 기록된 총 할당량은 280,059,040→276,458,608바이트로 3,600,432바이트(약 3.60MB, 1.3%) 감소했다. 이는 기록된 누적 할당량이며 최대 메모리나 프로세스 RSS가 아니다. 동일 잔차의 유한값 벡터 생성 10회를 1회로 줄인 효과다.
