# 다변수 상관분석 결측 패턴 성능·캐시 감사

2026-09-15. 최근 설치본에 포함된 상관분석 엔진의 다음 개선 후보를 선정하기 위한 측정이다. 제품 코드와 설치 파일은 변경하지 않았다.

## 측정

번들 R 4.5.3, 실제 환경설정 초기화, 시드 20260915 정규 합성 자료 10,000행·40변수·780쌍, 정규성 표 활성화. 완전 자료, 모든 변수에 같은 1,000행 결측, 변수마다 독립적으로 선택한 1,000행 결측을 비교했다. 마지막 조건은 변수마다 결측률 10%이며 쌍별 유효 행 수는 서로 다르다.

두 독립 R 프로세스에서 조건 순서를 반대로 실행했다. 각 조건은 준비 1회, 시간 측정 3회, 별도 Rprof 1회(10ms 간격)다. 아래 값은 비프로파일 3회 중앙값이다. 전체 분석 및 진단/표준출력 수집을 포함하고 데이터 생성·모듈 로딩·화면·저장은 제외한다. 이 표는 서로 다른 입력 조건 비교이며 최적화 전후 개선율이 아니다.

| 조건 | 프로세스 1 (초) | 프로세스 2 (초) |
| --- | ---: | ---: |
| Pearson 완전 자료 | 0.422 | 0.562 |
| Spearman 완전 자료 | 0.749 | 0.778 |
| Spearman 공통 결측 | 1.007 | 1.023 |
| Spearman 서로 다른 결측 | 2.382 | 2.340 |

서로 다른 결측 조건의 `base::rank` self 표본 비중은 46.88%/44.44%, total은 49.38%/50.62%였다. 순위 계산은 다음 검토의 주요 대상이다. 공통 결측에서는 `unique.default` self가 17.95%/10.29%였다. 단일 프로파일의 표본 변동이 있으므로 정밀한 구성비나 예상 단축률로 해석하지 않는다.

## 실제 캐시 계산 횟수

별도 함수 사본에서 캐시 내부의 `base::rank`와 `base::unique`만 계측했다. 원래 함수의 계산과 캐시 정책은 유지했다. 시간 표에는 계측 실행이 포함되지 않는다.

| 조건 | 실제 rank 계산 | 캐시 내부 unique 계산 | 최종 캐시 항목 | object.size (bytes) |
| --- | ---: | ---: | ---: | ---: |
| Pearson 완전 | 0 | 0 | 0 | 48 |
| Spearman 완전 | 40 | 40 | 40 | 9,623,728 |
| Spearman 공통 결측 | 40 | 0 | 40 | 5,778,288 |
| Spearman 서로 다른 결측 | 1,560 | 0 | 40 | 5,200,400 |

unique 0은 고유값 검사가 없다는 뜻이 아니다. 결측 조건에서는 기존 정책에 따라 unique 캐시가 비활성화되어 원래 통계 함수가 직접 계산한다. object.size는 캐시 목록의 R 객체 크기이며 실제 프로세스 RSS나 최고 메모리가 아니다.

780쌍의 순위 요청은 1,560개다. 완전/공통 결측은 40개 변수의 순위만 계산했지만 서로 다른 결측에서는 요청마다 다시 계산했다. 쌍마다 남는 관측치가 달라지므로 전체 열의 순위를 그대로 대입하면 통계 결과가 달라질 수 있다. 이를 적용하지 않는다.

## 정확성 및 다음 후보

프로파일 포함 프로세스 내부 32개, 프로세스 간 4개, 계측 사본 4개로 총 40개 비교에서 전체 반환 결과·속성·경고/메시지·표준출력·난수 상태가 `identical(..., num.eq=FALSE)`로 일치했다. 각 결과의 쌍별 표가 780행인지도 확인했다. 이번 비교는 현행 엔진에 대한 측정/계측의 비간섭 검증이다.

다음 후보는 **공통 결측 패턴에서 고유값 캐시를 제한적으로 활성화하는 것**이다. 현재 조건은 모든 변수가 완전 자료일 때만 활성화되지만, 공통 결측에서는 순위 캐시가 이미 40개로 재사용된다. 공통 패턴 탐지 비용, 특수 속성/NaN/진단 보존, 캐시 메모리 증가, 서로 다른 결측 조건의 성능 저하 여부를 A/B 검증한 뒤 적용 여부를 결정한다. 이번에는 후보 구현이나 속도 개선을 완료한 것으로 간주하지 않는다.

분석 출력이 변경되지 않아 이번 단계에서 내보내기 파일을 다시 생성하지 않았다.
