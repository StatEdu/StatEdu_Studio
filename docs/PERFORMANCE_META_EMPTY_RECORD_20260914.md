# 메타분석 빈 결과 표 생성 간소화 — 2026-09-14

`meta_empty_effects()`의 고정된 빈 열 목록을 `structure(list(...), class = "data.frame", row.names = integer(0))`로 만들도록 변경했다. 각 열의 타입과 길이가 이미 명시되어 있으므로 일반 `data.frame()` 생성자의 열별 변환을 반복할 필요가 없다. 열 이름·순서·타입·행 이름을 유지하며 매번 새 결과를 반환한다. 전역 캐시나 공유되는 수정 가능한 표를 추가하지 않았다.

## 전체 정규화·적합 측정

| 연구 수 | 기존 3회(초) | 후보 3회(초) | 중앙값 변화 |
|---|---|---|---|
| 120 | 0.33 / 0.28 / 0.32 | 0.17 / 0.22 / 0.19 | 0.32 → 0.19, 약 41% 감소 |
| 500 | 1.74 / 1.69 / 1.66 | 1.08 / 1.08 / 1.10 | 1.69 → 1.08, 약 36% 감소 |

직전 숫자 필드 일괄 대입 개선을 포함한 소스를 기준으로 비교했다. 과거 보고서의 시간과 직접 비교한 값이 아니다. 번들 R 4.5.3의 새 프로세스 3개를 순차 실행했으며 두 번째는 기존/후보 순서를 뒤집었다. 각 조건은 준비 실행 후 GC와 경과 시간 측정을 수행했다.

연구별 집계 효과 하나, -0.6~0.6의 효과값, 분산 0.1, g, 랜덤효과 REML, 95% 신뢰수준을 사용했다. 측정은 `meta_fit_aggregated()`의 정규화·전체 모형 적합·반환값 생성 및 입력 데이터프레임 구성·조건 수집을 포함한다. 앱 로딩·화면·내보내기는 제외하며, 모든 메타분석이나 앱 전체의 개선율로 해석하지 않는다. 메모리 사용량은 측정하지 않았다.

## 검증

- 기존 빈 표와 후보 빈 표를 `identical(..., num.eq=FALSE)`로 비교했다. 값·열 타입·이름·행 이름·속성이 일치한다. 반환 표를 수정해도 다음 빈 표가 변하지 않는 것을 확인했다.
- 신규 `scripts/validate_meta_empty_effects.R`은 지원 입력 형식 14개 × 9개 입력 변형의 126개 조건에서 기존 생성자와 비교했다. 반환값·속성·오류/경고/메시지 클래스와 문자열·표준출력·난수 상태가 일치했다. 수치 허용오차는 사용하지 않았으며 조건 객체의 호출 환경 자체는 비교하지 않는다.
- 두 연구 수 × 새 프로세스 3개의 준비 및 시간 측정에서 전체 모형·경고/메시지 문자열·난수 상태가 일치했다. 적용 후 실제 소스로 저장된 기존 모형 6개와 다시 비교해 모두 일치했다.
- 기존 입력·모형·UI, 숫자 필드, 연구별 제외, Trim-and-fill 검증을 수행했다.
