# 분할 입력 조회의 서버 이벤트 검증

2026-09-15. 기존 분할 조회 개선을 실제 `register_category_label_observers()`와 `apply_category_label_snapshot()`에 연결한 Shiny `testServer()` 환경에서 검증했다. 제품 코드는 추가 변경하지 않았다.

## 조건과 비교 범위

`scripts/benchmark_category_chunk_server.R`를 독립 R 프로세스 2개에서 실행했다. 500행 표에서 입력 없음, 일부 입력, 전체 입력을 비교했다. 일부 입력은 매 10번째 행의 4개 필드(변수 라벨·기준값·첫 범주값·첫 범주 라벨), 전체 입력은 모든 행의 25개 필드다.

버전별 새 테스트 서버를 만들고 첫 적용과 동일 값 재적용을 실행했다. 두 번째 프로세스에서는 구버전/신버전 순서를 뒤집었다. 첫 적용은 새 입력 의존성 등록, 최초 함수 실행 및 값 변경 비용을 포함한다. 따라서 첫 적용 시간을 충분히 준비된 수집 함수의 순수 비용으로 해석하지 않는다.

실제 이벤트 등록 함수를 사용하되 다른 편집 콜백은 빈 함수로 두었다. 저장 요청 콜백에서는 실제 스냅샷 함수를 호출해 저장 표를 갱신했다. 측정은 입력 수집 호출, 스냅샷 처리, `session$setInputs()`부터 이벤트 flush 반환까지의 세 구간으로 나눴다. 입력 객체 준비, 명시적 GC와 테스트 서버 종료는 측정 밖이다. 시간은 `Sys.time()` 기준이며 각 조건당 한 번씩이다.

두 버전의 요청 내용 전체, 최종 표 및 속성, `changed`, `var_label_updates`를 `identical(..., num.eq=FALSE)`로 비교했다. 3조건 × 2적용 × 2프로세스의 12쌍이 모두 일치했고, 모든 재적용의 `changed`가 FALSE임을 확인했다.

## 이벤트 flush까지의 시간

| 조건 | 적용 | 기존 초(실행 1 / 2) | 분할 초(실행 1 / 2) |
|---|---|---:|---:|
| 입력 없음 | 첫 적용 | 4.029 / 4.456 | 3.529 / 3.188 |
| 입력 없음 | 재적용 | 2.555 / 2.568 | 1.663 / 1.673 |
| 일부 입력 | 첫 적용 | 4.668 / 4.541 | 3.462 / 3.684 |
| 일부 입력 | 재적용 | 2.606 / 2.671 | 1.666 / 1.666 |
| 전체 입력 | 첫 적용 | 4.897 / 4.887 | 3.792 / 3.816 |
| 전체 입력 | 재적용 | 2.842 / 2.805 | 1.857 / 1.857 |

전체 입력의 재적용은 약 34~35% 단축됐다. 빈 입력과 일부 입력의 재적용도 각각 약 35%, 36~38% 단축됐다. 모든 측정 조건에서 이벤트 flush 반환까지의 시간이 줄었다.

## 측정 구간 해석

기존 수집 함수의 타이머가 끝난 뒤에도 외부 isolate 종료 시 콜백 정리 비용이 남는다. 분할 버전은 각 내부 isolate 종료 비용이 수집 함수 시간에 이미 포함된다. 따라서 두 버전은 수집 함수 자체의 시간만 비교하면 관리 비용의 위치 차이를 놓칠 수 있다. 이벤트 flush 반환까지의 시간을 함께 기록한 이유다. 세 구간은 포함 관계가 있으므로 합산하지 않는다.

전체 입력 재적용의 실제 스냅샷 함수 비용은 약 0.13~0.16초였다. 입력 수집/반응성 관리 비용이 여전히 더 크다. 초기 빈 입력의 스냅샷 함수는 프로세스에서 먼저 실행한 버전만 약 0.03~0.04초가 소요되어, 초기 실행 비용과 준비된 실행 비용을 구분해야 함도 확인했다.

이는 브라우저 없는 서버 테스트다. 실제 화면 반응, 네트워크, 파일 쓰기, 다른 앱 콜백, 분석 계산 또는 내보내기 시간을 포함하지 않는다. 이번 검사에서 진단/RNG 전체나 브라우저 저장 흐름을 새로 검증한 것은 아니다. 동결 입력 및 조회 순서의 검증은 앞선 `PERFORMANCE_CATEGORY_INPUT_CHUNKS_20260915.md`에 기록돼 있다.
