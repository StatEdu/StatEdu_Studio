# Cox VIF 보조회귀 반환 객체 축소 후보 검토 — 2026-09-14

## 결론

운영 코드를 변경하지 않았다. `survival_cox_collinearity()`에서 잔차만 사용하는 `stats::lm.fit()`을 일반 입력에 한해 `stats::.lm.fit()`으로 대체하는 후보를 시험했다. 10만 행·20공변량에서 중앙값이 1.76→2.08초로 약 18.2% 증가해 채택하지 않았다.

동봉 R 4.5.3 소스를 확인했다. 두 함수는 같은 `C_Cdqrls`와 기본 허용오차 1e-7을 사용한다. `.lm.fit()`은 `check=TRUE`이며 `lm.fit()`의 계수 이름, 효과 이름, 적합값 및 반환 객체 재구성 단계를 수행하지 않는다. 이번 측정만으로 속도 저하의 내부 원인을 특정하지는 않았다. 반환 단계가 짧다는 사실만으로 전체 실행이 빨라진다고 판단할 수 없다.

후보는 `others`와 `target`에 클래스가 없을 때만 `.lm.fit()`을 사용하고, 나머지는 원래 함수를 호출했다. 절편 행렬 구성, 열 순서, 잔차 제곱합, 총 제곱합, VIF 및 조건수 계산은 변경하지 않았다. 후보 코드는 출력 디렉터리 `current.R`에만 존재한다.

## 실행 시간

동봉 R 4.5.3, 정규 합성 입력, 시드 42. 각 공변량 수에서 기존/후보를 각각 새 프로세스로 3회 측정했고 두 번째 쌍은 후보부터 실행했다. 각 프로세스는 1천 행 다음 10만 행 순서로 다중공선성 진단 함수 전체를 실행했다. 자료 생성과 결과 저장은 제외하고 동일한 진단 수집 래퍼는 포함했다. 시간 측정 중 프로파일러나 별도 검증은 실행하지 않았다.

| 행 수 | 공변량 | 기존 3회(초) | 후보 3회(초) | 중앙값 기존 → 후보 |
|---|---:|---|---|---|
| 1,000 | 5 | 0.01 / 0.02 / 0.03 | 0.03 / 0.02 / 0.02 | 0.02 → 0.02 |
| 100,000 | 5 | 0.16 / 0.16 / 0.17 | 0.15 / 0.18 / 0.16 | 0.16 → 0.16 |
| 1,000 | 20 | 0.04 / 0.03 / 0.03 | 0.03 / 0.03 / 0.02 | 0.03 → 0.03 |
| 100,000 | 20 | 1.76 / 1.77 / 1.75 | 2.08 / 2.09 / 2.08 | 1.76 → 2.08 |

작은 입력의 0.01초 차이는 측정 변동을 고려해야 한다. 전체 Cox 분석이나 화면 대기 시간에 대한 측정은 아니다.

## 메모리와 동일성

10만 행·5공변량에서 각각 3회 예열하고 GC 후 한 번 별도로 측정한 Rprofmem 기록 할당량은 174,809,384→162,808,864바이트로, 12,000,520바이트(약 12.00MB, 6.9%) 감소했다. 이는 누적 기록 할당량이며 최대 사용 메모리나 RSS가 아니다. 20공변량의 메모리는 측정하지 않았다.

0/1/2/40행 × 일반 입력, NA, Inf, 상수열, 중복열, 행 이름, 데이터 프레임, 단일 열, 사용자 클래스 행렬의 36조건에서 반환값·오류/경고/메시지·난수 상태가 `identical(..., num.eq=FALSE)`로 일치했다. 공변량 5개와 20개 시간 측정의 총 12쌍에서도 전체 결과·진단·난수 상태가 일치했다. 모든 입력에 대한 동등성 증명은 아니다.
