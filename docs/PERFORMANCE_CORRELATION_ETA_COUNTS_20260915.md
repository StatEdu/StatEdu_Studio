# Eta 집단별 관측치 수 직접 집계

> 후속 검증: 적합 준비 단축까지 포함한 현재 제품의 통합 효과와 사용자 정의 대비의 진단·난수 보존은 [통합 검증 기록](PERFORMANCE_CORRELATION_ETA_COMBINED_20260915.md)을 참고한다. 개별 개선율은 합산하지 않는다.

## 변경

`correlation_eta_result`에서 `table(groups)` 대신 이미 준비된 factor의 코드를 `tabulate(groups, nbins=nlevels(groups))`로 세고 `levels(groups)`를 이름으로 지정한다. 결측 제거 및 `droplevels(factor(...))` 후의 집단을 사용하므로 남은 수준의 순서대로 관측치 수를 얻는다. 다시 일반 교차표를 구성하는 준비 비용을 줄인다.

집단 평균은 기존 `tapply`를 그대로 사용한다. 이어지는 `as.numeric(counts) * (means[names(counts)] - grand)^2`와 합산 순서도 변경하지 않았다. Eta 계수, lm 적합 및 ANOVA 요약 경로는 유지했다. 앞서 적용한 lm 적합 준비 단축 이후 소스를 기준으로 비교했으며 두 변경의 개선율을 합산하지 않는다.

## 검증

`scripts/validate_correlation_eta_counts.R`은 실제 제품 함수에서 기존 `table(groups)`를 복원하여 비교한다. treatment/sum/Helmert 대비, 2/3/6집단, 3/12/100행, 일반·인접 실수·동점·큰 수·결측·무한대·상수·ordered 자료의 216개 조건에서 다음이 일치했다.

- 전체 반환값·진단·stdout·난수 상태
- 집계 이후 계산에 쓰이는 수 벡터와 집단 이름, 집단 평균, 전체 및 집단 간 제곱합의 수집 결과
- 153개 조건에서 생성된 원시 ANOVA 요약 객체

기존 counts는 table이고 변경 counts는 이름이 있는 정수 벡터다. 내부 컨테이너 자체가 동일하다는 뜻은 아니다. 실제 기존 후속 계산에서 사용하는 `as.numeric(counts)`와 `names(counts)`를 비교했다. 최종 결과나 제곱합의 수치를 정규화한 것은 아니다. 모든 비교는 `identical(..., num.eq=FALSE)`로 수행했고 허용오차·반올림을 사용하지 않았다. 조기 반환되는 조건은 그 반환과 진단을 그대로 비교했다.

별도 입력 조합 100개와 전체 분석 네 조건도 검증했다. 제품 반영 후에는 이전 소스와 실제 제품 소스로 다시 실행하여 같은 검증을 통과했다.

## 성능

10,000행·20변수·190쌍, 여섯 범주의 명목형 및 연속형 10개/명목형 10개 혼합 자료를 사용했다. 결측 조건은 변수마다 다른 무작위 10% 결측이다. 시드 33, Pearson 지정, 정규성 및 잠재상관 비활성화 조건이다. 혼합형에는 Eta 100쌍이 있고 명목형은 변경 경로를 사용하지 않는 대조 조건이다.

각 소스 환경의 상관분석 함수를 명시적으로 컴파일하고 새 R 프로세스 세 개에서 순차 실행했다. 양쪽 예열 후 두 번째 프로세스에서 조건 및 기존/변경 실행 순서를 뒤집었다. 시간은 **전체 결과 준비·진단 수집·동일성 검사를 5회 반복한 총시간을 5로 나눈 값**이다. 프로파일러는 사용하지 않았다.

| 자료 | 기존 3회 값(초) | 변경 3회 값(초) |
|---|---|---|
| 명목형 | 0.236 / 0.244 / 0.218 | 0.234 / 0.252 / 0.222 |
| 명목형, 결측 10% | 0.220 / 0.250 / 0.216 | 0.222 / 0.232 / 0.214 |
| 혼합형 | 0.370 / 0.356 / 0.356 | 0.344 / 0.362 / 0.330 |
| 혼합형, 결측 10% | 0.340 / 0.344 / 0.330 | 0.310 / 0.316 / 0.302 |

결측 혼합형은 세 번 모두 단축됐고 중앙값 0.340→0.310초로 약 9% 감소했다. 결측 없는 혼합형은 두 번 단축, 한 번 증가했으며 중앙값은 0.356→0.344초다. 변경 경로가 없는 명목형에서도 변동이 있으므로 미세한 차이를 모두 코드 효과로 해석하지 않는다. 모든 조건이나 개별 호출에서 빨라진다고 보장하지 않는다.

12개 조건/프로세스 조합에서 각 반복의 전체 반환값·진단·stdout·난수 상태가 기존 기준 결과와 정확히 일치했다. 제품 반영 후 `product.R`의 시간은 컴파일 조건을 재정렬한 성능 근거로 사용하지 않고 결과 검증에만 사용한다.

## 자료와 범위

`output/correlation-eta-count-review-20260915/`에 이전 소스 `baseline.R`, 후보 생성 `setup.R`, `batch.R`, 시간 CSV 세 개, `validate.R`, `validate-state.R`, 제품 비교 `product.R`을 보존했다. R 4.5.3 번들 런타임, 영어 UTF-8 로캘, 기존 모듈 캐시와 패키지 설치 비활성화 환경을 사용했다.

표·UI·출력 코드는 변경하지 않았다. 프로그램 로딩·화면·내보내기의 개선율이 아니며 별도 내보내기 생성이나 배포 빌드는 수행하지 않았다.
