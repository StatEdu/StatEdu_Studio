# 추천 분석 이동 후 언어 전환

경쟁위험 추천에서 분석 화면으로 이동한 뒤 사용자가 회귀 옵션을 `both`에서 `fine_gray`로 바꾸어도, 일본어로 전환하면 `both`로 돌아가는 현상을 실제 Chrome에서 재현했다. 추천값을 담은 별도 상태가 계속 화면 입력보다 우선하고 있었다.

`R/server_survival.R`에서 추천 이동 시 값을 해당 분석의 세션 상태에 한 번 반영하도록 변경했다. 지속적인 추천값 우선 적용과 일시적인 UI 전용 전달 상태를 제거했다. KM·Cox도 사건 코드와 자료 구조를 일반 설정 상태에 함께 반영한다. 이후 사용자가 수정한 옵션이 화면 재생성에 사용된다.

검증 스크립트:

- `scripts/validate_survival_navigation_browser.cjs`: 생성 CSV로 경쟁위험 추천 이동, 사용자 옵션 수정, 8언어 왕복을 검사한다. 이어서 KM·Cox 추천 이동의 시간·사건·집단/공변량 배정과 사용자 사건 코드 `9`를 8언어에서 확인한다.
- `scripts/validate_survival_settings_persistence.R`: 기존 8언어 설정 파일 입출력, 지연 로딩 전후 복원, 복원 후 수정, 구형 설정 기본값 및 빈 벡터 검사를 다시 실행한다.

범위는 추천의 대표 세 분기와 설정 전달이다. 모든 추천 분기, 지연 진입·시작/종료 자료 구조의 실제 이동, 네이티브 파일 선택 대화상자까지 검증한 것은 아니다. 생성 자료로 추천만 실행하며 통계 분석 결과와 내보내기 코드는 바꾸지 않는다. 설치본을 만들지 않는다.

로그: `tmp/survival-navigation-browser.log`, `tmp/survival-navigation-settings-regression.log`. 브라우저 검사의 수정 전 실패는 `ja/regression: both != fine_gray`였다.

수정 후 위 두 검사는 모두 통과했다. 브라우저는 8언어 × 3개 대표 추천 경로를 통과했으며 페이지 오류가 없었다. 검증용 서버와 브라우저를 종료했다.
