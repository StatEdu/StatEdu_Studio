# 일반 변수 표의 역할 조회 재사용

## 변경

`R/data_io.R`의 variable_table_display_data에서 행별 vapply 역할 조회를 기존 검증된 roles_for_variables 호출로 교체했다. 공통 함수의 일반 문자형 일괄 조회 및 다른 자료형의 기존 경로 복귀를 그대로 사용한다. 체크 상태, 보이는 변수 필터, 종속변수의 측정수준 제한, 선택 상자 HTML과 정렬은 변경하지 않았다.

## 비교 결과

일반 변수 표는 각 행의 measurement_select_html 생성까지 포함하므로 회귀 설정 목록에서의 큰 개선율이 그대로 나타나지 않았다. 3,000개 변수 전체 표 준비 시간은 세 프로세스 모두 감소했지만 폭은 약 2~7%였다. 공통 함수 재사용으로 기존 중복 코드를 줄이는 변경이며 추가 캐시나 복잡한 경로를 도입하지 않았다.

|3,000개 변수 중앙값(초)|실행 1|실행 2|실행 3|
|---|---:|---:|---:|
|기존|1.8674|1.7907|1.7471|
|개선|1.7428|1.7295|1.7095|

1,000개 변수에서는 기존 0.569~0.597초, 후보 0.567~0.592초로 차이가 작았다. 번들 R 4.5.3에서 양쪽의 표시 함수와 상태 함수를 동일하게 바이트 컴파일하고, 준비 비교 후 순서를 교대해 각 3회 측정했다. 독립 프로세스 3개는 순차 실행했다. 역할 집합은 변수 이름을 약 1/3씩 나눴고 한국어 표시를 사용했다. 전체 반환 상태와 셀 HTML 문자열 준비 및 진단 캡처 시간이며 DT 직렬화나 브라우저 페인트는 포함하지 않는다.

## 검증 범위

변경 전 함수 두 개를 scripts/fixtures/variable_table_role_reference.R에 보존하고 scripts/validate_variable_table_role.R를 추가했다. 0/1/12개 변수, 한·영, 선택 적용 여부, 세 활성 역할, 일반/중복/factor 이름을 조합한 108조건에서 전체 표시 상태·셀 HTML·속성·진단·표준 출력·RNG가 `identical(..., num.eq=FALSE)`로 일치했다. 역할 중복, 다른 역할에 할당된 변수, measurement override와 체크된 변수를 포함했다.

추가로 고정 elementId의 DT 표 HTML을 한·영 두 조건에서 비교했다. 체크박스와 측정수준 선택 셀 및 compact 표 옵션이 포함된다. 실제 브라우저의 선택·저장 이벤트 검사는 아니다. 데이터 IO, 이전 회귀 역할 조회, 사례 선택·분할 변수 제외 검사도 통과했다. 저장 형식별 신규 검사는 이번 범위에 포함하지 않는다.
