# 생존분석 그래프의 첫 JIT 컴파일 비용 절감

2026-09-14. `R/result_survival_ui.R`의 `survival_draw_plot_with_risk_table`에 적용했다.

## 변경

기존 그림 생성 본문을 local 함수 `draw`에 그대로 보관하고, 외부 함수가 동기식 그림 생성 동안 JIT를 0으로 설정한다. `on.exit`에서 호출 전 설정을 복원하므로 지연 인수 평가 중 오류가 발생해도 설정이 남지 않는다. 함수 인수 및 그림 생성 순서는 유지했다.

통계 계산, x축 범위를 얻는 빌드, 좌표 설정, grob 생성, 위험집단 표 정렬, 범례 및 캡션은 기존 코드를 사용한다. 이 변경은 이미 컴파일된 패키지 함수를 역컴파일하지 않는다. 해당 호출 중 새로 발생하는 JIT 작업을 피한다. 공통 함수를 사용하는 KM 및 경쟁위험 그림 모두 검증했다.

## 성능

번들 R 4.5.3/JIT 3, 모듈 캐시 사용, 패키지 설치 검사 생략. 각 버전은 별도의 새 R 프로세스 3개에서 순차 실행했고 두 번째 세트는 버전 순서를 뒤집었다. fixture 업로드와 Pearson(time, age) 실행 후 첫 KM(time, status, sex)을 수행했다. KM에는 평가 시점 100/200/400, log-rank, 생존율·생존시간 표, 컬러 생존곡선, 신뢰구간과 중도절단 표시가 포함된다.

| 실제 적용 코드 측정 | 기존(초) | 적용(초) |
|---|---:|---:|
| 첫 KM 실행 1 | 2.08 | 2.00 |
| 첫 KM 실행 2 | 2.06 | 1.98 |
| 첫 KM 실행 3 | 2.08 | 2.00 |
| 첫 KM 중앙값 | **2.08** | **2.00** |
| 측정 단계 합계 + 모듈 로딩 중앙값 | 6.98 | 6.91 |

첫 KM 실행은 **0.08초, 약 3.8%** 단축되었다. 전체 측정 흐름은 0.07초, 약 1.0% 단축되었다. 실제 적용 코드의 측정치를 최종 수치로 사용한다. 별도 실험 wrapper의 첫 KM 중앙값 2.08→1.98초를 최종 적용 성능으로 인용하지 않는다.

실험 wrapper의 별도 그림 측정에서는 새 프로세스마다 첫 그림 후 같은 그림을 5회 더 출력했다. 1000×800 PNG, 120 dpi, 저장된 KM 결과를 사용했고 survival namespace를 먼저 로딩했다. 첫 그림 중앙값은 0.65→0.53초, 이후 15개 반복 출력 중앙값은 양쪽 모두 0.22초였다. 이 측정은 전체 분석을 다시 실행하는 시험이 아니다. 초기 저장 객체의 S3 메서드 로딩을 빠뜨린 시험 1개는 실패하여 제외했고, survival 로딩을 명시한 뒤 6개 프로세스를 모두 실행했다.

MockShinySession의 서버 실행·출력 처리를 측정했다. Electron 시작, R 프로세스 시작, 패키지 로딩, 실제 브라우저 DOM 표시는 위 단계 합계 밖이다. 최대 메모리 사용량은 이번에 측정하지 않았다.

## 결과 및 설정 보존

- 실제 적용 코드와 기존 코드의 3개 전체 handler 스냅샷이 `identical(..., num.eq=FALSE)`로 같았다. 상관·KM 결과, 표 HTML/의존성, 경고와 알림이 포함된다.
- 실험 wrapper의 PNG 18쌍이 바이트 단위로 같았고, 출력·경고·메시지·RNG 상태도 같았다.
- 최종 적용 함수는 생존/사건/누적위험/로그생존 × 컬러/흑백, CI·중도절단 표시 끔, 위험집단 표 없음, 캡션 없음, 경쟁위험 등 **12개 경우**에서 기존 본문과 PNG·조건·표준 출력·RNG가 같았다.
- 호출자의 JIT 0/1/2/3 각각에서 정상 종료 및 지연 인수 오류의 **8개 설정 복원 시험**을 통과했다. 인수는 한 번만 평가되었다.
- 변경 전 원본 소스와 적용 코드를 비교한 KM·경쟁위험 결과 패널, 그림이 포함된 저장 HTML, 조건·출력·RNG가 같았다. 그림 생성 후 원래 분석 결과의 직렬화 바이트도 그대로였다.
- 현재/누적 결과 HTML이 바이트 단위로 같았다. Excel 시트 값과 압축 내부 파일도 같았다(문서 생성·수정 시각만 정규화).

## 내보내기

KM와 경쟁위험 결과를 함께 넣은 현재 결과, 이를 한 번 더 추가한 누적 결과에서 HTML/PDF/Word/HWPX/Excel **10개 파일**을 생성했다.

| 검증 항목 | 현재 | 누적 |
|---|---:|---:|
| HTML 비어 있지 않은 표 셀 | 482 | 964 |
| Word/HWPX에서 동일한 셀 내용·개수 | 482 | 964 |
| HTML/Word/HWPX 그림 수 | 2 | 4 |
| PDF 페이지 | 18 | 36 |
| PDF 그림 수 | 2 | 4 |

Word/HWPX 표 내용은 공백을 정규화한 셀의 다중집합으로 검증했다. PDF 현재 결과 7쪽(KM)과 18쪽(경쟁위험)을 렌더링하여 곡선·축·범례·위험집단 표·캡션 표시를 확인했다. 모든 페이지의 픽셀 비교를 수행한 것은 아니다. 설치 파일은 빌드하지 않았다.
