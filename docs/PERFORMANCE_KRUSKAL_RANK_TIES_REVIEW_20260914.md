# Kruskal–Wallis 순위 기반 동점 집계 후보 검토

## 결정

후보를 적용하지 않았다. `kruskal.test.default`의 `TIES <- table(x)`를 기존 순위 `r`의 정수 빈도 집계로 대체하면, 매우 가까운 실수에서 검정통계량과 p값이 바뀐다. 결과를 정확히 유지한다는 최적화 조건을 충족하지 않는다. 성능 측정은 진행하지 않았다.

프로그램의 `R/analysis_ttest_anova.R`는 변경하지 않았고 SHA256은 이전과 동일한 `B18C774BF8A020F251EDF9EC398B2C8FD5A053F3ED83017D3699F614D5F947E4`다. 앞서 반영한 Wilcoxon 사후검정 최적화는 유지한다.

## 원인

현재 R의 Kruskal–Wallis 구현은 `r <- rank(x)`로 순위를 구하지만, 동점 보정에는 순위가 아닌 원자료의 `table(x)`를 사용한다. 서로 다른 인접 부동소수점 값이 `table(x)`의 수준 구성에서 같은 값으로 묶이는 사례가 있다. 순위의 동점 빈도를 사용하면 이 기존 동작까지 달라진다.

예를 들어 `x <- 1 + seq_len(4) * .Machine$double.eps`의 네 값은 서로 다르지만 `table(x)`에서는 하나의 수준으로 집계된다. 반면 `rank(x)`는 1, 2, 3, 4다. 후보는 `tabulate(2 * r, nbins = 2 * length(r))`에서 양수 빈도만 사용하므로 보정항이 달라진다. 앞선 Wilcoxon 최적화는 원래도 `table(r)`를 사용한 경로라서 이 후보와 전제가 다르다.

이는 기존 수치 동작의 관찰이다. 이번 성능 개선 범위에서 통계 구현을 교정하거나 결과를 바꾸지 않았다.

## 검증

원본 함수의 지역 복사본에서 해당 문장 하나만 바꾸고 나머지 계산은 그대로 유지했다. 2/4집단 × 표본 크기 4/20/100 × 일반·동점·상수·가까운 실수·큰 크기의 가까운 실수·결측의 36개 조건을 비교했다.

- 가까운 실수: `1 + seq_len(n) * .Machine$double.eps`
- 큰 크기의 가까운 실수: `1e12 + seq_len(n) * .0001220703125`
- 집단은 자료 순서대로 같은 크기의 연속 구간으로 나눴다.
- 원시 htest, 경고/메시지/오류, stdout, 난수 상태를 `identical(..., num.eq=FALSE)`로 비교했다. 정규화나 허용오차는 사용하지 않았다.

24개 일치, 12개 불일치였다. 모든 불일치는 두 종류의 가까운 실수 자료에서 발생했다. 다음은 4집단 사례이며 표의 유한 숫자는 읽기 쉽게 표시했다. 판정에는 저장된 원시 값을 사용했다.

원시 검정 단계에서 이미 불일치하므로 후보의 전체 분석·효과크기·내보내기 검증이나 속도 비교를 진행하지 않았다. 대체 후보는 기존 `table(x)`의 실제 동작까지 보존해야 한다.
