# 추가 요약표의 비모수 사후검정 재사용 — 2026-09-14

## 적용 결과

비모수 독립표본 분석에서 추가 평균·표준편차 표를 생성할 때 같은 사후검정 p값 행렬을 재사용하도록 적용했다. 2만 행·8집단 연속값 자료의 전체 분석 중앙 시간은 **0.76→0.45초(약 41%)**로 줄었다. 실제 적용 코드의 4조건 × 3회 비교가 모두 빨라졌다.

중앙값/IQR 표와 추가 평균·표준편차 표는 기존 경로로 각각 생성한다. 이번 재사용 대상은 `ttest_nonparametric_pairwise()` 결과이며 주 검정이나 결과표 전체를 저장해 복제하는 변경은 아니다.

## 구현과 범위

`R/analysis_ttest_anova.R`에 `ttest_cached_nonparametric_pairwise()`를 추가했다. 비모수 분석·추가 평균/표준편차·중앙값/IQR·사후검정 옵션이 모두 켜진 경우에만 한 번의 최상위 분석 호출 안에서 캐시를 만든다. 선택한 사후검정 함수를 core와 개별 분석에 선택적 인수로 전달해 두 표의 계산에 사용한다.

- 값 벡터, 집단 벡터, 조정 방법 전체를 `identical(..., num.eq=FALSE)`로 비교한다. 데이터 순서·형식·속성을 포함하며 다른 조합은 재사용하지 않는다.
- 경고나 메시지가 발생한 호출, RNG 상태가 달라진 호출은 저장하지 않는다. 오류는 원래 처리 경로로 전달하며 저장하지 않는다.
- 최대 16개 입력 조합만 보관한다. 초과 조합은 원래 함수를 실행한다. 개수 제한이며 바이트 단위 메모리 제한이나 메모리 감소 측정을 의미하지 않는다.
- 다음 최상위 분석에서는 새 캐시를 만든다. 입력 데이터나 결과 저장소에 캐시를 남기지 않는다.
- 원래 검정·사후 조정·표 생성 코드는 유지한다. UI·내보내기 코드는 변경하지 않았다.

## 실제 적용 코드의 전체 시간

R 4.5.3 번들. 20,000행, 4/8집단, `y=rnorm(20000)+g*.3` 또는 그 값을 반올림해 동순위를 만든 자료. 데이터 seed 939, capture seed 718. 비모수·사후검정·추가 평균/표준편차 옵션을 켰다. 3개의 새 R 프로세스를 순차 실행하고 각 조건에서 양쪽을 예열한 후 전체 경과 시간을 측정했다. 두 번째 프로세스는 집단 수 및 기존/현재 순서를 뒤집었다. 단위는 초다.

| 집단 수 | 자료 | 기존 1/2/3 | 현재 1/2/3 | 중앙값 기존→현재 |
|---|---|---|---|---|
| 4 | 연속값 | 0.42 / 0.40 / 0.41 | 0.31 / 0.27 / 0.28 | 0.41→0.28 |
| 4 | 반올림 | 0.19 / 0.18 / 0.18 | 0.11 / 0.11 / 0.11 | 0.18→0.11 |
| 8 | 연속값 | 0.76 / 0.77 / 0.75 | 0.45 / 0.47 / 0.45 | 0.76→0.45 |
| 8 | 반올림 | 0.36 / 0.36 / 0.36 | 0.23 / 0.22 / 0.21 | 0.36→0.22 |

초기 연구에서는 지역 환경의 함수 복사본에 같은 재사용 원칙을 적용했고 12회 모두 개선됐다. 제품은 선택적 함수 인수 전달 방식으로 구현한 뒤 위 표처럼 다시 3회 측정했다. 두 측정 세트를 섞어 중앙값을 계산하지 않았다. 개선율을 다른 크기·자료·컴퓨터에 일반화하지 않는다. 메모리·앱 로딩 시간은 측정하지 않았다.

## 검증

`scripts/validate_ttest_pairwise_reuse.R` 통과:

- 전체 결과 48조건: 2/4/8집단 × 일반/동순위/결측/상수 × Holm/Bonferroni × 추가 표 끔/켬. 각 자료는 종속변수 2개를 포함한다. 효과크기 옵션도 켰다. 전체 반환값과 진단·표준출력·RNG가 일치했다. 비상수 자료는 결과가 생성됐는지도 확인했다.
- quiet/경고/메시지/RNG/오류 mock 검증. 같은 입력 두 호출에서 quiet 결과만 1회 실행하고 나머지는 2회 실행한다. 진단·오류 문구·RNG 결과도 기준본과 일치했다.
- 18개 서로 다른 입력을 두 번 호출하여 16개 제한과 초과 조합 재실행을 확인했다. 집단·조정 방법·입력 저장형이 달라지는 경우도 별도로 실행됨을 확인했다.
- 실제 사후검정 호출이 추가 표 생성 시 **2회→1회**로 줄었고, 캐시에서 반환하는 원시 p값 행렬이 기존 두 행렬과 정확히 같았다. 다음 분석을 다시 실행하면 원래 사후검정을 한 번 새로 호출함도 확인했다.
- 연구 기준본과 제품 코드의 전체 예열·실측 결과도 동일했다. 제품 변경 직전 파일과 직접 diff 및 `git diff --check`를 확인했다.

수치 및 전체 결과 비교는 `identical(..., num.eq=FALSE)`이며 객체 정규화나 수치 허용 오차를 적용하지 않았다. 경고/메시지 및 오류의 클래스·문구, 표준출력, RNG를 비교한다. 전체 결과 48조건의 기준본은 제품의 캐시 생성만 비활성화한 경로이고, 성능 비교 기준본은 이번 변경 직전 원본 파일이다. 원시 p값 행렬 비교는 실제 호출 추적용 별도 4집단 자료에서 수행했다.

결과 내용·구조를 변경하지 않았으므로 문서 변환과 설치 파일 빌드는 재실행하지 않았다.
