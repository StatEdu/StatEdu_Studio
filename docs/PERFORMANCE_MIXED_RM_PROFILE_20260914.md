# 혼합 반복측정 분산분석 성능 조사 — 2026-09-14

## 결과

관측치 2,000개·집단 4개·시점 6개 조건에서 분석과 저장용 HTML 생성을 분리해 측정했다. 공변량을 포함하면 반복 실행 중앙값은 분석 0.34초, HTML 생성 0.55초였다. 저장 단계에서는 그림 재생성이 아니라 표 생성이 주요 조사 대상이다. 운영 코드는 이번에 변경하지 않았다.

원자료(최초 분석 / 반복 분석 / 최초 HTML / 반복 HTML, 초):

- 공변량 없음: `0.58/0.17/0.81/0.24`, `0.58/0.17/0.80/0.23`, `0.58/0.17/0.79/0.23`.

공변량 조건의 반복 시간 변동이 있어 중앙값을 사용했다. 두 조건은 출력 표 구성과 계산량이 다르며, 이 차이를 코드 변경의 개선율로 해석하지 않는다.

## 병목과 중복 호출

별도 프로파일 실행의 공변량 조건 반복 분석은 0.58초, 반복 HTML은 0.88초였다. 계측 오버헤드가 포함되므로 위 일반 측정과 섞지 않는다.

- 반복 분석에서 `mixed_rm_adjusted_pair_test` 150회, 합계 0.17초.
- 보정평균 `mixed_rm_adjusted_cell` 24회, 합계 0.07초. 현재 집단 4개 × 시점 6개이며 각 호출에서 같은 시점의 전체 자료 모형을 다시 적합한다.
- 반복 HTML의 UI 구성 0.56초. `coefficient_html_table`은 Rprof 표본의 63.16%에 포함됐다. 이는 경과 시간의 63.16%라는 의미가 아니며 중첩된 함수 비율을 합산해서는 안 된다.
- 저장 단계에서 분석용 보정평균/시점 비교 함수가 다시 호출되지는 않았다.

추가로 시점 비교 함수의 실제 입력을 직렬화해 비교했다. **150회 중 정확히 구별되는 입력은 135개, 동일 입력의 중복 호출은 15회**였다. 겉으로 비슷한 비교를 모두 같은 계산으로 간주할 수 없다. 이름·속성 등을 무시하는 캐시로 확대하지 않았다. 계측 결과도 기준 분석 결과와 허용오차 0에서 일치했다.

## 검증과 다음 후보

각 조건의 일반 측정 3회와 프로파일 1회 결과를 비교했다. 전체 결과 객체는 `all.equal(tolerance=0, check.environment=FALSE)`, HTML은 `identical`로 일치했다. 각 실행의 최초·반복 결과도 같고 난수 상태는 유지됐다. 경고·메시지도 비교했다. 환경 객체의 주소 동일성은 검사 대상이 아니며, 현재 스크립트가 저장한 표준 출력은 HTML 단계의 출력이다.

다음 후보는 두 가지다.

1. 저장 HTML의 표 구성 비용을 더 세분화해 동일 문자열·주석·표 메타데이터의 반복 처리를 찾는다. 이 경로가 이번 조건에서 분석보다 오래 걸렸다.
2. 보정평균 모형을 시점별로 적합하고 집단별 예측에 공유하는 방식을 검토한다. 이론상 모형 적합 24회를 6회로 줄일 여지가 있지만 아직 구현하거나 속도 향상을 검증한 것은 아니다. 오차·경고 처리, 범주형 공변량, 순위 부족 모형, 집단 순서와 표시값 동일성이 선행 검증 대상이다.

이번 단계는 읽기·계측만 했으므로 기존 화면/저장 코드와 분석 계산은 그대로다. 실제 5가지 형식의 변환 검증은 새로운 출력 경로를 구현할 때 수행한다.
