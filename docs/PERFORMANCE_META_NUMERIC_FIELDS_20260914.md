# 메타분석 숫자 필드 일괄 대입 — 2026-09-14

`meta_normalize_effect()`에서 숫자 필드별로 한 행의 데이터프레임을 반복 수정하던 코드를 한 번의 다중 열 대입으로 변경했다. `lapply`로 기존 필드 순서대로 동일한 `meta_number()`를 호출한다. 숫자를 변환하는 수식, 입력 검증, 표시 문자열, 결과 열의 순서·자료형은 유지한다. 정규화 결과를 다른 입력에 캐시하지 않는다.

## 전체 집계 자료 정규화 및 적합 측정

| 연구 수 | 기존 3회(초) | 후보 3회(초) | 중앙값(초) |
|---|---|---|---|
| 120 | 0.35 / 0.28 / 0.35 | 0.27 / 0.32 / 0.27 | 0.35 → 0.27 |
| 500 | 1.84 / 1.87 / 1.86 | 1.68 / 1.73 / 1.70 | 1.86 → 1.70 |

500개 연구에서는 세 번 모두 빨라졌으며 중앙값 기준 약 9% 감소했다. 120개에서는 두 번째 실행이 느려져 일관된 개선이라고 단정하지 않는다.

번들 R 4.5.3의 새 프로세스 3개를 순차 실행했다. 두 번째 프로세스는 기존/후보 순서를 뒤집었다. 각 조건을 준비 실행하고 GC 후 측정했다. 연구당 집계 효과 하나, -0.6~0.6의 효과값, 표집분산 0.1, g, 랜덤효과 REML, 95% 신뢰수준을 사용했다. `meta_fit_aggregated()`의 입력 정규화·모형 적합·전체 반환값 생성과 입력 데이터프레임 구성·조건 수집을 포함한다. 로딩·화면·내보내기는 제외한다. 앱 전체 또는 모든 메타분석의 개선율은 아니며 메모리는 측정하지 않았다.

- 반환값과 속성, 오류/경고/메시지 클래스·문자열, 표준출력, 난수 상태를 `identical(..., num.eq=FALSE)`로 비교했다. 수치 허용오차는 사용하지 않았다. 조건 객체의 호출 환경은 비교하지 않는다.
