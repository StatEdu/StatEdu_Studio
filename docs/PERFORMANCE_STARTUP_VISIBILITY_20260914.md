# 초기화 측정의 화면 가시성 보정 — 2026-09-14

기존 서버 측정에서 MockShinySession이 모든 출력의 hidden 값을 FALSE로 제공해, 실제로는 숨겨질 지연 UI까지 생성하는 것을 확인했다. 이번 작업에서는 별도 측정 하네스에 가시성 모델과 UI 호출 계수를 추가했다. 애플리케이션 코드는 변경하지 않았다.

## 실험 설계

- 번들 R 4.5.3, JIT 3, 기존 모듈 캐시를 사용했다. 매번 새 프로세스에서 순차 실행했다.
- all은 기존 MockShinySession 동작 그대로다.
- selected는 `output_lazy_*_hidden`만 제어한다. 초기에는 모두 숨기고, 생존분석 설정 단계에서 `lazy_analysis_survival_km`을 표시한다. 가시성은 reactiveVal을 사용해 출력의 재평가를 유발한다. 다른 clientData 접근은 원래 mock 메서드로 전달한다.
- 초기 navbar의 첫 화면은 데이터 화면이며, 지연 UI 생성 대상과 구분된다. 상관분석은 기존 하네스처럼 메뉴 선택으로 진입한다.
- 두 조건 모두 동일하게 `register_visible_ui_output`의 실제 UI 함수 호출 횟수를 계수했다. 각 조건 3회, 순서는 selected1/all1, all2/selected2, selected3/all3이었다.
- 브라우저 DOM에서 가시성을 읽은 실험은 아니다. 일반 출력의 숨김/정지 동작, 브라우저 렌더링, Electron 기동, 콜드 디스크 상태를 재현하지 않는다.

## 측정 결과

각 열은 3회 중앙값이며 단위는 초다.

| 조건 | 초기화 | 상관 설정 | 상관 실행 | 생존 설정 | 생존 실행 | 전체 흐름 | 지연 UI 호출 수 |
|---|---:|---:|---:|---:|---:|---:|---:|
| all | 2.78 | 0.36 | 0.44 | 1.12 | 2.14 | 7.42 | 70 |
| selected | 1.22 | 0.46 | 0.45 | 1.12 | 2.04 | 5.88 | 1 |

초기화 원자료는 all 2.78/2.78/2.76초, selected 1.22/1.25/1.22초다. selected의 유일한 지연 UI 호출은 생존분석 화면 진입 시의 KM UI 생성이었다. 초기 숨김 상태에서는 이들 UI가 생성되지 않았다.

이 차이는 **측정 조건의 차이**이며 제품 성능 개선률로 보고하지 않는다. 전체 흐름은 업로드·설정·두 분석을 포함하며 앱 로딩 시간과 다르다. 기존 코드의 `req(identical(hidden,FALSE))` 및 `suspendWhenHidden=TRUE`가 이미 지연 생성을 구현하고 있으므로 이를 중복 구현할 근거도 없다.

## 프로파일 및 다음 검토 대상

selected 조건의 별도 프로파일 1회 초기화 경과 시간은 1.26초였다. 샘플 합계 0.600초 중 `compiler:::tryCmpfun` 포함 스택 0.200초(33.33%), `renderUI` 포함 스택 0.100초(16.67%)가 관측됐다. 스택 비용은 겹칠 수 있고 경과 시간의 비율이나 제거 가능한 비용을 의미하지 않는다.

다음 최적화 후보는 초기 세션에서 처음 호출되는 함수의 컴파일 비용이다. JIT를 변경한다면 초기화만 측정하지 말고, 뒤따르는 첫 분석까지 포함해 비용 이동과 수치 결과 동일성을 함께 검증해야 한다. 실제 앱 로딩 시간의 확정에는 별도의 브라우저/Electron 측정이 필요하다.

## 검증과 산출물

- 여섯 실행 및 별도 프로파일 실행의 전체 스냅샷이 `output/server-first-analysis-20260913/current-auto-event-map-verified.rds`와 `identical(...,num.eq=FALSE)`로 일치했다.
- 비교 대상은 상관분석 및 KM 분석 객체 전체, 결과 HTML/의존성, 경고, 알림이다. 모든 실행에서 경고 0건이었다.
- `output/startup-visibility-20260914/measure.R`: 기존 전체 서버 하네스에 가시성 설정과 호출 기록을 추가한 측정 스크립트.
- 같은 디렉터리의 `visibility.R`, `compare.R`, `summary.csv`, 실행별 CSV/RDS 및 `*-ui.csv`: 가시성 모델, 동일성 검증, 원자료.
- `profile.R`, `selected.Rprof` 및 부속 CSV: 초기화 프로파일.
- 실행 시 `STATEDU_TEST_VISIBILITY=all` 또는 `selected`를 지정하고, `measure.R current all1` 형태로 독립 ID를 전달한다. 기존 측정 환경처럼 패키지 자동 설치를 비활성화하고 번들 라이브러리와 캐시 경로를 지정한다.
- 출력 코드 변경이 없어 내보내기 형식은 재검증하지 않았다. 설치 파일도 재빌드하지 않았다.
