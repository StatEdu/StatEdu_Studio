# 패널 잔차 상관 검정의 선택 원소 계산 검토

## 결론

Pesaran CD 검정에서 선택된 원소에만 제곱근과 곱셈을 적용하는 후보를 검토했다. 원시 검정값 비교는 통과했으나 전체 FE 실행의 개선이 불안정하고, 누적 할당 감소도 약 4%에 그쳤다. 패키지 내부 함수를 복사하는 유지보수 부담까지 고려하여 제품에 적용하지 않았다. RE 측정에서는 개선이 관찰됐으며 이를 무시하거나 두 모형 모두 느려졌다고 해석하지 않는다.

제품 `R/analysis_longitudinal.R`과 시작 시 스냅샷 SHA256은 모두 `1A57B5CB6E504ED5A8A1392FF0B1C86485A1107D4357BCF50598302CBBCA45B8`이다. 이번에 제품 소스와 출력은 변경하지 않았다.

## 후보 내용

설치된 plm의 `pcdres`는 전체 개체 간 상관행렬 rho와 공통 시점 수 행렬 t.ij를 만든 뒤 선택 행렬 selector.mat으로 검정에 포함할 원소를 고른다. CD 통계량의 다음 부분만 시험용 복사본에서 변경했다.

```r
# 기존
(sqrt(t.ij) * rho)[selector.mat]
# 후보
sqrt(t.ij[selector.mat]) * rho[selector.mat]
```

상관 계산, 공통 시점 수 계산, 원소 선택 및 합산 순서는 유지한다. 전체 행렬의 제곱근·곱셈을 줄이는 대신 두 번의 부분 추출이 필요하다. 전체 상관행렬 자체를 제거하는 변경은 아니다. 지역 환경의 pcdtest.panelmodel 복사본이 수정된 pcdres를 호출하며 패키지 namespace는 변경하지 않았다. 이는 탐색용이고 일반 S3 확장·임의 클래스에 대한 제품 호환성을 입증한 구현은 아니다.

## 전체 분석 성능

번들 R 4.5.3, seed 939, 2,000명 × 6시점(12,000행), 두 공변량과 시간 항, 비가중 gaussian 패널 FE/RE의 기본 민감도·가정 검사를 사용했다. 현재 제품과 후보를 독립 프로세스 3개에서 순차 비교했다. 워밍업 후 두 번째 프로세스는 후보부터 측정했다. 로딩을 제외하고 비교용 캡처·정규화를 포함한다.

| 모형 | 현재 1 / 2 / 3 (초) | 후보 1 / 2 / 3 (초) | 중앙값 |
|---|---|---|---|
| FE | 2.92 / 2.70 / 2.86 | 2.88 / 3.13 / 2.64 | 2.86 → 2.88초 |
| RE | 2.97 / 3.06 / 2.98 | 2.59 / 2.61 / 2.97 | 2.98 → 2.61초 |

FE는 두 번 빨라졌지만 한 번의 증가 폭이 크고 중앙값도 개선되지 않았다. RE는 세 번 빨라졌지만 세 번째 차이는 0.01초로 작다. 이 결과만으로 모형별 차이의 내부 원인이나 모든 RE 자료의 개선을 단정하지 않는다.

워밍업 6건과 측정 6건 각각에서 전체 결과, 조건 클래스·본문·순서, 표준 출력 및 RNG가 `identical(..., num.eq = FALSE)`로 일치했다. 같은 정상 자료의 반복 비교이며 12종 자료를 검증한 것은 아니다. formula/terms 환경과 함수 표현은 정규화했다. 원시 환경 객체의 동일성은 주장하지 않는다.

## 원시 결과 및 경계 검증

개체 수 2/5/30 × 균형/일부 행 제외/한 개체가 한 시점만 존재/한 개체 잔차가 상수 × 가중 인접행렬 NULL/대칭/하삼각/전부 0/잘못된 차원의 60개 조건을 비교했다. 모형 적합 없이 pdata.frame의 잔차용 pseries를 패키지 원본 pcdres와 후보에 직접 전달했다.

원시 htest 전체 필드(통계량·p값·속성 포함), 경고·메시지·오류 클래스 및 본문, 표준 출력, RNG가 60건 모두 수치 허용오차 없이 일치했다. 오류 사례도 동일성 검사에 포함했으며 성공 검정으로 간주하지 않는다. 2,000개체의 별도 원시 결과 비교와 메모리 계측 실행 결과도 일치했다.

## 메모리

별도 검증 프로세스에서 2,000명 × 6시점 잔차 자료를 워밍업한 뒤 Rprofmem으로 pcdres와 캡처의 할당을 측정했다.

| 항목 | 현재 | 후보 |
|---|---|---|
| 누적 할당 바이트 | 597,534,664 | 573,522,720 |
| 가장 큰 단일 할당 바이트 | 32,000,048 | 32,000,048 |

누적 할당이 24,011,944바이트(약 4.0%) 줄었다. 이는 최대 상주 메모리나 peak heap 측정이 아니며, 가장 큰 단일 할당 역시 최대 동시 메모리가 아니다. 큰 상관행렬과 선택행렬이 남아 있으므로 메모리 문제를 해결했다고 볼 수 없다.
