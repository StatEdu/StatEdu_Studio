# 생존시간 숫자 전처리 개선

`R/analysis_survival.R`의 `survival_coerce_duration`에서 속성이 없는 integer/double 입력은 불필요한 문자 변환과 공백 제거를 생략한다. 기존 숫자 변환 `as.numeric(values)`와 결측 판정은 그대로 유지한다. 기존 코드도 숫자를 문자열에서 다시 파싱하지 않았으며, 이번 변경은 결측 판정을 위해 만들던 문자열만 제거한다.

이름·차원·클래스·라벨 속성이 있는 숫자, factor, 문자, 날짜/시간, logical, list 등은 기존 경로를 유지한다. 분석 수식, 사례/분할 범위, 사건 매핑, 결과 형식은 변경하지 않았다.

## 정확성 확인

- `scripts/validate_survival_duration_numeric.R`: 64개 입력의 값, 결측/잘못된 인코딩 마스크, 속성, 경고·메시지·오류, stdout, RNG가 `identical(..., num.eq=FALSE)`로 일치. 정수/실수, 부호 있는 0, NA/NaN/Inf, 극소·극대 값, 특수 클래스와 난수를 소비하는 변환 메서드 포함.
- `scripts/validate_survival_duration_preflight.R`: 단일 기록·지연 진입·시작–종료 구조 × 5가지 시간 입력의 전체 전처리 결과/진단/stdout/RNG 15개 정확히 일치.
- `scripts/benchmark_survival_duration_numeric.R`: 20,000행 Cox 기본·층화·군집 보정·스플라인에서 성공 모형, 분석 행 수, 유한 계수 확인. 프로세스당 전체 결과 비교 49개(옵션별 준비 1개+측정 10개, 전처리 5개), 두 프로세스 모두 통과.
- Cox 비교는 수식의 `.Environment` 속성만 재귀적으로 제외했다. call 내부 수식도 포함하며, 숫자 허용오차는 사용하지 않았다. 원시 수식 환경 자체의 동일성을 주장하지 않는다.
- 기존 `validate_survival_preflight.R` 종합 검사 통과: KM/Cox, 지연 진입, 시작–종료, 층화, 군집, 스플라인, 시간가변 계수, ties, 경쟁위험 등 기존 검사 포함. 단독 실행은 `analysis_save_edition` 로딩 누락으로 저장 HTML 단계에서 중단됐으며, 실제 앱 bootstrap/모듈/환경설정 초기화 후 재실행하여 통과했다. 제품 변경으로 우회하지 않았다.

## 실행시간

번들 R 4.5.3, 실제 앱 모듈과 환경설정 초기화. 20,000행, 공변량 6개, 사건 확률 0.7, 층 3개, 군집 2,000개(각 10행), 스플라인 df=4. 조정 생존곡선/부트스트랩은 사용하지 않는다. 동일 난수 자료, 양쪽 함수 컴파일, 준비 실행 후 5회 중앙값. 두 독립 프로세스에서 기존/변경 실행 순서를 번갈아 측정했다. 타이머는 분석과 진단/stdout 수집을 포함하며 결과 정규화·비교는 제외한다.
