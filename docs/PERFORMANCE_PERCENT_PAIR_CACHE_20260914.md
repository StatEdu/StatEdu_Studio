# Percent agreement 쌍 인덱스 재사용 확대

## 적용

interrater_percent_agreement에서 유효 평가자 수별 쌍 인덱스를 지역 캐시에 보관하도록 변경했다. 이전에는 직전 크기만 재사용하므로 결측 때문에 평가자 수가 바뀌었다 돌아오면 동일 조합을 다시 만들었다.

캐시는 함수 호출 안에서만 존재하며 실제 사용한 32명 이하의 크기만 보관한다. 더 큰 크기는 기존 직전 크기 재사용을 유지한다. 각 행의 문자열 변환, 결측 제거, 일치 비교, 전체 쌍 수와 일치 수의 누적 순서 및 최종 비율은 그대로다. Gwet·Krippendorff의 캐시와 전역 상태를 공유하지 않는다.

## 전체 분석 성능

번들 R 4.5.3, 자료 seed 939, 5,000행·8평가자, A–E와 NA를 같은 확률로 표집했다. 기준 소스에는 Gwet·Krippendorff 캐시 개선이 이미 포함되어 있다. 명목형과 순서형의 전체 prepare_interrater_agreement_results를 비교했다.

독립 프로세스 3개를 순차 실행했고 워밍업 후 두 번째는 후보를 먼저 측정했다. 로딩을 제외하고 전체 결과 캡처를 포함한다.

| 유형 | 기존 1 / 2 / 3 (초) | 변경 1 / 2 / 3 (초) | 중앙값 |
|---|---|---|---|
| 명목형 | 0.22 / 0.14 / 0.23 | 0.10 / 0.20 / 0.11 | 0.22 → 0.11초 |
| 순서형 | 0.12 / 0.14 / 0.11 | 0.11 / 0.06 / 0.11 | 0.12 → 0.11초 |

명목형은 두 번 개선·한 번 증가, 순서형은 두 번 개선·한 번 같은 표시 시간이었다. 매우 짧은 실행으로 변동이 크며 이 중앙값 차이를 모든 자료의 보장된 개선율로 일반화하지 않는다. 결측이 없거나 유효 평가자 수가 연속해서 같으면 기존 캐시도 효과가 있다.

별도 percent agreement 함수 계측에서 combn 호출은 3,641→7회로 줄었다. 원시 반환 리스트(일치율·쌍 수·method)와 RNG가 일치했고, trace는 별도 검증 프로세스에서 사용한 뒤 해제했다. 다른 일치도 함수의 호출 횟수는 포함하지 않는다.

## 검증

각 워밍업 및 측정에서 전체 반환 객체, 조건 클래스·본문·순서, 표준 출력 및 RNG가 `identical(..., num.eq=FALSE)`로 일치했다. 수치 허용오차와 정규화는 사용하지 않았다.

`scripts/validate_percent_agreement_pairs.R`에 32/33/40평가자 조건을 추가했다. 평가자 수 1/2/3/10/30/32/33/40 × 완전·결측·전체 결측 행·상수·빈·factor·matrix 입력의 56개 조건에서 일치율, 전체 쌍 수, 속성, 진단 및 RNG가 일치했다.

변경 직전 실제 소스와의 비교 및 파일 인수 없는 독립 참조 비교를 각각 수행했다. 같은 56개 조건을 두 방식으로 확인한 것이며 112종 자료로 집계하지 않는다. 독립 참조는 매 행의 조합을 다시 생성한다. 기존 `scripts/validate_interrater.R`도 통과했다. 제품 함수 본문이 측정 후보와 동일함을 확인했다.

## 증거 및 범위

`output/percent-pair-cache-20260914/`에 baseline.R, candidate.R, bench.R, timing-1/2/3.csv, 실행 로그, baseline-validation.log, validation.log, regression.log, count.R 및 calls.csv/log를 보관했다.

표시·출력 내용과 형식은 변경하지 않았다. 전체 형식 변환과 설치 파일 빌드는 실행하지 않았다. 메모리 최고 사용량도 별도로 측정하지 않았다. 기존 다른 변경은 유지했다.
