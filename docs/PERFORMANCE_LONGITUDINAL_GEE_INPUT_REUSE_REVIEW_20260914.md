# GEE 상관행렬 생성 전 입력 재사용 검토

## 결론

검증 함수의 행렬 생성까지 생략하는 후보를 실험했으나 제품에는 적용하지 않았다. 검증 함수 자체는 빨라졌지만 이항형 전체 분석은 세 번 모두 느려져 전체 성능의 일관된 이득을 확인하지 못했다. 기존의 선택 모형 재사용 및 동일 행렬 고유값 검증 재사용은 유지한다.

## 후보

현재 함수는 상관행렬을 만든 뒤 직전 성공 행렬과 완전히 같으면 고유값 검증을 생략한다. 후보는 그 앞에 입력 비교를 추가했다.

- 일반 numeric/integer alpha의 exchangeable에서는 관측 개수가 같으면 같은 행렬로 판단한다.
- ar1에서는 속성이 없는 numeric/integer 시점 벡터가 직전 성공 입력과 `identical(..., num.eq = FALSE)`일 때만 행렬 생성도 생략한다.
- 클래스가 있는 alpha 또는 ar1의 속성 있는 시점은 기존 행렬 검증으로 진행한다. 직전 검증이 성공한 입력만 저장한다.

실험 파일만 만들었으며 제품 소스는 수정하지 않았다.

## 측정

번들 R 4.5.3, seed 936, 5,000명 × 4시점 = 20,000행, 두 공변량, 선택 상관구조 exchangeable, 기본 분석 옵션. 워밍업 후 독립 R 프로세스 3개를 순차 실행하고 두 번째 프로세스는 후보부터 측정했다. 로딩 시간은 제외했다.

| 전체 분석 | 현재 1 / 2 / 3 (초) | 후보 1 / 2 / 3 (초) | 중앙값 |
|---|---|---|---|
| gaussian | 2.09 / 1.58 / 2.04 | 1.60 / 2.00 / 1.55 | 2.04 → 1.60 |
| binomial | 1.80 / 1.64 / 1.62 | 1.83 / 1.75 / 1.77 | 1.64 → 1.77 |

Gaussian은 두 번 개선됐지만 한 번 느려졌고, binomial은 세 번 모두 느려졌다. 이 측정만으로 지연의 원인을 특정하지는 않는다. 전체 분석의 변동을 고려할 때 후보가 전반적으로 더 빠르다는 근거는 부족하다.

5,000개의 동일한 4×4 행렬에 대한 검증 함수만 별도로 10회 반복한 평균은 다음과 같다. 이 시간은 전체 분석과 별도 실행이며 합산하거나 차감하지 않는다.

| 검증 함수 | 현재 1 / 2 / 3 (초) | 후보 1 / 2 / 3 (초) | 중앙값 |
|---|---|---|---|
| exchangeable | 0.019 / 0.017 / 0.017 | 0.003 / 0.003 / 0.001 | 0.017 → 0.003 |
| ar1 | 0.021 / 0.022 / 0.022 | 0.003 / 0.001 / 0.003 | 0.022 → 0.003 |

해당 반복 입력에서 행렬 생성 호출은 두 구조 모두 1,000회에서 1회로 줄었다. 고유값 계산은 이전 개선 때문에 양쪽 모두 이미 1회다.

## 동일성 검증

현재 소스와 후보를 직접 로드하여 전체 분석 48개 조건과 직접 검증 함수의 경계 조건 462개를 비교했고 모두 통과했다. 가중치, offset, exponentiate, 결측과 역순 입력, 경고/메시지/RNG 소비/오류 주입, 특이행렬, 무효 alpha, 부호 있는 0, underflow, factor 및 이름 있는 시점 등을 포함했다.

전체 반환 객체, QIC 원값 6개 × 3개 상관구조, 조건 클래스/본문/순서, 표준 출력, RNG를 비교했다. 직접 검증은 반환 가시성과 오류 문구, 계산된 행렬/고유값 객체도 확인했다. `identical(..., num.eq = FALSE)`를 사용했으며 전체 모형의 formula/terms 환경 및 함수 표현만 정규화했다. 수치 허용오차는 사용하지 않았고 원시 환경·함수 객체의 동일성까지 주장하지 않는다.
