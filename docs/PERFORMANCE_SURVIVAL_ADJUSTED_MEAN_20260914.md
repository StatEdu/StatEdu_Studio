# 보정 생존곡선 평균 계산의 불필요한 결측 제거 생략 — 2026-09-14

`R/analysis_survival.R`의 `survival_adjusted_curve_once()`에 적용했다. 각 누적위험에서 계산한 `exp(-hazard * risk)` 벡터에 결측값이 없으면 `mean()`의 결측 제거용 벡터 복사를 생략한다. `NA` 또는 `NaN`이 있으면 기존처럼 `na.rm = TRUE`로 계산한다.

곱셈·지수·평균의 수식과 값의 순서, 누적위험 재사용, 모형 적합, 표본 추출, 난수 복원, 분위수 신뢰구간 및 대비 계산을 유지한다. 부트스트랩 반복수를 줄이거나 근사식을 도입하지 않았다.

## 병목 확인

현재 소스로 600건과 2,000건, 3집단, 사건 생성 확률 0.45, 연속 생존 시간·나이 공변량, 부트스트랩 60회와 선택 시점 0·10·20을 측정했다. 새 R 프로세스 3개에서 준비 실행, 비프로파일 실행, 10ms Rprof 실행을 순차 수행했다. 현재 비프로파일 시간 중앙값은 각각 1.02초와 5.83초였다.

2,000건에서 `mean` 호출 경로의 total 표본 비중은 72.70%, 68.62%, 72.68%였다. 여기에는 지수 계산 등 인수 평가와 하위 호출이 포함된다. 이 비율 전체가 결측 제거 비용이라는 뜻은 아니며, 중첩된 함수 비율을 합산하지 않는다. 600건의 표본 비중은 35.90~55.71%로 변동이 컸다. 프로파일 실행과 비프로파일 실행의 전체 결과가 같고, 프로세스 간 결과도 동일했다.

## 변경 전후 시간

번들 Windows R 4.5.3에서 버전별 새 프로세스 3개를 순차 실행했고, 두 번째 비교는 버전 순서를 뒤집었다. 각 자료 조건을 한 번 준비 실행한 뒤 GC하고 전체 `survival_adjusted_curve()`를 측정했다. 최초 Cox 적합·자료 생성·R 패키지 및 앱 로딩·화면 렌더링·저장 작업은 시간에 포함하지 않는다. 통계적 부트스트랩 60회 재적합과 곡선·신뢰구간·대비 계산은 모두 포함한다.

| 자료 크기 | 기존 3회(초) | 변경 후 3회(초) | 중앙값 | 단축률 |
| --- | --- | --- | --- | --- |
| 600건 | 1.01 / 1.03 / 1.02 | 0.92 / 0.92 / 0.92 | 1.02 → 0.92초 | 9.8% |
| 2,000건 | 5.79 / 5.83 / 5.77 | 4.68 / 4.67 / 4.71 | 5.79 → 4.68초 | 19.2% |

모든 비교에서 후보가 빨랐다. 이전 프로파일 시간과 이번 기준 시간을 섞어 개선율을 계산하지 않았다. 이 결과는 해당 보정곡선 조건의 국소 측정이며, 기본값인 부트스트랩 2,000회 전체 실행이나 보정곡선 없는 Cox, 앱 로딩 속도에 대한 측정은 아니다. 메모리 최고 사용량은 별도 측정하지 않았다.

## 수치 및 통합 검증

- 측정한 6개 변경 전후 전체 반환값·경고/메시지·표준출력·난수 상태가 `identical(..., num.eq = FALSE)`로 일치했다. 각 실행에서 부트스트랩 60회가 모두 성공했고 신뢰구간이 유한했다. 각 준비/측정 결과도 같았다.
- 지속 검증 스크립트 `scripts/validate_survival_adjusted_mean.R`: 60개 보정곡선 검사와 120개 평균 경계값 검사 통과. 2/3집단, 사건 비율, 동률 시간, 부트스트랩 0/25회, 중복·역순·결측 선택 시점, 빈 벡터, NA/NaN, 무한대, 부호 있는 0, 극소·극대 값 등을 포함한다. 기존 오류가 나는 빈 시점도 같은 오류를 유지했다.
- 180건·3집단·부트스트랩 25회로 실제 전체 `prepare_cox_analysis_result()`를 실행했다. 전체 결과와 진단·표준출력·난수 상태가 같았다. 비교 시 재귀적으로 `.Environment` 속성만 제거했으며 수치나 그 밖의 속성을 정규화하지 않았다.
- 호출 전 난수 상태가 없었던 경우에도 변경 전후 모두 없는 상태로 복원했다.
- 측정 후보와 적용 소스의 전체 파싱 결과가 동일하다. 주석과 줄바꿈만 다르다. 적용 소스 SHA-256은 `5B8AA42D3D4ECD96919C0E4EDBE93EEC382BDA90A6804EF10BFF21FF1204E348`이다. 해당 소스의 `git diff --check`를 통과했다.

## 화면과 저장 결과

영문 전체 Cox 패널 렌더링과 실제 그림이 삽입된 저장 HTML이 변경 전후 정확히 일치했다. 현재·누적 HTML 파일도 바이트 단위로 같았고, Excel의 시트·셀과 패키지 내용은 생성/수정 시각만 정규화하면 동일했다.

현재·누적 HTML/PDF/Word/HWPX/Excel 총 10개 파일을 모두 생성했다. HTML 표의 비어 있지 않은 셀 405개/810개가 Word와 HWPX에서 개수와 내용별 빈도까지 같았다. HTML 그림 4개/8개에 대응하는 Word/HWPX 그림 참조도 4개/8개였다. PDF는 15쪽/30쪽이며 이미지 4개/8개와 보정 생존 구간을 확인했다.

현재 PDF의 10쪽(보정 결과·시점별 표), 11쪽(집단 대비), 12쪽(보정곡선·신뢰구간)을 렌더링해 육안 확인했다. 모든 페이지를 육안 검수하거나 Word/Hancom 편집 화면을 별도 조작한 것은 아니다. 설치 파일은 재빌드하지 않았다.
