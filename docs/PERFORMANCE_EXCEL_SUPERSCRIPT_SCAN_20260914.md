# 위첨자 없는 행의 셀별 검색 생략 — 2026-09-14

`result_html_table_cells()`에서 행에 위첨자(`sup`)가 있는지 먼저 확인한다. 위첨자가 없는 행의 셀은 기존 검색 결과와 같은 빈 위첨자 문자열을 사용한다. 위첨자가 있는 행은 기존 셀별 검색과 텍스트 끝부분 일치 검사를 그대로 수행한다. 병합과 본문 텍스트 처리도 유지한다.

측정 HTML의 구조로 계산한 검색 횟수는 기존 셀별 2,883회에서 행별 93회로 줄었다. 해당 표에는 위첨자가 없어 추가 셀별 검색은 0회였다. 위첨자가 많은 표는 기존 셀 검색도 수행하므로 같은 개선율을 기대할 수 없다.

## 전체 Excel 저장 시간

같은 30변수 상관분석 HTML, 3개 시트, 번들 R 4.5.3을 사용했다. 앞선 적용 최적화는 비교 양쪽에 포함된다. 새 프로세스에서 모듈과 설정을 로드한 뒤 전체 저장을 측정했다. 프로파일러 없이 3쌍을 순차 실행하고 두 번째 쌍의 순서를 뒤집었다. 비교 함수는 같은 전역 도우미 환경을 사용했고 파일 비교는 측정 밖에서 수행했다.

| 반복 | 변경 전(초) | 변경 후(초) |
| --- | ---: | ---: |
| 1 | 1.93 | 1.69 |
| 2 | 1.96 | 1.70 |
| 3 | 1.94 | 1.69 |
| 중앙값 | 1.94 | 1.69 |

이 파일의 전체 저장 시간은 **약 13% 감소**했으며 세 쌍 모두 개선되었다. 이전 개선율과 합산하지 않는다. 시작 시간과 통계 계산 시간은 이번 측정 대상이 아니다.

## 검증

- `scripts/validate_excel_superscript_scan.R`: 개별 표 9개와 누적 결과 1개 통과. 기본 문서용 데이터를 포함한 전체 표 반환값, 인쇄 방향, 개별 저장의 경고와 RNG 상태가 동일했다.
- `verify_cells.R`: 빈/중첩 표, 임의 생성 표, 잘못된 병합 속성, 서식, 위첨자와 다국어 등 123개 사례에서 전체 셀 데이터와 조건·RNG 상태가 동일했다.
- `verify_superscripts.R`: 빈 위첨자, 앞/뒤/중간 위치, 여러 위첨자, 내부 굵게 태그, 공백, 다국어, 중첩 표를 병합 셀 및 일반 행과 함께 구성한 10개 사례에서 전체 셀 데이터가 동일했다.
- 검증 Excel의 시트 이름과 읽어 들인 값, 모든 비-core 내부 파일이 동일했다. core도 생성·수정 시각만 정규화하면 동일했다.
- 전체 크기 측정 파일 6개도 기존 기준 파일과 내부 비교를 통과했으며 저장 중 경고가 없었다.
- `git diff --check -- R/result_saved_ui.R` 통과.

통계 계산과 출력 내용을 변경하지 않는 검색 생략이다. PDF/Word/HWPX 완성 파일과 설치 파일은 이번에 재생성하지 않았다.
