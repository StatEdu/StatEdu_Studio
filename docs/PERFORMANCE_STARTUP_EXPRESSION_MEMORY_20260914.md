# 파싱된 모듈 캐시의 메모리 후속 검증 — 2026-09-14

## 결과

앞서 적용한 식 캐시를 유지한다. 초기 UI 생성까지 관측한 R 프로세스 최고 메모리는 기존 방식과 실질적으로 비슷했다. 반복 로딩 실험에서도 두 번째 이후 생존 R 객체 수가 일정했다. 이번 작업에서 운영 코드는 추가로 변경하지 않았다.

## 프로세스 최고 메모리

단위 MB는 1,000,000 bytes이다. 각 버전·조건마다 새 프로세스 3개를 순차 실행했고 두 번째 세트는 순서를 뒤집었다.

| 조건 | 기존 3회(bytes) | 식 캐시 3회(bytes) | 중앙값 MB 기존 → 식 캐시 |
|---|---|---|---|
| 유효 캐시 재사용 | 264302592 / 262008832 / 264069120 | 264105984 / 264175616 / 265551872 | 264.07 → 264.18 |
| 새 캐시 생성 | 260997120 / 260857856 / 263294976 | 260104192 / 262098944 / 260493312 | 261.00 → 260.49 |

재사용 중앙값 차이는 +106,496 bytes(약 0.11 MB), 최초 생성은 -503,808 bytes(약 0.50 MB)다. 회차별 변동 범위에 비해 작은 차이이므로 메모리 개선이나 회귀를 단정하지 않는다. 최초 생성이 항상 더 적은 메모리를 쓴다는 의미도 아니다.

## 측정 범위

번들 R 4.5.3, JIT 3, 기존 패키지와 UTF-8 환경을 사용했다. R 프로세스에서 bootstrap/패키지/모듈 로딩, 서버 함수 생성, 초기 UI 생성 및 HTML 렌더링을 실행했다. 모듈 로딩과 UI 렌더링 사이에 명시적 GC는 넣지 않았다. 그 뒤 GC, 초기 출력 저장 및 UI 객체 해제를 수행했고 관측 프로세스의 최고 작업 집합을 기록했다.

PowerShell이 실제 R 계산 PID의 `PeakWorkingSet64`를 약 20ms 간격으로 관측했다. 캐시 miss는 회차별 새 디렉터리를 사용했고 hit는 이전에 준비된 유효 캐시를 사용했다. 측정 중 다른 R 작업을 동시에 실행하지 않았다.

이는 R 프로세스 범위다. Electron/브라우저, 실제 Shiny 사용자 세션 초기화, 업로드 및 분석 실행의 메모리를 포함하지 않는다. 운영체제 파일 캐시를 비우지 않았고 메모리 할당 패턴이 다른 조건의 수치를 일반화하지 않는다. 이번 작업에서 실행 시간을 다시 측정하지 않았다.

## GC 후 생존 객체와 반복 로딩

초기 UI를 유지한 상태와 해제한 상태에서 GC 후 Ncells/Vcells를 기록했다. 유효 캐시 조건의 중앙값은 다음과 같다. 이 수치는 객체 저장 단위의 사용 개수이며 프로세스 메모리 바이트가 아니다.

| 상태 | 기존 Ncells / Vcells | 식 캐시 Ncells / Vcells |
|---|---|---|
| UI 유지 | 1750726 / 1658804 | 1751249 / 1659953 |
| UI 해제 | 1743042 / 1637693 | 1743562 / 1638837 |

별도 새 프로세스에서 각 로더로 같은 모듈을 10회 다시 읽고 매회 GC했다. 기록용 벡터는 미리 고정 크기로 할당해 기록 목록의 증가가 결과에 섞이지 않게 했다.

| 로더 | 2~10회 Ncells | 2~10회 Vcells | 전역 바인딩 수 |
|---|---:|---:|---:|
| 기존 | 1668381 | 1422517 | 4006 |
| 식 캐시 | 1669092 | 1423747 | 4007 |

두 로더 모두 두 번째부터 열 번째까지 세 지표가 동일했다. 새 구현은 보조 함수 한 개를 추가하므로 전역 바인딩 수가 하나 많다. 이 제한된 재로딩 실험에서 누적 증가를 관측하지 않았다는 뜻이며 실제 장시간 앱 사용 전반의 메모리 누수 부재를 증명하지 않는다.

## 검증 및 상태

- hit/miss 12개 초기 스냅샷이 `identical(..., num.eq=FALSE)`로 일치했다. 초기 HTML의 자동 생성 숫자 탭 ID만 정규화했고 HTML 의존성, 서버 함수 본문과 인자를 함께 비교했다.
- `verify_repeat.R`에서 두 로더 모두 2~10회 생존 셀 수 및 전역 바인딩 수가 일정함을 검사했다.
- 분석 수치 및 첫 사용자 세션의 동일성은 직전 적용 보고서 `PERFORMANCE_STARTUP_EXPRESSION_CACHE_20260914.md`의 검증 범위다. 이번 메모리 프로세스에서 분석을 다시 실행했다고 주장하지 않는다.
- 현재 `R/app_bootstrap.R`이 실험 시작 시 사본과 동일함을 확인했다. 출력 및 설치 파일을 변경하지 않았다.

자료는 `output/startup-expression-memory-20260914/`에 있다. `memory.ps1`/`memory.R`은 유효 캐시, `memory_miss.ps1`/`memory_miss.R`과 `miss/`는 최초 생성, `repeat.R`은 반복 로딩이다. CSV/RDS 및 `compare.R`, `compare_miss.R`, `verify_repeat.R`에 원자료와 검사를 보관했다.
