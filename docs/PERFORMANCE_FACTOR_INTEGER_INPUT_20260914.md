# PCA·요인분석 정수 입력 변환 단축 — 2026-09-14

공유 함수 `factor_analysis_numeric_matrix()`에서 속성이 전혀 없는 integer 벡터에 한해 `as.numeric(values)`를 사용하도록 변경했다. 기존의 문자 왕복 변환과 동일한 double 값을 얻되 문자 벡터 생성·파싱을 생략한다. PCA의 함수 별칭도 모듈 로딩 시 이 구현을 사용한다.

double, factor/ordered, 날짜, 이름·라벨·클래스 등 속성이 있는 열은 기존 `suppressWarnings(as.numeric(as.character(values)))`를 유지한다. 일반 double의 문자 왕복 반올림을 없애는 변경은 하지 않았다. 정수처럼 보이는 double 값도 빠른 경로 대상이 아니다.

## 전체 분석 측정

| 입력 / 분석 | 기존 3회(초) | 변경 후 3회(초) | 중앙값 |
|---|---|---|---|
| 20,000행·30변수, 1–5 integer PCA | 0.14 / 0.25 / 0.14 | 0.11 / 0.11 / 0.10 | 0.14 → 0.11 |
| 20,000행·30변수, 넓은 값 범위 integer PCA | 0.32 / 0.31 / 0.33 | 0.09 / 0.09 / 0.09 | 0.32 → 0.09 |
| 20,000행·12변수, 넓은 값 범위 integer 요인분석 | 0.09 / 0.08 / 0.07 | 0.01 / 0.02 / 0.01 | 0.08 → 0.01 |
| 5,000행·30변수, double PCA 대조군 | 0.26 / 0.27 / 0.25 | 0.25 / 0.26 / 0.25 | 0.26 → 0.25 |

정수 입력은 세 번 모두 빨라졌다. double 대조군의 0.01초 차이는 뚜렷한 개선으로 해석하지 않는다. 특히 요인분석의 변경 후 시간은 매우 짧아 시간 해상도와 실행 변동을 고려해야 한다. 다른 자료 크기·모형에서 같은 개선율을 보장하지 않는다.

번들 R 4.5.3의 새 프로세스 3개를 순차 실행했고 두 번째는 비교 순서를 뒤집었다. 각 입력에서 양쪽 준비 실행 후 GC 및 전체 분석 시간을 측정했다. 다른 R 타이밍 작업은 동시에 실행하지 않았다.

시드 924, 공통 정규 잠재값에 독립 정규 오차를 더한 자료를 사용했다. 낮은 정수는 경계 -1/-0.3/0.3/1로 구간화한 1–5이며, 넓은 정수는 값을 100,000배한 뒤 반올림하고 integer로 저장했다. PCA는 Pearson·고정 3성분·회전 없음, 요인분석은 Pearson·주축요인·고정 1요인·회전 없음·정규성 검사 끔이다. 분석 전 시드 718로 초기화했다.

최초 시험은 이 단일 잠재요인 자료에 2요인을 요청해 기존 요인분석 적합이 실패했다. 변경 효과로 해석하지 않고 자료 생성 구조에 맞춰 1요인으로 수정한 뒤 세 프로세스의 전체 측정을 다시 수행했다. 위 표는 수정 후 결과만 포함한다.

시간은 분석·결과표 준비와 비교용 스냅샷 구성을 포함한다. 입력 생성·로딩·그림 렌더링·저장은 제외한다. 메모리는 측정하지 않았다.

## 동일성 검증

- 네 입력 × 세 프로세스의 준비/측정 실행에서 전체 반환 객체, 경고·메시지 클래스와 문자열·순서, 난수 상태가 `identical(..., num.eq=FALSE)`로 일치했다. 객체 정규화나 수치 허용오차를 적용하지 않았다.
- `scripts/validate_factor_integer_input.R`: 52개 비교 통과. 기준 함수는 기존 숫자 변환 구현 그대로이며 제품 구현 및 PCA 별칭 연결을 확인한다.
- 입력 16개: 빈 정수, 단일 정수, NA와 양/음 정수 경계, 전부 NA, 연속 정수, 큰 양/음 무작위 정수, 이름·라벨 속성, factor/ordered, integer Date, 사용자 클래스/메시지, double의 NA/NaN/Inf/-Inf/-0/pi, 문자, 논리형을 비교했다.
- 전체 분석 36개: PCA 상관/공분산/순서형 상관/Pearson 전환의 24개, 요인분석 Pearson/순서형 상관의 12개. 회전 없음/Varimax/Oblimin과 결측 유무를 조합하고 점수 저장 옵션을 켰다. 모두 실제 분석 결과 타입을 확인해 양쪽 오류만 같아 통과하는 경우를 제외했다.
- 기존 `scripts/validate_factor_pca.R` 통과: 요인분석/PCA 옵션, 그림 및 내보내기 관련 기존 검증 포함.
- 변경 파일의 `git diff --check` 통과.
