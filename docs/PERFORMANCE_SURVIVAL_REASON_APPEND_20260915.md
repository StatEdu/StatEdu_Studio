# 기존 제외 사유에 단일 사유 추가 개선

`survival_preflight`의 `add_reason`은 기존 사유가 없으면 첫 사유를 바로 기록하고, 사유가 있으면 새 코드의 포함 여부를 확인한다. 새 코드가 없을 때만 끝에 추가하며 이미 있으면 목록을 갱신하지 않는다. 내부 사유는 단일 문자열이고 기존 목록은 처음부터 중복 없이 유지되므로 전체 목록에 매번 `unique`를 다시 적용하지 않아도 첫 등장 순서와 중복 제거가 유지된다.

공변량별 검사, missing_covariate 행 번호 보관, 첫 사유 기록, 분석 행 선택과 수치 연산은 유지한다. 이전 최적화를 모두 적용한 직전 코드와 비교하며 누적 개선율이 아니다.

## 검증

- `validate_survival_reason_append.R`: 0/1/30/120행, 단일 기록·지연 진입·시작–종료, 정상·중첩·분산·전부 결측, 변수 순서·중복 역할·집단/공변량 역할 중첩의 전체 결과 96개 비교. 사용자 정의 결측 검사 2개, 같은 시간 인코딩/집단 사유가 반복되는 조건 4개 추가.
- 기존 매핑 helper 294개 및 전처리 36개 회귀 검사도 함께 실행한다.
- `benchmark_survival_reason_append.R`: 두 독립 프로세스 각각 1,000/100,000행 × 네 결측 조건의 성공 전처리 및 전체 결과 88개 비교.
- `validate_survival_reason_append_cox.R`: 정상·중첩·분산 결측 × Cox 기본·층화·군집·스플라인 12조건. 성공 모형, 분석 행 수, 유한 계수와 전체 결과 확인.
- 전체 값/속성·진단·stdout·RNG를 `identical(..., num.eq=FALSE)`로 비교한다. Cox만 call 내부를 포함한 수식 `.Environment` 속성을 제외하며 수치 허용오차는 사용하지 않는다.
- 위 검사는 모두 통과했다. 기존 `validate_survival_preflight.R` 종합 검사도 실제 앱 초기화 후 통과했다.

## 측정 조건

번들 R 4.5.3, 실제 앱 모듈·환경설정 초기화, 동일 시드, 양쪽 함수 컴파일. 기존/변경 교대 실행, 준비 후 5회 중앙값. 전체 전처리 및 진단/stdout 수집을 포함하고 결과 비교는 타이머 밖이다.

중첩은 동일한 절반의 행에 사건·집단·공변량 6개가 모두 결측이다. 분산은 공변량별 결측 행이 서로 겹치지 않는다. sparse는 사건 5%와 집단 5%가 서로 다른 행에 결측이다. 정상은 결측이 없다.

### 분산 결측 추가 측정

별도 두 독립 프로세스에서 조건별 15회 중앙값을 확인했다. 각 프로세스의 전체 결과 비교 62개도 통과했다.

| 조건 | 추가 실행 1 기존→변경(ms) | 추가 실행 2 기존→변경(ms) |
|---|---:|---:|
| 100,000행 분산 | 169.99 → 166.92 | 166.65 → 167.40 |
| 1,000행 분산 | 4.036 → 3.980 | 4.002 → 4.004 |

100,000행은 약 -1.8% / +0.4% 차이로 처음 관측한 약 9% 저하가 지속적으로 재현되지 않았다. 최초/추가 프로세스 사이의 절대 시간도 달라 서로 다른 프로세스의 절대값을 전후 효과로 비교하지 않는다. 이 조건의 개선율을 주장하지 않으며 중첩 조건의 개선을 근거로 적용을 유지했다.

추가 데이터는 같은 출력 폴더의 `focused-times-1.csv`, `focused-times-2.csv`이다. 재현 인자: `scripts/benchmark_survival_reason_append.R 1 disjoint`, `2 disjoint`.
