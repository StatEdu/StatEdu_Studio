# 패널 Hausman 검정 결과 재사용

## 적용

패널 분석의 민감도 분석과 가정 검토가 각각 수행하던 같은 비가중 Hausman 검정을 분석 호출 안에서 재사용한다. FE/RE 적합과 `plm::phtest` 계산은 `longitudinal_hausman_test`로 공통화했다. 계산식과 적합 옵션은 그대로다.

준비 데이터, formula, ID, time을 확정한 지역 provider를 두 소비자에게 전달한다. 첫 검정이 경고·메시지 없이 끝나고 RNG가 변하지 않은 경우에만 작은 검정 결과 객체를 저장한다. 오류는 저장하지 않고 기존 소비자별 오류 처리로 전달한다. 전역 캐시나 패키지 namespace 수정은 없다.

정상 경로의 Hausman 계산은 2회에서 1회로 줄어 FE/RE 재적합 한 쌍을 생략한다. 가정 검토 또는 해당 Hausman 옵션이 꺼져 있으면 기존과 같이 민감도 분석의 검정 1회만 실행한다. 기존 비가중 Hausman 정의를 유지하며 가중 주모형을 대신 사용하지 않는다. provider가 없는 기존 개별 호출도 계산을 수행한다.

## 성능

번들 R 4.5.3, seed 939, 2,000명 × 6시점 = 12,000행, 연속 반응, 두 공변량, 기본 비가중 패널 분석. 워밍업 후 독립 프로세스 3개를 순차 실행하고 두 번째 프로세스는 변경 후 코드부터 측정했다. 로딩은 제외하고 비교용 캡처와 정규화는 포함했다.

| 모형 | 변경 전 1 / 2 / 3 (초) | 변경 후 1 / 2 / 3 (초) | 중앙값 |
|---|---|---|---|
| FE | 3.67 / 3.25 / 3.25 | 3.50 / 2.82 / 3.08 | 3.25 → 3.08초, 약 5% 감소 |
| RE | 3.15 / 3.50 / 3.29 | 2.81 / 2.92 / 2.93 | 3.29 → 2.92초, 약 11% 감소 |

두 모형 모두 세 번 빨라졌다. 해당 자료와 환경의 측정이며 동일한 개선율을 보장하지 않는다. 기준 소스에는 이전 선택 모형 재사용이 이미 포함되어 있으므로 표는 이번 추가 개선의 비교다.

## 동일성 검증

`scripts/validate_longitudinal_hausman_reuse.R`의 32개 조건과 독립 원본 계산 비교가 통과했다. FE/RE 각각에서 전체 가정 검토, Hausman 옵션 끄기, 가정 검토 전체 끄기를 경고/메시지/RNG 소비/오류/정상 조건과 조합한 30개 및 결측·역순 자료 2개다.

반환 결과, 조건 클래스/본문/순서, 표준 출력, RNG를 비교한다. 반올림 전 Hausman 검정 객체 전체도 비교하여 통계량, 자유도, p값, 이름과 방법 등의 일치를 확인한다. 참조 계산은 기존 FE/RE 적합과 phtest의 원문을 별도로 정의하고 항상 다시 실행한다. 정상 검정 2→1회와 예외 시 2회 유지, 옵션 비활성화 시 1회 유지도 확인했다.

수치는 `identical(..., num.eq = FALSE)`로 허용오차 없이 비교한다. 전체 모형 반환 객체에서는 formula/terms 환경과 함수 표현만 정규화하며 원시 환경·함수 객체의 동일성까지 주장하지 않는다. Hausman 원본 검정 객체 비교는 수치 정규화 없이 수행했다.

전체 성능 측정의 워밍업 및 측정 결과는 변경 전 소스를 직접 로드해 비교했다. 기존 패널 선택 모형 22개, GEE 48개, LMM 20개 회귀 검증도 실행했다.

## 범위와 증거

분석 출력 형식과 내용은 변경하지 않았다. 기존 가중 패널 공분산 미지원 및 특이행렬 사례의 생략 결과는 유지한다. 이전 종합 테스트의 Excel 셀 위치 비교 실패는 이번에 해결하거나 재실행하지 않았다. 관련 회귀 검증을 수행하고 전체 형식 변환과 설치 파일 빌드는 실행하지 않았다.

`output/longitudinal-hausman-reuse-20260914/`에 `baseline.R`, `candidate.R`, `bench.R`, `normalize.R`, `timing-1/2/3.csv`, `validation.log`, `panel-regression.log`, `gee-regression.log`, `lmm-regression.log`를 보관한다. 기존 작업 트리의 다른 변경은 유지했다.
