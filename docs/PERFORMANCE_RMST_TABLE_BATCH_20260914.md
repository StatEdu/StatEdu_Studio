# RMST 비교 결과표 일괄 조립 — 2026-09-14

`R/analysis_survival.R`의 survival_rmst_contrasts에서 비교마다 한 행 데이터프레임을 만드는 대신, 같은 순서로 계산한 값을 목록에 저장한 후 결과표를 한 번 조립하도록 개선했다. 앞서 적용한 RMST 행 접근 개선 이후의 소스를 기준으로 비교했다.

## 결과 보존

기존 일반 데이터프레임/속성 없는 원자 열 조건에 더해 Strata·Tau·RMST·SE가 존재하고 Tau·RMST·SE가 숫자일 때만 일괄 조립한다. 그 외에는 기존 data.frame 및 rbind 경로를 유지한다. 각 쌍의 차이·SE·z·p·비율·신뢰구간의 계산식과 순서, 쌍 순서 및 마지막 Holm 보정은 바꾸지 않았다. 표의 이름·열 순서·자료형과 행 이름을 검증했다.

100집단의 4,950개 비교에서 한 행 데이터프레임 생성 4,950회를 최종 데이터프레임 생성 한 번으로 줄인다. 이것은 결과표 조립의 변경이며 생존 추정법을 대체하지 않는다.

## 시간 측정

번들 R 4.5.3, 앱 설정 적용, 자동 설치 비활성화. 새 프로세스에서 변경 전후 3쌍을 순차 실행했고 두 번째 쌍은 순서를 반대로 했다. 각 프로세스는 3집단 다음 100집단을 실행했다. 함수 환경은 동일한 전역 환경으로 연결했으며, 검증은 측정과 동시에 실행하지 않았다.

| 집단 수 | 변경 전 3회(초) | 변경 후 3회(초) | 중앙값 전→후 |
|---|---|---|---|
| 3 | 0.01 / 0.01 / 0.01 | 0.03 / 0.01 / 0.02 | 0.01→0.02 |
| 100 | 1.46 / 1.46 / 1.44 | 0.11 / 0.09 / 0.10 | 1.46→0.10 |

100집단에서는 약 93% 감소했다. 3집단에서는 개선이 없고 중앙값이 0.01초 증가했다. 작은 입력의 첫 호출에는 컴파일 등을 포함한 변동이 있으므로 이를 제거한 순수 계산 속도라고 주장하지 않는다. 100집단은 많은 쌍을 비교하는 부하 조건이며 일반 사용 규모를 뜻하지 않는다.

시간은 RMST 비교 함수의 전체 호출이다. 생존 모형 적합, 앱 로딩, 화면 렌더링 및 내보내기는 포함하지 않는다.
