# 순서형 교차분석 Gamma의 영역 합 재사용

2026-09-15. `R/analysis_crosstabs.R`의 Gamma 계산을 개선했다. 기존 셀 순서와 concordant/discordant 누적 순서를 유지하면서, 각 셀에서 다시 계산하던 아래쪽 행의 누적 열 합을 한 번 준비해 사용한다. 빈도표, 추세 검정 방법, 표시 및 저장 형식은 바꾸지 않았다.

## 적용 범위와 정확성

기본 matrix/array 또는 table 클래스의 비음수 정수값 빈도표, 64~1,000,000셀에만 준비 경로를 사용한다. 총빈도는 94,906,265 이하로 제한해 빈도 합과 쌍 수 계산이 double의 정확한 정수 범위 안에 있도록 했다. 원래 integer 표에서는 `최대 셀 빈도 × 총빈도 <= .Machine$integer.max`도 요구한다. 원래 정수 곱셈에서 발생할 수 있는 overflow 경고/NA를 double 연산으로 바꾸어 없애지 않기 위한 보수적인 조건이다.

소수·음수·비유한 값·사용자 클래스·큰 빈도·작은 표 등 미지원 조건은 원래 부분행렬 합산식을 사용한다. 누적 준비는 해당 함수 호출 안에서만 유지한다. 원래 연산을 보존한 `scripts/fixtures/crosstab_gamma_reference.R`와 지속 검사 `scripts/validate_crosstab_gamma.R`를 추가했다.

160개 비교에서 Gamma 반환값, 조건 클래스/내용/순서, 표준 출력 및 최종 RNG가 `identical(..., num.eq=FALSE)`로 일치했다. 빈 차원/단일 차원/임계 크기, integer/double/table, 0빈도, NA/NaN/Inf, 음수/소수, 큰 빈도, integer overflow 및 사용자 클래스를 포함한다. 모든 표 크기·가능한 입력의 전수 검증은 아니다.

별도 12개 비대칭 빈도·결측·추세 켜짐/꺼짐 조건에서는 `prepare_crosstab_results`의 전체 반환값과 진단/RNG가 정확히 일치했다. 추세가 켜진 사례의 Gamma가 0이 아님도 확인해 균형표의 0 결과만 검사하지 않았다. 기존 `scripts/validate_crosstabs.R`도 저장 helper 검사까지 끝까지 통과했다.

## 전체 분석 성능

번들 R 4.5.3, 행/열 각각 4·12·40·80수준의 순서형 변수, 모든 셀에 8명인 균형자료를 사용했다. 예를 들어 80×80은 51,200행이다. 충분한 기대빈도로 Monte Carlo Fisher 경로는 사용하지 않는다. 추세와 행/열/전체 백분율을 켜고 분석 전체 반환값을 생성했다. HTML 렌더링·저장·앱 시작은 제외한다.

수정 전/후 소스를 별도 환경에 읽고 양쪽 분석 모듈 함수에 동일하게 compiler::cmpfun을 적용했다. 독립 R 프로세스 3개를 순차 실행하고, 준비 비교 후 조건별 3회를 측정했다. 두 번째 프로세스의 측정 순서는 반대로 했다. 시간에는 동일한 진단/출력 캡처가 포함되며 정확 비교는 타이머 밖이다.

|행×열 수준|프로세스별 기준 중앙값(초)|프로세스별 현재 중앙값(초)|
|---|---|---|
|4×4|0.01 / 0.01 / 0.01|0.00 / 0.01 / 0.00|
|12×12|0.02 / 0.03 / 0.03|0.02 / 0.02 / 0.02|
|40×40|0.17 / 0.17 / 0.17|0.16 / 0.16 / 0.16|
|80×80|0.69 / 0.70 / 0.69|0.61 / 0.61 / 0.61|

80×80 기준 중앙값은 약 0.69→0.61초, 약 12% 감소했다. 이 합성 조건의 분석 시간이며 앱 전체 개선율이 아니다. 작은 표의 0.00/0.01초 차이는 타이머 분해능에 가까워 개선율로 해석하지 않는다. 4×4는 원래 계산을 유지한다.

각 프로세스의 준비·측정 결과 비교가 모두 통과했다. 비교 대상은 전체 반환값 및 진단/RNG이며 HTML/PDF/Word/HWPX/Excel 각각의 새 교차 형식 비교가 아니다. 표시·저장 형식을 변경하지 않았으므로 전체 내보내기 및 설치 파일 빌드는 하지 않았다.

첫 실행들에서 사용자 캐시 경로에 쓰기 권한이 없다는 모듈 로딩 경고가 발생했지만 스크립트는 정상 실행됐고 로딩은 타이머 밖이었다. 마지막 추가 검사는 작업 공간 캐시 경로를 지정했다. 이 경고를 분석 내부 진단으로 집계하거나 숨기지 않았다.
