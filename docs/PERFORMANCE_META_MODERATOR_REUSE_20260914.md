# 조절변수 문자열 해석 재사용 — 2026-09-14

조절변수 목록 생성과 값 추출에서 같은 문자열 쌍을 반복 해석하지 않도록 적용했다. `meta_moderator_parser()`는 처리 한 번에만 유지되는 최대 8개 항목의 FIFO 캐시를 제공한다. 범주형·연속형 문자열과 각각의 인코딩 표시를 별도 목록 원소로 비교하므로 구분자 결합에 따른 키 충돌이 없다. 결측, 비문자, 속성이 있는 단일 입력은 기존 함수를 호출한다. 경고·메시지가 발생한 결과는 저장하지 않으며 오류도 저장하지 않는다.

일반 문자형 두 열의 조합이 모두 다르면 중복 확인 후 기존 해석 함수를 그대로 반환한다. 다른 분석 사이에 결과를 공유하지 않는다. 8개는 항목 수 제한이며 총 바이트 제한은 아니다. 수치 추정 코드와 표시·저장 형식은 변경하지 않았다.

## 최종 측정

연구 1,000개, 문자열 조합 2개가 번갈아 반복되는 경우와 1,000개 모두 다른 경우를 비교했다. 새 번들 R 4.5.3 프로세스 3개를 순차 실행했고 두 번째에서는 기존/후보 순서를 뒤집었다. 준비 실행 후 GC와 경과 시간을 측정했으며 다른 R 작업을 동시에 실행하지 않았다.

| 자료 / 기능 | 기존 3회(초) | 최종 후보 3회(초) | 중앙값 |
|---|---|---|---|
| 반복 / 목록 생성 | 1.15 / 1.12 / 1.14 | 0.22 / 0.22 / 0.21 | 1.14 → 0.22 |
| 반복 / 값 추출 | 1.46 / 1.45 / 1.37 | 0.03 / 0.03 / 0.03 | 1.45 → 0.03 |
| 모두 다름 / 목록 생성 | 1.64 / 1.70 / 1.70 | 1.73 / 1.71 / 1.71 | 1.70 → 1.71 |
| 모두 다름 / 값 추출 | 1.39 / 1.39 / 1.45 | 1.43 / 1.45 / 1.42 | 1.39 → 1.43 |

반복 조건은 각각 약 81%, 98% 감소했다. 모두 다른 조건에서는 중앙값이 약 1%, 3% 증가했다. 전처리 비용과 실행 편차를 분리해 측정하지 않았으므로 증가 전체의 원인을 단정하지 않는다. 중복이 없는 자료에서 속도 개선을 주장하지 않는다. 캐시 항목 수보다 많은 서로 다른 조합이 교대로 나타나는 자료도 이번 속도 측정에는 포함하지 않았다.

반복 자료는 `region=Asia`/`region=Europe`, `age=40`이다. 비반복 자료는 `region=Group1`부터 `region=Group1000`까지이며 연속형 문자열은 같다. 전체 목록 생성/값 추출 및 조건 수집을 포함하지만 입력 생성·소스 로딩·수치 모형 적합·화면·저장은 제외한다. 전체 메타분석의 개선율이 아니다. 메모리 사용량은 측정하지 않았다.

첫 후보는 중복 사전 확인 없이 8개 항목을 검색했다. 모두 다른 자료의 추가 비용이 확인되어 사전 확인을 추가한 뒤 새 프로세스 3개로 최종 측정했다. 초기 결과는 상위 폴더, 위 표의 최종 결과는 `final/`에 구분해 보관했다.

## 검증

- 최종 크기·자료·기능 조합 4개 × 프로세스 3개에서 준비 및 측정의 전체 반환값·경고/메시지 문자열·난수 상태가 기존 소스 사본과 `identical(..., num.eq=FALSE)`로 일치했다. 수치 허용오차를 사용하지 않았다.
- 신규 `scripts/validate_meta_moderator_reuse.R`은 반복·비반복·빈 문자열·결측·factor·한글·잘못된 문법·중복 이름·구분자 포함의 9개 입력 형태와 목록/범주형/연속형/출판연도/잘못된 키의 5개 작업, 총 45개 조건을 비교한다. 전체 반환값·오류/경고/메시지 클래스 및 문자열·표준출력·난수 상태가 일치했다. 조건 객체의 호출 환경 자체는 비교하지 않았다.
- 별도로 캐시 적중, 8개 초과 시 제거, 반환값 수정 후 원본 보존, 경고·메시지 발생 시 매번 재실행, 모두 다른 문자열의 기존 함수 반환을 확인했다.
- 기존 메타분석 입력·모형·UI 검증이 모두 통과했다.
