# 위험집단 표 테마 반복 생성·재사용 후보 — 2026-09-14

## 판단

설정이 고정된 묶음에서 기본 테마를 한 번 만들어 재사용하는 후보는 위험집단 표 객체 반복 생성 시간을 줄였다. 제품에는 아직 적용하지 않았다. 실제 다중 그림·현재/누적 내보내기 흐름의 성능, 설정 변경과 확장 테마 요소의 수명을 검증한 변경이 아니기 때문이다.

## 반복 비용

번들 R 4.5.3을 사용해 JIT 0 및 3 각각 새 프로세스 3개를 순차 실행했다. 패키지·모듈 로드 후 ggplot2 네임스페이스를 명시적으로 로드하고 측정했다.

| 구간 (100회, 초 중앙값) | JIT 0 | JIT 3 |
| --- | ---: | ---: |
| theme_classic(base_size=10) 생성 | 1.75 | 1.75 |
| 위험집단 표 객체 생성 | 2.09 | 2.08 |

이 조건의 첫 테마 호출은 0.00~0.02초였다. 앞선 실제 세션의 첫 테마 호출 0.31초와는 패키지 로드 및 초기화 경로가 다르므로 같은 비용으로 비교하지 않는다. 반복 호출 비용은 약 18밀리초이며, 그래프를 파일에 그리는 시간은 이 표에 포함하지 않는다.

## 묶음 내 재사용 실험

제품 함수 복사본의 `ggplot2::theme_classic(base_size=10)` 호출 하나만 지역 캐시 함수로 교체했다. 각 후보 프로세스에서 새로운 캐시를 만들고 첫 호출 시 테마를 생성했다. 2집단·4시점의 고정 입력과 고정 팔레트를 사용했다. 전역·영구 캐시는 만들지 않았다.

기준/후보 각 3개 새 프로세스를 순차 실행했고 두 번째 쌍은 후보부터 실행했다. 실제 그림 경로와 같이 JIT 0 조건을 사용했다.

| 표 객체 100개 구성 | 1회 | 2회 | 3회 | 중앙값 |
| --- | ---: | ---: | ---: | ---: |
| 기준 | 2.87 | 2.86 | 2.88 | 2.87 |
| 후보 | 0.59 | 0.58 | 0.55 | 0.58 |

단위는 초다. 중앙값 약 80% 감소는 **고정 입력의 객체 100개 구성**에 대한 수치이며 분석 전체나 파일 저장 전체의 속도 개선이 아니다. 별도로 마지막 객체 하나를 PNG로 그리는 시간은 기준 0.08초, 후보 0.07~0.08초였다. 반복 비용 측정과 묶음 실험은 사전 준비 순서가 다르므로 서로의 절대 시간을 직접 합산하지 않는다.

## 결과 검증과 남은 범위

- 기준/후보 PNG 3쌍은 크기와 RGBA 픽셀이 완전히 같았다.
- 3쌍의 그림 데이터, 경고, 난수 상태가 정확히 동일했다.
- 저장한 테마 객체는 3쌍 모두 `all.equal()`이 TRUE였다. 별도 프로세스 RDS 사이의 `identical()`은 FALSE였으며, 기준 프로세스끼리도 FALSE였다. 테마 객체의 엄격한 동일성을 통과했다고 주장하지 않는다.
- 로컬 ggplot2 코드 확인 결과 `theme_classic()`은 `theme_bw()`와 `theme_grey()`를 거치며, `theme_grey()`는 패키지 전역의 `theme_all_null`을 사용한다. 따라서 단순 영구 캐시를 도입하기 전에 확장 테마 등록 등 변경 가능한 상태와 캐시 유효 범위를 검증해야 한다.
- 글꼴·전역 테마 변경, 다른 팔레트, 실제 여러 결과 누적, HTML/PDF/Word/HWPX/Excel 출력의 검증은 이번 고정 조건 실험에 포함하지 않았다.

제품 및 출력 코드는 수정하지 않았고 설치 파일도 빌드하지 않았다. 다음 구현 검토는 실제 여러 그림을 만드는 동일 작업 안에서만 테마를 공유할 수 있는 호출 경계를 찾는 것이다. 단일 그림의 첫 테마 생성 비용을 없애는 개선은 아니다.
