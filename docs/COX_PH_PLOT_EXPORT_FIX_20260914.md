# Cox 다변수 PH 그래프 저장 오류 수정 — 2026-09-14

## 수정 결과

20공변량 Cox 결과에서 재현된 `figure margins too large` 오류와, 큰 그림을 HTML에 삽입할 때 발생한 `MAX_URI_LENGTH` 오류를 수정했다. 수치 분석 코드는 변경하지 않았다.

- `R/result_survival_ui.R`: PH 그래프의 두 열 배치를 유지하고 행마다 240px을 확보한다. 화면의 최소 높이는 620px, 저장의 최소 높이는 760px을 유지한다. 20항은 10행이므로 높이가 2400px이다. Cox와 원인별 Cox 화면·저장 사양에 같은 규칙을 적용했다.
- `R/result_export_files.R`: 원인별 Cox 독립 그림 파일도 같은 높이 규칙을 인치로 환산해 사용한다. 기존 최소 높이 6.2인치는 유지한다.
- `R/result_saved_ui.R`: 큰 PNG/JPEG data URI를 임시 표식으로 XML 직렬화한 뒤 원래 그림 데이터를 삽입한다. libxml의 URI 이스케이프 길이 제한을 피하며 기존 CR/LF의 `%0D`/`%0A` 표현을 유지한다. DOM의 원래 속성은 종료 시 복원한다. 생존분석 인라인 그림, 누적 결과 HTML 및 PDF 페이지 구성에서 공통 함수를 사용한다. 이미지 축소·재압축은 하지 않는다.

곡선, 잔차, 신뢰구간, 변수 순서와 모든 결과표·주석은 그대로 유지한다. 큰 그래프의 높이와 그에 따른 문서 페이지 배치는 달라질 수 있다.

## 검증

1. 0/1/4/6/10/20항의 높이 계산과 빈 결과를 확인했다. 20항 실제 PH 그래프는 화면·저장 높이에서 오류 없이 그려졌다. 4항의 기존/현재 PNG는 바이트 단위로 일치했다.
2. 1천 행·20공변량 실제 결과에서 변경 전후 화면 HTML을 비교했다. PH 그래프 높이만 정규화하면 결과가 일치했다. 그림 및 저장 생성 전후 분석 객체의 직렬화 바이트도 일치했다.
3. 짧은 URI, 긴 URI, LF/CRLF, 표식 충돌 및 DOM 보존을 검증했다. 기존 직렬화가 가능한 입력은 기존 출력과 동일했고, 길이 제한을 넘는 그림 데이터도 유지됐다.
4. 현재 결과 1개와 누적 결과 2개에 대해 HTML·Word·Excel·PDF·HWPX 총 10개 파일 생성에 성공했다. 실제 저장용 HTML·Excel 생성 경로도 성공했다.
5. HTML·Word·HWPX에 포함된 세 그림의 SHA-256이 저장 HTML의 원본 그림 데이터와 일치했다. 그림 참조 수는 현재 3개, 누적 6개였다. PDF에서 PH 그림의 해상도와 포함 페이지를 확인했다. 현재 PDF는 15쪽이며 PH 그림은 8–9쪽, 누적 PDF는 30쪽이며 PH 그림은 8–9쪽 및 23–24쪽에 포함됐다. 현재 PH 두 페이지를 렌더링해 20개 패널이 빠짐없이 표시되는 것을 시각적으로 확인했다. Word/HWPX의 앱 화면 렌더링까지 수행한 것은 아니다.
6. `scripts/validate_survival_ph_height.R`와 기존 `scripts/validate_survival_ui_smoke.R`가 통과했다. 전자는 원인별 Cox 저장 사양도 검사한다. `git diff --check` 통과.

PDF 검증에서는 제한된 환경의 Chrome 실행이 차단되어 허용된 별도 실행으로 확인했다. HWPX 검증에서는 상속 환경의 `PATH`/`Path` 중복을 검증 R 프로세스에서만 정리한 뒤 설치된 한글로 변환했다. 사용자 환경이나 운영 변환 스크립트를 수정하지 않았다. 최초 실패와 최종 성공을 구분하며, 최종 `export-status.csv`의 10건은 모두 성공이다.
