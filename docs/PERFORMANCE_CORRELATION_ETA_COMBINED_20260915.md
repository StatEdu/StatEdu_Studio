# Eta 적합 준비·집단 집계의 통합 검증

## 결론

두 변경을 적용하기 전 소스와 현재 제품 소스를 직접 비교했다. 적합 준비 단축과 집단 코드 직접 집계를 함께 사용해도 결과 및 관찰 가능한 진단·난수 동작이 검증 조건에서 보존됐다. 결측 혼합형의 5회 묶음 측정은 세 프로세스 모두 단축됐으며 중앙값 0.334→0.312초, 약 7% 감소였다. 기존 개별 변경의 약 9% 수치들을 합산하지 않는다. 이번에는 제품 코드를 추가로 변경하지 않았다.

## 소스와 범위

기준 소스는 `output/correlation-eta-lm-review-20260915/baseline.R`이며, aov 호출과 table 집계를 모두 사용한다. 현재 소스는 lm 적합에 aov 클래스를 부여하여 기존 ANOVA 요약을 사용하고, 준비된 factor 코드를 tabulate로 집계한다. 이번 폴더의 `baseline.R`, `current.R`에 각각 보존했다.

집단 평균, 제곱합 산식, 관측치 순서, 대비와 QR 적합, ANOVA 요약 및 p값 계산은 유지된다. 내부 적합 객체와 집계 컨테이너가 완전히 같은 형태라는 뜻은 아니다. 실제 계산에 쓰이는 수 벡터·이름·제곱합, 원시 ANOVA 요약 및 최종 결과를 검증한다.

## 정확성

- 216개 조건에서 전체 결과와 집계값·집단 평균·전체/집단 간 제곱합의 수집 결과가 일치했다. treatment/sum/Helmert 대비, 2/3/6집단, 3/12/100행, 일반·인접 실수·동점·큰 수·결측·무한대·상수·ordered 자료를 포함한다. 그중 원시 ANOVA 요약이 생성된 153개는 해당 요약 객체도 정확히 일치했다.
- 사용자 정의 대비 함수가 경고, 메시지, 난수 소비 및 이 세 동작을 함께 발생시키는 16개 조건에서 결과·진단·stdout·난수 상태 및 대비 함수 호출 횟수가 일치했다. 각 조건에서 사용자 함수가 실제 호출됐음도 확인했다.
- 100개 입력 조합의 경계 검증을 각 성능 프로세스에서 반복했다.
- 전체 분석 네 조건 × 세 프로세스에서 예열 및 각 5회 묶음의 모든 반복 결과가 기존 기준과 일치했다.

결과 비교는 `identical(..., num.eq=FALSE)`로 수행하며 허용오차·반올림·정규화를 사용하지 않았다. 집계 비교는 원래 후속 계산이 사용하는 `as.numeric(counts)`와 `names(counts)`를 대상으로 한다. 조기 반환이나 오류가 나는 입력은 그 결과와 진단을 비교했다. 모든 사용자 확장이나 모든 자료 형태에 대한 증명을 뜻하지 않는다.

## 실행 시간

10,000행·20변수·190쌍, 명목형 또는 연속형 10개/명목형 10개 혼합 자료다. 명목형은 여섯 범주이며 결측 조건에서는 변수마다 다른 10%를 결측 처리했다. 시드 33, Pearson 지정, 정규성 및 잠재상관 비활성화 조건이다. 혼합형에는 Eta 100쌍이 있고 명목형은 변경 경로를 사용하지 않는 대조 조건이다.

소스별 환경에 정의된 상관분석 함수들을 명시적으로 컴파일했다. 새 R 프로세스 세 개를 순차 실행하고 양쪽 예열 후 두 번째 프로세스의 조건 및 측정 순서를 뒤집었다. 프로파일러 없이 전체 결과 준비·진단 수집·동일성 검사를 5회 반복한 총시간을 5로 나눴다.

| 자료 | 기존 3회 값(초) | 현재 3회 값(초) | 기존/현재 중앙값(초) |
|---|---|---|---|
| 명목형 | 0.268 / 0.234 / 0.252 | 0.262 / 0.236 / 0.248 | 0.252 / 0.248 |
| 명목형, 결측 10% | 0.248 / 0.220 / 0.236 | 0.244 / 0.240 / 0.234 | 0.236 / 0.240 |
| 혼합형 | 0.406 / 0.354 / 0.390 | 0.358 / 0.378 / 0.354 | 0.390 / 0.358 |
| 혼합형, 결측 10% | 0.340 / 0.334 / 0.332 | 0.318 / 0.312 / 0.310 | 0.334 / 0.312 |

결측 혼합형은 세 번 모두 단축됐다. 결측 없는 혼합형은 두 번 단축, 한 번 증가했으며 중앙값 기준 약 8% 감소했다. 변경 경로를 사용하지 않는 명목형에서도 변동이 나타나므로 모든 시간 차이를 코드 효과로 해석하지 않는다. 모든 개별 호출에서 빨라진다고 보장하지 않으며, 프로그램 로딩·화면·내보내기의 개선율이 아니다.
