# Pearson 순위 준비 생략 검토 — 미반영

## 후보와 결론

모든 유효 변수가 연속형이고 Pearson을 명시적으로 선택했을 때 Spearman용 `correlation_rank_test()` 생성을 생략하는 후보를 검토했다. 기존 Kendall 전용 조건을 `continuous_method %in% c("pearson", "kendall")`로 확장하는 변경이다. 혼합 변수 및 자동 선택의 준비 경로는 유지했다.

결과 동일성은 확인했지만, 실제 코드 재측정에서 첫 호출 중앙값 개선을 확인하지 못해 후보를 되돌렸다. 기존 Kendall 최적화는 유지한다.

## 검증

- 후보를 실제 소스에 적용한 상태에서 `scripts/validate_correlation_kendall_rank_prep.R`의 기대 호출 횟수를 Pearson까지 확장하여 실행했다. 64개 조건의 전체 결과, 경고·메시지, 표준 출력 및 RNG 상태가 `identical(..., num.eq=FALSE)`로 일치했다. 전부 오류 없이 완료했다.
- 명시적 연속형 Pearson/Kendall은 준비 함수 0회, 다른 구성은 1회였다. 기준은 이전의 무조건 준비 조건으로 복원했다.
- 첫 호출 측정의 독립 프로세스 12개 전체 캡처도 정확히 일치했다. 검증 스크립트의 기대값은 후보를 되돌린 후 기존 Kendall 전용으로 복구했다.

## 측정

번들 Windows R 4.5.3, JIT 3. 모듈 로딩 및 환경설정 후 n=2,000, p=6 연속 정규 난수 데이터에서 Pearson을 실행했다. 정규성 검사와 잠재 상관분석은 비활성화했다. 각 측정은 별도 프로세스로 순차 실행하고 두 번째 쌍은 실행 순서를 반대로 했다.

|실험|기준 첫 호출(초)|후보 첫 호출(초)|중앙값|
|---|---|---|---|
|후보 함수|0.15 / 0.14 / 0.16|0.14 / 0.14 / 0.12|0.15→0.14|
|실제 소스 적용|0.14 / 0.16 / 0.14|0.12 / 0.14 / 0.14|0.14→0.14|

실제 소스 비교는 2쌍이 0.02초 단축, 1쌍이 동일했지만 중앙값은 같았다. 두 번째 호출은 대부분 0.00초로 기록되고 일부 0.02초였다. 이는 타이머 해상도와 변동을 포함하며 실행 비용이 없다는 뜻이 아니다. 미세한 차이만으로 성능 개선을 확정하지 않았다. UI/프로세스 시작/패키지 및 모듈 로딩 시간은 포함하지 않았다.
