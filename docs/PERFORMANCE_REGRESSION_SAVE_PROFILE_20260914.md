# 회귀분석 진단 그림 저장 병목 검토 — 2026-09-14

일반 OLS 회귀분석의 저장용 HTML 생성을 측정했다. 4개 모형의 반복 저장에서 PNG 생성이 계측 경과 시간의 약 89%를 차지했다. 모형별 진단 그림 재사용이 다음 개선 후보이며, 이번에는 제품 코드를 변경하지 않았다.

## 조건과 범위

번들 R 4.5.3, Windows, seed 714, 2,000행, 연속 예측변수 2개를 사용했다. 종속변수 1개 또는 4개에 각각 독립적인 OLS 모형을 적합했다. `auto_method=FALSE`, `residual_diagnostics=TRUE`이며 준비된 부트스트랩 작업이 0개임을 확인했다. 자동 강건 추정, 부트스트랩, 위계적 회귀 성능으로 일반화하지 않는다.

모형마다 Q-Q 그림과 표준화 잔차-적합값 그림을 저장했다. 기본 600 dpi이며, 그림은 각각 2,625×2,625 픽셀이다. 로딩·분석 후 HTML 생성만 측정해 앱 시작, 분석 시간, 저장 대화상자, 파일 형식 변환은 제외했다.

각 조건 새 프로세스 3개, 별도 프로파일 프로세스 1개씩을 순차 실행했다. 2회차는 조건 실행 순서를 바꿨다. 다른 R 실행과 겹치지 않았다.

## 시간과 병목

| 모형 / 그림 수 | 첫 저장 3회(초) | 반복 저장 3회(초) | 첫 / 반복 중앙값 |
|---|---|---|---|
| 1 / 2 | 1.03 / 1.03 / 1.03 | 0.35 / 0.36 / 0.38 | 1.03 / 0.36초 |
| 4 / 8 | 1.89 / 1.89 / 1.95 | 1.17 / 1.15 / 1.17 | 1.89 / 1.17초 |

별도 계측 실행은 1개 모형 첫 1.08초·반복 0.38초, 4개 모형 첫 1.93초·반복 1.18초였다.

| 계측 구간 | 1개 첫 / 반복 | 4개 첫 / 반복 |
|---|---:|---:|
| PNG URI 생성 합계 | 0.28 / 0.27초 | 1.04 / 1.05초 |
| 실제 그리기 함수 합계 | 0.08 / 0.06초 | 0.26 / 0.22초 |

그리기 시간은 PNG 생성 시간에 포함된다. 4개 모형의 반복 실행에서는 1.05/1.18, 약 89%가 PNG 생성이었다. 계수 표 블록 합계는 첫 약 0.37초, 반복 약 0.03초였다. 짧은 개별 구간에서 0초 표시는 비용이 없다는 뜻이 아니다.

`Rprof(interval=.01)`의 4개 모형 반복 샘플에서 `grDevices::dev.off` 총 비중은 54.43%, `stats::qqnorm`은 8.86%, `stats::lowess`는 1.27%였다. 이들은 샘플 비율이며 전체 경과 시간 비율과 혼동하면 안 된다. LOWESS나 잔차 계산식을 변경하는 것보다 반복 PNG 생성 제거를 우선 검토할 근거다.

## 결과 표현 변화의 확인

초기 검사에서 저장 전후 전체 직렬화 값이 달라져 측정을 중단했다. 차이를 추적한 결과 모형의 `residuals`, `fitted.values`에 붙은 행 이름이 R의 지연 문자열 변환 표현에서 일반 문자열 벡터로 바뀌었다. 숫자와 이름은 `identical(..., num.eq=FALSE)`로 정확히 같았다. 통계값 차이를 허용오차로 무시한 것이 아니다.

최종 검사에서는 **검사용 복사본**의 두 벡터 이름만 일반 문자열로 통일한 뒤 전체 결과를 직렬화해 비교했다. 숫자나 이름 내용, 모형, 표 또는 다른 속성을 제거하지 않았다. 정규화·비교는 시간 측정 밖에서 수행했고 실제 프로그램 결과를 수정하지 않았다. 최초 중단 실행의 시간은 성능 표에 포함하지 않았다.

이 사례에서는 원시 직렬화 바이트를 캐시 키로 사용하면 의미상 같은 결과에서도 불필요한 실패가 생길 수 있다. 향후 캐시 검증에서도 수치 변경과 내부 표현 변경을 구분해야 한다.

- PNG 원본 합계는 모형 1개 140,268 bytes, 4개 548,489 bytes였다. `object.size` 결과 추정치는 각각 573,896 / 2,291,120 bytes, HTML은 699,864 / 1,349,872 bytes였다. 프로세스 최대 메모리는 이번에 측정하지 않았다. 모형의 환경 참조 등이 있어 이 값만으로 캐시의 실제 메모리 비용을 계산하면 안 된다.
