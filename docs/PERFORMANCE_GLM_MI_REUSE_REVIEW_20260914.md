# 다중대치 Poisson 선별 모형 재사용 후보 — 2026-09-14

선별 단계에서 적합한 Poisson 모형을 대치 자료별로 보관하고, 이후 같은 자료의 카운트 적합에서 재사용하는 후보를 구현했다. 전체 분석 성능이 일관되게 개선되지 않아 제품에는 반영하지 않았다.

## 후보 동작

선별 적합이 수렴하고 경고·메시지가 없을 때만 모형을 보관한다. 조건은 억제하지 않고 관찰하며, 조건이 발생한 적합은 원래대로 다시 수행한다. 재사용된 모형의 저장 호출식에서 data 인수는 기존 `data` 표현식으로 복원한다. 음이항 적합·family 결정·강건 표준오차·계수 풀링은 그대로 실행한다. 캐시는 한 MI 실행 안의 대치 자료별 리스트다.

## 전체 분석 시간

| 입력 | 기존 3회(초) | 후보 3회(초) | 중앙값 |
|---|---|---|---|
| Poisson, 2,000행 | 0.31 / 0.28 / 0.33 | 0.28 / 0.29 / 0.28 | 0.31 → 0.28 |
| Poisson, 10,000행 | 0.98 / 0.83 / 0.85 | 0.75 / 0.92 / 0.94 | 0.85 → 0.92 |
| 음이항, 2,000행 | 0.43 / 0.25 / 0.25 | 0.23 / 0.22 / 0.23 | 0.25 → 0.23 |
| 음이항, 10,000행 | 1.08 / 1.08 / 0.87 | 0.83 / 1.00 / 0.82 | 1.08 → 0.83 |

음이항 입력에서는 세 번 모두 빨라졌지만, 10,000행 Poisson 입력에서는 세 번 중 두 번 느려졌다. 따라서 모든 카운트 MI에 적용하는 이 후보의 도입은 보류한다. 감소한 적합 횟수만으로 전체 분석 개선을 보장할 수 없다. 음이항으로 family가 잠긴 경우만 재사용하는 제한적 후보는 별도 검증할 여지가 있으나 이번에는 구현·측정하지 않았다.

## 측정과 동일성 범위

- 번들 R 4.5.3, 새 프로세스 3개 순차 실행. 각 입력에서 양쪽 준비 실행 후 GC와 전체 분석 시간을 측정했고 두 번째 프로세스는 후보를 먼저 측정했다. 다른 R 타이밍 작업은 동시에 실행하지 않았다.
- 시드 916, 정규 예측변수 6개, mu=exp(0.2*x1-0.1*x2), Poisson 또는 size=0.5 음이항 y. x1–x3 각각 15% 결측, 대치 5개·반복 3회, 강건 표준오차 켬·VIF 끔. 분석 호출 전 시드 713.
- 전체 분석 시간은 적합과 결과 준비 및 비교용 스냅샷 구성을 포함한다. 입력 생성·모듈 로딩·화면·저장은 제외한다. 이전 프로파일 수치와 직접 비교하는 실험이 아니다.
- 네 입력 × 세 프로세스에서 준비 실행과 측정 실행의 반환 내용, 정규화한 전체 대표 모형, 저장된 호출식, 계수·적합값·잔차·deviance·weights·theta·SE.theta, 경고/메시지 문자열, 난수 상태가 `identical(..., num.eq=FALSE)`로 일치했다.
- 공식과 terms의 환경을 `.GlobalEnv`로 통일하고 함수는 인수·본문으로 비교했다. 처음 비교에서 model frame의 terms 속성 안에 남은 환경 차이를 검출했으며, 해당 환경까지 정규화한 뒤 재측정했다. 수치 허용오차를 추가한 것은 아니다. 모든 클로저 환경 자체의 동일성을 입증한 것은 아니다.
- 경고/오류 주입, 외부 조건 처리기의 부작용, 특수 formula, 범주형·오프셋, 대규모 대치 수의 경계 검증은 수행하지 않았다. 따라서 조용한 선별 적합만 재사용하는 설계가 모든 조건 동작을 보존한다고 확정하지 않는다.
- 대치 수만큼 Poisson 모형을 보관하므로 추가 메모리가 필요하다. 최대 메모리 및 할당량은 이번에 측정하지 않았다.
