# Start-stop 대상자 목록의 위치 기반 조회 — 2026-09-14

`survival_preflight()`가 대상자별 구간 목록을 순회할 때 매번 이름으로 목록 요소를 조회하던 부분을 위치 기반 조회로 변경했다. 대상자 이름은 별도로 같은 위치에서 읽으므로 처리 순서와 순서 관련 안내에 쓰이는 ID는 유지한다. 이전 단일 구간 검사 생략은 양쪽 모두 적용되어 있다.

빈 문자열 ID에서는 기존 이름 조회가 NULL을 반환하고 후속 정렬에서 오류가 발생했다. 이번 성능 변경으로 이 동작까지 달라지지 않도록 빈 이름은 기존과 같은 NULL 경로를 유지했다. 빈 ID 오류를 수정하는 변경은 포함하지 않는다.

## 전체 입력 검증 시간

대상자 1만 명의 합성 start-stop 자료를 사용했다. 대상자당 구간은 1개 또는 2개이며 총 행 수는 구성에 따라 1만·1만5천·2만이다. 번들 R 4.5.3의 새 프로세스에서 모듈·설정 로딩 후 세 조건을 같은 순서로 측정했다. 프로파일러 없이 3쌍을 순차 실행하고 두 번째 쌍의 변형 순서를 뒤집었다. 비교 함수는 같은 전역 도우미 환경을 사용했다.

| 대상자 구성 | 변경 전 중앙값(초) | 변경 후 중앙값(초) | 감소율 |
| --- | ---: | ---: | ---: |
| 모두 단일 구간 | 0.28 | 0.16 | 약 43% |
| 단일/복수 구간 각 50% | 0.34 | 0.21 | 약 38% |
| 모두 복수 구간 | 0.52 | 0.41 | 약 21% |

| 최종 반복 | 모두 단일 전/후 | 혼합 전/후 | 모두 복수 전/후 |
| --- | --- | --- | --- |
| final1 | 0.28 / 0.16 | 0.35 / 0.21 | 0.53 / 0.42 |
| final2 | 0.30 / 0.15 | 0.34 / 0.23 | 0.52 / 0.41 |
| final3 | 0.28 / 0.16 | 0.34 / 0.21 | 0.52 / 0.40 |

초기 반복 1–3은 빈 이름 경계 처리 보완 전 후보의 측정이다. 최종 비교에는 `final1`–`final3`만 사용했다. 값은 입력 검증 전체 시간이며 Cox 적합, 일반 단일기록 분석이나 프로그램 시작 시간의 감소율이 아니다. 이전 개선율과 합산하지 않는다.

## 검증

- `scripts/validate_survival_subject_index.R`: 48개 입력 검증 사례의 전체 결과/오류, 조건 및 RNG 일치.
- `verify_intervals.R`: 단일/혼합/복수 구간, 잘못된·겹치는·뒤섞인 구간, 사건·공변량 결측 등 40개 추가 사례 일치.
- `verify_ids.R`: 빈 문자열·공백·앞자리 0·다국어·문자열 NA·결측·factor ID를 포함한 4개 사례에서 겹치는 구간의 전체 결과 또는 기존 오류 일치.
- 최종 대용량 9쌍의 전체 입력 검증 결과가 `identical(..., num.eq = FALSE)`로 일치했다.
- `verify_integrated.R`: 150명 혼합 구간 자료의 실제 start-stop Cox 분석에서 입력 검증, 모든 데이터프레임 결과, 회귀계수·분산·로그우도, 경고·메시지와 RNG가 정확히 동일했다.
- 전체 Cox 패널 HTML과 개별·누적 Excel이 동일했다. Excel은 모든 비-core 내부 파일의 바이트 일치와 core의 생성·수정 시각만 정규화한 일치를 확인했다.
- `git diff --check -- R/analysis_survival.R` 통과.

PDF/Word/HWPX 완성 파일과 설치 파일은 이번에 재생성하지 않았다.
