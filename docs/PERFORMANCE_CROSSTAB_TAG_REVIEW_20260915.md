# 교차분석 HTML 태그 중첩 후보 검토

## 결정

행 태그 생성 시 이름 없는 일반 리스트를 평탄화하는 후보는 적용하지 않았다. 12×12 교차표에서 빈도/백분율 분리 옵션을 켜면 기존 HTML과 머리글 인라인 정렬 스타일이 달라졌다. 출력 보존을 통과하지 못했으므로 속도 개선으로 보고하지 않는다. 제품 코드는 변경하지 않았다.

## 재현과 원인

`output/crosstab-tag-review-20260915/compare.R`는 같은 현재 UI 소스를 두 환경에 읽고, 후보 환경에서만 `tags$tr`를 감싸 일반 리스트 인자를 평탄화한다. 실제 태그 객체와 이름 있는 속성은 유지하며 HTML 문자열을 직접 조립하지 않는다. 셀당 8개 관측, 순서형 변수, 추세 및 세 백분율 옵션, 특수문자와 HTML 형태 문자열을 포함한 변수 라벨을 사용했다.

첫 12×12 비분리 조건은 비교를 통과했으나 분리 조건에서 중단됐다. 예정했던 40×40 조건과 전체 시간 비교는 완료되지 않았다. `mismatch.rds`, `reference.html`, `candidate.html`에 실패 조건을 저장했다.

`result_table_apply_contract()`의 내부 `center_headers()`는 태그가 아닌 입력을 바로 반환한다. 자식 리스트를 한 단계 순회하지만 그 아래의 일반 리스트를 재귀 순회하지는 않는다. 따라서 행 생성 단계에서 리스트 중첩을 제거하면 기존에 도달하지 않던 머리글에도 `text-align:center !important`가 붙는다. 표 구조의 단순 변경이 현재 스타일 처리 범위까지 바꾸는 경우다.

저장된 실패 조건을 `inspect.R`로 확인한 결과:

- 원본 HTML은 정확히 일치하지 않는다.
- 캡처한 경고/메시지, 표준 출력, 최종 RNG는 각각 정확히 일치한다.
- 해당 중앙 정렬 인라인 스타일 속성을 양쪽 문자열에서 제거하면 HTML 전체가 정확히 일치한다. 이는 차이의 위치를 진단한 것이며 출력 동일성 통과로 취급하지 않는다.

브라우저에서 실제 보이는 정렬 차이는 검사하지 않았다. 계산 코드를 바꾸지 않았으며 이번 실험은 수치 계산의 추가 검증도 아니다. 후보를 반영하지 않았으므로 새로운 내보내기 변경은 없다.
