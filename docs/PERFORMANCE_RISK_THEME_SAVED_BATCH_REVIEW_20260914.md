# KM 다중 그림 저장에서 테마 재사용 후보 검토 — 2026-09-14

## 결정

테마 재사용 후보를 실제 KM 저장용 그림과 HTML 콘텐츠 생성에 연결해 검증했다. 픽셀과 HTML이 동일하고 시간이 줄었지만, HTML 전체 절감은 중앙값 0.18초(약 2.2%)였다. 변경 가능한 테마 설정과 캐시 수명 처리를 추가하기 전에 더 큰 전체 저장 비용을 우선 조사하기로 하고 제품 적용은 보류했다. 후보 코드는 output 폴더에만 있다.

## 후보 범위

저장된 기존 KM 분석 객체를 사용했다. 분석은 다시 실행하지 않았다. 생존확률·누적사건확률·누적위험·로그생존의 4종과 색상·흑백 2종으로 총 8개 그림을 만들었다.

`survival_saved_plot_specs()` 복사본의 환경에만 KM 위험집단 표 생성 함수와 테마 재사용 함수를 연결했다. 후보마다 새 지역 캐시를 생성하고 첫 그림에서 기본 크기 10의 테마를 만들었다. 제품 함수나 설치 패키지는 변경하지 않았다.

번들 R 4.5.3, JIT 3, 기존 모듈 캐시를 사용했다. 기준/후보 각각 새 프로세스 3개를 순차 실행하고 두 번째 쌍은 후보부터 실행했다. 그림 함수 내부의 기존 JIT 제어를 유지했다. 저장된 survfit 객체의 S3 메서드를 사용하도록 survival 네임스페이스를 측정 전에 로드했다. 최초 탐색에서는 이 등록이 빠져 기준·후보 모두 오류로 중단됐으며, 실패 실행은 최종 수치에서 제외했다.

## 측정

| --- | --- | --- | --- |
| 저장용 그림 8개 구성·PNG 출력 | 2.42 / 2.44 / 2.41 | 2.27 / 2.28 / 2.28 | 2.42 → 2.28, 약 5.8% |
| 8개 그림 포함 HTML 콘텐츠 생성 | 8.32 / 8.42 / 8.35 | 8.17 / 8.17 / 8.17 | 8.35 → 8.17, 약 2.2% |

HTML 측정은 `survival_saved_results_content()`의 결과 패널 생성, 그림 렌더링, base64 변환과 HTML 삽입을 포함한다. 외부 문서 래퍼, PDF/Word/HWPX 변환, 앱 기동과 분석 계산은 포함하지 않는다. PNG 직접 출력 실험과 HTML 실험은 별도 프로세스·출력 설정이므로 두 시간을 빼서 특정 하위 단계 비용이라고 단정하지 않는다.

이전 객체 100개 구성 실험의 약 80% 개선은 실제 저장 전체의 개선률이 아니었다. 이번 결과는 그것을 실제 사용 흐름에서 제한적으로 확인한 것이다. 단일 그림의 최초 테마 생성 비용은 재사용으로 없어지지 않는다.

## 동일성 확인

- 실제 저장용 그림 8개 × 3쌍, 총 24쌍의 크기와 RGBA 픽셀이 정확히 동일했다.
- 각 그림의 ID·제목·크기, 경고·메시지와 난수 상태가 3쌍 모두 동일했다.
- 그림을 포함한 HTML 문자열, 경고·메시지와 난수 상태가 3쌍 모두 `identical(..., num.eq=FALSE)`로 일치했다. HTML에 포함된 이미지 데이터도 이 비교에 포함된다.
- 한 작업 도중 전역 테마나 확장 테마 요소를 변경하는 경우는 검증하지 않았다. 일반적인 영구 캐시의 안전성을 입증하는 실험이 아니다.
- 제품 `R/result_survival_ui.R` SHA256은 `4D08F58364B94CF9C3079EFE5FB9EC499D9DC58137678EA36F0F85F9A9002E55`로 동일하다.

제품에 적용하지 않았으므로 현재/누적 PDF·Word·HWPX·Excel 변환 및 설치 파일 빌드는 실행하지 않았다. 이들 출력 검증을 완료한 제품 변경으로 취급하면 안 된다.

## 재현과 후속 우선순위

`output/risk-theme-saved-batch-20260914/`에 `measure.R`, `html.R`, `compare.R`, `compare_pixels.py`, 기준/후보 PNG·HTML·RDS·CSV를 저장했다. HTML 하네스 CSV의 `plots=0`은 직접 PNG 출력 루프를 비활성화한 자리표시 값이며 HTML의 그림 수를 의미하지 않는다. HTML 경로의 입력은 동일한 8개 그림 설정이다.

다음은 전체 HTML 콘텐츠 생성 시간을 패널 생성, 실제 그림 출력 및 HTML 삽입으로 직접 나누는 것이다. 작은 테마 캐시를 먼저 제품에 추가하기보다 실제 큰 구간에 개선 작업을 집중한다.
