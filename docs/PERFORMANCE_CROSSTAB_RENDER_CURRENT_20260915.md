# 교차분석 현재 HTML 생성 단계 측정

2026-09-15. 네 가지 수치/표 생성 개선 이후의 현재 결과 UI 객체 생성과 HTML 문자열 변환을 분리 측정했다. 제품 코드는 변경하지 않았다.

## 조건 및 결과

번들 R 4.5.3, 영어 UI, 각 셀에 8명인 4×4·12×12·40×40 순서형 교차표다. 추세와 행/열/전체 백분율을 모두 켰다. 각 자료의 분석 결과를 먼저 한 번 계산한 뒤 재사용한다. 40×40은 12,800행이다.

독립 R 프로세스 3개를 순차 실행했다. 조건마다 UI+renderTags 준비 호출 후, UI 객체 생성(`crosstab_results_ui`), 이미 만들어진 객체의 HTML 문자열 변환(`htmltools::renderTags`), 저장용 HTML 생성(`saved_crosstab_results_html`)을 각각 3회 측정했다. 저장용 HTML 생성은 UI 및 문서 래퍼를 다시 만드는 별도 경로이며 앞의 두 단계에 추가되는 독립 비용으로 합산하면 안 된다.

|40×40 단계|프로세스별 중앙값 1/2/3(초)|
|---|---|
|UI 객체 생성|0.12 / 0.12 / 0.12|
|HTML 문자열 변환|0.21 / 0.23 / 0.22|
|저장용 HTML 생성 전체|0.38 / 0.36 / 0.37|

4×4와 12×12의 자세한 시간은 CSV에 기록했다. 4×4의 작은 0.00~0.02초 수치는 정밀한 단계 차이로 해석하지 않는다. 실제 브라우저의 DOM 삽입/레이아웃/그리기, Shiny 전송, 앱 시작 및 파일 쓰기는 포함하지 않는다. 최초 사용자 호출의 cold-start 측정도 아니다.

각 프로세스/조건에서 반복 생성한 화면 HTML 문자열이 해당 프로세스의 준비 결과와 정확히 일치했다. 저장용 HTML은 생성 시간만 측정했고 이번에 반복 내용 비교를 추가하지 않았다. 원시 수치·전체 내부 태그 객체·진단/RNG 또는 프로세스 간 HTML 동일성을 새로 검증한 것은 아니다. 기존 통합 수치 및 저장 내용 검증을 대체하지 않는다.

## 별도 프로파일 및 다음 후보

첫 프로세스의 40×40 UI+HTML 생성 5회만 별도로 Rprof 0.005초 간격으로 측정했다. 총 표본 시간은 0.65초다. UI 인자를 평가하는 시간도 renderTags 포함 스택에 잡히므로 문자열 변환만의 프로파일로 해석하지 않는다.

포함 스택 비중은 rewriteTags 약 58%, tagify 약 44%, tagWrite 약 34%였다. 이는 중첩되므로 더하지 않는다. 이미 개선한 수치 계산과 달리 결과 태그 구성/정리/문자열 직렬화가 다음 검토 대상이다. 내부 htmltools 단계를 임의로 건너뛰거나 텍스트 escaping을 생략하는 변경은 하지 않았다. 제한된 프로파일 표본만으로 특정 함수 대체의 안전성이나 개선율을 확정하지 않는다.

초기 연구 스크립트는 전역 변수 `tags`가 Shiny의 태그 생성기를 가려 저장 HTML 생성에서 중단됐다. 연구 변수명을 `tag_tree`로 바꾸고 세 프로세스를 새로 실행했다. 최종 로그/CSV는 이 수정 후 실행 결과이며 제품 결함으로 보고하지 않는다.

증거: `output/crosstab-render-current-20260915/measure.R`, `run-1/2/3.log`, 각 `run-*/times.csv`, `run-1/render.Rprof`, `run-1/by-total.csv`, `run-1/by-self.csv`. 제품·출력 형식 변경이 없어 내보내기 전 형식 검사와 설치 파일 빌드는 실행하지 않았다.
