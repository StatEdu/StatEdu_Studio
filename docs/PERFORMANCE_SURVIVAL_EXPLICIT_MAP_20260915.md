# 생존분석 명시적 사건 매핑 전처리 개선

`survival_normalize_event_map`에서 반환에 쓰지 않는 관측 코드 목록의 생성만 생략했다. 조건은 속성 없는 integer/double 사건 벡터, 클래스가 정확히 data.frame인 매핑, raw_value/role 열의 존재이다. 문자/factor/날짜/특수 클래스, 자동 매핑, 불완전한 매핑은 기존 관측 코드 계산을 유지한다. 사건 관심값 변환, 매핑 열 정리, 중복/미매핑 검사와 제외 사유는 그대로다.

## 정확성

- `scripts/validate_survival_explicit_map.R`: 직접 helper 294개 조건 및 전체 전처리 36개 조건 비교 통과. 정수/실수/NA/NaN/Inf/극소·극대값, 이름·차원·특수 클래스, 문자/factor/날짜/list/logical/raw/complex, 잘못된 매핑·중복·누락, 관심값 오류와 경고/메시지/난수를 발생시키는 변환 메서드를 포함한다. 단일 기록·지연 진입·시작–종료 구조 및 결측/음수 시간도 포함한다.
- `scripts/benchmark_survival_explicit_preflight.R`: 독립 프로세스마다 성공 결과와 분석 행 수 확인, 전체 전처리 76개 비교 통과. 자동/명시적 매핑 × 1,000/100,000행.
- `scripts/benchmark_survival_explicit_map.R`: 20,000행 명시적 매핑의 Cox 기본·층화·군집·스플라인 모형이 성공하고 유한 계수를 반환했다. 프로세스마다 전체 결과 44개와 보조 전처리 5개 비교 통과.
- 비교는 `identical(..., num.eq=FALSE)`로 전체 값/속성, 진단·stdout·RNG를 확인했다. Cox만 call 내부를 포함한 수식 `.Environment` 속성을 제외한다. 수치 허용오차를 늘리지 않았다.
- 기존 `validate_survival_preflight.R`는 실제 앱 bootstrap·모듈·환경설정 초기화 후 실행하여 통과했다. 기존 생존분석/경쟁위험/매핑/범위 검사를 포함한다.

## 성능

번들 R 4.5.3와 앱 초기 환경설정. 양쪽 모듈의 함수 컴파일, 동일 자료와 난수 시드. 두 독립 프로세스, 기존/변경 번갈아 실행. 전처리는 준비 후 9회 중앙값, Cox는 준비 후 5회 중앙값이다. 진단/stdout 수집을 포함하며 비교·Cox 환경 정규화 비용은 제외했다.

| 전처리 조건 | 실행 1 기존→변경(ms) | 실행 2 기존→변경(ms) |
|---|---:|---:|
| 명시적 매핑 100,000행 | 68.49 → 53.92 | 69.73 → 53.52 |
| 명시적 매핑 1,000행 | 3.18 → 2.68 | 3.25 → 2.90 |
| 자동 매핑 100,000행 | 52.96 → 52.37 | 53.19 → 53.62 |
| 자동 매핑 1,000행 | 2.53 → 2.60 | 2.45 → 2.64 |

명시적 매핑 100,000행 전처리는 약 21~23% 단축했다. 자동 매핑에는 개선 효과를 주장하지 않는다. 작은 자동 매핑에서는 약 0.07~0.19ms 증가가 측정됐다.

| 전체 Cox 옵션 | 실행 1 기존→변경(ms) | 실행 2 기존→변경(ms) |
|---|---:|---:|
| 기본 | 199.20 → 196.30 | 197.14 → 193.55 |
| 층화 | 203.40 → 193.77 | 199.37 → 205.69 |
| 군집 | 239.73 → 220.51 | 222.23 → 219.83 |
| 스플라인 | 302.71 → 297.80 | 298.31 → 281.27 |

전체 Cox 개선 폭은 작고 층화는 실행별 방향이 달랐다. 따라서 전처리 단축률을 전체 Cox, 앱 로딩, 렌더링·내보내기 효과로 확대하지 않는다. 분석 수식과 출력은 변경하지 않았고 모든 형식의 현재/누적 내보내기를 새로 검사한 것은 아니다.
