# 상관분석 최적화 이후 재측정 — 2026-09-14

## 범위와 결과

기존 순위 재사용 및 고유 범주 변환을 적용한 현재 상관분석을 다시 측정했다. 이번 작업은 진단이며 제품 코드는 변경하지 않았다. 순서형 상관은 확률 계산 경로가 주된 비용이고, Spearman에서는 같은 입력의 고유값 검사가 반복되는 것을 확인했다.

번들 R 4.5.3에서 10,000행·20변수(190쌍), 시드 33으로 실행했다. 순서형 자료는 세 범주이며 결측 조건은 각 변수에 서로 다른 무작위 결측 10%를 넣었다. 정규성 검사를 켜고 순서형 조건에서 잠재상관을 사용했다. 입력 생성, 프로그램 로딩, 화면 및 저장 시간은 포함하지 않는다.

## 현재 실행 시간

새 R 프로세스 세 개를 순차 실행했다. 각 프로세스에서 조건별로 준비 실행, 프로파일러 없는 시간 측정, 별도 프로파일링을 수행했다. 변경 전후 비교가 아니므로 아래 수치는 추가 개선율을 의미하지 않는다.

| 조건 | 3회 실행 시간(초) | 중앙값(초) |
| --- | --- | --- |
| Pearson | 0.14 / 0.13 / 0.12 | 0.13 |
| Spearman | 0.23 / 0.19 / 0.17 | 0.19 |
| 순서형 잠재상관 | 3.14 / 3.03 / 2.98 | 3.03 |
| 순서형 잠재상관, 결측 10% | 3.34 / 2.92 / 2.97 | 2.97 |

각 조건에서 준비 실행·시간 측정·프로파일링의 전체 결과, 경고/메시지, 표준 출력, 난수 상태가 `identical(..., num.eq=FALSE)`로 일치했다.

순서형 조건에서 `cached_pmvnorm` 아래 실행 경로가 프로파일 표본의 약 81~85%를 차지했다. 여기에는 내부 확률 계산과 인자 검사가 포함된다. 이는 캐시 자체의 비용을 뜻하지 않으며, 중첩된 누적 비율을 더하거나 벽시계 실행 시간 비율로 해석하면 안 된다. 기존 범주 변환 최적화를 다시 적용할 여지는 없었다.

## Spearman 고유값 검사 감사

기존 순위 캐시는 유지하고 `cor.test.default`의 고유값 검사에 기록용 래퍼를 넣었다. 래퍼는 입력을 기록한 뒤 원래 `base::unique`를 그대로 실행한다. 별도의 완전 자료, 반올림 동률 자료, 변수별 결측 자료를 각각 10,000행·20변수로 검사했다.

| 조건 | 고유값 검사 호출 | 서로 다른 입력 |
| --- | ---: | ---: |
| 완전 자료 | 380 | 20 |
| 동률 자료 | 380 | 20 |
| 변수별 결측 10% | 380 | 380 |

기록용 래퍼 적용 전후의 전체 결과·경고/메시지·표준 출력·난수 상태는 정확히 일치했다. 고유값 검사 결과를 재사용하는 기능은 아직 구현하지 않았다.

다음 후보는 기존 분석 단위 순위 캐시와 함께 고유값 검사 결과를 제한적으로 재사용하는 것이다. 완전 자료와 동률 자료에서는 재사용 여지가 있지만, 변수마다 결측 위치가 다르면 입력이 모두 달라 캐시 탐색·보관 비용만 늘 수 있다. 수치 및 조건 발생 동작의 동일성과 결측 조건의 시간·메모리 회귀를 검증한 뒤 적용 여부를 결정해야 한다. 현재 Spearman 총시간이 짧아 표본 수가 적으므로 고유값 검사만의 정밀한 비용 비율이나 예상 개선율은 제시하지 않는다.
