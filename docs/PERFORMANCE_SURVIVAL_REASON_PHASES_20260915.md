# 생존분석 제외 사유 기록 비용 분리

제품 코드는 변경하지 않았다. `survival_preflight`의 지역 함수 `add_reason`을 별도 메모리 사본에서 계측해 조건 인자 평가, 행 인덱스 구성, 사유 목록 갱신 시간을 나누었다. 이전 Rprof에서 `add_reason` 경로에 포함되던 문자열 처리 등 지연 평가 비용을 실제 기록 비용과 구분하는 작업이다.

## 방법과 검증

`scripts/profile_survival_reason_phases.R`는 현재 모듈 두 사본을 읽고 한쪽의 지역 함수만 AST로 교체한다. 먼저 mask를 평가한 다음 원래의 `which(!is.na(mask) & mask)`와 `unique(c(reasons[[index]], code))` 반복문을 그대로 실행한다. 반환 결과에 계측 정보를 넣지 않으며 제품 파일을 수정하지 않는다.

번들 R 4.5.3, 실제 앱 모듈·환경설정 초기화, 동일 시드, 공변량 6개, 집단 3수준, 사건 확률 0.7. 20,000/100,000행 × 아래 3조건을 두 독립 프로세스에서 반대 순서로 실행했다.

- complete: 결측 없음.
- sparse: 사건 5%, 집단 5%가 서로 다른 행에 결측. 분석 행 90%.
- overlap: 동일한 50% 행에 사건·집단·공변량 6개 모두 결측. 분석 행 50%.

원래 함수는 준비 후 5회 전체 시간을 측정했다. 계측 사본은 준비 후 3회 각 단계 시간을 측정했다. 두 함수의 성공 결과·분석 행 수를 확인하고, 프로세스마다 준비/반복 결과 54개를 `identical(..., num.eq=FALSE)`로 비교했다. 전체 반환값·속성·진단·stdout·RNG가 일치했다. 두 프로세스의 저장 결과 6쌍도 정확히 일치했다. 환경 속성 정규화나 수치 허용오차는 사용하지 않았다.

단계 시간은 계측 사본의 별도 실행이며 시계 호출과 계측에 따른 실행 비용 변화가 포함된다. 따라서 원래 함수의 전체 시간으로 나누어 정확한 비중이나 예상 개선율을 계산하지 않는다. 특히 겹친 결측의 계측 기록 시간은 별도 측정한 원래 전체 시간보다 클 수 있다.

## 원래 전체 전처리 시간

각 칸은 독립 실행 1 / 2의 중앙값(ms).

| 조건 | 20,000행 | 100,000행 |
|---|---:|---:|
| complete | 9.11 / 12.84 | 42.25 / 55.45 |
| sparse | 21.42 / 20.80 | 97.45 / 102.12 |
| overlap | 289.20 / 289.80 | 1,548.55 / 1,521.78 |

## 100,000행 단계별 합계

각 반복에서 모든 add_reason 호출의 단계 시간을 합한 뒤 3회 중앙값을 구했다. 단위 ms, 독립 실행 1 / 2.

| 조건 | 조건 인자 평가 | 인덱스 구성 | 사유 목록 갱신 |
|---|---:|---:|---:|
| complete | 13.41 / 17.12 | 6.38 / 1.99 | 0.023 / 0.040 |
| sparse | 15.26 / 16.66 | 6.32 / 6.24 | 31.62 / 30.90 |
| overlap | 10.54 / 10.43 | 2.81 / 2.85 | 1,646.59 / 1,532.09 |

결측이 없는 조건의 사유 목록 갱신 시간은 극히 작아 해상도와 계측 오버헤드의 영향을 받는다. 겹친 결측에서는 실제 목록 갱신이 주요 병목으로 확인됐다.

overlap 조건의 missing_covariate는 공변량 6개마다 같은 50,000행을 처리해 총 300,000회 갱신한다. 이 코드의 기록 시간 합 중앙값은 1.286 / 1.201초였다. 사건 사유 50,000회는 0.169 / 0.158초, 집단 사유 50,000회는 0.192 / 0.172초였다. 최종 제외 문자열은 이미 `unique`로 중복이 제거된다. 즉 결과에서 필요한 missing_covariate는 행당 한 번이지만 내부에서는 같은 사유를 반복 처리한다.
