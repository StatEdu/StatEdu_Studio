# 복합표본 회귀 계수 요약의 계산 생략 후보 검토

2026-09-15. 직전 프로파일에서 계수 원시 표 생성이 약 19~24%를 차지하여 번들 survey의 `summary.svyglm` 구현을 조사했다. 제품에는 반영하지 않았다.

## 확인된 계산

기존 `complex_sample_svyglm_raw_table`은 `summary(fit)$coefficients`만 사용한다. 번들 요약 함수는 먼저 Pearson 잔차의 조사설계 기반 분산을 `svyvar`로 계산하고, deviance 잔차 등을 반환 객체에 추가한다. 계수 표 자체는 기존 coef/vcov, 표준오차, t 통계량 및 잔여 자유도에 따른 p값으로 만든다. 이 버전에서 계산된 dispersion은 계수 표 계산에 사용되지 않는다.

연구용 후보는 기존 원시 표 함수의 로컬 복사본에서만 summary를 계수 전용 함수로 대체했다. 제품 및 survey namespace는 수정하지 않았다. 번들 요약의 연산 순서와 df <= 0에서 NaN을 채우는 분기는 유지했다.

## 결과

완전자료 10,000행, 200 PSU, 10층, 양의 불균등 가중치에서 Gaussian, quasibinomial, quasipoisson, Gamma 및 하위모집단 적합을 검사했다. 추가로 단일 PSU 층이 있는 적합을 adjust 정책에서 검사했다. 여섯 조건의 원시 계수 표 전체(Estimate/SE/Statistic/p 및 속성), 진단 클래스·본문·순서, 표준 출력 및 최종 RNG가 `identical(..., num.eq=FALSE)`로 정확히 일치했다. 전체 svyglm 객체 또는 전체 앱 결과 비교는 아니다.

그러나 adjust 정책에서 적합한 단일 PSU 모형에 대해 요약 전에 정책을 fail로 변경하면 기준은 `Stratum (1) has only one PSU at stage 1` 오류를 냈고 후보는 표를 반환했다. 이 조건은 요약 경계 검증이며 앱의 정상적인 한 번 분석 흐름에서 같은 정책 변경이 일어난다는 주장은 아니다. 무조건 대체하면 기준의 오류 동작을 보존하지 못한다는 증거다.

Gaussian 적합 객체 하나를 대상으로 각 함수에 compiler::cmpfun을 적용하고 준비 호출 후, 한 프로세스에서 50회 블록을 세 번 순차 측정했다. 두 번째 블록은 순서를 바꿨다. 기준은 호출당 0.0210 / 0.0246 / 0.0208초, 후보는 0.0000 / 0.0004 / 0.0004초였다. 0.0000은 타이머 분해능 아래의 관측값이며 계산 비용이 없다는 뜻이 아니다. 앱 전체 실행이나 독립 프로세스 반복 성능 비교는 수행하지 않았다.

## 판단

계수와 무관한 계산을 생략할 여지는 있지만, 이 후보는 오류 보존 요건을 충족하지 못해 미반영이다. 다음 구현 검토에는 survey 버전/메서드 확인 및 지원 조사설계·PSU·분산 조건의 명시적 제한, 미지원 조건에서 기존 summary로 복귀하는 경로가 필요하다. 경계 조건을 단순히 검사에서 제외하거나 오류를 숨기는 방식은 사용하지 않는다. 복제 가중치, 사용자 정의 메서드 및 전수 경계 검증은 아직 수행하지 않았다.

제품 파일 `R/setup_complex_sample_ui.R`은 이번에 편집하지 않았다. 작업 종료 시 SHA256은 `2DDEDF6A46A822053E8F6D57FD083C0E783C47033579E9A2645CFA93D40B8D15`이며 기존 작업 트리의 수정 상태를 유지했다. 출력 제품 코드 변경이 없어 전체 내보내기와 빌드는 실행하지 않았다.
