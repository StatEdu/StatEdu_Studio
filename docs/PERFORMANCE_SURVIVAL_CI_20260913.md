# 보정 생존곡선 신뢰구간 집계 — 2026-09-13

`survival_adjusted_curve()`에서 부트스트랩 표본의 하한·상한을 별도 `apply(..., quantile)` 호출로 구하던 부분을 하나의 호출로 통합했다. 동일한 표본, `stats::quantile` 기본 방식, 결측 처리, .025/.975 확률을 유지한다. 재표집, Cox 적합, 생존확률 계산, 표본 성공 기준, 대비 계산, 난수 복구는 변경하지 않았다.

## 측정

동봉 R 4.5.3, 변경 전후 실행 순서를 교대로 5회 측정한 중앙값.

| 범위 | 변경 전 | 변경 후 |
|---|---:|---:|
| 2,000회 표본 × 1,000시점의 신뢰구간 집계 | 0.11초 | 0.06초 |
| 90행·3집단·50회 재표집 보정 생존곡선 전체 | 0.27초 | 0.25초 |

집계 단계는 약 45% 줄었으나 전체 작은 사례의 절감량은 0.02초다. 모든 생존분석이나 프로그램 로딩이 45% 빨라졌다는 의미는 아니다. 로딩 경로도 재검토했지만 이번에는 로딩 코드를 수정하지 않았다.

## 검증

- `scripts/validate_survival_ci_reuse.R`: 150개 비교에서 반환값·속성·경고·메시지·오류·난수 상태가 `identical(..., num.eq=FALSE)`로 정확히 일치했다.
- 분위수 비교는 1/2/20/39/40/41/1,999/2,000개 표본, 1/3/10열, 임의 값·동률·상수·일부 결측·전체 결측·무한대를 포함했다.
- 변경 직전 파일과 전체 보정곡선을 비교했다. 재표집 0/5/25회, 기존 난수 상태의 유무를 확인했고, 충분한 성공 표본에서 신뢰구간이 실제 생성되는지도 검사했다. 선택 시점·집단 대비·성공 표본 정보 등 전체 반환 객체를 비교했다.
- `git diff --check` 통과.
- `validate_survival_complex_screen_table_contract.R`는 `Note.` 접두사를 기대하는 오래된 주석 검사에서 중단됐다. 변경 전 분석 파일로 동일 실패를 재현했다. 현재 AGENTS.md는 그 접두사를 사용하지 않도록 규정한다. 이 검사를 통과로 처리하지 않았다.
- `validate_survival_preflight.R`는 보정 생존곡선을 포함한 분석 검사를 진행한 뒤 저장 HTML에서 `analysis_save_edition()` 누락으로 중단됐다. 변경 전 분석 파일에서도 같은 실패를 재현했다. 전체 검사 통과로 간주하지 않는다.

표시·저장 내용 구성은 변경하지 않았다. 모든 입력에 대한 불변 증명은 아니며 위 시험 범위의 정확 일치 검증이다. 설치 파일은 재빌드하지 않았다.
