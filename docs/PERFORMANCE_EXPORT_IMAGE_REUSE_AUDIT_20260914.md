# 결과 저장 경로의 그림 재사용 점검 — 2026-09-14

## 결론

회귀·계층적 회귀, 상관, 빈도, ANCOVA, 요인분석, PCA의 문서 저장 경로에는 이미 세션별 그림 캐시가 연결되어 있다. 누적 결과 HTML도 저장된 그림을 재사용한다. 이번 점검에서는 제품 코드를 수정하지 않았다.

생존분석 개별 저장은 그림을 다시 생성하지만, 기존 캐시를 그대로 연결하는 후보는 효과가 없었다. KM 그림의 좌표계 변경 안내 메시지 때문에 기존 캐시의 저장 조건을 충족하지 못한다. 메시지를 임의로 없애거나 캐시의 조건 보존 정책을 완화하지 않았다.

## 코드 확인

- `server_analysis.R`: 회귀·계층적 회귀 저장에 `export_images$render` 연결.
- `server_correlation.R`, `server_frequencies.R`, `server_ancova.R`, `server_factor_analysis.R`, `server_pca.R`: 개별 HTML/PDF/Excel 저장 경로에서 기존 그림 캐시 전달.
- `server_survival.R`: 개별 저장 및 생존분석 결과 추가의 HTML 생성 경로는 `saved_survival_results_html()` 계열을 호출한다.
- `saved_result_collection_html()`은 누적된 항목의 HTML 콘텐츠를 사용한다.

`correlation_export_image_cache()`는 그림 함수·결과·크기·해상도·환경 설정 등을 키로 사용하고, 경고·메시지가 없으며 난수 상태가 바뀌지 않은 결과만 저장한다. 메모리·항목 수 상한도 적용되어 있다.

## 생존분석 캐시 적용 가능성 실험

번들 R 4.5.3에서 기존 KM 객체, 동일한 그림 함수와 입력으로 기존 캐시를 두 번 호출했다. 초기화에 따른 context 변화가 실험을 혼동시키지 않도록 **실험에서만** context를 NULL로 고정하고 메모리 상한을 64MiB로 설정했다. 제품 캐시 설정은 변경하지 않았다.

결과:

- 실제 렌더러 호출 횟수는 첫 호출 후 1회, 두 번째 호출 후 2회였다.
- 두 번의 PNG 데이터 URI, 메시지와 난수 상태는 정확히 동일했다.
- 두 번 모두 기존 좌표계 교체 안내 메시지가 발생했다. 따라서 같은 입력·안정적인 함수·고정 context에서도 `quiet` 조건 때문에 캐시에 저장되지 않았다.
- 경과 시간은 1.23초와 0.92초였지만 두 번째도 실제 렌더링했다. 이 차이는 캐시 적중에 따른 개선이 아니다. 속도 비교용 반복 실험이 아니라 분기 동작 확인이다.

이 결과는 모든 생존분석 그림이 캐시에 들어갈 수 없다는 의미가 아니다. 이번 KM 곡선·위험집단 표 조합에 대한 확인이다.

## 누적 결과 재사용 검증

각각 8개 그림이 포함된 기존 KM HTML 스냅샷 2개를 누적 결과로 저장했다. `plot_data_uri`, `survival_saved_results_content`, `prepare_km_analysis_result`를 호출하면 오류를 내는 대역으로 바꿔 불필요한 재생성 여부를 검사했다.

누적 HTML 생성은 성공했으며, 최종 16개 이미지 URI가 입력 스냅샷의 URI와 순서까지 정확히 동일했다. 따라서 이 검사 범위에서 누적 결과 저장은 분석과 그림을 다시 실행하지 않는다. PDF·Word·HWPX 변환 전체를 이번에 실행한 검사는 아니다.

## 후속 판단

동일 그림 재생성 감소를 위해 이미 작동하는 누적 스냅샷 흐름을 다시 구현할 필요는 없다. 생존분석 개별 저장에 캐시를 추가하려면 그림 명세의 안정적인 키, 설정 변경, 메시지 전달 정책 및 실제 화면 스냅샷과의 관계를 먼저 설계해야 한다. 단순한 기존 캐시 연결만으로 성능 개선을 주장하지 않는다.

제품·출력 내용 변경이 없어 내보내기 전 형식 변환과 설치 파일 빌드는 실행하지 않았다. 재현 자료는 `output/survival-image-cache-audit-20260914/`의 `verify.R`, `collection.R`, `captures.rds`, `conditions.txt`, `collection.html`이다.
