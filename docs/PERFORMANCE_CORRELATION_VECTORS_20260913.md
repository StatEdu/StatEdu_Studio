# 상관분석 변수 변환 재사용 — 2026-09-13

## 변경

`R/analysis_correlation.R`에서 사전 검사에 사용한 변수별 숫자 변환·범주 코딩 값을 같은 분석의 변수 쌍 계산에 재사용한다. 일반 상관과 잠재상관 경로 모두 적용한다. 공개 쌍 계산 함수는 기존 호출을 그대로 지원하며, 준비된 값이 없으면 이전처럼 변환한다.

변환이 경고나 메시지를 내면 그 변수는 재사용하지 않는다. 기존 쌍마다 발생하던 진단 횟수와 내용이 유지된다. 사전 검사에서 제외된 변수는 캐시에서도 제외한다. 다음 분석에는 이전 값을 전달하지 않는다. 정규성 검사, 쌍별 결측 제거, 검정과 신뢰구간 계산, 출력 구성은 유지했다.

정상적인 p개 변수의 사전 검사·쌍 계산 변환 횟수는 p²회에서 p회로 줄어든다. 별도 정규성 검사의 변환은 이 횟수에 포함하지 않는다. 분석 실행 동안 변환 벡터들을 보관하므로 메모리 사용량과 속도를 맞바꾸는 변경이다. 최종 결과에 캐시는 포함하지 않는다.

## 측정

동봉 R 4.5.3에서 2,000행·20변수, 정규성 검사를 끈 수동 Pearson 설정으로 `prepare_correlation_results()` 전체 시간을 측정했다. 측정 순서를 교대로 5회 실행한 중앙값이다. 이분형·순서형 변수에는 기존의 측정 수준별 방법 선택이 그대로 적용된다.

| 자료 | 변경 전 | 변경 후 | 시간 감소 |
|---|---:|---:|---:|
| 연속형 | 1.85초 | 1.81초 | 약 2% |
| 이분형 문자열 | 1.92초 | 1.78초 | 약 7% |
| 순서형 문자열 | 2.21초 | 1.96초 | 약 11% |

범주 코딩을 반복하던 자료에서 개선이 더 컸다. 연속형의 작은 차이는 측정 변동을 고려해야 한다. 앱 로딩이나 모든 분석의 개선율을 의미하지 않는다. 이전 사전 검사 중복 제거가 이미 반영된 파일을 기준으로 비교했다.

## 검증

- `scripts/validate_correlation_vector_reuse.R`: 변경 직전 실제 파일과 44개 전체 결과·속성·경고·메시지·오류·난수 상태 비교가 `identical(..., num.eq=FALSE)`로 통과했다. 연속형, 문자열 순서형과 사용자 지정 범주 순서, 이분형, 명목형, 결측, 공백, 상수, 숫자 문자열, 요인형 입력과 자동/Pearson/Spearman/Kendall 및 잠재상관 설정을 포함한다.
- 변수 3개에서 변환 9→3회 확인. 한 변수에서 경고·메시지를 주입하면 5회로 실행되며 원래의 진단 3회씩을 보존한다.
- `validate_correlation_auto.R`: 자동 방법 선택과 잠재상관 추론 검증 통과.
- 관측상관·잠재상관 각각 화면 HTML과 저장 HTML의 정확 일치, Excel 시트 이름과 모든 시트 내용 일치 확인.
- `git diff --check` 통과.

표시·저장 결과 구성은 변경하지 않았다. 위 검증은 명시한 범위의 정확 일치이며 모든 입력에 대한 불변 증명은 아니다. 설치 파일은 재빌드하지 않았다.

재현 자료: `output/correlation-vector-performance-20260913/`의 `baseline.R`, `benchmark.R`, `benchmark.csv`, `session.txt`, `verify-display.R`, 변경 전후 HTML·Excel 파일. 독립 반복 검증은 `scripts/validate_correlation_vector_reuse.R`로 실행한다. 선택적으로 첫 번째 인수에 이전 소스 파일을 지정하면 그 파일을 기준으로 비교한다.

## 후속 측정: 앱 설정 적용 상태

후속 프로파일링에서 위 독립 실행은 `statedu_apply_preferences()`를 호출하지 않아 출력 형식을 조회할 때 저장 설정 파일을 반복 읽는 비용을 포함했음을 확인했다. 실제 앱은 `app_server.R`에서 세션 설정을 적용한다. 앞의 수치는 독립 실행 조건의 측정이며 앱 세션 성능으로 일반화하면 안 된다.

앱처럼 설정을 적용한 2,000행·20변수 자료의 교대 5회 중앙값은 연속형 0.14→0.13초, 이분형 0.26→0.11초, 순서형 0.39→0.16초였다. 이 비교는 변수 변환 최적화 직전 파일과 비교하며, 후속 방법명 변환 최적화 적용 전이다. 새 합성 자료를 사용했으므로 앞 표와 시간 차이를 전부 설정 효과로 해석하지 않는다. 결과 객체도 정확 일치를 확인했다.
