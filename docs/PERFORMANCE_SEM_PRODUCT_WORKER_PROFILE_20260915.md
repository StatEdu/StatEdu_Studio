# 전체 조합 제품지표 SEM 작업자 내부 프로파일

2026-09-15. 제품 변경 없음. 직전 5,000회 실제 작업에서 약 203초였던 재표집 구간의 후속으로, 동일한 전체 조합 DMC fixture를 200회로 제한해 작업자 내부를 계측했다. 모형 최적화와 계수 공분산/Hessian 계산이 큰 구간으로 반복 관측됐다.

## 범위와 실행

240행·관측 지표 9개·잠재변수 3개·제품지표 9개인 기존 `stable_all_pairs_dmc` fixture, ML/FIML, `std_lv=FALSE`, bias-corrected CI, seed 20260833, 작업자 4개, 청크 100개다. 원모형의 수렴·허용 가능 여부와 제품지표 수를 확인했다. 번들 Windows R 4.5.3과 번들 라이브러리를 부모·자식에 사용했다.

실제 `structural_canvas_effect_bootstrap_fixed_index_worker`의 메모리 사본에 블록별 Rprof 시작/종료만 추가했다. 제품 파일이나 추정 코드는 변경하지 않았다. 10ms 표본 간격으로 screen/full 블록을 구분해 저장했다. 세 독립 부모 프로세스에서 원본/계측을 순차 실행했고 두 번째 프로세스에서는 순서를 뒤집었다.

직접 준비된 엔진을 isolated-worker 설정에서 실행하므로 이전 실제 백그라운드 작업의 시작·파일 I/O·UI 시간 측정과 범위가 다르다. 이번에는 표본 원계수까지 비교하려고 `return_draws=TRUE`를 사용했다. 제품 기본 반환 설정이나 반복 수를 변경한 것이 아니다. 200회 표본의 구성비를 5,000회 전체의 정확한 구성비로 환산하지 않는다.

## 포함 스택 비중

블록별 표본 시간을 먼저 합산하고 전체 작업자 표본 시간으로 나눴다. 표본 시간 합계는 21.42/21.37/22.11초로, 사용자 대기시간이 아니다.

| 함수/구간 | 실행 1 | 실행 2 | 실행 3 |
|---|---:|---:|---:|
| lavaan 전체 재적합 | 96.03% | 96.35% | 95.75% |
| 모형 최적화 `lav_step11_estoptim` | 51.96% | 52.27% | 52.83% |
| 계수 공분산 `lav_step13_vcov_boot` | 38.00% | 37.67% | 36.54% |
| Hessian `lav_model_hessian` | 37.77% | 37.44% | 36.45% |
| 자료 준비 `lav_step03_data` | 1.63% | 1.17% | 1.49% |
| 표본 통계 `lav_step05_samp` | 1.07% | 1.03% | 1.36% |
| 계수·유효성 추출 `context$extract_fit` | 1.87% | 2.01% | 2.40% |

상위 재적합 안에 최적화·공분산 등 하위 함수가 포함되고, Hessian도 공분산 구간과 중첩된다. 비중을 서로 더하지 않는다. Hessian과 공분산의 포함 시간이 비슷하다는 점은 다음 조사 대상을 좁히는 근거이지 해당 계산을 생략해도 된다는 근거가 아니다.

각 실행에서 screen 파일 8개, full 파일 40개, 합계 48개를 얻었다. 전체 144개 프로파일이다. screen 표본 시간 합은 0.82/0.77/0.90초, full은 20.60/20.60/21.21초였다. 실제 full 적합 경로가 대부분의 작업자 비용을 차지했다. 이 블록 수를 표본 수로 해석하지 않는다.

제품지표 생성 루프 자체의 개별 시간은 이번에 직접 분리하지 않았다. 작은 `mean` 호출이나 작업자 자체 실행 시간만으로 정확한 생성 비용을 추정하지 않는다. 계수 추출 또한 내부 유효성 검사 등을 포함하므로 순수 데이터 복사 비용이 아니다.

## 동일성

- 세 프로세스 각각 원본/계측의 전체 반환 결과에서 `timings` 속성만 제거하고 부모에서 포착한 경고·메시지, stdout, RNG를 함께 `identical(..., num.eq=FALSE)`로 비교해 통과했다.
- `bootstrap_draws`의 200개 표본 행 인덱스, 200개 유효 마스크, 원계수 및 표준화계수 200행과 최종 요약이 비교에 포함됐다. 모든 실행 유효 200/200이었다.
- 프로세스 간 원본 결과도 첫 실행과 나머지 두 실행의 전체 캡처 객체를 비교해 통과했다.
- 양쪽 경로에서 fixed-index 활성, product-aware 활성, fallback 0, 작업자 4개·청크 100개를 확인했다.
- 숫자 허용오차·반올림·환경 속성 정리는 사용하지 않았다. 실행 시간 속성까지 같은 원본 객체라는 뜻은 아니다. 기존 작업자 내부에서 억제한 자식 경고 전체를 새로 수집한 검사도 아니다.

## 판단과 다음 단계

이번에는 속도 변경을 적용하지 않았다. 준비나 계수 추출의 작은 반복을 먼저 바꾸기보다, 큰 비용이 관측된 Hessian 계산 안에서 동일 입력의 중복 계산이 있는지 확인한다. 표준오차·추론·유효성 검사를 유지하면서 실제로 재사용 가능한 동일 계산이 확인될 때만 후보를 만든다. 수렴 허용오차, 시작값, 추정법, 반복 수, 표본별 통계량을 바꾸지 않는다.

기존 일반 SEM 역행렬 캐시 후보는 성능 저하로 미적용한 상태를 유지한다. 이번 프로파일만으로 그 후보를 재추진하지 않는다.
