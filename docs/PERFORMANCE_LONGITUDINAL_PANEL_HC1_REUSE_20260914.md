# 패널 민감도 분석의 HC1 표준오차 재사용

## 적용 내용

패널 FE/RE 적합의 계수표에는 반올림 전 HC1 표준오차가 보관된다. 이를 Driscoll–Kraay 민감도 비교에서 재사용하여 같은 모형의 HC1 공분산과 계수 검정을 다시 계산하지 않도록 변경했다.

`longitudinal_panel_driscoll_kraay_summary`에 선택적 `hc1_table` 인자를 추가하고, 원래 계수표의 SE와 Term을 전달한다. DK 공분산 계산, 공통 항목 선택, 비율과 요약 계산은 그대로다. 기본 NULL 호출은 기존처럼 HC1을 계산한다.

민감도 적합에 경고·메시지가 있거나 RNG가 바뀌면 계수표를 재사용하지 않는다. 필요한 열이 없는 경우도 기존 계산으로 진행한다. 선택 모형을 재사용하는 경우에는 기존 선택 모형 보호 조건도 적용된다. 진단을 억제하지 않고, 새로운 전역 캐시나 반환 결과 필드를 추가하지 않는다.

## 성능

번들 R 4.5.3, seed 939, 2,000명 × 6시점 = 12,000행, 연속 반응, 두 공변량, 기본 비가중 패널 분석. 워밍업 후 독립 프로세스 3개를 순차 실행했으며 두 번째 프로세스는 후보부터 측정했다. 로딩은 제외하고 비교용 캡처와 정규화를 포함한다.

다음은 보호 조건을 포함한 최종 후보 측정이다.

| 모형 | 변경 전 1 / 2 / 3 (초) | 변경 후 1 / 2 / 3 (초) | 중앙값 |
|---|---|---|---|
| FE | 3.77 / 2.92 / 3.03 | 3.09 / 2.61 / 2.53 | 3.03 → 2.61초, 약 14% 감소 |
| RE | 3.25 / 2.75 / 3.14 | 2.60 / 2.53 / 2.53 | 3.14 → 2.53초, 약 19% 감소 |

두 모형 모두 세 번 빨라졌다. 해당 자료·환경의 측정이며 모든 자료에서 같은 개선율을 보장하지 않는다. 초기 보호 조건 없는 시제품도 별도로 보관하지만 위 결과에는 사용하지 않았다.

## 검증

`scripts/validate_longitudinal_panel_hc1_reuse.R`에서 FE/RE 각각의 정상, 경고, 메시지, RNG 소비, 오류 조건을 검사했다. 실제 `vcovHC.plm` 메서드 진입을 계측하고 진단/난수/오류를 주입했다. 메서드 trace는 검증 프로세스 안에서만 사용하고 종료 전에 해제했다.

10개 조건에서 전체 반환 결과, 조건 클래스/본문/순서, 표준 출력, RNG가 일치했다. HC1 표준오차, DK 표준오차, 항목별 DK/HC1 비율도 포맷팅 전 원값을 추출해 비교했다. 정상 HC1 호출은 4→2회, 경고·메시지·RNG 조건은 양쪽 모두 5회, 오류 조건은 양쪽 모두 1회였다.

비교는 `identical(..., num.eq = FALSE)`로 수치 허용오차 없이 수행한다. 전체 반환 모형은 formula/terms 환경과 함수 표현만 정규화하며 원시 환경·함수 객체의 동일성까지 주장하지 않는다. 참조 DK 요약은 계수표 전달을 무시해 원래 HC1 계산을 강제로 수행한다. 성능 비교는 변경 전 소스 전체를 별도 환경에 직접 로드했다.

기존 패널 선택 모형 검증 22개 및 Hausman 검증 32개도 통과하여 앞선 재사용과 예외 처리를 확인했다.

## 범위 및 증거

분석 출력 내용과 형식은 변경하지 않았다. 기존 가중 패널 공분산 미지원과 특이행렬 시험 자료의 생략 결과는 유지한다. 이전 종합 테스트의 Excel 셀 위치 비교 실패는 이번에 해결하거나 재실행하지 않았다. 관련 패널 검증을 수행하고 전체 형식 변환과 설치 파일 빌드는 실행하지 않았다.

`output/longitudinal-panel-hc1-review-20260914/`에 `baseline.R`, `prototype.R`, `candidate.R`, `bench.R`, `bench-guarded.R`, `guarded-timing-1/2/3.csv`, `validation.log`, `panel-regression.log`, `hausman-regression.log`를 보관한다. 기존 작업 트리의 다른 변경은 유지했다.
