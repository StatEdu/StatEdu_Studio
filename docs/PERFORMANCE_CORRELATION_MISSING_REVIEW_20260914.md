# 결측 위치에 따른 상관분석 성능 확인 — 2026-09-14

앞선 anyNA 경로가 결측이 없는 자료에서 유리한 반면, 결측이 있으면 추가 검사 후 기존 complete.cases 경로로 돌아간다는 점을 확인하기 위해 불리한 입력을 측정했다. 이번에는 애플리케이션 코드를 변경하지 않았다.

## 측정 조건

번들 R 4.5.3, 기존 모듈 캐시, 5만 행·15변수의 숫자형 자료에서 Pearson 분석과 정규성 검사 비활성 조건을 사용했다. 기준은 anyNA 적용 직전 `output/correlation-anyna-20260914/baseline.R`이며 현재와 같은 전역 함수 환경으로 연결했다.

새 프로세스에서 3쌍을 순차 실행하고 두 번째 쌍은 순서를 반대로 했다. 각 프로세스 안에서는 first, last, staggered, random10 순서로 실행했다. 따라서 조건 간 시간 차이는 워밍업 차이가 포함돼 있으며, 각 조건의 변경 전후만 비교한다.

## 결과

전체 결과 준비 시간의 3회 중앙값(초):

| 결측 배치 | 변경 전 | 현재 |
|---|---:|---:|
| 모든 변수 첫 행에 NA | 0.38 | 0.39 |
| 모든 변수 마지막 행에 NA | 0.27 | 0.28 |
| 변수마다 끝부분의 서로 다른 행에 NA | 0.28 | 0.26 |
| 변수마다 임의의 10% 행에 NA | 0.27 | 0.26 |

모든 변수의 첫 행 또는 마지막 행에 NA가 있는 조건에서 중앙값 0.01초 증가가 관측됐다. 모든 입력에서 속도가 개선된다고 주장할 수 없다. 반면 다른 두 조건에서는 작은 감소가 관측됐다. 이 실험은 통계적 유의성 검정이나 사용자 데이터 분포의 대표성 평가가 아니다.

앞서 확인한 완전 자료에서의 시간·할당량 이득을 고려해 현재 구현은 유지한다. 이번 증가를 숨기거나 0으로 취급하지 않으며, 무조건적인 성능 개선이라는 해석을 피한다. 실제 사용 자료에서 모든 변수에 결측이 있는 작업이 중심이라면 해당 자료의 반복 측정이 필요하다.

## 검증 및 자료

4조건 × 3쌍의 전체 결과 객체, 경고·메시지, 난수 상태가 `identical(...,num.eq=FALSE)`로 정확히 일치했다.

`output/correlation-missing-review-20260914/measure.R`, `compare.R`, `summary.csv` 및 실행별 CSV/RDS를 보관했다. 측정은 기존 anyNA common.R을 사용하며 자동 패키지 설치는 비활성화했다.

화면·내보내기 구현은 변경하지 않았고 HTML/PDF/Word/HWPX/Excel은 이번에 재검증하지 않았다. 설치 파일은 재빌드하지 않았다.
