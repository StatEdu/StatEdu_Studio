# GLM 추가 상태 설명

2026-09-16. 설치본은 만들지 않았다.

## 변경

6개 언어에 사용자 선택/실제 적합, 강건 공분산 사용, 강건 공분산 계산 실패 후 모형기반 공분산 표시, 노출량 오프셋, 생성한 코딩 행 수 등 5개 동적 문장 형식을 추가했다. 분포 명칭은 시스템 값으로 번역하고 HC 방식·사용자 변수명·수치는 그대로 삽입한다.

## 검증

- `scripts/validate_glm_multilingual.R`: 8개 언어 통과. 실제 분포 선택 사유 생성 함수의 count → negative_binomial 문장, HC2/HC3, 괄호·퍼센트·번역 대상과 같은 단어가 포함된 사용자 오프셋 변수명 보존을 검사했다.
- 기존 실제 Gaussian/binomial/count 본표 영어 및 옵션 값 보존 검사 유지. 합성 count 분석의 기존 음이항 반복 한도 경고는 발생했지만 출력 검사는 통과했다.
- `scripts/validate_i18n_contract.R`: 통과.
- 일본어 현재/누적 HTML·Word·HWPX·Excel 내용 비교와 PDF 생성 통과. `scripts/validate_multilingual_pdf.py`의 두 PDF 실제 텍스트 비교도 통과했다.

## 남은 범위

GLM 표의 추가 헤더·상태·요약과 다른 분석 화면을 계속 점검해야 한다. 이번 검증은 강건 공분산 계산 실패를 실제로 유발하는 계산 시험이 아니라 해당 출력 문장과 표시 계약의 검사이다.
