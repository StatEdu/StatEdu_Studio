# SEM 완전자료·결측자료 현재 기준 및 정확성 검증

제품 코드를 변경하지 않고 기존 일반 SEM fixture의 완전자료/결측 FIML 경로를 측정했다. 200회 재표집 기준으로 결측 경로에서 더 많은 재적합 시간이 관측됐다. 5,000회나 제품지표 모형 전체의 성능으로 환산하지 않는다.

## 먼저 수정한 측정 환경

처음 실행은 부모 lavaan 0.7-2와 병렬 작업자 0.6-21이 섞여 유효 반복 0회가 발생했다. 실패 시간을 성능 자료로 사용하지 않았다. 진단 실행의 `complete-diagnostic.rds` 및 diagnostic.log를 보관했다.

R 부모의 `.libPaths()`만 맞추는 것으로 자식 라이브러리 설정이 일치하지 않았다. 연구용 실행기에 `R_LIBS_USER=R.home('library')`를 명시해 다시 실행했다. 제품 Electron의 `main.js`도 이미 `R_LIBS_USER: bundledRLibraryPath()`를 설정한다. 따라서 이번 실패를 설치 앱의 재현된 결함이라고 보고하지 않는다. 제품 코드·패키지를 교체한 것이 아니라 측정 환경을 제품 설정에 맞춘 것이다.

## 기준 측정

번들 Windows R 4.5.3, 240행, 연속 지표 9개/잠재변수 3개, A→B/A→C/B→C 일반 SEM, ML/FIML, std_lv=FALSE. 완전자료와 변수별 10% 결측(총 216셀)에 동일한 데이터 생성 규칙을 사용했다. 재표집 seed 20260826, 200회, 작업자 4개, chunk 100. 원래 반복 수 5,000을 제품에서 변경한 것이 아니라 기존 벤치마크의 반복 수 옵션으로 작은 조건을 측정했다.

새 부모 프로세스 및 새 실제 백그라운드 작업으로 각 조건 3회 순차 실행했다. 두 번째 쌍은 결측 조건을 먼저 실행했다. 기존 점추정의 수렴·허용 가능 여부를 확인한 뒤 작업 시작부터 결과 파일 읽기까지 측정했다. 초기 패키지/모듈 로딩, 점추정 적합, UI/내보내기는 제외했다.

|조건|1회|2회|3회|전체 중앙값|재표집 단계 중앙값|유효 반복|
|---|---:|---:|---:|---:|---:|---|
|완전자료|3.912초|3.908초|3.907초|3.908초|2.611초|매회 199/200|
|10% 결측|7.487초|7.476초|7.724초|7.487초|6.176초|매회 200/200|

두 조건 모두 현재 fixed-index 경로가 활성화되고 fallback 0이었다. expected-information 고속 경로는 실제 결측 조건에서 활성화됐다. 완전자료의 제외된 1회를 유효 처리하거나 반복 수를 맞추기 위해 재시도하지 않았다. 이 기록만으로 해당 반복의 제외 사유를 단정하지 않는다.

각 조건에서 결과의 `timings` 속성만 제거한 뒤 나머지 전체 반환 객체를 `identical(..., num.eq=FALSE)`로 비교해 3회가 정확히 같았다. 수치 반올림·환경 속성 정리는 하지 않았다. 시간 메타데이터까지 같은 원본 객체라는 뜻은 아니다.

## 별도 결측 경로 비교

기존 `validate_sem_missing_fiml_fixed_index.R`의 결측 fixture에서 100회/작업자 4개로 lavaanList 기준 경로와 fixed-index 경로를 실행했다. 기존 검사는 timing 속성을 제외한 `all.equal(tolerance=0)`를 사용하므로 추가로 `identical(..., num.eq=FALSE)`를 검사했다.

검사 통과: 100/100 유효, 표본 행 인덱스·유효 마스크·원계수·표준화계수를 포함한 반환 결과가 정확히 일치했다. `bootstrap_draws`의 네 필드도 포함한다. 경로 활성/expected information 활성/fallback 0 검사를 통과했다.

해당 단일 검증 실행 시간은 기준 8.925초, fixed-index 3.484초였다. 이는 이미 적용된 경로의 검증 실행이며 이번에 만든 새 개선율이 아니다. 순서 교차 및 3회 성능 검사를 한 A/B가 아니므로 이 수치로 일반적인 배속을 주장하지 않는다. 기존 도구는 경고를 억제하므로 경고·메시지 전체 또는 부모 RNG 동일성을 검증했다고 주장하지 않는다.
