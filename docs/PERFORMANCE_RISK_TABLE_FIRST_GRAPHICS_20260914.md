# 위험집단 표의 첫 그래픽 초기화 검토 — 2026-09-14

## 결론

첫 위험집단 표 구성에서 관찰된 큰 비용은 위험집단 수의 반복 계산이 아니라 그래픽 패키지 로드와 첫 기본 테마 생성에 집중됐다. 이번 검토에서는 제품 코드를 변경하지 않았다. 패키지를 시작 시 미리 읽는 방식은 대기 위치만 바꿀 수 있어 적용하지 않았다.

## 측정

번들 R 4.5.3, JIT 3, 기존 모듈 캐시를 사용해 새 프로세스 3개를 순차 실행했다. 앞선 첫 분석 하네스와 동일하게 초기 UI·서버를 구성하고 데이터를 업로드한 뒤 Pearson 상관분석, KM 생존분석, 동일 입력 재실행을 수행했다.

메모리상의 `survival_risk_table_plot()` 복사본에서 `ggplot2::함수` 조회를 계측용 조회로 바꿨다. 조회 시 `getExportedValue()` 시간과 새로 로드된 네임스페이스를 기록하고, 반환한 함수는 `fn(...)`으로 호출하여 인수의 지연 평가를 유지했다. 설치 패키지와 제품 소스는 변경하지 않았다.

| 구간 | 1회 | 2회 | 3회 | 중앙값 |
| --- | ---: | ---: | ---: | ---: |
| 첫 ggplot 조회 및 네임스페이스 로드 | 0.50 | 0.53 | 0.48 | 0.50 |
| 첫 theme_classic 호출 | 0.30 | 0.31 | 0.31 | 0.31 |
| 계측된 첫 KM handler/flush 전체 | 2.95 | 3.06 | 3.09 | 3.06 |

단위는 초다. 첫 조회에서 공통으로 새로 로드된 네임스페이스는 ggplot2를 포함한 14개였다: gtable, dplyr, tidyselect, scales, ggplot2, generics, tibble, pillar, RColorBrewer, S7, vctrs, glue, farver, pkgconfig.

따라서 첫 ggplot 조회 시간은 그림 데이터 계산이 아니라 패키지 초기화 경로를 포함한다. 테마 호출 시간도 첫 사용 시 내부 초기화를 포함할 수 있어 반복 호출 비용으로 일반화하지 않는다. 계측은 포함 시간이며 `theme()`와 그 인수 구성처럼 중첩된 호출을 더해서는 안 된다.

위험집단 표 함수는 분석 결과의 `summary_at$n.risk`를 사용한다. 해당 KM 경로는 그림을 위해 원자료의 위험집단 수를 다시 추정하지 않는다. 이 사실은 다른 생존분석 방법의 구현에 일반화하지 않는다.

- 3개 계측 실행의 초기 UI, 상관·KM 분석 객체, 결과 HTML·의존성, 경고와 알림이 앞선 비계측 기준과 `identical(..., num.eq=FALSE)`로 일치했다. 초기 UI의 자동 숫자 탭 ID만 정규화했다.
- 각 프로세스에서 첫 분석과 동일 입력 재실행의 분석 객체가 동일했다.
- 그래프 좌표계 교체 안내는 기존대로 나타났다. 이번 비교는 PNG 픽셀 동일성 검증이 아니며 제품 그림 코드도 수정하지 않았다.

- Electron 시작, 브라우저 표시, 콜드 디스크 시작은 측정하지 않았다. 기존 JIT 제어와 그래프 축 정렬 동작을 유지했다.
- 제품 `R/result_survival_ui.R` SHA256은 이전 검토와 동일한 `4D08F58364B94CF9C3079EFE5FB9EC499D9DC58137678EA36F0F85F9A9002E55`다.

제품 코드와 출력 변경이 없어 문서 내보내기 및 설치 파일 빌드는 수행하지 않았다.
