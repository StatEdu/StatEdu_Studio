# Elastic Net alpha 후보 보관 개선

## 적용

`R/analysis_penalized.R`의 choose_fit에서 모든 alpha 후보의 cv.glmnet 적합을 리스트에 모으던 처리를 순차 비교로 변경했다. 현재 최선의 후보와 비교 중인 후보만 필요하므로 이전의 탈락 후보들을 전체 탐색이 끝날 때까지 보관하지 않는다. 대입 평가 중 일시적인 참조와 회수되지 않은 객체까지 포함해 항상 두 객체만 메모리에 존재한다는 뜻은 아니다.

alpha 탐색 순서, 각 적합 호출과 시드, CV MSE 계산, 최종 선택 결과를 유지한다. 점수가 엄격히 작을 때만 교체하므로 동점은 원래처럼 먼저 나온 alpha를 선택한다. Ridge/LASSO의 단일 alpha 분기는 변경하지 않았다. 패키지 내부 함수나 namespace, 병렬 워커 구성도 변경하지 않았다.

## 성능

번들 R 4.5.3, 자료 seed 939, 분석 seed 7731, 3,000행·연속 설명변수 20개, 연속 반응, Ridge/LASSO/Elastic Net 전체 분석을 사용했다. 기본 alpha 후보 9개, 방법별 부트스트랩 2회, 워커 1개다. 기본 부트스트랩 500회 실행의 개선율은 아니다.

독립 프로세스 3개를 순차 실행했다. 워밍업 후 비교하고 두 번째 프로세스는 후보부터 측정했다. 로딩을 제외하고 결과 캡처를 포함한다.

| 실행 | 기존(초) | 변경(초) |
|---|---:|---:|
| 1 | 1.00 | 0.78 |
| 2 | 0.92 | 0.94 |
| 3 | 0.92 | 0.74 |
| 중앙값 | 0.92 | 0.78 |

중앙값은 약 15% 감소했고 세 번 중 두 번 빨라졌다. 두 번째는 0.02초 증가했으므로 매 실행의 개선을 주장하지 않는다. 주된 적합 연산 횟수는 동일하다.

각 측정 전에 gc(reset=TRUE)를 실행하고 이후 max used Vcells를 읽었으나, 기존/변경은 각각 10,146,343/10,146,320, 10,146,709/10,146,328, 12,255,483/12,255,591이었다. 이 실행에서 최대 벡터 힙 감소는 관찰하지 못했다. R의 미회수 객체·GC 동작과 함께 전체 분석의 값이며, 프로세스 최대 상주 메모리 측정도 아니다. 탈락 후보 참조 제거를 실제 peak 메모리 감소율로 환산하지 않는다. 두 번째 측정 시 첫 결과가 비교용 리스트에 남아 있으므로 이 수치는 엄밀한 독립 메모리 벤치마크가 아니다.

## 검증

각 프로세스의 워밍업과 측정에서 전체 반환 객체·조건 클래스/본문/순서·표준 출력·RNG가 `identical(..., num.eq=FALSE)`로 일치했다. 반환 객체의 수치를 반올림하거나 환경을 정규화하지 않았다. 정상 자료 한 종류의 반복 비교다.

추출한 기존/후보 choose_fit 함수를 mock 적합과 함께 비교했다. 감소/증가 점수, 동점, 모두 Inf, NA·NaN 포함, 빈 CV 값, -Inf 동점, 단일 후보의 8개 조합에 정상/경고/메시지/RNG/두 번째 적합 오류 5개 동작을 적용한 40건이 통과했다. 선택된 적합과 alpha뿐 아니라 호출 횟수, 조건 순서, 출력 및 RNG도 비교했다. min(..., na.rm=TRUE)가 모두 결측 또는 빈 값에서 Inf와 경고를 반환하는 경로도 보존했다. 이 시험은 사용자 정의 cvm 클래스 전부에 대한 보장은 아니다.

제품 적용 후 `scripts/validate_penalized.R`가 direct glmnet 비교를 포함해 통과했다. 제품 fit_penalized_models의 함수 본문이 측정한 후보와 identical인 것도 확인했다.
