# 추천 설계·사건 매핑 언어 전환

개발 소스의 실제 Chrome 검사에서 언어 변경 후 연구 목적이 competing에서 group_comparison으로 초기화되는 문제를 재현했다. 추천 설계 상위 화면은 언어 변경 때 기본 선택값으로 다시 생성되고, 시간/사건 설정과 매핑 화면도 저장된 입력값을 전달하지 않았다.

수정:

- 설계·시간 정의·변수 배정 값을 세션에 보존하고 상위/하위 UI 재생성 시 반영한다.
- 사건 매핑은 사건 변수와 관측 코드 목록을 기준으로 보존한다. 변수/코드 목록 변경 시 매핑과 확인 체크를 초기화한다.
- Shiny 선택 목록의 HTML 문자열과 일반 입력 태그를 처리하는 설정 UI 전용 복원 함수를 추가했다. 선택하지 않은 option의 selected 속성을 실제로 제거하며 사용자 문구를 번역하지 않는다.

검증:

- `validate_survival_design_browser.cjs`: 경쟁위험·두 추정량, 시간 원점/단위/변수, 사용자 사건 라벨, 경쟁사건 역할과 확인 체크를 지정하고 추천을 실행했다. 8언어 왕복에서 모든 지정값과 추천 분석 버튼 유지 통과. 사건 변수를 x로 바꾸자 확인 체크 해제·새 원자료 라벨·unknown 역할 확인. 페이지 오류 없음.
- `validate_survival_design_restore_ui.R`: 8언어 단일/다중 선택 복원, 사용자 문자열, 사건 역할·확인 체크 검사 통과.
- 기존 사건 매핑 8언어 UI 검사 재통과.

개발용 생성 CSV를 사용했으며 추천 엔진만 실행했다. 실제 통계 분석/출력/내보내기는 변경하지 않았다. 추천 버튼을 통한 분석 화면 이동과 추천 설계의 파일 저장은 이번 검증에 포함하지 않는다. 모든 자료 변경 상황의 매핑 초기화를 검증한 것은 아니다. 네이티브 파일 대화상자 검증은 기존과 같이 미완료다.

로그: `tmp/survival-design-browser.log`, `tmp/survival-design-restore-ui.log`, `tmp/survival-design-map-regression.log`. 검사 후 테스트 서버와 브라우저를 종료했다. 설치본을 만들지 않았다.
