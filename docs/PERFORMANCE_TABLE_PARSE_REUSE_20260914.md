# 저장용 표 해석 결과 재사용 — 2026-09-14

`R/result_saved_ui.R`의 `result_entry_tables()`는 같은 HTML 표를 화면 보존 데이터와 문서 변환 데이터용으로 두 번 해석했다. 첫 해석이 경고나 메시지 없이 끝나면 그 결과를 `result_docx_table_payload()`에 전달하여 두 번째 해석을 생략한다. 재사용 범위는 현재 표 한 개이며 저장 호출 사이에 데이터를 보관하지 않는다.

`result_docx_table_payload(table_node)`의 기존 호출 방식은 그대로 작동한다. 선택 인자 `parsed`를 생략하면 원래처럼 직접 해석한다. 첫 해석에서 경고나 메시지가 발생한 경우에도 기존처럼 다시 해석하여 진단 발생 횟수와 순서를 유지한다. 표 값이나 문서 변환 규칙은 변경하지 않았다.

## 전체 Excel 저장 측정

30변수 상관분석의 저장된 HTML, 3개 시트, 번들 R 4.5.3을 사용했다. 이전의 값 쓰기 묶음, 서식 캐시, 서식 적용 묶음 최적화는 양쪽 모두 활성화했다. 각 측정은 새 R 프로세스에서 모듈과 환경 설정을 로드한 뒤 수행했다. 프로파일러 없이 3쌍을 순차 실행하고 두 번째 쌍의 실행 순서를 뒤집었다. 비교 함수는 동일한 전역 도우미 환경을 사용했으며 파일 검증 시간은 제외했다.

## 검증

- `scripts/validate_table_parse_reuse.R`: 개별 표 9개와 누적 결과 1개에서 Excel 내부 파일 비교 통과. 문자열, 빈 셀, 병합, 헤더, 다양한 서식 및 연속 구간을 포함한다.
- 시트 이름과 읽어 들인 값이 동일하다. core 메타데이터 이외의 모든 압축 내부 파일이 바이트 단위로 동일하다. core 메타데이터도 생성·수정 시각만 정규화하면 동일하다.
- 9개 표의 `result_entry_tables()` 반환 데이터 전체가 정확히 동일하다. 개별 저장의 경고 순서와 RNG 상태도 동일하다.
- 빈 표를 포함하여 문서용 표 변환 함수의 기본 호출과 명시적 해석 결과 전달이 같은 결과를 반환한다.
- 주입한 경고·메시지 검사에서 발생 순서, 결과, RNG가 동일했다. 정상 해석 호출은 표당 2회에서 1회로 줄었으며 진단이 발생하면 2회를 유지했다.
- 실제 30변수 상관분석 HTML의 표 3개도 화면 보존 데이터, 문서용 데이터, 주석 및 주변 텍스트를 포함한 전체 반환값이 동일하다.
- 측정한 Excel 파일 6개 모두 기존 기준 파일과 내부 구성 비교를 통과했고 저장 중 경고가 없었다.
- `scripts/validate_screen_table_export.R`: REML UN/AR1 총 36개 표의 화면/보고서 내용 및 방향 유지 검사 통과.
- `git diff --check -- R/result_saved_ui.R` 통과.

분석 결과나 출력 내용을 변경하지 않는 중복 해석 제거다. HTML/PDF/Word/HWPX 작성기는 변경하지 않았으며 PDF/Word/HWPX 완성 파일은 이번에 재생성하지 않았다. 설치 파일도 재빌드하지 않았다.
