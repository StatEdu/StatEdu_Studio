# 생존분석 PNG 출력 장치 비교 — 미적용

2026-09-14. 고해상도 PNG 생성 속도를 높이기 위해 장치 교체를 시험했다. **빠른 후보에서도 기존 픽셀이 보존되지 않아 운영 장치를 유지했다.**

## 조건

번들 R 4.5.3의 `grDevices::png` 함수 본문을 확인했다. 이 Windows 빌드에서는 type을 생략하면 `windows`가 선택된다. 현재 `plot_data_uri`는 type을 지정하지 않는다. 설치된 Cairo 지원 및 ragg를 사용하여 다음 네 장치를 비교했다.

- 기존 `grDevices::png(type='windows')`
- `grDevices::png(type='cairo')`
- `grDevices::png(type='cairo-png')`
- `ragg::agg_png`

모두 **5455×3927픽셀, 600 dpi, 투명 배경**을 지정했다. 기존 JIT 최적화를 포함한 생존 그래프 함수와 동일한 분석 입력을 사용했다. KM은 survival_validation.csv의 time/status/sex와 평가 시점 100/200/400, 경쟁위험은 seed 410의 120행 자료와 평가 시점 5/10/20이다.

장치마다 별도의 새 R 프로세스 3개, 총 12개 프로세스를 순차 실행했다. 두 번째 세트에서는 장치 순서를 뒤집었다. 각 프로세스에서 KM 그림을 먼저 그리고 경쟁위험 그림을 이어서 그렸다. 따라서 경쟁위험 수치는 완전히 차가운 첫 그림 비용이 아니다. 분석 준비 및 앱 모듈 로딩은 시간 측정 밖이다.

## 속도

아래는 장치 열기·그림 그리기·장치 닫기를 포함한 3회 중앙값이다. base64 변환, HTML 삽입 및 문서 변환은 포함하지 않는다.

| 장치 | KM(초) | 경쟁위험(초) |
|---|---:|---:|
| Windows 기존 | 1.30 | 1.10 |
| Cairo | **0.91** | **0.63** |
| Cairo-PNG | 1.36 | 1.07 |
| ragg | 1.43 | 1.03 |

Cairo의 KM은 약 30%, 경쟁위험은 약 43% 빨랐다. 그러나 이는 아래 동일성 조건을 통과하지 못한 후보의 속도이며, 적용된 성능 개선이 아니다. 다른 후보도 일관된 큰 이득을 보이지 않았다.

## 이미지 보존

파일 바이트나 압축 방식 차이만으로 탈락시키지 않고, Pillow로 각 PNG를 RGBA로 디코딩하여 픽셀을 비교했다. 모든 파일 크기는 5455×3927로 일치했다.

| 후보 | KM에서 다른 RGBA 픽셀 비율 | 경쟁위험에서 다른 RGBA 픽셀 비율 |
|---|---:|---:|
| Cairo | 약 6.965% | 약 1.544% |
| Cairo-PNG | 약 6.965% | 약 1.544% |
| ragg | 약 7.006% | 약 1.442% |

세 후보 × 세 프로세스 × 두 그림의 **18개 비교가 모두 픽셀 불일치**였다. 기존 Windows 장치는 서로 다른 프로세스 사이에서도 RGBA 픽셀이 완전히 같았다.

투명 영역의 RGB 값만 다른 경우를 구분하기 위해 흰 배경에 합성한 픽셀도 비교했다. 모든 후보에서 차이가 남았다. 예를 들어 첫 KM의 흰 배경 합성 후 차이는 Cairo 1,491,942픽셀, Cairo-PNG 246,108픽셀, ragg 257,372픽셀이었다. 따라서 단순한 PNG 인코딩 차이 또는 완전 투명 영역만의 차이가 아니다. 픽셀 차이 비율은 사람이 느끼는 품질 저하의 비율을 의미하지 않는다.

조건(경고·메시지), 표준 출력 및 RNG 상태는 각 실행에서 기존 장치와 같았다. 이는 그림이 같다는 뜻은 아니며, 본 검토에서는 실제 픽셀 비교를 별도로 수행했다.

## 판단과 한계

동일 해상도만 지정해서는 장치 간 동일 픽셀을 보장하지 않는다. 이번 목표는 기존 결과 표시까지 보존하는 최적화이므로 **장치 교체를 적용하지 않는다.** 다음 후보는 기존 Windows 렌더러를 유지한 상태의 출력 경로여야 한다.

전체 저장 HTML, 현재/누적 결과의 모든 문서 형식 및 최대 메모리 사용량은 이번 시험 범위가 아니다. 후보가 픽셀 동일성에서 탈락했고 운영 코드 변경이 없어 전체 형식 내보내기와 설치 파일 재빌드는 진행하지 않았다.

픽셀 검사 도구의 최초 파일명 `inspect.py`가 Python 표준 모듈 이름과 충돌하여 실행에 실패했다. `compare_pixels.py`로 이름을 바꾼 뒤 전체 검사를 완료했다. 이 문제는 R 성능 측정 완료 후 발생했으며 측정치에 포함되지 않는다.
