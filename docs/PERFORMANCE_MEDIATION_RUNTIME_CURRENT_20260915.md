# 매개·조절 백그라운드 10,000회 현재 기준 측정

기존 `scripts/validate_mediation_moderation_runtime.R`의 실제 작업 시작·결과 읽기·첫 HTML 생성 검사를 현재 코드에서 실행했다. 제품 코드를 변경하지 않았고 새 최적화의 성능 개선율을 측정한 것이 아니다. SEM 경로는 이번 실행에 포함하지 않았다.

독립변수 X1/X2 각각 5,000회, 총 10,000회 재표집을 동일 fixture/seed/options로 새 백그라운드 작업자에서 3회 순차 실행했다. 부모 프로세스는 하나다. 분석 옵션과 원래 검사 기준을 완화하지 않았다. 번들 Windows R 4.5.3을 사용했고, callr 파이프를 사용하는 검증이므로 승인된 제한 밖 로컬 실행으로 수행했다.

## 결과

|관측|1회|2회|3회|
|---|---:|---:|---:|
|작업 시작→정상 작업 종료|3.06초|2.98초|2.95초|

- 작업 시간 중앙값 2.98초. 기존 검사의 중앙값 20초/최대 25초 조건 통과.
- finalizing→complete 최대 0.06초. 결과 읽기는 타이머에서 모두 0.00초로 기록됐으며 비용이 전혀 없다는 뜻은 아니다.
- 첫 작업 결과를 읽고 작업 정리를 완료한 뒤 결과 UI 구성 및 `htmltools::renderTags()`를 한 번 실행: 0.88초. 기존 5초 기준 통과.
- 단계 순서 및 필수 단계 관측 검사 통과. 마지막 세션에서 preparing은 약 0.25초, resampling은 약 1.01초, finalizing은 약 2.90초에 처음 관측됐다. 10ms 폴링 관측 시점이며 정밀한 내부 함수별 CPU 시간은 아니다.
- 작업자 종료 및 임시 디렉터리 정리 확인.

HTML 생성은 R 쪽 문자열 생성까지이며 브라우저 화면 표시·레이아웃·그림 로드 시간은 포함하지 않는다. 앱 자체 시작 시간도 제외한다. 8월 기록과 모형/환경을 맞춘 A/B 실행이 아니므로 이전 수치 대비 개선율은 제시하지 않는다.

## 동일성 검사의 범위

기존 검사가 X1/X2 경로, 각 효과의 요청 반복수 5,000, 기록된 seed 및 부모 RNG 불변을 확인했다. 세 작업 결과 비교는 `runtime_canonical_result()`를 거친 뒤 `identical(..., num.eq=FALSE, single.NA=FALSE)`를 사용했다.

이 정리는 환경 객체, 함수의 환경 및 `.Environment` 속성의 환경 참조를 비교용 사본에서 `emptyenv()`로 바꾼다. 수치 반올림이나 허용오차는 없지만 **원본 전체 R 객체를 무변환으로 비교한 검사는 아니다.** 작업자 경고/메시지 전체의 동일성 검사로도 해석하지 않는다. 모든 효과의 유효 반복이 5,000인지 별도 집계한 것은 아니므로 요청 횟수를 유효 횟수라고 보고하지 않는다.

검증 스크립트는 결과 비교 후 각 sample의 result를 제거한다. 저장한 samples.rds는 시간·단계·정리 상태 자료이며 원본 결과 사본이 아니다. 검증 자체의 통과 로그와 이 한계를 함께 남긴다.
