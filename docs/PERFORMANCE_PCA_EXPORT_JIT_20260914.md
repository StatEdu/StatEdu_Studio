# 주성분분석 첫 저장 컴파일 비용 개선 — 2026-09-14

주성분분석의 저장용 HTML 생성에 한해 동기 호출 동안 JIT 컴파일을 일시 중지하고, 종료 시 기존 설정을 복원하도록 적용했다. 실제 적용 코드의 첫 저장 중앙값은 1.31초에서 0.88초로 약 32.8% 줄었다. 요인분석 후보는 반복 저장이 소폭 느려져 적용하지 않았다.

## 변경 범위

`R/result_saved_ui.R`의 `saved_pca_results_html`만 변경했다. 기존 문서 생성 본문을 지역 함수에 보관하고, 공개 함수의 인자와 기본값을 유지했다. 진입 시 `compiler::enableJIT(0)`으로 이전 값을 보관하며 `on.exit`에서 정상·오류 종료 모두 복원한다. 통계 분석, 표시 내용, 그림 그리기, DPI, 파일 변환 알고리즘은 그대로다. 기존에 컴파일된 함수의 바이트코드를 제거하는 변경도 아니다.

이는 저장용 HTML 생성 구간에 국한된 최적화다. 앱 시작이나 분석 실행 시간을 줄였다는 의미가 아니며, 비동기 작업이나 이벤트 루프를 추가하지 않았다. 설치 파일은 빌드하지 않았다.

## 실제 적용 코드 성능

번들 R 4.5.3, Windows, seed 714의 2,000행·20변수 자료, 상관행렬 PCA, 고정 2성분, 회전 없음, 스크리 그림·바이플롯, 600 dpi 조건이다. 패키지·모듈 로딩과 분석 완료 후 첫 HTML 생성과 반복 생성을 측정했다. 각 방식 3개의 새 프로세스를 순차 실행했으며 2회차는 실행 순서를 반대로 했다. 다른 R 검증이나 파일 변환은 동시에 실행하지 않았다.

| 회차 | 기존 첫 저장 | 적용 첫 저장 | 기존 반복 | 적용 반복 |
|---|---:|---:|---:|---:|
| 1 | 1.52초 | 0.88초 | 0.97초 | 0.79초 |
| 2 | 1.31초 | 0.87초 | 0.78초 | 0.78초 |
| 3 | 1.31초 | 0.88초 | 0.80초 | 0.75초 |
| 중앙값 | **1.31초** | **0.88초** | **0.80초** | **0.78초** |

반복 저장 차이는 작으므로 안정적인 추가 가속으로 단정하지 않는다. 이 수치는 HTML 생성만 포함하며 대화상자와 PDF/Word/HWPX/Excel 변환은 제외한다. 전체 파일 저장이 33% 빨라진다는 의미가 아니다.

별도 사전 후보 시험에서 PCA 첫 저장 중앙값은 1.32→0.87초, 반복은 0.82→0.78초였다. EFA 후보는 첫 저장 1.12→0.53초, 반복 0.47→0.49초였다. EFA 반복 차이는 작지만 일관된 이득이 확인되지 않아 확장하지 않았다. 이 사전 후보는 출력 함수 전체를 감싼 실험 코드이고 위 표는 최종 제품 코드 측정이다.

## 정확성 및 설정 복원

- 사전 후보 PCA/EFA 각 3쌍과 실제 적용 PCA 3쌍, 총 9쌍에서 HTML 전체(내장 PNG 포함), 경고·메시지, 표준 출력, 난수 상태가 `identical(..., num.eq=FALSE)`로 일치했다. 각 실행의 첫·반복 출력도 일치했다.
- 실제 적용 함수와 변경 전 함수를 12가지 표시·자료 조건에서 비교했다: 기본, 보고서 모드, 사용자 CSS, 소수점 쉼표 표시, 영어, 변수 라벨, 300 dpi, 그림 끄기, 1성분, varimax, 공분산행렬, 결측 자료. 기본 그림 검사는 600 dpi다. 분석 완료 후 소수점 표시 옵션을 바꿔 저장 단계를 비교했다.
- 모든 조건에서 HTML·PNG·경고·메시지·표준 출력·난수 상태가 정확히 일치했고, 분석 결과 직렬화 값이 저장 전후 동일했다.
- `scripts/validate_pca_export_jit.R`: 기존 JIT 수준 0·1·2·3 각각에서 정상 및 오류 종료를 검사했다. 렌더링 구간은 JIT 0, 종료 후 설정은 원래 값이며, 인자와 오류 메시지가 유지됐다. 이 테스트는 렌더러를 대체해 복원 경계를 검사하고, 실제 렌더러 동일성은 위 표시 검사에서 확인한다.

## 현재·누적 결과 5종 저장

240행·8변수 PCA 결과를 사용했다. 현재 결과는 단일 저장 스냅샷, 누적 결과는 그 스냅샷을 다른 ID로 두 번 추가한 목록이다. 실제 UI 클릭 자동화 검사는 이번 범위에 포함하지 않는다.

HTML/PDF/Word/HWPX/Excel 총 10개 파일을 기존 변환기로 생성했다. 변경 전후 현재·누적 HTML 바이트가 같고, Excel 시트·셀과 패키지 내용은 생성/수정 시각을 정규화한 뒤 같았다.

| 범위 | HTML 비어 있지 않은 표 셀 | Word/HWPX 표 셀 | 그림 수 | PDF 페이지 |
|---|---:|---:|---:|---:|
| 현재 | 134 | 각각 134 | 각각 2 | 4 |
| 누적 | 268 | 각각 268 | 각각 4 | 8 |

Word/HWPX 셀 내용은 공백을 정규화해 HTML과 대조했다. PDF 그림 수는 현재 2개·누적 4개이며 현재 PDF 3·4쪽을 렌더링해 스크리 그림, 바이플롯 및 고유값 표를 육안 확인했다.
