# 복수 회귀모형의 VIF 재사용 — 2026-09-14

## 적용 내용

`R/analysis_regression.R`에 분석 호출 단위의 VIF·공차 재사용을 적용했다. 복수 종속변수 분석에서 생성한 `regression_collinearity_cache`를 단일 모형 준비와 계수 표 함수에 전달한다. 종속변수가 하나인 경우와 캐시 인자를 전달하지 않은 기존 호출은 원래 함수를 사용한다.

실제 숫자 설계행렬의 값·행/열 이름·속성을 `identical(..., num.eq=FALSE)`로 비교한다. contrasts 및 na.action 설정도 비교한다. 직전 결과 한 개만 보관하고, 원소 수 100만 개 초과 또는 지원하지 않는 객체는 재사용하지 않는다. 계산 중 경고·메시지·오류 또는 난수 상태 변화가 발생하면 그 결과를 보관하지 않는다. 난수 상태가 원래 없던 경우도 유지한다.

회귀계수·표준오차·효과크기는 각 종속변수별로 기존처럼 계산한다. VIF 계산 수식과 내부 적합도 변경하지 않는다. 위계적 분석의 기존 직접 단일모형 호출에는 캐시를 추가하지 않았다.

## 실행 시간

번들 R 4.5.3, 시드 714, 2,000행, 예측변수 12개, 종속변수 4개, 일반 OLS, 잔차 진단 활성화 및 자동 강건 추정 비활성화 조건이다. 단일 모형 비교에서는 같은 자료 중 종속변수 하나만 사용했다. 부트스트랩 작업이 0개인지 확인했다.

버전별 새 프로세스 세 개를 순차 실행하고 두 번째 비교는 후보부터 실행했다. 각 조건을 준비 실행한 뒤 전체 분석 5회를 측정했다. 로딩·입력 생성·화면·저장은 제외하며 다른 R 작업과 동시에 측정하지 않았다.

| 조건 | 기존 3회(초, 각 5분석) | 적용 후보 3회(초, 각 5분석) | 중앙값 기존→후보 |
| --- | --- | --- | --- |
| 완전 자료 | 1.14 / 1.15 / 1.28 | 0.83 / 0.85 / 0.91 | 1.15→0.85, 약 26% 감소 |
| 공통 결측 10% | 1.58 / 1.62 / 1.59 | 1.23 / 1.27 / 1.39 | 1.59→1.27, 약 20% 감소 |
| 종속변수별 다른 결측 10% | 1.68 / 1.61 / 1.69 | 1.70 / 1.70 / 1.55 | 1.68→1.70 |
| 단일 종속변수 | 0.39 / 0.42 / 0.40 | 0.42 / 0.40 / 0.33 | 0.40→0.40 |

다른 결측 조건과 단일 모형은 변동 범위에서 작은 차이를 보였다. 이 결과는 지정한 다중 종속변수 OLS 자료에 한정되며 전체 프로그램이나 자동 강건 추정의 개선율이 아니다.

첫 측정 도중 별도 캔버스 모듈의 구문 오류로 앱 로딩이 실패했다. 해당 파일은 수정하지 않았다. 위 표의 최종 측정은 양쪽 모두 `setup_custom_model_canvas_structural_render_tables.R`만 제외한 동일 모듈 구성으로 처음부터 다시 수행한 결과다. 이후 해당 파일의 구문 오류가 해소되어 전체 모듈 로딩, 화면 및 실제 저장 검증은 정상 모듈 구성에서 수행했다. 초기 중단된 측정 수치는 표에 섞지 않았다.

## 호출 및 메모리

실제 전체 분석에서 VIF 함수 호출은 완전 자료 및 공통 결측에서 4→1회로 줄었다. 서로 다른 결측은 4회, 단일 종속변수는 1회였다. 변수 이름이 같아도 실제 분석 행이 달라지면 재계산한다.

이 자료의 보관 항목 `object.size`는 341,744바이트였다. 이는 행렬·결과·설정의 객체 크기이며 추가 프로세스 RSS나 최고 메모리 사용량은 아니다. 보관은 직전 항목 한 개로 제한된다.

## 검증

- `scripts/validate_regression_collinearity_cache.R`: 48개 실제 VIF 반복 사례(일반·상수·특이·결측·행 이름·범주형 설계행렬)에서 값·조건·표준 출력·난수 상태 일치.
- 같은 검증에서 입력값·행 이름·설정 변경, 새 캐시, 크기 제한, 경고·메시지·오류·난수 사용 우회, 난수 상태 부재를 검사했다.
- 전체 분석 네 조건 × 세 쌍의 12개 기존/후보 결과·조건·표준 출력·난수 상태가 일치했다. 독립 프로세스 수식의 `.Environment` 속성만 테스트 사본에서 재귀 제거한 뒤 `identical(..., num.eq=FALSE)`로 비교했다. 제품 결과는 정규화하지 않았다.
- 실제 통합 호출 수 검증 통과.
- 제품 소스와 측정 후보 SHA256 일치: `860C55EFC1A141F63596B4D9708E2134B1C9F67ABAAD1318C8949A0140D9E83D`.

기존 `scripts/validate_regression_coefficients.R`는 `Expected skipped regression Excel sheet`에서 실패했다. 변경 전 분석 소스로 교체한 같은 검증에서도 동일하게 실패하여 이번 캐시 도입으로 발생한 차이는 아니었다. 이 기존 검증 전체가 통과했다고 간주하지 않는다.
