# 로지스틱 위계 모형의 기준 모형 재사용 — 2026-09-14

## 적용 결과

같은 종속변수의 위계적 모형에서 기준 모형(절편만 포함)을 재사용하도록 `R/analysis_logistic.R`에 적용했다. 5만 행·6예측변수·3단계 분석에서 기준 모형 적합이 3회에서 1회로 줄었다. 이전 Hessian 작업 행렬 후보는 포함하지 않았다.

| 입력과 실제 분석 | 기준 3회(초) | 적용 후보 3회(초) | 중앙값 및 감소 |
|---|---|---|---|
| 이항 → 이항 | 1.20 / 1.20 / 1.21 | 1.01 / 1.01 / 1.02 | 1.20 → 1.01, 15.8% |
| 순서형 → 다항 자동 전환 | 4.02 / 4.04 / 4.03 | 3.81 / 3.79 / 3.78 | 4.03 → 3.79, 6.0% |
| 명목형 → 다항 | 3.47 / 3.47 / 3.47 | 2.89 / 2.87 / 2.88 | 3.47 → 2.88, 17.0% |

순서형 입력은 기존 평행선 검정에 따라 다항으로 전환된 자료다. 이 시간을 순수 순서형 적합의 개선율로 해석하면 안 된다. 별도 5천 행 검사에서는 실제 순서형 경로도 기준 모형 1회 적합과 2회 재사용을 확인했다.

## 구현과 범위

`logistic_cached_null()`은 모형 종류, 종속변수 벡터(수준·속성 포함), 행 이름이 정확히 같은 경우에만 재사용한다. 각 종속변수의 단계 반복 직전에 새 환경을 생성해 다른 종속변수·분석 호출과 공유하지 않는다. 캐시 환경은 결과 목록에 추가하지 않는다. `fit_logistic_model()`의 선택 인수 `null_cache`를 생략하면 원래대로 적합한다.

경고나 메시지가 발생한 적합은 저장하지 않고 오류도 그대로 전달한다. 같은 조건에서 반복되는 진단을 생략하지 않도록 했다. 실제 전체 결과의 난수 상태도 비교했으며, 설치된 nnet의 기본 multinom 경로가 `rang=0`일 때 난수를 생성하지 않는 분기를 사용하는 것을 로컬 소스로 확인했다. 적합식, 수렴 허용오차, 적합 알고리즘, 계수 및 검정 계산은 유지했다.

## 측정 방법

번들 R 4.5.3 및 기존 모듈 캐시를 사용했다. 각 버전은 새 프로세스 3개에서 순차 실행했고 두 번째 세트는 순서를 뒤집었다. 각 프로세스에서 이항→순서형→명목형 순서로 측정했다. 시드 719의 연속 예측변수 6개를 두 개씩 추가한 3단계 모형이다. 각 조건 전에 같은 종류의 360행 자료로 준비 실행했다.

입력 생성·부트스트랩·소스 로딩·사전 GC는 시간에서 제외했다. 전체 결과 준비, 진단·표준출력 수집 및 비교용 공식 환경 정규화는 포함했다. 메모리 측정은 시간 측정과 별도로 수행했으며 다른 R 검증을 동시에 실행하지 않았다. 화면 렌더링·저장·프로그램 로딩 시간은 위 시간에 포함하지 않는다.

## 결과 및 출력 검증

- 전체 결과 18조건: 이항·순서형·명목형 × 일반·결측·범주형 예측변수·상수·중복열·반올림 예측변수. 실험 스크립트에서 반올림 사례의 이름 `weights`는 가중 분석을 뜻하지 않는다.
- 추가 전체 결과 6조건: 세 분석 종류 각각 단일 단계 및 3단계, 종속변수 두 개. 결과 개수와 전체 동일성을 확인했다.
- 실측 결과 9쌍과 메모리 측정 결과 3쌍도 일치했다. 전체 반환값·진단·표준출력·난수 상태를 `identical(..., num.eq=FALSE)`로 비교했다. 공식 환경 참조만 `.GlobalEnv`로 통일했으며 수치 허용오차는 사용하지 않았다.

- 지속 검증 `scripts/validate_logistic_null_cache.R`와 기존 `scripts/validate_logistic_analysis.R`이 통과했다. 기존 검증 중 극단 적합에 대한 `glm.fit: fitted probabilities numerically 0 or 1 occurred` 경고가 출력됐으며 검증은 통과했다.
