# 생존분석 이미지 재사용 시 메시지 보존 검토 — 2026-09-14

## 결과

고정된 KM 그림에서 기존 PNG를 재사용하고 저장한 메시지 조건 객체를 다시 전달하는 실험이 통과했다. 제품 캐시는 아직 변경하지 않았다. 이 실험은 캐시 무효화·메모리 제한·실제 저장 연결을 갖춘 구현이 아니라 메시지 보존 가능성을 확인하는 작은 실험이다.

## 실험

번들 R 4.5.3, JIT 3, 기존 모듈 캐시에서 별도 프로세스 3개를 순차 실행했다. 각 프로세스에서 같은 KM 객체로 다음 순서를 실행했다.

1. 처음 PNG를 생성하면서 메시지 조건 객체를 저장한다.
2. 저장한 PNG URI를 반환하며 `message(condition)`으로 메시지를 전달한다.
3. 실제 그림을 다시 생성하여 비교한다.

| 구간 (초) | 1회 | 2회 | 3회 |
| --- | ---: | ---: | ---: |
| 최초 실제 생성 | 1.24 | 1.24 | 1.24 |
| 저장 URI와 메시지 재전달 | 0.00 | 0.00 | 0.00 |
| 실제 재생성 | 1.05 | 1.10 | 1.08 |

0.00초는 측정 분해능에서 작은 값이라는 뜻이다. 이 수치에는 실제 캐시 키 구성·조회·무효화 비용이 없으므로 제품 저장 속도 개선으로 표현하지 않는다. 각 프로세스의 실제 렌더러 호출 횟수는 2회다.

세 경로의 PNG 데이터 URI, 메시지 문구·클래스·호출 정보, 난수 상태가 각 프로세스에서 `identical(..., num.eq=FALSE)`로 일치했다. 메시지는 기존 좌표계 교체 안내이며 클래스는 `rlang_message`, `message`, `condition`, 호출 정보는 NULL이었다. 메시지를 단순 문자열로 바꾸거나 제거하지 않았다.

## 추가로 확인한 캐시 키 문제

동일 결과로 `survival_saved_plot_specs()`를 두 번 호출하면 ID·제목·크기는 동일하지만 반환된 `draw` 함수는 `identical()`이 FALSE다. 각각의 저장 호출에서 만들어진 클로저 환경이 다르기 때문이다. 기존 일반 그림 캐시는 함수도 키에 포함하므로 메시지 재전달 기능만 추가해서는 저장 간 재사용이 해결되지 않는다.

이 확인은 현재 단일 KM 그림 명세에서 수행했다. 서로 다른 그림의 ID만 같다고 같은 이미지로 취급하면 안 된다.

## 제품 적용에 필요한 범위

- 안정적인 그림 실행 함수와 명세: 실제 결과, 곡선 종류, 색상/흑백, 크기·해상도, 언어와 그리기 함수 버전을 구별한다.
- 설정 변경: 기존 캐시의 DPI·options·locale·글꼴 등 구분을 유지하고 테마 관련 변경도 검토한다.
- 메시지: 이번에 확인한 안내 메시지의 조건 정보 보존과 반복 전달을 검증한다. 경고·오류·난수 변화 또는 다른 부수효과가 있는 임의의 그림까지 캐시 가능하다고 일반화하지 않는다. 메시지 핸들러가 설정을 바꾸는 등 부수효과를 갖는 경우도 이번에 검증하지 않았다.
- 세션별 용량 제한·분석 변경 시 무효화와 현재/누적 출력 전체의 동일성을 검증한다.

제품 코드를 변경하지 않았고 PDF·Word·HWPX·Excel 변환이나 설치 파일 빌드도 하지 않았다. 재현 자료는 `output/survival-message-cache-review-20260914/measure.R`, 세 실행의 시간 CSV와 스냅샷 RDS에 있다.
