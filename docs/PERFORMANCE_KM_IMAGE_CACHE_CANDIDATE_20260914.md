## 구현 범위

`output/km-image-cache-candidate-20260914/cache.R`에 검증용 캐시를 구현했다. 제품 저장 버튼에는 연결하지 않았다. 저장마다 생성되는 클로저 대신 안정적인 그리기 함수와 명세를 구분한다.

키는 결과 객체, 곡선 종류, 색상/흑백, 언어, 크기, 해상도, 그리기 함수, 호출자가 제공한 환경 정보다. FIFO 항목·메모리 상한과 clear 기능을 갖는다. 실제 그림 실험의 환경 정보에는 기존 그림 캐시의 DPI/options/locale/작업 경로/Windows 장치·글꼴 설정에 더해 ggplot2 전역 테마와 요소 트리를 넣었다.

캐시는 다음 조건에서만 저장한다.

- 경고가 없고 난수 상태가 변하지 않는다.
- 렌더링 전후 환경 정보가 같다.
- 메시지가 없거나, 기존 좌표계 교체 안내의 문구·클래스·NULL 호출 정보가 정확히 일치한다.

알 수 없는 메시지나 경고는 그대로 전달하고 해당 결과를 저장하지 않는다. 오류는 전파되며 저장하지 않는다. 적중 시 저장된 안내 메시지 조건 객체를 다시 전달한다. 기존 일반 그림 캐시의 동작을 변경하지 않았다.

## 경계 검증

`verify.R`은 동일 키 적중, 결과·곡선·버전·언어·크기·해상도·환경 변경 시 재생성, clear, 항목 수·바이트 제한, 알려진 메시지 재전달을 검증했다. 알 수 없는 메시지·경고·난수 변화·오류·렌더링 중 환경 변경은 재사용하지 않는 것도 확인했다. 메시지·반환값·난수 상태 비교를 포함한다.

## 실제 600dpi 그림 검증

번들 R 4.5.3, JIT 3, 새 프로세스 3개를 순차 실행했다. 기존 KM 분석 객체로 색상 첫 생성→색상 반복→흑백 첫 생성→흑백 반복→색상 별도 재생성→흑백 별도 재생성 순서를 사용했다. 분석을 다시 실행하지 않았다. survival·ggplot2 패키지 로드는 측정 밖이다.

| --- | ---: |
| 색상 첫 캐시 생성 | 1.16 |

0.00초는 측정 분해능에서 작은 값이라는 뜻이다. 고정 순서의 캐시 동작 확인이며 제품 전체 저장 속도 개선률을 의미하지 않는다. 첫 호출 시간을 항상 더 느리거나 빠르다고 일반화하지 않는다.

각 프로세스에서 캐시를 통한 실제 렌더러 호출은 색상 1회·흑백 1회, 총 2회였다. 각 버전의 최초·적중·별도 재생성 PNG URI, 메시지 문구·클래스·호출 정보, 난수 상태가 정확히 동일했다. URI 동일성은 PNG 바이트를 포함한다.
