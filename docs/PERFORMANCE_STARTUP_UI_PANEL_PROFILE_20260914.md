# 초기 UI 구성 비용 검토 — 2026-09-14

## 결론

이번 검토에서는 제품 코드를 변경하지 않았다. 분석 설정은 이미 `lazy_tab_panel()`의 `uiOutput()`으로 지연 구성된다. 초기 UI 구성 시간을 숨겨진 분석 계산 비용으로 해석하거나 동일한 지연 생성을 다시 구현할 근거는 없다.

## 측정

번들 R 4.5.3, JIT 3, 패키지·모듈 로드와 환경설정 적용 후 첫 `app_ui()`를 측정했다. 유효한 모듈 캐시를 사용했다. 각 조건은 별도 프로세스에서 3회 순차 실행했다. 아래 시간은 초이며 브라우저 표시, 서버 초기화, 데이터 읽기를 포함한 전체 앱 시작 시간이 아니다.

helper 시간은 포함 시간이다. 중첩된 `lazy_tab_panel()` 시간을 분석 메뉴에 더하면 안 된다. 래퍼는 인수를 먼저 평가하여 R의 지연 평가로 인한 잘못된 시간 귀속을 줄였다. 0.00초는 비용이 전혀 없다는 의미가 아니다.

추가 3개 프로세스에서 Rprof를 켠 첫 UI 생성은 0.37/0.34/0.33초, 같은 프로세스의 두 번째 생성은 0.08/0.10/0.08초였다. 첫 호출 추가 비용을 시사하지만 JIT, 패키지 내부 초기화, 캐시 각각의 기여는 분리하지 못했다. 각 Rprof 실행은 표본이 단 하나만 기록되어 세부 함수별 비율은 해석하지 않는다. 이 비교는 최적화 전후 비교가 아니며 사용자에게 적용된 속도 향상이 아니다.

## 코드 확인과 검증

- `R/data_ui.R`은 초기 데이터 화면의 태그와 출력 자리만 구성한다. DT 패키지는 `load_app_packages()`에서 이미 로드된다. 데이터 화면 helper 0.14초 전부를 DT 패키지 로딩이나 데이터 계산이라고 볼 수 없다.
- `R/analysis_menu_ui.R`과 `R/ui_helpers.R`의 분석 메뉴는 실제 분석 설정 대신 지연 출력 자리를 구성한다.
- 계측 유무 총 6개 실행의 HTML, 의존성, 경고·메시지, 난수 상태가 동일했다. HTML의 자동 숫자 탭 ID만 정규화했다.
- `R/ui_helpers.R` SHA256은 검토 전후 `7D82C5AB8707320AF2D9596B41ACD0A8AE94B8B9E28B3074C7C9BDECE7815E5D`로 동일하다.
- 제품 코드나 결과 출력 변경이 없어 이번에는 문서 변환 및 설치 파일 빌드를 실행하지 않았다.
