# 첫 KM 그래프 생성 비용 분리 — 2026-09-14

## 결론

첫 KM 실행에는 그래프 관련 패키지의 최초 로딩 비용이 포함돼 있다. 동일한 분석 결과로 그래프를 다시 만들었을 때 비용이 줄었다. 이번에는 계측 자료를 추가했으며 애플리케이션 코드는 변경하지 않았다. 설치 파일도 재빌드하지 않았다.

## 전체 서버 탐색

기존 selected 가시성 모의 세션에서 첫 KM 실행을 프로파일한 경과 시간은 2.12초였다. 함수별 경과 시간은 분석 결과 준비 0.53초, 결과 패널 구성 0.44초, 결합 그래프 생성·그리기 1.07초였다. 마지막 시간에는 위험집단 수 표 생성 0.61초와 주 그래프 생성 0.07초가 포함돼 있다. R의 지연 인자 평가 때문에 이 시간을 독립 단계처럼 합산하면 안 된다.

프로파일에서 패키지 로딩 경로가 관측됐으므로, 위험집단 수 표의 0.61초를 표 데이터 처리 자체의 비용으로 해석하지 않았다. 이 실행은 프로파일과 래퍼 계측이 포함된 탐색 자료다.

## 그래프만 별도 측정

기존에 검증한 72행·2집단 KM 결과 객체를 읽고, 수치 분석을 다시 실행하지 않았다. 번들 R 4.5.3, JIT 3, 기존 모듈 캐시를 사용했다. survfit의 S3 메서드를 등록하기 위해 survival namespace를 측정 전에 로드했다. 새 프로세스 3개에서 각각 동일 그래프를 2회 생성했다.

실제 함수의 평가 순서처럼 위험집단 수 표를 먼저 만들고 주 그래프를 만든 뒤 결합해 그렸다. PNG는 1000×800, res=100으로 고정했다. 중앙값은 다음과 같다(초).

| 단계 | 첫 회 | 두 번째 회 |
|---|---:|---:|
| 위험집단 수 표 ggplot 생성 | 0.29 | 0.02 |
| 주 그래프 ggplot 생성 | 0.08 | 0.03 |
| 축 정렬·grob 생성·그리기 | 0.27 | 0.24 |
| 세 단계 합계 | 0.63 | 0.29 |

합계는 회차별 합계의 중앙값이므로 단계별 중앙값의 합과 다를 수 있다. 장치 열기·닫기와 파일 쓰기 완료 비용은 타이머 범위 밖이다. 실제 Shiny 렌더러의 크기·해상도·이미지 전달 비용과도 다르므로 전체 서버의 1.07초와 직접 비교하지 않는다.

첫 위험집단 수 표 생성에서 ggplot2, S7, scales, gtable, dplyr, tibble 등 15개 namespace가 새로 로드됐다. 두 번째 회에는 이 단계에서 새 namespace가 로드되지 않았다. 감소분 전부가 패키지 로딩이라고 단정할 수는 없다. 첫 호출의 컴파일 등도 함께 달라질 수 있다.

## 중복 빌드 검토

`survival_draw_plot_with_risk_table`은 먼저 주 그래프를 빌드해 x.range를 구한다. 이후 주 그래프와 위험집단 수 표에 같은 시간 범위와 확장 설정을 적용하고, 주 그래프의 x축·범례·여백·caption 배치를 조정한 뒤 grob를 생성한다.

따라서 첫 빌드와 나중의 grob 생성은 동일한 그래프 상태를 대상으로 하지 않는다. 첫 빌드를 단순 제거하거나 변경 전 빌드 결과를 그대로 재사용하면 축 정렬 또는 표시 내용이 달라질 수 있어 이번에는 적용하지 않았다. 그래프 패키지를 초기 로딩 단계로 옮기는 변경도 총비용 감소를 입증하지 못하므로 적용하지 않았다.
