# Select cases and split file

Data Editor now provides Select cases and Split file. Conditions are session-local and reset when the active file changes. Neither operation modifies or deletes source rows.

Active case-selection and split variables are excluded from analysis terms in every loaded-file analysis, regardless of whether a condition leaves one or multiple values. The scoped data carries `statedu_scope_excluded` into workers; preparation entry points remove these names from their explicit variable arguments (including regression blocks, covariates and repeated-measure groups). Original data and menu assignments are preserved, so turning the scope off restores eligibility. Canvas analyses use a pruned analysis snapshot, including connected paths and residual nodes. Required-variable validation applies after exclusion. A common run notification identifies the excluded variables. Survey design metadata is kept separate from analysis terms.

- Both menus use three blocks: available variables, selected variable (arrow or double-click transfer), and conditions. Categorical variables offer category selection or a condition expression using raw codes; continuous variables offer values/ranges or expressions. Inclusive/exclusive lower and upper bounds are configurable, and blank bounds cover the minimum/maximum. Multiple case conditions use OR. Multiple split ranges/expressions define named, non-overlapping groups. Turn off restores all cases.
- Split file selects one variable. Each observed nonmissing category gets a separate run with frozen input options and a snapshot of its own data. Case selection runs first. Empty/unavailable groups are reported rather than replaced with whole-file results.
- Loaded-file analyses use `analysis_dataset`; variable metadata and data editing continue to use `dataset`. Manually entered meta-analysis studies and sample-size calculators are separate inputs, not cases from the active file.
- `analysis_scope_run()` serializes group execution and captures the displayed output after tracked background jobs finish. Current results contain group headings and captured tables/figures. A failed group receives an error section. Users may stop after the current group.
- Output snapshots are static: interactive table controls/duplicate Shiny output IDs are removed from group copies. Model editing continues to use the canvas; rerunning generates new group results.
- Result addition and current HTML/PDF/Word/HWPX/Excel saves use the complete captured collection, including all headings, notes, figures and orientation. Figure export uses PNGs from all groups. HWPX visibility remains restricted to the Korean Results screen.
- Ordinary run buttons, regression syntax, mediation/moderation and structural canvas run paths share the dispatcher. New analyses must use the analysis dataset, dispatcher and tracked result/job values; never apply case filters to the editable source dataset.

Validation: `validate_analysis_scope.R` covers filtering, combinations, missing/empty cases, group sequencing, frozen inputs, asynchronous waiting, cancellation and stale response rejection. `validate_analysis_scope_ui.cjs` uses the real frequency handler and checks distinct group means, identical options, combined filtering, and returning to unsplit analyses. `validate_analysis_scope_exports.R` verifies all displayed table text/group labels/notes in current and accumulated exports across five formats; PDF extraction checks groups and statistics. Existing common canvas figure receiver tests also pass.
