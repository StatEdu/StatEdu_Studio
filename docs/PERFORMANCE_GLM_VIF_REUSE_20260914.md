# GLM VIF 중복 계산 제거 — 2026-09-14

VIF와 가정 점검을 모두 켠 GLM 분석은 같은 모형식·진단 자료로 VIF를 두 번 계산했다. 가정 점검의 최대 VIF와 별도 VIF 표가 한 분석 내부의 공급 함수를 공유하도록 변경했다. 최초 호출이 경고·메시지 없이 반환했을 때만 작은 결과표를 재사용하며, 조건 발생 시 이를 억제하지 않고 이후 호출도 기존대로 계산한다. 오류는 기존대로 전파된다.

계산 시점과 호출 인수는 유지한다. VIF 또는 가정 점검이 꺼져 있으면 불필요한 VIF 계산을 추가하지 않는다. 계산된 모형 행렬이나 회귀 모형을 별도 캐시에 보관하지 않으며 전역 캐시도 없다. 직접 호출하는 `generalized_assumption_checks()`의 기본 공급자는 기존 `generalized_vif_table`이다.

## 전체 분석 시간

| 50,000행 입력 | 기존 3회(초) | 변경 후 3회(초) | 중앙값 |
|---|---|---|---|
| Gaussian, 예측변수 6개 | 0.78 / 0.65 / 0.78 | 0.40 / 0.58 / 0.42 | 0.78 → 0.42, 약 46% 감소 |
| Binomial, 예측변수 12개 | 0.89 / 1.12 / 0.89 | 0.52 / 0.52 / 0.51 | 0.89 → 0.52, 약 42% 감소 |
| Gamma, 예측변수 12개 | 0.85 / 0.85 / 0.86 | 0.67 / 0.67 / 0.68 | 0.85 → 0.67, 약 21% 감소 |

세 모형 모두 세 번의 비교에서 빨라졌다. VIF와 가정 점검을 모두 켰고 강건 표준오차를 사용했다. 이 옵션이 꺼진 분석이나 앱 로딩·화면 렌더링의 개선율이 아니다.

번들 R 4.5.3의 새 프로세스 3개를 순차 실행했다. 각 입력 양쪽 준비 실행 후 GC와 전체 분석 시간을 측정하고 두 번째 프로세스는 순서를 뒤집었다. 다른 R 타이밍 작업은 동시에 실행하지 않았다. 시드 917, 정규 예측변수, eta=0.2*x1-0.1*x2를 사용했다. Gaussian은 eta+정규오차, binomial은 plogis(eta), gamma는 shape=2·scale=exp(eta)/2에서 생성한 완전 자료다. 분석 전 시드 713으로 초기화했다.

시간에는 적합·결과 준비·비교용 스냅샷 구성을 포함한다. 로딩·입력 생성·화면·파일 저장은 제외했다. 메모리 크기·최대 사용량은 별도 측정하지 않았다. 기준 소스에는 직전 결측 패턴 최적화가 포함돼 있다.

## 검증

- 세 모형 × 세 프로세스에서 준비/측정 결과가 수치 허용오차 없이 `identical(..., num.eq=FALSE)`로 일치했다. 반환 내용, 정규화한 전체 대표 모형·저장 호출식, 수치 벡터, 경고/메시지 문자열과 난수 상태를 비교했다. 공식·terms 환경은 통일하고 함수는 인수·본문으로 비교했다. 모든 클로저 환경 자체의 동일성을 주장하지 않는다.
- 변경 전 소스와 후보의 72개 비교 통과: 일반·이항·감마·카운트 모형 × VIF 및 가정 점검 on/off × 정상/경고/메시지/오류의 64개 조합과 각 모형 MI/IPW의 8개 비교다. 범주형 변수를 포함했다. 반환 결과, 오류/경고/메시지 클래스·문자열·발생 순서, 표준 출력 및 난수 상태를 비교했다.
- 동일 검증에서 VIF 실제 호출 횟수를 확인했다. 두 옵션이 켜진 정상 계산은 2회→1회, 경고·메시지 발생 시 2회 유지, 오류 시 1회 유지, VIF 끔은 0회, 가정 점검만 끔은 1회다.
- 지속 검증 `scripts/validate_generalized_vif_reuse.R`도 72개 통과했다. 제품 구현과 재사용 반환 분기를 제거해 매번 계산하도록 한 참조를 비교한다. 변경 전 소스와의 독립 비교는 위 보관 실험에서 수행했다.
- 기존 `scripts/validate_generalized.R` 통과. 일반·이항·음이항, MI/IPW, HTML 및 설정 UI 관련 기존 검증 범위를 포함한다.
- 변경 파일의 `git diff --check` 통과.
