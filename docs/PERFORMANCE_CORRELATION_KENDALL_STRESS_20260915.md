# Kendall 빠른 경로의 범주 수·불균형 확대 검증

> 후속 조정: 이 기록은 최소 길이 조정 전의 검증이다. 현재 128행 사례 45개는 기존 경로를 사용하며, 나머지 51개는 빠른 경로를 사용한다. 조정 후 전체 재검증도 통과했다. [최소 길이 조정](PERFORMANCE_CORRELATION_KENDALL_SMALL_20260915.md) 참고.

## 결과

추가 96개 사례에서 기존 stats::cor.test.default와 현재 제품의 전체 원시 htest·진단·stdout·난수 상태가 정확히 일치했다. 모든 사례가 실제 빈도 집계 경로를 사용했음도 확인했다. 제품 계산 코드는 유지하고 `scripts/validate_correlation_kendall_engine.R`에 이 사례들을 회귀 검증으로 추가했다.

## 추가 조건

128/1,000행 × 2/16/64범주 × 균형·불균형·완전 정상관·완전 역상관·거의 정상관 × 시드 1~3의 90개 조합을 사용했다. 이어 10,000행 × 2/16/64범주 × 균형·불균형의 6개를 추가했다.

균형 자료는 각 범주를 같은 확률로 표집했다. 불균형 자료는 첫 범주 표집 확률을 0.99로 두고 나머지 0.01을 다른 범주에 나눴다. 양쪽 변수의 첫 k개 관측치에는 모든 범주를 넣어 명시한 범주 수가 실제로 존재하도록 했다. 따라서 최종 불균형 비율이 정확히 99%라는 뜻은 아니다. 완전 정상관은 y=x, 역상관은 y=k+1-x, 거의 정상관은 y=x에서 마지막 관측치의 범주를 하나 변경했다.

Kendall, exact=FALSE, 번들 Windows R 4.5.3 및 영어 UTF-8 로캘이다. 원래 검정이 오류 없이 완료됐는지, 현재 엔진이 활성화돼 있는지, 각 입력에서 빠른 도우미가 NULL 대신 값을 반환하는지를 확인했다.

## 확인 범위

`identical(..., num.eq=FALSE)`로 전체 원시 검정 객체, 경고·메시지의 클래스와 내용, stdout, `.Random.seed`를 비교했다. 결과 반올림·정규화·허용오차를 사용하지 않았다. 96개 모두 불일치가 없었다.

영구 검증 스크립트에 추가한 뒤 전체를 다시 실행해 기존 720개 원시 검정, 직접 cor 경계/복귀 16개, 방법·exact 조합 18개 및 새 96개가 모두 통과했다. 기존 버전·플랫폼·함수 소스 보호와 엔진 재사용 검사도 유지했다.

이번 작업은 정확성 확대 검증이다. 새로운 성능 측정이나 지원 범위 확대는 하지 않았다. 특히 64범주의 작은 자료에서도 빨라진다고 주장하지 않는다. 전체 분석 결과의 재측정·출력 생성·UI/내보내기 검증·배포 빌드도 수행하지 않았다.
