# KM 메시지 재전달 캐시 최종 호환성 검사 — 2026-09-14

## 결정

앞선 검증용 KM 캐시 후보를 제품 적용 대상에서 제외했다. 캐시 적중 때 메시지가 발생하는 그래픽 장치 상태가 원래 렌더링과 달랐다. 제품 코드와 저장 버튼은 변경하지 않았다.

기존 실험에서 PNG·HTML·메시지 문구·클래스·호출 정보·난수 상태가 같았다는 결과를 뒤집는 것은 아니다. 다만 그 검증 항목만으로 전체 동작 보존을 판단할 수 없다는 추가 근거다.

## 재현

기존 실제 KM 결과와 600dpi PNG 생성 함수를 사용했다. 같은 메시지 처리기에서 문구와 `grDevices::dev.cur()`를 기록했다. 최초 생성, 캐시 적중, 별도 새 생성 순으로 실행했다.

| 경로 | 메시지 처리 중 장치 |
| --- | --- |
| 최초 실제 렌더링 | png, 장치 2 |
| 캐시 적중 | null device, 장치 1 |
| 별도 실제 렌더링 | png, 장치 2 |

세 경로의 PNG URI는 동일했다. 최초와 별도 실제 렌더링의 관측값 전체도 동일했다. 그러나 캐시 적중의 메시지 장치 상태는 달랐다. 이 검사는 처리기에서 장치를 관찰할 뿐 수정하지 않았다.

이 결과가 현재 앱 화면에 이미 오류가 발생했다는 뜻은 아니다. 후보가 메시지 처리기에 제공하는 실행 환경을 보존하지 않는다는 호환성 차이다. 출력이나 장치 상태에 관여하는 처리기까지 동일하게 동작한다고 보장할 수 없다. 임시 PNG 장치를 열고 메시지만 재전달하는 방식도 원래 메시지 발생 시점의 그림 상태를 복원한 것으로 볼 수 없어 적용하지 않았다.

## 작업 정리

- 실험 캐시 파일에 REJECTED 상태와 근거 문서를 표시했다.
- 이전 HTML 통합 보고서에도 후속 제외 결정을 기록했다.
- 메시지를 버리거나 기존 공통 캐시의 조건 보존 정책을 완화하지 않았다.
- 이미 작동 중인 회귀·상관 등의 그림 캐시와 누적 HTML 스냅샷 재사용은 유지했다.
- 제품 변경이 없어 현재/누적 PDF·Word·HWPX·Excel 변환과 설치 파일 빌드는 실행하지 않았다.

재현 스크립트와 결과는 `output/km-cache-saved-flow-20260914/message_device.R`, `message-device.rds`에 있다. 이 후보의 제품 연결 검토는 여기서 종료한다. 이후 개선 작업은 다른 수치 계산이나 부수효과 없는 중복 작업에 집중한다.
