## 구간 관측

별도 계측 실행 12건에서 관측한 함수별 시간 범위다. 호출되지 않은 조건까지 포함하는 시간 0은 호출 횟수 CSV와 함께 구분해야 한다.

| 함수 | 시간 범위(초) |
|---|---:|
| Gwet AC1/AC2 | 0.11–0.14 |
| Krippendorff alpha | 0.07–0.10 |
| Percent agreement | 0.05–0.08 |
| Light kappa | 0.00–0.01 |
| Fleiss kappa | 0.00–0.02 |
| 범주 수준 준비 | 0.00–0.02 |
| 권장 결과 구성 | 0.00–0.02 |

0.00초는 타이머에서 잡히지 않은 작은 비용 또는 미호출일 수 있으며 비용이 없다는 뜻이 아니다. 계측 실행의 구간 시간을 별도 비계측 전체 시간과 더하거나 빼서 정확한 비중을 산출하지 않았다. 모든 내부 동작을 빠짐없이 계측한 프로파일도 아니다.

Light/Fleiss는 순서형 경로에서 실행되지 않는다. 명목형의 해당 함수에는 완전 사례가 전달되므로 결측이 있으면 처리 행 수도 줄어든다. 결측이 늘수록 일반적으로 분석이 빨라진다는 결론을 내릴 수 없다.

## 동일성 및 다음 범위

4개 자료 조건 × 3개 프로세스에서 워밍업 대비 비계측 결과와 계측 결과를 각각 `identical(..., num.eq=FALSE)`로 비교했다. 전체 반환 객체·조건 클래스/본문/순서·표준 출력·RNG가 일치했다. 수치 허용오차나 정규화는 사용하지 않았다. 정상 자료 반복 시험이며 새로운 예외 주입이나 개별 커널 경계 검증을 수행한 것은 아니다.

다음 후보는 Gwet의 매 행 문자열 변환·범주 매칭·행 추출이다. 다만 숫자/혼합형/사용자 클래스의 변환 의미와 누적 순서를 유지해야 한다. 이번 측정은 후보 선정을 위한 근거이며 해당 처리를 줄여 수치가 보존되거나 속도가 개선된다는 입증은 아직 아니다. 이전 Light 범주 코드 후보가 전체 실행에서 불안정했다는 판단도 유지한다.
