# Friedman 동순위 빈도 계산 최적화 — 2026-09-14

## 적용 결과

20,000행 × 6회 측정의 비모수 반복측정 전체 분석에서 중앙 실행 시간이 연속형 **2.01→0.97초(약 52%)**, 순서형 **1.50→0.55초(약 63%)**로 줄었다. 각 입력의 3회 비교 모두 개선됐다. 이 시간은 Friedman 검정뿐 아니라 Wilcoxon 사후검정 15쌍과 요약·표시표 생성을 포함한다. 특정 자료 조건의 측정이며 다른 자료에서 동일한 비율을 보장하지 않는다.

## 구현

`R/analysis_paired_rm.R`에 `paired_rm_build_friedman_engine()`과 지연 초기화하는 `paired_rm_friedman_test()`를 추가했다. 일반 반복측정의 Friedman 호출 두 곳과 `R/analysis_nonparametric_paired.R`의 호출 한 곳을 연결했다.

설치된 `stats`의 `friedman.test.default` 코드 서명이 검증된 번들 구현과 일치할 때만 함수 복사본의 다음 문장을 대체한다.

```r
TIES <- tapply(c(r), row(r), table)
```

평균 순위는 정수 또는 반정수이므로 `2 * r[i, ]`를 `tabulate()`의 인덱스로 사용하고 빈도가 0인 구간을 제거한다. 각 행의 오름차순 동순위 빈도와 정수 저장형을 유지한다. 뒤의 `u^3 - u`, 전체 합산, 통계량과 p값 계산, 순위 계산, 결측 행 처리 및 반환 객체 구성은 원래 함수 그대로다.

일반 double/integer 행렬에만 이 경로를 사용한다. 그 밖의 입력은 원래 `stats::friedman.test()`로 처리한다. 검증한 코드 서명 또는 대상 문장이 달라져도 원래 함수로 돌아간다. `stats` 네임스페이스를 수정하지 않는다. 엔진은 첫 호출에서 만들고 재사용하므로 모듈 로드 시 함수 서명 계산을 추가하지 않는다. 앱의 기존 호출은 모두 지역 변수 `y`를 전달하며 기존 데이터 이름 표기도 유지된다.

코드 서명은 `deparse(reference)`를 줄바꿈으로 연결한 텍스트의 SHA256으로 검사한다. 초기 연구에서 함수 객체 직렬화 서명은 실행 후 비교에서 일치하지 않아 원래 경로로 돌아가는 문제가 발견됐다. 최종 구현은 코드 텍스트 서명을 사용하며, 검정 실행 전후에 같은 엔진이 생성되는지도 검사한다. 알려지지 않은 코드를 강제로 최적화하는 방식으로 검증을 완화하지 않았다.

## 실제 제품 경로 측정

번들 R 4.5.3. 데이터 seed 939, capture seed 718. 연속형은 정규 난수, 순서형은 1~5 균등 표본이고 결측치가 없다. 이전 변화 여부 검사 최적화가 포함된 소스를 이번 기준본으로 사용했다.

3개의 새 R 프로세스를 순차 실행하고 각 입력에서 양쪽을 예열한 후 측정했다. 두 번째 프로세스는 입력 순서와 기존/개선 실행 순서를 뒤집었다. 시간 단위는 초다.

| 입력 | 기존 1/2/3 | 개선 1/2/3 | 중앙값 기존→개선 |
|---|---|---|---|
| 연속형 | 2.44 / 1.91 / 2.01 | 1.00 / 0.92 / 0.97 | 2.01→0.97 |
| 순서형 | 1.53 / 1.50 / 1.45 | 0.55 / 0.61 / 0.51 | 1.50→0.55 |

초기 연구 복사본에서도 독립 3회 비교를 수행했다. 연속형 기존 2.02/1.89/2.05→개선 0.94/0.96/0.97초, 순서형 1.42/1.44/1.42→0.50/0.61/0.51초였다. 위 표는 지연 초기화 및 입력 분기가 포함된 실제 적용 코드로 다시 확인한 결과다. 두 측정 세트를 섞어 중앙값을 계산하지 않았다. 메모리 사용량과 최초 앱 로딩 시간은 이번에 측정하지 않았다.

## 검증

`scripts/validate_friedman_ties.R`:

- 원시 `htest` 135조건: 통계량, 자유도, p값, 이름, 클래스까지 전체 반환값을 `identical(..., num.eq=FALSE)`로 비교. 경고/메시지와 오류의 클래스·문구, 표준출력, RNG 상태도 비교했다. 작은 표본, 빈 행/열, 다수 동순위, 상수, 결측, NaN, Inf, 인접 double, 정수, 논리/문자/복소수의 기존 경로, dimnames를 포함한다.
- 동순위 24조건: 원래 빈도표에서 메타데이터만 제거한 정수 빈도 순서와 후보 빈도를 정확히 비교하고, 보정항의 원시 합도 정확히 비교했다. 원시 `htest`와 전체 결과 비교에는 정규화를 사용하지 않았다.
- 전체 분석 48조건: 일반/비모수 반복측정 × 연속형/순서형/이분형 × 정상/결측/변화 없음/마지막 셀 변화 × 가정검사 켬/끔. Holm 조정·중앙값 옵션을 포함하며 결과와 진단·표준출력·RNG가 일치했다. 정상/결측 입력은 오류가 아님도 확인했다. 변화 없는 입력의 기존 오류는 오류 보존 검사로 구분한다.
- 서명이 다른 함수의 원래 경로 복귀, 검정 실행 후 엔진 코드 유지, `stats` 원본 함수가 바뀌지 않았음을 확인했다.

대규모 연구 및 실제 제품 경로 측정에서도 각각 예열/실측 전체 결과가 정확히 일치했고, 두 대규모 입력의 원시 `htest`도 기존 함수와 일치했다. 제품 엔진과 연구 후보의 실행 코드 텍스트가 같은지 추가 확인했다.

기존 `scripts/validate_paired_rm_change_check.R`도 재실행해 경계 입력 170개, 전체 대응·반복측정 24개, 혼합 반복측정 3개를 통과했다. 반복 실행한 같은 테스트 수를 서로 다른 사례로 합산하지 않았다. 수정 파일의 `git diff --check`도 통과했다.

UI, 결과 구조, 내보내기 코드는 변경하지 않았으며 문서 변환 및 설치 파일 빌드는 재실행하지 않았다.
