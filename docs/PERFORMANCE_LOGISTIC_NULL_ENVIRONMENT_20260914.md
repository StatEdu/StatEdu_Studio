# 로지스틱 기준 모형 캐시의 공식 환경 축소 검토 — 2026-09-14

## 판단

후보는 적용하지 않았다. 최고 메모리는 약 22.59 MB 줄었으나 다항 전체 분석은 세 쌍 모두 느려졌다. 앞서 적용한 기준 모형 재사용은 그대로 유지한다.

## 후보와 참조 확인

현재 기준 모형의 공식은 `fit_logistic_model()` 실행 환경을 참조한다. 캐시가 이 공식을 가진 모형을 보관하면 그 환경의 `model_data`, `null_cache` 및 다른 지역 변수에도 접근할 수 있다.

후보는 기준 공식의 반응이 단순 심벌이고 종속변수 이름과 정확히 같을 때만, 이미 `make_formula()`에서 만든 전체 모형 공식의 작은 환경으로 연결한다. 이 환경에는 `y`, `xs` 인수만 있다. 계산식·반응 값·모형 데이터·캐시의 키와 저장 규칙은 변경하지 않았다. 단순 열 이름 이외의 반응 표현식은 기존 환경을 유지한다.

`references.R`에서 이항·순서형·다항 세 종류의 실제 기준 모형 공식 환경을 검사했다. 기준 환경에 `model_data`, `null_cache`가 있고 후보 환경의 지역 바인딩은 `y`, `xs`뿐임을 확인했다. 이 검사는 환경 참조 구조에 관한 것이며 그 자체로 메모리 절감량을 뜻하지 않는다.

## 별도 메모리 측정

5만 행·6예측변수·3단계 다항 분석의 새 프로세스 최고 작업 집합이다.

| 버전 | 3회(bytes) | 중앙값(bytes) |
|---|---|---|
| 현재 캐시 구현 | 380891136 / 382779392 / 380665856 | 380891136 |
| 공식 환경 축소 후보 | 358305792 / 356655104 / 366907392 | 358305792 |

중앙값 감소는 **22,585,344 bytes(약 22.59 MB, 5.9%)**다. 전체 프로세스 최고 사용량이며 캐시 객체만의 크기가 아니다. 캐시 도입 이전 코드를 이번 실험에서 함께 측정하지 않았으므로 이전 보고서의 다른 실행과 직접 차감해 추가 절감률을 계산하지 않는다.

## 전체 분석 시간

5만 행의 예측변수 6개를 두 개씩 추가한 3단계 모형이다.

| 입력과 실제 분석 | 현재 3회(초) | 후보 3회(초) | 중앙값(초) |
|---|---|---|---|
| 이항 → 이항 | 1.04 / 1.03 / 1.02 | 1.03 / 1.01 / 1.03 | 1.03 → 1.03 |
| 순서형 → 다항 자동 전환 | 3.81 / 3.83 / 3.82 | 4.00 / 3.97 / 4.06 | 3.82 → 4.00 |
| 명목형 → 다항 | 2.93 / 2.92 / 2.89 | 3.08 / 3.11 / 3.14 | 2.92 → 3.11 |

명목형 다항은 중앙값 약 6.5%, 순서형 입력의 자동 전환 경로는 약 4.7% 느려졌다. 이항은 동일했다. 프로파일링이나 GC 원인 분석은 하지 않았으므로 속도 저하의 내부 원인을 특정하지 않는다. 3회 측정으로 통계적 유의성을 주장하지 않는다.

번들 R 4.5.3과 기존 모듈 캐시를 사용했다. 각 버전은 새 프로세스 3개에서 순차 실행했고 두 번째 세트의 순서는 반대로 했다. 시간 측정 전에 같은 분석 종류의 360행 자료로 준비 실행했다. 입력 생성·부트스트랩·소스 로딩·사전 GC는 제외하고 전체 결과 준비와 진단/표준출력 수집, 비교용 공식 환경 정규화는 포함했다. 메모리 측정과 시간 측정은 별도로 순차 수행했다. 프로그램 로딩이나 화면 렌더링 시간은 측정하지 않았다.

- 공식의 환경 변경이 모형 객체의 모든 외부 재평가 용도에서도 동일하다는 검증은 하지 않았다. 확인한 범위는 앱의 전체 결과 생성 경로와 위 참조 검사다.
