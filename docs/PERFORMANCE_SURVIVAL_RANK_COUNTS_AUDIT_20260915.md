# 생존분석 위험집단·사건 수 사전 집계 재검증

## 판단

가중 순위검정의 위험집단·사건 수 사전 집계는 유지한다. 관련 함수의 컴파일 조건을 맞춘 이번 전체 Kaplan–Meier 결과 준비 측정에서도 24회 중 23회 단축됐고, 전체 반환값·진단·stdout·난수 상태가 정확히 일치했다. 성능이 재현되지 않아 되돌린 공통 스칼라 이동과는 별개의 변경이다. 이번 작업에서 제품 코드는 변경하지 않았다.

## 비교 조건

`output/survival-rank-counts-audit-20260915/baseline.R`은 사전 집계 적용 전 소스이고 `current.R`은 스칼라 이동을 되돌린 현재 소스다. 두 소스의 차이가 집계 도우미 추가 및 가중 순위검정의 집계 호출/기존 경로 분기에 한정되는 것을 확인했다.

각 소스를 별도 환경에 읽고 양쪽의 다음 함수를 `compiler::cmpfun`으로 명시적으로 컴파일했다.

- `prepare_km_single_analysis_result`
- `survival_weighted_rank_test`
- `survival_km_posthoc_table`

현재 소스에만 있는 `survival_rank_counts`도 명시적으로 컴파일했다. 앞선 사후검정 검토에서 발견한 하위 검정의 컴파일 차이를 줄이는 조건이다. 모든 의존 함수의 JIT 상태나 운영체제 실행 상태까지 통제한 실험은 아니다.

5,000행·4집단, 연속/동점 시간, 지연 진입 없음/있음, Breslow/Tarone–Ware의 8조건을 새 R 프로세스 세 개에서 순차 측정했다. 양쪽 예열 후 측정했고 두 번째 프로세스는 기존/현재 실행 순서 및 연속/동점 자료 순서를 뒤집었다. 평가 시점은 10/20이며 기본 결과 표를 사용하고 그림은 제외했다. 전체 결과 준비와 반환값·진단·stdout·난수 상태 수집이 측정 범위다. 함수별 추적은 넣지 않았다.

## 시간

세 실행의 중앙값을 초 단위로 소수 둘째 자리까지 표시했다. 원시 시간은 `timing-1.csv`부터 `timing-3.csv`에 보존했다.

| 시간 자료 | 지연 진입 | 검정 | 기존 | 사전 집계 |
|---|---|---|---:|---:|
| 연속 | 없음 | Breslow | 0.69 | 0.08 |
| 연속 | 없음 | Tarone–Ware | 0.50 | 0.08 |
| 연속 | 있음 | Breslow | 0.80 | 0.09 |
| 연속 | 있음 | Tarone–Ware | 0.64 | 0.10 |
| 동점 | 없음 | Breslow | 0.07 | 0.03 |
| 동점 | 없음 | Tarone–Ware | 0.06 | 0.02 |
| 동점 | 있음 | Breslow | 0.08 | 0.03 |
| 동점 | 있음 | Tarone–Ware | 0.10 | 0.03 |

연속시간 네 조건은 총 12회 모두 단축됐다. 각 조건의 중앙값 기준 약 84~89% 감소했다. 동점 자료는 12회 중 11회 단축됐다. 유일한 증가 사례는 두 번째 실행의 동점·진입 없음·Breslow로 0.08→0.21초였다. 같은 조건의 다른 실행은 0.06→0.01초와 0.07→0.03초였다. 해당 증가의 원인은 분리하지 않았고, 모든 호출에서 빨라진다고 주장하지 않는다.

이 결과는 지정된 5,000행·4집단 조건의 결과 준비 성능이다. UI·그림 생성·내보내기·프로그램 로딩 시간이나 다른 자료 규모에 그대로 적용할 수 없다. 앞선 다른 실험의 함수 단독 시간과 비율을 섞지 않았다.

## 정확성 및 재현

`check.R`은 각 조건의 기존/현재 예열 결과를 비교하고, 양쪽 시간 측정 결과도 같은 기준 결과와 비교한다. `identical(..., num.eq=FALSE)`로 전체 반환값, 경고/메시지/오류, stdout 및 `.Random.seed`를 비교하며 결과 수치의 반올림·정규화·허용오차를 사용하지 않는다. 기존 결과가 오류로 종료하지 않았음도 검사한다. 8조건 × 3프로세스의 모든 검증이 통과했다.

R 4.5.3 번들 런타임, `English_United States.utf8`, 패키지 자동 설치 비활성화, 기존 모듈 캐시 경로를 사용했다. 재현은 저장소 루트에서 동일 환경 변수를 설정한 뒤 `check.R`에 인수 1, 2, 3을 각각 전달하여 순차 실행한다. 별도 그림/내보내기 검증이나 배포 빌드는 수행하지 않았다.
