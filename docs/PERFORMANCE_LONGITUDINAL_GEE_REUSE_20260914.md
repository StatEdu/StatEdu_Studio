# GEE 선택 모형의 민감도 분석 재사용

## 적용 내용

`R/analysis_longitudinal.R`에서 기본 GEE 적합 후 민감도 분석이 같은 상관구조를 다시 적합하던 작업을 재사용하도록 변경했다. 같은 분석 호출 안에서 동일한 준비 데이터, 반응/시간/ID, 설명변수, 가중치, cluster, offset, exponentiate 인자로 적합한 결과만 전달한다. 전역 캐시는 사용하지 않는다.

적용 범위는 gaussian/binomial/poisson/gamma, independence/exchangeable/ar1, random_slope가 FALSE인 경우다. 첫 적합에서 경고 또는 메시지가 발생하거나 RNG 상태가 달라지면 기존처럼 재적합한다. 기존 경고와 메시지를 억제하지 않는다. 오류 처리도 유지한다. 비정수 이항 가중치에서 발생하는 실제 패키지 경고 역시 재적합 경로를 사용한다.

QIC는 기존 `geepack::QIC`를 그대로 호출하므로 내부 independence 재적합 3회는 유지한다. 다른 상관구조, 음이항 GLM 경로, LMM/GLMM/panel의 재적합 정책은 변경하지 않았다. 민감도 함수의 새 선택 인자는 기본 NULL이므로 기존 호출은 기존 동작을 유지한다.

## 성능

번들 R 4.5.3에서 seed 936, 5,000명 × 4시점 = 20,000행, 공변량 2개, 선택 상관구조 exchangeable, 기본 가정 검토를 포함한 전체 분석을 측정했다. 워밍업 후 독립 프로세스 3개를 순차 실행했으며 두 번째 프로세스에서는 변경 후 코드를 먼저 측정했다. 로딩 시간은 제외했다.

| 분포 | 변경 전 1 / 2 / 3 (초) | 변경 후 1 / 2 / 3 (초) | 중앙값 |
|---|---|---|---|
| gaussian | 2.56 / 2.15 / 2.47 | 1.75 / 1.91 / 1.72 | 2.47 → 1.75초, 약 29% 감소 |
| binomial | 1.96 / 2.15 / 1.96 | 1.77 / 1.70 / 1.74 | 1.96 → 1.74초, 약 11% 감소 |

두 분포 모두 세 번의 실행에서 개선됐다. 이 수치는 해당 합성 자료와 실행 환경의 결과이며 모든 자료에 같은 개선율을 보장하지 않는다. 정상 재사용 조건에서 앱 적합 함수 호출 수는 4회에서 3회로 줄었다.

## 동일성 검증

`scripts/validate_longitudinal_gee_reuse.R`의 48개 조건을 통과했다.

- 4개 분포 × 3개 상관구조 × 가중치 유무: 24개. exponentiate 옵션을 달리하고 Poisson에는 exposure offset을 포함했다.
- 4개 분포 × 경고/메시지/RNG 소비/오류 주입: 16개.
- 4개 분포 × random_slope TRUE: 4개. 재사용하지 않는 것을 확인했다.
- 4개 분포 × 결측 행 및 역순 입력: 4개.

전체 반환 객체, 조건의 클래스/본문/순서, 표준 출력, 최종 RNG 상태를 `identical(..., num.eq = FALSE)`로 비교했다. QIC 메서드 반환값도 계측하여 각 정상 분석에서 3개의 6원소 벡터(QIC, QICu, Quasi Lik, CIC, params, QICC)를 수치 허용오차 없이 비교했다. 표시용 반올림 값만 비교한 것이 아니다. 적합 호출 수를 검사하여 정상 재사용과 예외 재적합을 각각 확인했다.

비교에서는 formula/terms 환경과 함수 객체 표현을 정규화했다. call에 직접 저장된 함수 머리는 고정 심벌로 바꾸고 호출 인자는 보존했다. 수치 자료를 반올림하거나 허용오차로 비교하지 않았다. 원시 환경·함수 객체까지 동일하다는 의미는 아니다.

지속 검증 스크립트는 참조 경로에서 선택 모형 전달을 무시하여 재계산하게 한다. 추가로 변경 전 소스 스냅샷을 직접 로드한 독립 비교에서도 같은 48개 조건이 통과했다. 성능 측정의 워밍업 및 측정 결과 역시 변경 전 소스와 직접 비교하여 일치했다.

## 종합 테스트의 제한

기존 `scripts/validate_longitudinal.R`을 실행했으나 Excel 셀 비교(`exported[cell$row + 2L, cell$col]`)에서 실패했다. 변경 전 소스를 로드하여 같은 종합 테스트를 다시 실행했을 때도 동일한 assertion에서 실패했다. 따라서 이 실패를 이번 재사용 변경에 의한 회귀로 보지는 않지만, 종합 테스트 전체가 통과했다고 보고하지 않는다. 해당 Excel 비교 문제는 해결하지 않았고 실패 지점 뒤 검사는 실행되지 않았다.

분석 출력 형식과 내용은 변경하지 않았다. 전체 PDF/Word/HWPX 변환 및 설치 파일 빌드는 실행하지 않았다. 기존 작업 트리의 다른 변경은 유지했다. 대상 파일의 `git diff --check`는 통과했다.
