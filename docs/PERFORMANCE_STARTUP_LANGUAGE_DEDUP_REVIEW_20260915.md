# 자동 언어 입력 중복 억제 후보 — 미반영

## 변경 후보와 결론

`easyflowSendAppLanguage()`의 자동 전송 한 곳에서만 `{priority: 'event'}`를 제거하고 Shiny의 기본 입력 전송을 사용하는 후보를 시험했다. 0/100/500/1000ms 재시도 예약과 명시적인 사용자 언어 적용 함수는 변경하지 않았다. 별도 캐시를 제품에 추가하지 않았다.

초기 data_steps 재전송 횟수는 줄었지만 화면 준비 시간의 일관된 개선을 확인하지 못해 **후보를 제품에 적용하지 않았다.** 전송 횟수 감소와 사용자가 기다리는 시간 감소를 구분한다.

## 실험

기존 JavaScript를 snapshot으로 보관하고 Playwright route에서 기준 또는 후보를 제공했다. 해당 리소스 route가 실제 사용됐고 치환 대상이 정확히 한 곳인지 검사했다. 기준도 같은 route를 사용했다. 디스크의 제품 JavaScript는 수정하지 않았다.

각 실행은 새 R 프로세스 및 headless Chrome이며, 모듈 캐시 hit·초기 한국어·미로드 데이터 조건이다. 3쌍을 순차 실행하고 두 번째 쌍은 후보를 먼저 실행했다. 준비 완료 조건은 기존의 파일 입력 생성, 파일 버튼 trial click, Shiny busy 해제 및 두 프레임 대기와 같다. Chrome 시작은 타이머 밖이며 Electron 시작은 제외한다.

|실행|기준 준비 시간|후보 준비 시간|기준/후보 data_steps 횟수|
|---|---:|---:|---|
|1|2.5578초|2.5018초|4 / 2|
|2|2.4582초|2.4814초|4 / 2|
|3|2.4494초|2.5228초|3 / 2|
|중앙값|2.4582초|2.5018초|—|

각 기준에서 첫 출력 이후에는 같은 payload가 반복됐다. 후보에서도 첫 출력 이후 같은 payload가 한 번 더 관측됐다. 횟수는 결과 캡처 시점까지이며 이후 모든 재시도를 포괄하는 고정 시간 창은 아니다. 앞선 실험과 같은 3,197문자 payload를 기록했지만 길이 일치만으로 기준/후보의 모든 표시 내용이 정확히 같다고 주장하지 않는다.

R 시작과 페이지 준비 변동이 포함된다. 소켓 연결 관측→준비 완료의 중앙값은 기준 약 915ms, 후보 약 909ms로 차이가 작고 회차별 방향도 일정하지 않았다. 따라서 후보가 본질적으로 느리다고 결론 내리지도 않는다. 현재 시험에서 체감 지연을 줄이는 근거를 얻지 못했다는 판단이다.

## 검증 범위와 보류 이유

6회 모두 파일 선택 버튼의 조작 가능 검사를 통과했고 JavaScript pageerror 및 화면에 표시된 Shiny 오류가 없었다. 재시도와 명시적 언어 적용 코드는 그대로 두었지만, 실제 영어 초기 표시·언어 전환·설정 복원·소켓 재연결은 이번에 검증하지 않았다. 성능 채택 기준에서 이득이 확인되지 않아 해당 확대 검증 전에 보류했다. 이 기능들이 검증됐다는 의미로 ‘보존 확인’이라 표현하지 않는다.

추후 이 후보를 채택하려면 위 기능 검증과 실제 화면 내용 비교를 수행하고, 동일한 시작 조건에서 의미 있는 속도 개선 또는 별도의 안정성 이점을 입증해야 한다. 재전송 횟수만으로 적용하지 않는다.
