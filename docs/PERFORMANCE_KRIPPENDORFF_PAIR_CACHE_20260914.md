# Krippendorff alpha 쌍 인덱스 재사용 확대

## 적용

interrater_krippendorff_alpha의 행별 관측 불일치 계산에서 유효 평가자 수별 쌍 인덱스를 재사용하도록 변경했다. 이전에는 바로 이전 크기만 재사용하여, 결측 때문에 평가자 수가 바뀌었다 돌아오면 동일한 combn을 다시 실행했다.

캐시는 함수 호출 안에서만 존재하고 실제 사용된 32명 이하 크기만 저장한다. 더 큰 크기는 기존처럼 직전 크기를 재사용한다. 쌍 순서, 거리 함수, 단위 가중치, 합산 순서, 적격 행 선택 및 기대 불일치 계산은 그대로다. 연속형 헬퍼의 전체 pooled 쌍 생성도 변경하지 않았다. 기존 Gwet 캐시와는 각 함수 호출의 독립적인 지역 상태다.

## 전체 분석 성능

번들 R 4.5.3, 자료 seed 939, 5,000행·8평가자, A–E와 NA를 같은 확률로 표집했다. 명목형(category)/순서형(ordered)의 prepare_interrater_agreement_results 전체 실행을 현재 제품과 비교했다. 기준 소스에는 직전 Gwet 최적화가 이미 포함된다.

독립 프로세스 3개를 순차 실행하고 워밍업 후 두 번째는 후보부터 측정했다. 로딩을 제외하고 전체 결과 캡처를 포함한다.

| 유형 | 기존 1 / 2 / 3 (초) | 변경 1 / 2 / 3 (초) | 중앙값 |
|---|---|---|---|
| 명목형 | 0.31 / 0.22 / 0.25 | 0.19 / 0.22 / 0.17 | 0.25 → 0.19초 |
| 순서형 | 0.16 / 0.17 / 0.14 | 0.16 / 0.11 / 0.12 | 0.16 → 0.12초 |

두 유형 모두 두 번 빨라졌고 한 번은 같은 표시 시간이었다. 중앙값 기준 약 24%와 25% 감소다. 짧은 실행의 측정이며 모든 입력의 개선율을 보장하지 않는다. 유효 평가자 수가 바뀌지 않으면 기존 캐시도 작동한다.

별도 Krippendorff 함수 계측에서 명목형·순서형 combn 호출은 각각 3,641→7회였다. 전체 분석의 다른 함수 호출은 포함하지 않는다. 계측 전후 원시 계수와 RNG가 일치했고 trace는 별도 프로세스에서 사용 후 해제했다.

## 검증

각 워밍업과 측정에서 전체 반환 결과, 조건 클래스·본문·순서, 표준 출력 및 RNG가 `identical(..., num.eq=FALSE)`로 일치했다. 수치 허용오차나 정규화는 사용하지 않았다.

`scripts/validate_krippendorff_pair_reuse.R`에 32/33/40평가자 조건을 추가했다. 평가자 수 1/2/3/10/20/32/33/40, 완전·결측·희소·상수·빈·factor 자료와 nominal/ordinal/continuous 조합, 큰/작은 연속값 조건을 포함한 147개 원시 계수·조건·RNG 비교가 통과했다.

변경 직전 실제 소스와의 비교, 파일 인수 없는 독립 참조 비교를 각각 실행했다. 같은 147개 조건을 두 참조 방식으로 확인한 것이며 별개 자료 294종으로 합산하지 않는다. 독립 참조는 매 행에서 combn(row, 2L)를 수행한다.

기존 `scripts/validate_interrater.R`가 통과했고 제품 Krippendorff 함수 본문과 측정 후보의 동일성도 확인했다. 일반 화면에서 사용하지 않는 continuous 헬퍼도 원시 검증에는 포함했다.

표시·출력 내용과 형식은 변경하지 않았다. 전체 형식 변환과 설치 파일 빌드는 실행하지 않았다. 기존 Gwet·ICC 및 다른 작업 트리 변경은 유지했다.
