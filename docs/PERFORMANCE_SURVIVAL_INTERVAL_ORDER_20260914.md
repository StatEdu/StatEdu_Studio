# Start-stop 시작 시점 선택 재사용과 정렬 생략 — 2026-09-14

`survival_preflight()`의 일반 데이터프레임 경로에서 대상자의 시작 시점 선택 결과를 재사용한다. 시작 시점이 엄격한 오름차순이면 기존 정렬 키 `(start, stop, source row)`의 순서도 이미 결정되어 있으므로 `order()`를 생략한다. 시작 시점 동률이나 역순은 기존 정렬을 수행한다.

사용자 정의 데이터프레임과 tibble은 기존 열 접근 및 정렬 경로를 유지한다. 기존 순서 경고, 구간 겹침, 사건 이후 구간과 다중 사건 검사의 계산식과 대상은 변경하지 않는다. 빈 ID의 기존 오류도 유지한다.

## 전체 입력 검증 시간

대상자 1만 명, 대상자당 1개 또는 2개 구간이며 시작 시점은 원래 오름차순인 합성 자료다. 총 행 수는 구성에 따라 1만·1만5천·2만이다. 번들 R 4.5.3의 새 프로세스에서 모듈·설정 로딩 후 세 조건을 같은 순서로 측정했다. 프로파일러 없이 3쌍을 순차 실행하고 두 번째 쌍의 변형 순서를 뒤집었다. 함수는 같은 전역 도우미 환경을 사용했다.

| 대상자 구성 | 변경 전 중앙값(초) | 변경 후 중앙값(초) | 감소율 |
| --- | ---: | ---: | ---: |
| 모두 단일 구간 | 0.17 | 0.17 | 차이 없음 |
| 단일/복수 구간 각 50% | 0.10 | 0.07 | 약 30% |
| 모두 복수 구간 | 0.18 | 0.11 | 약 39% |

| 반복 | 모두 단일 전/후 | 혼합 전/후 | 모두 복수 전/후 |
| --- | --- | --- | --- |
| 1 | 0.17 / 0.17 | 0.11 / 0.07 | 0.18 / 0.11 |
| 2 | 0.17 / 0.17 | 0.10 / 0.07 | 0.18 / 0.11 |
| 3 | 0.17 / 0.16 | 0.10 / 0.08 | 0.18 / 0.11 |

단일 구간은 앞선 최적화로 이미 비교를 생략한다. 각 조건은 같은 프로세스에서 순차 실행되므로 조건끼리의 절대 시간을 비교하지 않는다. 시작 시점이 동률이거나 뒤섞인 자료에 위 개선율을 적용하지 않는다. Cox 모형 적합이나 프로그램 시작 시간의 감소율도 아니다.

## 검증

- 기존 입력 검증 48개, 구간 검증 40개, ID 검증 4개, 사용자 정의 데이터프레임/tibble 검증 4개가 모두 통과했다. 전체 결과 또는 기존 오류, 검사에 포함된 조건과 RNG 상태를 허용 오차 없이 비교했다.
- `verify_order.R`: 대상자 1만 명의 오름차순·역순·시작 시점 동률 자료에서 전체 검증 결과가 정확히 같았다. 순서 경고와 구간 오류 판정도 포함한다.
- 대용량 측정 9쌍의 전체 입력 검증 결과가 `identical(..., num.eq = FALSE)`로 일치했다.
- `verify_integrated.R`: 실제 start-stop Cox 분석의 입력 검증, 모든 데이터프레임 결과, 회귀계수·분산·로그우도, 조건 및 RNG가 동일했다.
- 전체 Cox 패널 HTML과 개별·누적 Excel이 동일했다. Excel의 모든 비-core 내부 파일은 바이트 단위로 같았고 core도 생성·수정 시각만 정규화하면 동일했다.
- `git diff --check -- R/analysis_survival.R` 통과.

PDF/Word/HWPX 완성 파일과 설치 파일은 이번에 재생성하지 않았다.
