# 현재 소스의 실제 브라우저 초기 화면 준비 시간

현재 `run_app.R`과 headless Chrome을 연결해 로컬 서버 시작부터 데이터 파일 선택 버튼이 표시되고 조작 가능한 상태까지 측정했다. 제품 코드 변경이나 속도 개선은 하지 않았다.

## 범위와 준비 완료 정의

번들 R 4.5.3, 한국어 초기 화면, 데이터 미로드, 기존 유효 모듈 캐시, 별도 테스트 환경설정 경로를 사용했다. 각 실행은 새 R 프로세스와 새 브라우저 컨텍스트를 사용한다. Chrome 프로세스는 측정 전 한 번 시작해 공유했다. OS 파일 캐시는 초기화하지 않았다. 3회 순차 실행하고 측정용 서버와 브라우저를 종료했다.

시작 시각은 R 프로세스 생성 직전이다. TCP 연결 가능을 50ms 간격으로 확인하고 첫 페이지로 이동했다. 준비 완료는 다음 조건을 모두 충족한 시각이다.

- Shiny 소켓 연결과 메뉴 표시.
- 파일 입력 요소 생성 및 표시된 `.btn-file`의 Playwright trial click 동작 가능 검사 통과.
- Shiny busy 표시 해제 후 requestAnimationFrame 2회.

실제로 파일 선택 창을 열거나 사용자의 자료를 업로드하지 않았다. 시험에서 정의한 초기 화면 준비 상태이며 전체 기능의 정상 동작을 보장하는 검사는 아니다. 최종 캡처에서 데이터 파일 열기·CSV/DAT 설정·세션 설정·데이터 미리보기 영역이 채워진 것을 확인했다. JavaScript pageerror와 화면의 Shiny 오류는 3회 모두 없었다.

## 측정 결과

R 프로세스 생성 직전부터 경과 시간(초):

|DOM 구성 이벤트|1.5306|1.4783|1.4466|1.4783|

처음 시도한 ‘소켓 연결+메뉴+busy 해제’만의 조건은 빈 데이터 패널에서도 통과했다. 캡처로 확인하고 그 시간을 최종 화면 준비 시간으로 채택하지 않았다. 파일 선택 버튼의 조작 가능 검사까지 추가해 위 3회를 다시 측정했다. 연결 완료와 화면 준비 완료를 혼동하지 않는 것이 이번 검토의 주요 확인 사항이다.

## 해석과 남은 범위

현재 조건에서 약 2.44초는 R 시작부터 데이터 입력 화면 준비까지의 기준값이다. **Electron 실행 파일 클릭부터의 전체 로딩 시간은 아니다.** Electron 프로세스 시작·창 생성, Chrome 자체 시작, 설치본과 현재 소스의 차이, 캐시 miss, 실제 사용자 클릭 이벤트는 포함하지 않는다. Lighthouse나 Core Web Vitals 측정값으로도 부르지 않는다.

세션 연결 이후에도 화면 내용이 생성되는 구간이 확인됐다. 다음 후보는 그 구간의 초기 데이터 화면 반응형 처리와 브라우저 DOM 반영을 따로 측정하는 것이다. 이번 경과 시간 차이만으로 서버 또는 브라우저 어느 쪽이 병목이라고 확정하거나 특정 최적화의 절감량을 예측하지 않는다.

Chrome DevTools MCP 전용 스킬은 도구가 연결되어 있지 않아 실행하지 못했다. 기존 저장소의 Playwright 검사 방식을 사용했다. 브라우저/프로세스 실행은 승인된 제한 밖 로컬 명령으로 수행했다.

## 산출물

`output/live-startup-current-20260915/measure.cjs`, result-1~3.json, ready-1~3.png, server-1~3.log, startup-1~3.log. JSON과 PNG는 보완한 최종 실행 결과다. startup 로그는 앱의 append 기록 방식 때문에 초기 불충분한 조건의 실행과 최종 실행을 함께 포함한다. 각 파일의 마지막 실행 블록이 최종 측정에 해당한다. 서버 표준 출력 로그는 최종 실행으로 덮어썼다.

측정기는 실제 사용자 설정 파일 대신 테스트 전용 경로를 전달한다. 기존 모듈 캐시 경로는 공유했지만 실행 모듈, UI 코드 및 설치 파일은 수정하지 않았다. 수치 분석 실행/내보내기 변경이 없으므로 새로운 수치 동일성 검증이나 내보내기 성능 주장은 없다.
