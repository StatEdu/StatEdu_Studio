# 최근 분석 최적화 이후 초기 로딩 비교 — 2026-09-14

최근 상관·생존·신뢰도 최적화가 R 내부 초기 로딩을 지연시키는지 비교했다. 이번 범위에서는 뚜렷한 지연을 관측하지 못했다. 운영 코드나 캐시 정책은 변경하지 않았다.

## 비교 범위

현재 R 폴더의 파일 224개를 두 비교용 사본으로 복사했다. 기준 사본에서만 다음 세 파일을 해당 최적화 직전 소스로 교체했다.

- `analysis_correlation.R`: 순서형 상관 행렬 검사 캐시 통합 직전.
- `analysis_survival.R`: 보정 생존곡선 평균 계산의 결측 제거 생략 직전.
- `analysis_reliability.R`: 순서형 신뢰도 문항쌍 캐시 통합 직전.

파일 SHA-256 비교로 두 사본 사이에 이 세 파일만 다른지, 현재 사본 224개가 실제 R 폴더와 같은지 확인했다. 로더·UI·서버·자료 처리 등 나머지 코드는 양쪽 모두 현재 버전이다. 모든 과거 최적화를 되돌린 버전이나 과거 설치 배포본과 비교한 것이 아니다.

현재 `R/app_bootstrap.R`와 `source_app_modules(dir=...)`를 사용했다. 유효 캐시는 버전별 별도 경로에 미리 생성했고, miss는 매 실행마다 존재하지 않는 새 경로를 사용했다. 번들 Windows R 4.5.3, JIT 3, `keep.source=FALSE`, UTF-8, `load_app_packages(check=FALSE)` 조건이다. 패키지 자동 설치를 비활성화했다.

버전×hit/miss별 새 프로세스 3개, 총 12개를 순차 실행했다. 두 번째 세트는 버전 순서를 뒤집었다. 캐시 사전 생성용 두 프로세스는 시간 집계에서 제외했다. OS 파일 캐시는 비우지 않았다.

| 단계 | 기준 hit | 현재 hit | 기준 miss | 현재 miss |

| 실행별 측정 단계 합계의 중앙값 | 0.94초 | 0.93초 | 1.61초 | 1.60초 |

bootstrap 소싱과 서버 함수 생성 중앙값은 타이머에서 0초로 기록됐다. 실제 비용이 없다는 의미가 아니다. 합계는 개별 실행에서 bootstrap·패키지·모듈·서버 함수 생성·UI·태그 렌더링 시간을 더한 값의 중앙값이다. 단계별 중앙값을 더한 값과는 다를 수 있다.

0.01초 차이를 새 속도 개선으로 해석하지 않는다. 유효 캐시에서는 초기 UI 구성 약 0.37초가 관측 단계 중 가장 크고, miss에서는 모듈 및 캐시 생성 약 0.92초가 가장 크다. 후속 검토에서는 UI 구성 내부 비용과 실제 서버 세션 초기화를 구분해서 측정해야 한다.

## 결과 검증

12개 스냅샷 모두 `identical(..., num.eq=FALSE)`로 일치했다. 초기 UI의 자동 생성 숫자 탭 ID만 정규화했고 탭의 내용·순서는 유지했다. HTML 의존성, 서버 함수 본문/형식 인수, 전체 Pearson 상관 및 집단별 생명표 결과, 해당 분석의 경고/메시지·표준출력·난수 상태도 비교했다.

분석 검증은 단계 시간 측정 후 수행했다. 이번 스냅샷은 최근 변경된 세 고비용 분석 경로를 모두 새로 실행한 검사가 아니다. 해당 경로의 수치 검증은 개별 통합 보고서에 있으며, 이번 목적은 같은 초기 화면/기본 분석 동작을 유지한 로딩 비교다.

## 해석 한계

**실제 Electron 앱의 시작 시간 측정이 아니다.** R 프로세스 시작, 실제 기본 패키지 설치 확인, 브라우저/Electron DOM 렌더링, 네트워크 연결과 실제 사용자 서버 세션 초기화는 포함하지 않는다. 서버 함수 생성은 서버 세션을 실행한 것이 아니다. 메모리·내보내기·설치 파일은 이번에 재검증하거나 재빌드하지 않았다.
