# Kendall 정규화 연산 순서 대조

## 결과와 현재 상태

앞선 빈도 집계 후보의 비트 불일치를 줄이기 위해, 같은 집계값에 서로 다른 정규화 연산을 적용했다. `2*S / (sqrt(2*A) * sqrt(2*B))` 형식은 395개 계수 비교에서 기존 R과 정확히 일치했다. 이 형식을 원래 cor.test.default의 cor 호출 자리에 시험적으로 연결한 추가 720개 사례에서도 전체 원시 검정 객체·진단·stdout·난수 상태가 일치했다.

이는 검증을 확장할 수 있는 후보를 찾은 결과다. 제품에는 반영하지 않았다. 기존 C 커널의 소스를 확보하지 못했고, 전체 상관분석 연결·성능·범주 수 및 메모리 제한·예외 입력의 기존 경로 복귀를 아직 검증하지 않았다.

## 소스 확인과 대조 방법

로컬 작업공간에는 해당 C 소스가 없었다. R 4.5.3 태그 및 4.5 브랜치의 cov.c를 원격으로 읽으려 했으나 웹 도구 조회 실패와 직접 연결 거부로 확보하지 못했다. 따라서 아래 식이 기존 C 구현의 정확한 소스 표현이라고 주장하지 않는다. 번들 R 4.5.3의 실행 결과를 참조로 삼은 실험이다.

`S`는 일치/불일치 쌍 차이, `A`와 `B`는 각각 x와 y의 비동점 쌍 수다. 이전 후보의 집계 함수를 그대로 사용했다. 5/10/30/100/1,000행, 2/3/5/7범주, 시드 1~20의 400조합 중 한 축이 상수인 다섯 사례를 제외했다.

| 후보 정규화 | 비교 수 | 정확히 일치 | 불일치 |
|---|---:|---:|---:|
| `S / sqrt(A*B)` | 395 | 273 | 122 |
| `S / (sqrt(A)*sqrt(B))` | 395 | 224 | 171 |
| `S / sqrt(A) / sqrt(B)` | 395 | 175 | 220 |
| `2*S / (sqrt(2*A)*sqrt(2*B))` | 395 | 395 | 0 |
| `2*S / sqrt(2*A) / sqrt(2*B)` | 395 | 276 | 119 |

각 식 뒤에는 기존 후보처럼 [-1,1] 범위 제한을 적용했다. 이 실험은 수학적 비율이 같아도 스케일·제곱근·곱셈·나눗셈 순서가 원시 부동소수점 결과에 영향을 준다는 점을 보여준다. 이전 첫 사례의 S=1, A=B=6에서도 선택된 후보는 기존의 `0.16666666666666669`와 일치한다. 첫 후보의 불일치를 허용오차로 통과시킨 것이 아니라 계산식을 바꾼 새 후보를 비교한 것이다.

## 원시 검정 결과 확대 검증

번들 stats의 cor.test.default 함수를 별도 환경에 복사하고 그 환경의 cor 호출만 기록된 빈도 집계·새 정규화 후보로 연결했다. stats 네임스페이스나 제품 코드를 수정하지 않았다. 검정 통계량·동점 보정·p값 계산은 원래 함수에 맡겼다.

5/20/100/1,000행, 2/5/9범주, 시드 1~10, 정수·음수·인접 실수·비정규화 작은 수·큰 유한수·부호 있는 0의 720조합을 검사했다. Kendall, exact=FALSE 조건이며 두 함수에 같은 호출 표현을 사용하여 htest의 data.name 등도 포함해 비교했다.

720개 전체 원시 htest·경고/메시지의 클래스와 내용·stdout·난수 상태가 `identical(..., num.eq=FALSE)`로 일치했다. 최종 수치를 반올림하거나 정규화하지 않았다. 현재 실험용 cor 대체 함수는 Kendall 호출만 받아들이도록 단언하고 있으며 일반 배포용 대체 함수가 아니다.

결측·무한대·상수·사용자 클래스·대규모 집계의 정수 정확성 한계·더 많은 범주의 메모리 비용은 검증 범위 밖이다. 다른 R 버전이나 모든 플랫폼에서도 일치한다는 보장은 하지 않는다. 실제 프로그램 결과 및 성능도 이 단계에서 주장하지 않는다.
