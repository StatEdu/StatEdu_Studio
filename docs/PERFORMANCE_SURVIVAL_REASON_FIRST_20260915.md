# 제외 사유 최초 기록의 불필요한 중복 제거 생략

`survival_preflight`의 `add_reason`에서 기존 사유가 NULL인 행은 내부의 단일 사유 문자열을 바로 대입한다. 이미 사유가 있는 행은 기존 `unique(c(existing, code))`를 그대로 사용한다. 사유의 순서·중복 제거, 모든 변수 검사, 행 선택, 숫자 연산과 분석 수식은 유지한다.

직전의 missing_covariate 중복 갱신 방지와 기록된 행 번호 보관 방식은 이번에 변경하지 않았다. 이번 변경은 최초 사유 기록에서만 빈 목록과 문자열의 결합 및 중복 제거 호출을 생략한다. 빈 사유일 때 불필요했던 연산을 없애므로, 결측이 분산된 자료도 개선 대상이 된다.

## 검증

- `scripts/validate_survival_reason_first.R`: 빈 자료·단일 행·30/120행, 정상·결측 중첩·결측 분산·전부 결측, 단일 기록·지연 진입·시작–종료, 변수 순서/중복 역할/집단과 공변량 역할 중첩 등 전체 결과 96개 비교. 사용자 정의 결측 검사에서 경고·메시지·난수를 발생시키는 2개 조건도 비교한다.
- 기존 사건 매핑 helper 294개와 전처리 36개 검사도 함께 실행한다. 이번 변경의 96개 비교와 구분한다.
- `scripts/benchmark_survival_reason_first.R`: 두 독립 프로세스마다 1,000/100,000행 × 정상/사건·집단 일부 결측/공변량 중첩/공변량 분산의 성공 결과 및 전체 결과 88개 비교.
- `scripts/validate_survival_reason_first_cox.R`: 600행·공변량 6개, 정상/중첩/분산 결측 × 기본/층화/군집/스플라인 Cox 12조건의 성공 모형, 분석 행 수, 유한 계수와 전체 결과 비교.
- 반환값/속성·진단·stdout·RNG는 `identical(..., num.eq=FALSE)`로 비교한다. Cox만 call 내부를 포함한 수식 `.Environment` 속성을 제외하며, 수치 허용오차는 사용하지 않는다.
- 위 검증은 모두 통과했다. 기존 `validate_survival_preflight.R` 종합 검사도 실제 앱 초기화 후 통과했다.

## 측정 조건

번들 R 4.5.3, 실제 앱 모듈·환경설정 초기화, 양쪽 함수 컴파일, 동일 시드. 각 조건 준비 후 기존/변경을 번갈아 5회씩 측정한 중앙값이다. 전체 전처리와 진단/stdout 수집을 포함하며 동일성 비교는 타이머 밖에서 수행한다.

중첩 조건은 같은 절반의 행에 사건·집단·공변량 6개의 결측이 겹친다. 분산 조건은 공변량별 결측 행이 서로 겹치지 않는다. sparse는 사건 5%와 집단 5%가 서로 다른 행에 결측이다. 기준은 직전 중복 갱신 방지까지 적용된 코드이며 여러 단계의 누적 개선율이 아니다.

100,000행 전처리는 분산 결측 약 53%, 중첩 결측 약 22~25%, sparse 약 30~35% 단축했다. 1,000행 분산 결측도 약 28~34% 단축했다. 정상 조건에는 사유를 기록하는 행이 없어 이번 빠른 경로를 사용하지 않으며, 100,000행에서는 약 0.2~1.4ms 증가도 측정되어 개선을 주장하지 않는다.

이전 작업에서 분산 결측에 남았던 행 번호 확인 비용 자체를 없앤 것은 아니다. 그 방식은 유지하되 최초 기록 비용을 줄여, 직전 코드보다 전체 전처리가 크게 개선됐다.
