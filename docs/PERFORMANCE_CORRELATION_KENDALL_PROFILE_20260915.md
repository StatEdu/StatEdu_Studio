# Kendall 상관의 행 수 증가와 중복 호출 검토

## 결론

현재 Kendall 분석의 주요 비용은 `cor.test` 아래 `cor()` 계산 경로에 집중됐다. 6변수·15쌍의 연속 자료에서 행 수가 1,000→3,000으로 증가하자 전체 결과 준비 중앙값은 0.14→1.31초가 됐다. 같은 변수쌍의 반복 계산은 발견하지 못했다. 단순한 쌍 결과 캐시로 이 비용을 줄일 근거가 없어 캐시나 계산식 변경을 적용하지 않았다.

기존 300행·다수 변수 검토와 달리 이번에는 변수 수를 고정하고 행 수를 늘렸다. 두 자료 크기만으로 일반적인 시간복잡도를 입증한 것은 아니다.

## 조건과 시간

번들 R 4.5.3, 시드 33, 정규 합성 자료 6변수다. 동점 자료는 각 열을 반올림했고, 결측 자료는 각 변수에서 서로 다른 무작위 10%를 결측 처리했다. Kendall 지정, 정규성 검사 및 잠재상관은 비활성화했다.

상관분석 소스를 별도 환경에 읽고 그 환경의 함수들을 명시적으로 컴파일했다. 새 R 프로세스 세 개를 순차 실행했다. 각 조건에서 준비 실행, 프로파일러 없는 시간 측정, 별도 Rprof 실행을 수행했다. 아래 시간은 전체 결과 준비와 반환값·진단·stdout·난수 상태 수집을 포함한다. 자료 생성·프로그램 로딩·화면·내보내기는 제외했다.

| 행 수 | 자료 | 3회 시간(초) | 중앙값(초) |
|---:|---|---|---:|
| 1,000 | 연속 | 0.14 / 0.15 / 0.14 | 0.14 |
| 1,000 | 동점 | 0.14 / 0.12 / 0.14 | 0.14 |
| 1,000 | 결측 10% | 0.10 / 0.09 / 0.11 | 0.10 |
| 3,000 | 연속 | 1.29 / 1.31 / 1.31 | 1.31 |
| 3,000 | 동점 | 1.36 / 1.38 / 1.37 | 1.37 |
| 3,000 | 결측 10% | 0.86 / 0.85 / 0.86 | 0.86 |

결측 자료는 실제 변수쌍의 관측치 수가 줄어든다. 1,000행에서 쌍별 N은 805~816, 3,000행에서는 2,424~2,438이었다. 결측 조건의 짧은 시간을 최적화 효과로 해석하지 않는다.

## 프로파일과 재사용 가능성

0.01초 간격 Rprof에서 3,000행 연속 자료의 `cor` self 표본 비율은 98.86/97.70/96.59%였다. 동점 자료는 96.74/93.48/97.80%, 결측 자료는 94.83/98.25/96.55%였다. 별도 표본 기반 비율이며 실제 경과 시간 비율이 아니다. 중첩된 누적 시간을 합산하지 않는다. 1,000행 조건은 표본이 적어 정밀한 비율 판단에 사용하지 않았다.

추가로 별도 환경의 `cor.test.default`에 기록용 `cor` 래퍼를 넣었다. 래퍼는 입력을 기록한 뒤 원래 `stats::cor`를 그대로 호출한다. 여섯 조건 모두 cor 호출 15회, 정확히 구분되는 입력 쌍 15개였다. 입력 비교에도 `identical(..., num.eq=FALSE)`를 사용했다. 기록 전후 전체 분석 결과와 진단·stdout·난수 상태가 정확히 같았다.

따라서 이번 자료에서 같은 쌍의 결과를 재사용하는 캐시는 적중할 대상이 없다. 주요 비용을 줄이려면 Kendall 계산 내부를 검토해야 하며, 다른 계산법으로 교체하기 전에 동점 보정·연산 순서·경계값 및 원시 검정 결과를 엄격히 비교해야 한다. 아직 대체 알고리즘을 시험하거나 구현한 것은 아니다.

## 결과 보존 및 자료

6조건 × 3프로세스에서 준비/시간 측정/프로파일 실행의 전체 반환값·진단·stdout·난수 상태가 `identical(..., num.eq=FALSE)`로 일치했다. 결과 표가 15쌍임을 확인했다. 세 프로세스 간 같은 조건의 전체 수집 결과도 일치했다. 수치 허용오차·반올림·정규화를 적용하지 않았다.

`output/correlation-kendall-profile-20260915/`에 `source.R`, `profile.R`, `audit.R`, 시간 CSV, 원시 Rprof와 self/total CSV, 결과 RDS, `call-audit.csv`를 보존했다. 영어 UTF-8 로캘, 기존 모듈 캐시와 패키지 설치 비활성화 환경을 사용했다. 제품 소스가 스냅샷과 같은 해시임을 확인했다. 출력 코드 변경이나 별도 내보내기 생성·배포 빌드는 수행하지 않았다.
