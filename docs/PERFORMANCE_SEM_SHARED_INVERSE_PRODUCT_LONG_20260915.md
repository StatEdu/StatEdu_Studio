# SEM 역행렬 공유 제품 통합 후 긴 작업 검증

2026-09-15. 제품 통합 후 실제 앱의 callr 부트스트랩 경로에서 긴 작업 성능과 반환 결과를 비교했다. **전체 작업 시간 9.9~11.0% 단축**, 정확 비교 통과.

재표집 구간은 각각 11.18%와 10.26% 단축됐다. 각 프로세스의 A/B 두 비교와 비활성/활성 각각의 프로세스 간 두 비교, 총 네 정확 비교를 통과했다. 네 작업 모두 최종 유효 반복 5,000/5,000, 작업자 4개, 청크 100, fixed-index 활성, fallback 0이었다. 활성 작업은 네 작업자 모두 공유 최적화 설치를 확인했고 비활성 작업은 설치 기록이 없었다.

총 요청 반복은 20,000회다. 제품 소스 해시는 측정 전후 동일하며, 이번 작업에서 제품 코드를 수정하지 않았다. 두 측정의 관측 범위를 보고한 것이며 통계적 신뢰구간이나 다른 자료에 대한 보장된 개선율은 아니다.

## 조건과 비교 범위

- 번들 R 4.5.3/lavaan 0.7.2, 번들 라이브러리 고정.
- 기존 안정적인 전체 조합 DMC: 240행, 제품지표 9개, ML/FIML, std.lv=FALSE.
- 각 작업 5,000회, 시드 20260833, 작업자 4개, 청크 100, 편향 보정 신뢰구간.
- 같은 제품 코드의 내부 `statedu.internal.disable_sem_shared_inverse`만 바꿔 비교한다. 연구용 함수 교체는 없다.
- 독립 부모 프로세스 두 개에서 비활성→활성, 활성→비활성 순서로 실행한다.
- 전체 시간은 작업 생성 호출 직전부터 결과 파일을 읽고 결과를 반환할 때까지다. 부모에서 별도로 준비한 원모형 최초 적합, 앱 최초 로딩, 화면 렌더링 시간은 포함하지 않는다. 0.1초 간격의 완료 확인 비용은 양쪽에 포함된다.
- 실제 앱 경로는 개별 draw 배열을 반환하지 않는다. 이번 검사는 timings만 제외한 전체 반환 결과와 부모 진단·stdout·RNG 비교이며, 개별 표본 원계수 비교는 이전 prepared 엔진 검증을 참조한다. 내부에서 억제되는 자식 진단을 새로 수집하지 않았다.
- 계측 래퍼의 elapsed와 결과에서 분리한 timings만 비교에서 제외한다. 수치 비교는 허용 오차 없이 `identical(..., num.eq=FALSE)`를 사용한다.
