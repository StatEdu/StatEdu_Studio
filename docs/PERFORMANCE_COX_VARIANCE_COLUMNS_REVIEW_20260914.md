# Cox 다중공선성 분산 계산 후보 검토 — 2026-09-14

## 결론

운영 코드는 변경하지 않았다. `survival_cox_collinearity()`의 `apply(design, 2L, stats::var)`를 일반 행렬에 한해 열별 `vapply()` 호출로 바꾸는 후보를 시험했다. 분산 계산 함수, 보조회귀, VIF, 조건수 계산은 그대로 유지하고 열 이름을 복원했다. 클래스가 있는 행렬은 기존 경로를 유지했다.

행렬 재배열에 따른 할당량은 줄었으나 대규모 입력에서 실행 시간 개선이 확인되지 않아 채택하지 않았다. 후보는 아래 출력 디렉터리의 `current.R`에만 있다.

## 실행 시간

동봉 R 4.5.3에서 정규 합성 자료와 공변량 5개를 사용했다. 기존/후보 각각 새 프로세스에서 3회 실행했으며 두 번째 쌍은 후보부터 실행했다. 각 프로세스는 1천 행 다음 10만 행 순서로 진단 함수 전체를 측정했다. 자료 생성과 결과 저장은 측정에서 제외했고, 경고·메시지·난수 상태를 수집하는 동일 래퍼는 포함했다. 프로파일러와 별도 검증은 시간 측정 중 실행하지 않았다.

| 행 수 | 기존 3회(초) | 후보 3회(초) | 중앙값 기존 → 후보 |
|---|---|---|---|
| 1,000 | 0.02 / 0.01 / 0.03 | 0.03 / 0.01 / 0.01 | 0.02 → 0.01 |
| 100,000 | 0.17 / 0.15 / 0.16 | 0.17 / 0.17 / 0.17 | 0.16 → 0.17 |

0.01초 차이는 측정 해상도와 변동을 고려하면 가속 또는 회귀로 단정하기 어렵다. 전체 Cox 적합이나 실제 화면 대기 시간을 측정한 결과는 아니다.

## 메모리 및 동일성

10만 행·5공변량에서 각각 3회 예열하고 GC 후 별도로 한 번 측정한 Rprofmem 기록 할당량은 174,809,384 → 170,809,336바이트로, 4,000,048바이트(약 4.00MB, 2.3%) 감소했다. 이는 누적 기록 할당량이며 최대 사용 메모리나 RSS가 아니다.

0/1/2/40행과 일반 입력, NA, Inf, 상수열, 중복열, 행 이름, 데이터 프레임, 단일 열, 사용자 클래스 행렬의 36조건에서 반환값·오류/경고/메시지·난수 상태가 `identical(..., num.eq=FALSE)`로 일치했다. 시간 측정의 6쌍도 전체 반환값·진단·난수 상태가 일치했다. 동일성 검증을 통과했더라도 모든 입력의 동등성을 증명한 것은 아니다.
