# Spearman 순위 재사용 후보 검토 — 2026-09-14

## 결과

한 분석 호출 안에서 동일 벡터의 순위를 재사용하는 실험 후보를 만들었다. 1만 행·20변수에서 완전 연속 자료 중앙값 0.55→0.33초(약 40%), 반올림으로 동률을 만든 자료 0.50→0.19초(약 62%)였다. 변수별 결측 10%는 0.43→0.42초로 실질적인 개선을 확인하지 못했다. 운영 코드에는 적용하지 않았다.

## 방법

현재 번들 R의 `cor.test.default` 소스를 확인했다. Spearman 경로는 `cor(rank(x), rank(y))`로 계수를 계산하고 그 뒤 S 통계량과 p값을 계산한다. 검정식을 새로 작성하거나 Pearson 검정으로 바꾸지 않고, 기존 함수의 복사본에서 `rank`만 호출별 캐시 함수로 연결했다. stats 패키지 네임스페이스는 수정하지 않는다.

속성 없는 integer/double 벡터이며 기본 rank 인자를 사용하는 경우만 캐시한다. 입력이 `identical(..., num.eq=FALSE)`로 같을 때 재사용한다. 순위는 기존 `base::rank()`로 계산한다. 별도 인자나 속성이 있는 값은 원본 rank 경로를 사용하고, 테스트 호출 자체도 Spearman 및 속성 없는 x/y 조건을 벗어나면 원래 `stats::cor.test`로 보낸다.

캐시 상한은 선택 변수 수이며 최근 사용 순서를 갱신하고 가장 오래 사용하지 않은 항목을 제거한다. 분석 호출마다 새로 만들며 결과 객체에 캐시를 포함하지 않는다. 변수마다 결측 위치가 달라 쌍별 벡터가 바뀌면 기존 결과를 강제로 재사용하지 않는다. 벡터와 순위의 참조를 유지하는 메모리 비용은 존재하며 최대 메모리는 아직 측정하지 않았다.

## 측정

시드 33의 정규 합성 자료, 1만 행·20변수, `continuous_method='spearman'`, `normality=TRUE`를 사용했다. 동률 조건은 소수점 한 자리로 반올림했고 결측은 각 변수에 무작위 10%를 넣었다.

각 버전을 새 프로세스에서 3회 측정하고 두 번째 묶음은 순서를 반대로 했다. 각 프로세스는 완전 자료→동률→결측 순서다. 측정 범위에는 실험 스냅샷 함수 로딩, 후보 함수/캐시 생성(기준 버전에서도 동일하게 생성하되 미사용), 전체 분석 및 진단/표준출력 수집이 포함된다. bootstrap·입력 생성·gc·저장은 제외한다. 따라서 이전 순수 분석 프로파일의 시간과 직접 비교하지 않는다. 프로파일링이나 별도 R 검증은 타이밍과 동시에 실행하지 않았다.

| 조건 | 기준 3회(초) | 후보 3회(초) | 후보 순위 캐시 적중/미적중 |
|---|---|---|---|
| 완전 연속 자료 | 0.55 / 0.55 / 0.55 | 0.33 / 0.33 / 0.33 | 360 / 20 |
| 동률 자료 | 0.50 / 0.50 / 0.51 | 0.19 / 0.19 / 0.19 | 360 / 20 |
| 변수별 결측 10% | 0.43 / 0.43 / 0.42 | 0.43 / 0.42 / 0.40 | 0 / 380 |

후보 캐시는 세 조건 모두 최대 20항목이었다. 자료가 바뀌면 재사용률과 개선율이 달라진다.
