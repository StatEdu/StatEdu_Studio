# 공개 무료판 최소 지원 버전 정책

2026-09-24 구현. Pro 출시 이후 기존 무료 공개판의 지원을 종료할 수 있는
시작 시 버전 정책이다. Pro 구매 확인이나 기능별 라이선스 제어는 포함하지 않는다.
Windows와 macOS가 공통 `app.R` 및 `R/update_check.R`를 사용한다.
2026-09-24 후속 결정에 따라 공개 준비 소스 `VERSION`은 1.3.1이며 개발판에도 동일 코드를 포함한다. 기존 1.3.0 설치본은 변경하지 않는다.

## 운영

기본 주소는 `https://studio.statedu.com/releases/latest.json`이다.
`STATEDU_UPDATE_MANIFEST_URL`로 HTTPS 주소를 변경할 수 있다.
기존 `version` / `minimumSupportedVersion`과 신규
`latest_version` / `minimum_version` 이름을 모두 지원하며 신규 이름이 우선한다.

```json
{
  "latest_version": "1.3.0",
  "minimum_version": "1.3.0"
}
```

이 정책에서는 1.3.0이 정상 실행된다. 최신 버전 번호만 올리면 필수 업데이트가
되지 않는다. 실제 배포된 후속 버전을 확인하고 최소 지원 버전을 올리면 그보다
낮은 버전은 다음 앱 시작 시 업데이트 안내 화면만 표시한다. 분석 서버와
파일 편집 핸들러는 등록하지 않으며 기존 데이터와 결과 이력은 변경하지 않는다.
실행 중 작업을 강제로 중단하지 않는다.

최소 지원 버전은 최신 버전보다 높을 수 없다. 잘못된 정책은 적용하지 않는다.
최소 버전을 다시 낮추면 다음 온라인 실행에서 제한이 해제된다.
운영 서버 정책은 이 코드 변경으로 자동 수정되지 않는다.

## Pro 준비

Pro판은 패키징 시 `STATEDU_PRODUCT_EDITION=pro`를 지정해야 한다.
기본값은 `free`이며 현재 개발판도 무료판 정책을 따른다.
Pro 도입 시 정책을 아래처럼 분리한다. 아래 버전 번호는 설명용 예시다.

```json
{
  "editions": {
    "free": { "latest_version": "1.4.0", "minimum_version": "1.4.0" },
    "pro": { "latest_version": "2.0.0", "minimum_version": "2.0.0" }
  }
}
```

무료판 1.3.0은 `editions.free`에 의해서만 제한된다. `editions.pro`의 변경은
무료판에 영향을 주지 않는다. 해당 에디션 정책이 없으면 유효한 정책으로
취급하지 않는다. 기존 최상위 정책은 무료판에만 적용된다.
Pro 출시 자체가 무료판 차단 조건은 아니다. 무료판 지원 종료 시 대체 배포물,
다운로드 안내와 이용 조건을 준비한 뒤 무료판 정책을 변경한다.

## 네트워크와 한계

- 시작할 때 정책 파일만 요청한다. 연구 데이터와 분석 결과를 전송하지 않는다.
- 확인 제한 시간은 8초다. HTTPS로 성공적으로 읽고 검증한 정책을 사용자
  설정 디렉터리의 `version-policy.rds`에 저장한다.
- 네트워크 실패 또는 잘못된 응답에서는 같은 주소에서 마지막으로 확인한
  정책을 사용한다. 이미 제한된 버전은 오프라인에서도 제한된다.
- 유효한 캐시도 없으면 실행을 허용한다. 따라서 계속 오프라인인 사용자,
  로컬 코드나 캐시를 변경하는 사용자까지 막는 라이선스 보안 수단은 아니다.
- 안내 링크 기본값은 언어에 맞는 공식 다운로드 페이지다. 스토어 배포물은
  `STATEDU_UPDATE_PAGE_URL`을 해당 스토어 HTTPS 상세 페이지로 설정한다.
  스토어별 패키지 설정과 실제 링크 연결은 해당 배포 때 검증해야 한다.
- 기존에 설치된 기능 없는 1.3.0에는 소급 적용되지 않는다. 이 코드가 포함된
  설치본을 배포하고 사용자가 설치해야 이후 정책을 적용할 수 있다.

## 검증

`scripts/validate_minimum_version_policy.R`은 경계 버전, 숫자 버전 비교,
기존 필드 호환, 잘못된 정책, 에디션 분리, 오프라인·캐시 손상, 정책 철회,
토큰 검사 및 제한 시 일반 분석 서버의 미생성을 검증한다.
분석 출력이나 내보내기 내용은 변경하지 않는다.
