# Cox 잔차 진단 자료의 열별 결합 — 2026-09-14

> 검증 범위 정정 (2026-09-14): 아래의 경쟁위험/Fine–Gray 전체 결과 검증 표현은 당시 `integration.R`이 `regression`을 지정하지 않아 기본 CIF/Gray 경로만 실행한 것을 잘못 기술한 것이다. 그 검증은 원인별 Cox 또는 Fine–Gray 회귀 검증으로 볼 수 없다. 직접 함수 및 Cox 검증 결과는 별개다. 이후 `regression="both"`를 명시한 600행·20공변량 자료에서 초기 Cox 최적화 전과 현재 모듈 전체의 결과·진단·난수 상태를 비교해 통과했다. 상세 내용은 [원인별 Cox 저장·통합 검증](COMPETING_PH_EXPORT_VALIDATION_20260914.md)을 참고한다.

`survival_cox_functional_form_data`에서 공변량별 자료를 rbind로 합치던 부분에 열별 일괄 결합 경로를 추가했다. 중간 자료 목록에 이름이 없고, 각 자료가 자동 행 이름을 사용하며, 모든 열이 속성 없는 원자 벡터일 때만 사용한다. 그 밖에는 기존 rbind를 유지한다. 값 계산과 제외 행 선택, 공변량 순서, 열 이름·자료형은 유지한다.

이름 있는 공변량 목록은 rbind가 행 이름에 목록 이름을 반영할 수 있으므로 빠른 경로에서 제외했다. 자동 행 이름과 열 속성도 확인해 명시적 행 이름·클래스의 동작을 유지한다. 검사 후 각 열을 기존 자료 순서대로 합쳐 최종 데이터프레임을 한 번 구성한다.

## 시간과 메모리

번들 R 4.5.3, 앱 설정 적용, 자동 설치 비활성화. 최종 가드를 포함한 후보로 새 프로세스에서 변경 전후 3쌍을 순차 측정했고 두 번째 쌍은 순서를 반대로 했다. 각 프로세스는 숫자 공변량 10개, 1천 행 다음 10만 행의 유한 자료를 실행했다. 검증과 메모리 계측은 시간 측정과 분리했다.

| 입력 행 수 | 변경 전 3회(초) | 변경 후 3회(초) | 중앙값 전→후 |
|---|---|---|---|
| 1,000 | 0.02 / 0.02 / 0.02 | 0.02 / 0.02 / 0.02 | 0.02→0.02 |
| 100,000 | 0.31 / 0.30 / 0.31 | 0.03 / 0.04 / 0.03 | 0.31→0.03 |

10만 행·10공변량의 100만 행 진단용 자료 생성에서 약 90% 감소했다. 작은 조건의 중앙값은 같았다. 측정은 진단용 자료 생성 함수 전체이며 Cox 적합·다른 진단·UI·앱 로딩·내보내기는 포함하지 않는다.

별도 Rprofmem 계측은 각 함수를 3회 준비 실행하고 gc() 후 1회 호출했다. 기록된 누적 할당량은 244,455,568→94,891,920바이트로 149,563,648바이트(약 149.56MB, 61.2%) 감소했다. 이는 최대 메모리나 프로세스 RSS 감소를 뜻하지 않는다.
