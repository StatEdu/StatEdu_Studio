# 결측이 많은 자료의 패턴 요약 성능 — 2026-09-14

결측 없는 행을 건너뛰는 최적화의 미측정 범위인 고결측·다변수 자료를 확인했다. 이번에는 제품 코드를 변경하지 않았다.

결측이 적을수록 건너뛸 행이 많아 개선 효과가 컸다. 변수가 많으면 셀 결측률이 낮아도 대부분의 행에 결측이 생겨 효과가 작아진다. 모든 행에 결측이 있으면 현재 구현의 행 검사·부분 행렬 처리에 비해 건너뛸 작업이 없어, 중앙값 기준 약 10–30ms의 증가가 관측됐다. 전체 입력에서 빨라진다는 의미가 아니다.

전체 행 결측 조건의 절대 증가가 작고 반복 변동도 있어 이번 측정만으로 분기를 추가하지 않았다. 현재 구현을 유지한다. 모든 셀이 결측이라는 뜻이 아니며 각 행에 적어도 한 셀이 결측인 자료를 포함한 실험이다.

## 방법과 동일성 범위

- 번들 R 4.5.3, 새 프로세스 3개 순차 실행. 각 입력에서 기준/현재 준비 실행 후 GC 및 각 1회 경과 시간을 측정했다. 두 번째 프로세스는 비교 순서를 뒤집었다. 다른 R 타이밍 작업은 동시에 실행하지 않았다.
- 시드 919로 정규 난수 자료와 결측 마스크를 생성했다. 모든 행 결측 보장 조건은 70% 마스크에 행별 순환 열 위치를 추가로 결측 처리했다. 실제 행 수는 표와 CSV에 기록했다.
- 기준 함수는 `scripts/fixtures/generalized_missing_pattern_reference.R`, 현재 함수는 제품의 `generalized_missing_pattern_summary()`다. 인덱스 자동 계산, 요약표 생성 및 비교용 조건·난수 스냅샷 구성을 포함했다.
- 여섯 입력 × 세 프로세스의 준비/측정 결과에서 요약표 전체, 경고·메시지 클래스와 문자열·순서, 난수 상태가 `identical(..., num.eq=FALSE)`로 일치했다. 시간 측정 후 생성한 행 수 집계는 경과 시간에 포함하지 않았다.
- **이 수치는 요약 함수만의 시간이다.** 모형 적합·다중대치·전체 분석·로딩·화면·내보내기 성능을 측정한 것이 아니다. 모든 행에 결측이 있는 자료로 완전 사례 분석이 가능하다는 의미도 아니다. 메모리 할당량은 측정하지 않았다.
