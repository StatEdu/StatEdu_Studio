# 상관분석의 완전 관측 검사 배열 생략 — 2026-09-14

`R/analysis_correlation.R`의 `correlation_complete_pair`를 추가 개선했다. 앞선 변경은 complete.cases 배열을 만든 뒤 결측이 없으면 벡터 복사를 생략했다. 이번에는 길이가 같고 속성이 없는 정수·실수 벡터에 대해 anyNA로 결측값 유무만 검사한다. 결측이 없으면 원래 벡터와 길이를 반환해 검사 배열 생성과 그 합산까지 생략한다.

결측값, 이름·클래스·차원 등 속성, 다른 자료형 또는 길이가 다른 입력은 기존 complete.cases 및 부분 추출로 처리한다. 복소수는 빠른 경로에서 제외해 기존 오류 동작을 유지한다. 무한값은 기존처럼 결측값으로 취급하지 않는다.

## 측정

이번 변경 직전 파일을 기준으로 번들 R 4.5.3, 기존 모듈 캐시, 새 프로세스에서 3쌍을 순차 실행했다. 두 번째 쌍은 순서를 반대로 했다. 함수 환경은 같은 전역 환경으로 연결했다. 5만 행·15변수, Pearson, 정규성 검사 비활성 조건에서 전체 결과 준비 시간을 측정했다.

| 조건 | 변경 전 중앙값(초) | 변경 후 중앙값(초) |
|---|---:|---:|
| 모든 값 관측 | 0.36 | 0.31 |
| 첫 변수의 10% 결측 | 0.25 | 0.20 |

각각 약 14%, 20% 감소했다. 완전 자료 원자료는 변경 전 0.37/0.36/0.36초, 변경 후 0.32/0.31/0.30초다. 결측 자료 원자료는 변경 전 0.25/0.26/0.25초, 변경 후 0.20/0.20/0.20초다.

각 프로세스에서 완전 자료 후 결측 자료를 실행했으므로 두 조건 간 시간을 직접 비교하지 않는다. 결측 조건에서도 첫 변수를 포함하지 않는 쌍은 새 경로를 사용한다. 실제 앱 기동이나 그래프 렌더링의 개선률이 아니다.

## 메모리 계측

별도 Rprofmem 실험에서 5만 개 값의 완전한 숫자 벡터 두 개를 미리 만들고, 함수별 5회 호출 후 10회 호출을 기록했다. 기록된 할당 바이트 합계는 변경 전 2,000,480, 변경 후 0이었다. 이전 단계에서 남아 있던 큰 complete.cases 배열 할당이 제거됐음을 확인했다.

0은 이 조건에서 Rprofmem이 기록한 할당 합계다. 함수가 모든 종류의 메모리를 전혀 사용하지 않거나 프로그램 전체 메모리가 0이라는 의미가 아니며, 최고 사용량·상주 메모리도 측정하지 않았다.

## 동일성 검증

- 48개 전체 상관분석 조건의 결과·진단·난수 상태가 동일했다.
- 빈 벡터, NA/NaN/무한값, 이름·임의 속성, factor, 행렬, Date, 논리·문자·복소수·리스트 및 서로 다른 길이의 169개 입력 쌍에서 반환값 또는 오류 메시지가 동일했다.
- 6개 성능 측정 결과 쌍의 전체 결과·진단·난수 상태가 `identical(...,num.eq=FALSE)`로 일치했다.
- 추가 3조건에서 auto 결과와 HTML/의존성, 변환 진단이 일치했다. 기존 numeric-data 직접 호출 비교도 통과했다.
- 실제 서버 하네스의 상관·KM 결과 객체, HTML/의존성, 경고·알림이 기존 `output/startup-jit-20260914/current-final1.rds`와 정확히 일치했다. 새 스냅샷은 같은 폴더의 `current-correlation-anyna.rds`다.
