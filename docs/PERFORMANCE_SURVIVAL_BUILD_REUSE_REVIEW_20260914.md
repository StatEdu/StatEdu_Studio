# 생존 그래프 빌드 재사용 검토 — 미적용

2026-09-14. 현재 JIT 최적화가 적용된 코드를 기준으로, `survival_draw_plot_with_risk_table`의 첫 ggplot 빌드 결과를 재사용하여 두 번째 주 곡선 빌드를 생략하는 후보를 검토했다. **그림 보존 조건에 실패하여 운영 코드에는 적용하지 않았다.**

## 후보와 실패 원인

기존 코드는 첫 `ggplot_build(main_plot)`로 x축 범위를 얻고, 새 `coord_cartesian`과 최종 테마·레이블을 적용한 뒤 `ggplotGrob(main_plot)`에서 다시 빌드한다.

첫 후보는 저장한 빌드의 plot을 최종 main_plot으로 바꾸고 `ggplot_gtable`을 호출했다. 학습된 가이드 상태가 사라져 범례의 `direction` 관련 오류가 발생했다. 이 실패 소스와 로그는 `rejected-untrained-plot.*`로 남겼다.

두 번째 후보는 학습된 plot을 유지하면서 theme/labels/coordinates만 최종 값으로 옮겨 gtable을 생성했다. 실행은 가능했지만 기존 panel_params가 남아 **12개 그림 중 7개 PNG가 달랐다.**

## 동일성 시험

번들 R 4.5.3, ggplot2 4.0.2, 1000×800 PNG, 120 dpi. KM fixture는 `scripts/fixtures/survival_validation.csv`, 평가 시점은 100/200/400, 그룹은 sex이다. 경쟁위험 fixture는 seed 410의 120행 자료다. 각 경우는 기존/후보의 같은 입력으로 실행했다.

| 경우 | PNG 바이트 동일 |
|---|---|
| 생존곡선 컬러/흑백 | 아니오 / 아니오 |
| 사건곡선 컬러/흑백 | 아니오 / 아니오 |
| 누적위험 컬러/흑백 | 예 / 예 |
| 로그생존 컬러/흑백 | 예 / 예 |
| CI·중도절단 표시 끔 | 아니오 |
| 위험집단 표 없음 | 예 |
| 캡션 없음 | 아니오 |
| 경쟁위험 | 아니오 |

12개 모두 경고·메시지·표준 출력·RNG 상태는 기존과 같았다. 위험집단 표가 없는 경우에는 원래의 빠른 반환 경로를 거쳐 재사용 코드가 실행되지 않는다. 생존곡선 PNG 쌍을 직접 확인하여 수직 위치 차이도 확인했다.

## 좌표 진단

원래 KM 생존/사건 및 경쟁위험 plot은 y 제한을 0~1로 설정한다. 현재 운영 코드가 추가하는 새 좌표는 x 제한만 지정하므로, 두 번째 빌드는 y 범위를 데이터에서 다시 계산한다. 첫 panel_params를 재사용하면 이 과정이 생략된다.

| 그림 | 첫 빌드 y 범위 | 기존 최종 빌드 y 범위 |
|---|---|---|
| 생존곡선 | -0.05 ~ 1.05 | -0.043419 ~ 1.049687 |
| 사건곡선 | -0.05 ~ 1.05 | -0.049687 ~ 1.043419 |
| 경쟁위험 | -0.05 ~ 1.05 | -0.037475 ~ 0.786981 |

누적위험과 로그생존에서는 두 범위가 같았다. 다섯 기본 그림 모두 첫/최종 빌드의 x 범위와 layer data는 `identical(..., num.eq=FALSE)`로 같았다. 따라서 수치 데이터가 같더라도 최종 그림 좌표는 달라질 수 있다.

이번 목표는 기존 표시까지 보존하는 최적화다. y축 정책을 바꾸거나, 일치하는 일부 사례만 보고 재사용을 적용하지 않았다. 이 결과는 모든 빌드 재사용 방법이 불가능하다는 뜻은 아니다. 후속 후보는 가이드와 좌표의 최종 상태까지 보존해야 한다.

동일성 조건에서 탈락했으므로 성능 벤치마크나 전체 형식 내보내기를 진행하지 않았다. 속도 개선 수치를 주장하지 않는다. 운영 코드와 설치 파일은 변경하지 않았다.
