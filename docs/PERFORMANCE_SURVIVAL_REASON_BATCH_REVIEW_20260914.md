# 생존분석 제외 사유 기록 묶음 검토 — 미적용 — 2026-09-14

`survival_preflight()`의 지역 함수 `add_reason()`에서 행별 사유 목록을 하나씩 갱신하는 반복문을 선택 행의 `lapply()` 및 목록 일괄 대입으로 바꾸는 후보를 시험했다. `unique(c(existing, code))`를 유지하여 사유의 중복 제거와 추가 순서를 보존했다.

동일성 검사는 통과했지만 속도 개선이 없어 **적용하지 않았다**. 실행 소스는 실험 전 스냅샷과 SHA-256이 동일하도록 복원했다. 앞서 적용한 정상 행의 제외 사유 문자열 처리 생략과 Cox 보정곡선 최적화는 유지한다.

## 전체 입력 검증 시간

10만 행, 시간·사건·집단·연령 변수로 비교했다. 결측 조건은 연령 10%를 NA로 지정했다. 번들 R 4.5.3의 새 프로세스에서 모듈과 설정을 로드한 뒤 정상 자료, 결측 자료 순서로 전체 입력 검증을 측정했다. 프로파일러 없이 3쌍을 순차 실행하고 두 번째 쌍의 변형 순서를 뒤집었다. 함수는 같은 전역 도우미 환경을 사용했다.

| 조건 | 기존 중앙값(초) | 후보 중앙값(초) |
| --- | ---: | ---: |
| 정상 자료 | 0.36 | 0.36 |
| 연령 결측 10% | 0.28 | 0.28 |

정상 자료는 기존과 후보의 세 반복 모두 0.36초였다. 결측 자료는 기존 0.28/0.28/0.27초, 후보 0.28/0.28/0.28초였다. 다른 규모나 결측 비율에서의 성능을 단정하지 않지만 현재 근거로 추가 목록 추출을 도입할 이유가 없다.

## 검증 및 보관

- `scripts/validate_survival_reason_batch.R`: 48개 사례의 전체 반환값/오류, 경고·메시지, RNG 상태가 정확히 동일했다. 빈 자료, 전부 제외되는 자료, 여러 사유가 겹치는 행, 지연 진입과 start-stop 검증을 포함한다.
- 10만 행 측정의 6쌍에서도 분석 자료, 행별 사유, 건수와 이슈 등 전체 결과가 `identical(..., num.eq = FALSE)`로 일치했다.
- 복원 후 소스의 SHA-256과 `git diff --check -- R/analysis_survival.R`를 확인했다.
- 미적용 후보이므로 화면 및 내보내기를 추가 생성하지 않았고 설치 파일도 재빌드하지 않았다.
