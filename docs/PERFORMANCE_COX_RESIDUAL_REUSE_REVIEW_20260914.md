# Cox 영향 진단 잔차 재사용 후보 검토 — 2026-09-14

Cox 및 원인별 Cox 진단에서 DFBETA와 DFBETAS를 별도로 요청하는 경로를 검토했다. 설치된 survival의 residuals.coxph 구현을 읽고, DFBETA를 공분산 대각 원소의 제곱근으로 나누어 DFBETAS를 얻는 단순 재사용 후보를 시험했다. 실행 코드는 변경하지 않았다.

## 판정: 미적용

12개 조건 모두에서 원본 DFBETAS와 후보 사이에 수치 차이가 발생했다. 최대 절대 차이는 조건별 2.78e-17~1.11e-16이었다. 이는 매우 작은 부동소수점 차이이며 통계적 해석이 달라졌다는 뜻은 아니다. 그러나 사용자의 결과 정확 보존 조건에 맞지 않으므로 후보를 적용하지 않았다. 정확성 검증에서 탈락했기 때문에 속도 향상치를 측정하거나 주장하지 않았다.

원본의 단일 공변량 경로는 점수 잔차에 sqrt(vv)를 곱한다. 다중 공변량 경로는 `(rr %*% vv) %*% diag(sqrt(1/diag(vv)))`를 계산한 뒤 가중치를 적용한다. 후보는 이미 계산된 DFBETA를 sqrt(diag(vv))로 나누므로 곱셈·나눗셈 및 가중치 적용 순서가 원본과 달라진다. 수학적으로 동등한 식이어도 부동소수점 결과가 완전히 같지는 않았다.

이 결론은 이번의 단순 나눗셈 후보에 한정한다. 원본 연산 순서까지 보존하는 다른 재사용 구현의 가능성을 부정하는 결과는 아니다.

## 검증

번들 R 4.5.3과 설치된 survival을 사용했다. 600행 합성 생존 자료에서 공변량 수 1/3/10, 단위 가중치 또는 0.5~2의 비정수 가중치, Efron/Breslow 동점 처리의 조합 12개를 각각 적합했다. 모델의 naive.var가 있으면 이를 사용하고 없으면 var를 사용해 원본의 공분산 선택을 따랐다.

- 전체 객체와 숫자 벡터를 각각 identical(..., num.eq=FALSE)로 비교했다.
- 조건별로 169~3,178개 잔차 값이 달랐다. 단순 속성 차이가 아니라 실제 숫자 차이였다.
- 경고·메시지와 난수 상태는 12조건 모두 일치했다.
- 실행 모듈과 직전 적용 스냅샷의 SHA256이 일치한다: 62DE51BA633D62D9A8CFE7BBFB5BF545365315E124E3CC174150AFB3C86FE768.
