# 신뢰도 분석의 현재 병목과 문항쌍 입력 중복 — 2026-09-14

운영 코드 변경 없이 다음 최적화 대상을 측정했다. 순서형 신뢰도의 문항별 진단에서 다분상관행렬 계산이 주요 병목이다. 완전 자료에서는 동일 문항쌍 입력이 반복되지만, 결측 자료에서는 문항 삭제에 따라 분석 행이 달라진다. 상관행렬을 무조건 잘라 재사용하는 변경은 적용하지 않았다.

## 전체 분석 시간

번들 Windows R 4.5.3, 2,000건·8문항을 사용했다. 시드 719로 공통 정규 성분 0.6과 문항별 독립 정규 성분 0.8을 합성했다. 순서형 자료는 같은 연속 값을 동일 확률의 5범주로 변환했고, 결측 조건은 각 문항에서 독립적으로 200건을 제거했다. 세 조건 모두 omega와 normality 옵션을 켰다. 기본 조건은 문항별 진단을 끄고, 상세 조건은 문항 삭제 시 신뢰도와 문항-전체 상관을 모두 요청한다.

새 프로세스 3개를 순차 실행했다. 각 프로세스에서 연속형→순서형→순서형 결측 순서로 기본/상세를 각각 준비 실행, 비프로파일 측정, 10ms Rprof 실행했다. 호출마다 시드 941로 시작했다. 패키지·앱 로딩과 자료 생성은 제외하고 전체 `prepare_reliability_results()`와 진단·표준출력 수집을 포함한다. 기본/상세는 요청 기능이 다른 조건이지 변경 전후 성능 비교가 아니다.

| 조건 | 기본 중앙값 | 문항별 진단 포함 중앙값 |
| --- | ---: | ---: |
| 연속형 | 0.06초 | 0.10초 |
| 순서형 완전 자료 | 0.17초 | 1.17초 |
| 순서형 결측 자료 | 0.16초 | 1.12초 |

순서형 상세 프로파일에서 `reliability_polychoric_correlation()`의 total 표본 비중은 완전 자료 87.80~91.25%, 결측 자료 89.74~90.91%였다. 문항별 진단 경로 비중은 각각 84.15~86.25%, 85.90~87.01%다. 서로 중첩되므로 더하지 않는다. 연속형 상세 프로파일은 7~8개 표본에 불과해 세부 순위를 강한 근거로 삼지 않았다.

## 실제 입력 중복 확인

시간 측정과 별개로 다분상관행렬 도우미 호출을 기록했다. 각 호출에서 완전 사례를 선택한 뒤 문항명과 문항쌍의 두 수치 벡터를 직렬화한 SHA-256으로 입력 중복을 확인했다. 이는 패키지 내부의 최적화 반복 횟수나 확률 함수 호출 횟수가 아니다.

| 조건 | 상관행렬 도우미 호출 | 요청 문항쌍 입력 | 서로 다른 입력 | 호출별 분석 행 수 |
| --- | ---: | ---: | ---: | ---: |
| 완전 자료 | 9 | 196 | 28 | 모두 2,000 |
| 결측 자료 | 9 | 196 | 196 | 855~960 |

전체 8문항의 28쌍과, 문항 하나씩 삭제한 7문항의 21쌍×8회가 합쳐져 196쌍이다. 완전 자료에서는 168쌍이 반복 입력이다. 이는 재사용 기회이며 실제 계산을 85.7% 단축했다는 뜻은 아니다.

결측 자료에서는 삭제한 문항에만 결측이 있던 행이 다시 포함될 수 있다. 따라서 문항 이름만 같은 쌍을 같은 계산으로 취급할 수 없다. 첫 행렬의 부분행렬을 반환하면 기존 문항 삭제 분석의 자료 선택을 바꾸게 된다.

다음 후보는 **동일한 완전 사례와 문항쌍 입력이 보장되는 범위의 계산 재사용**이다. 실제 구현 전에는 `psych::polychoric`의 임계값 설정과 행렬 보정, 패키지 호출의 조건·난수 상태까지 보존하는지 별도로 확인해야 한다. 이번 입력 중복 관찰만으로 완성된 상관행렬이나 추정 결과의 재사용이 안전하다고 결론 내리지 않는다.

## 검증과 범위

- 6개 조건×3개 프로세스 모두 준비/측정/프로파일 결과가 `identical(..., num.eq = FALSE)`로 일치했다. 전체 반환값, 경고/메시지, 표준출력과 난수 상태를 포함한다.
- 여섯 조건 각각에서 프로세스 간 결과도 동일했다. 모든 실행에서 두 신뢰도 추정치가 유한하며, 상세 조건은 8행 진단표를 반환했다.
- 두 입력 추적 실행도 추적 없는 기준 결과·조건·표준출력·난수 상태와 정확히 일치했다.
- 이는 현재 코드의 반복 가능성과 병목 검증이며, 아직 구현하지 않은 후보의 결과 동일성 시험은 아니다.
- 메모리·화면·내보내기는 재측정하지 않았고 설치 파일을 재빌드하지 않았다.

재현 자료는 `output/reliability-current-profile-20260914/`의 현재 소스 사본, `profile.R`, `compare.R`, `trace.R`, 결과 RDS·시간/프로파일 CSV·원시 Rprof·입력 추적표에 보관했다. 실제 소스와 측정 사본의 SHA-256 동일성을 확인했다.
