# 서버 초기화 중 JIT 비용 감소 — 2026-09-14

## 적용 내용

`R/app_server.R`의 서버 함수 본문 시작에서 기존 JIT 수준을 저장하고 `compiler::enableJIT(0)`을 호출한다. `on.exit(..., add=TRUE)`로 정상 종료와 오류 시 원래 수준을 복원한다. 따라서 동기적인 서버 초기화 중의 새 컴파일을 피하고, 반환 이후 reactive flush와 분석은 원래 JIT 설정으로 실행한다. 이미 컴파일된 함수는 그대로 사용한다.

서버 함수의 인자·클로저 구조 및 기존 본문은 유지했다. 전역 JIT를 계속 비활성화하거나 첫 flush까지 비활성화하는 정책은 적용하지 않았다. 설치 파일은 재빌드하지 않았다.

## 최종 측정

번들 R 4.5.3, JIT 3, 기존 모듈 캐시, 새 R 프로세스를 사용했다. 이전 가시성 모델을 적용해 초기에는 지연 UI를 숨기고 KM 화면 진입 시 해당 UI를 표시했다. 3쌍을 순차 실행하고 두 번째 쌍은 순서를 반대로 했다. baseline은 이번 수정 직전에 저장한 서버 모듈의 함수이며 전역 환경으로 다시 연결했다.

각 값은 3회 중앙값(초)이다.

| 단계 | 변경 전 | 변경 후 |
|---|---:|---:|
| 서버 초기화 및 첫 flush | 1.22 | 0.74 |
| 업로드·변수 선택 | 0.58 | 0.59 |
| 상관분석 설정 | 0.45 | 0.48 |
| 첫 상관분석 | 0.45 | 0.46 |
| 생존분석 설정 | 1.12 | 1.16 |
| 첫 KM 분석 | 2.08 | 2.10 |
| 동일 입력 상관분석 재실행 | 0.01 | 0.01 |
| 동일 입력 KM 재실행 | 0.03 | 0.02 |
| 전체 흐름 | 5.97 | 5.56 |

초기화는 약 39%, 전체 흐름은 약 7% 감소했다. 일부 후속 단계의 비용은 증가했지만 전체 이득이 유지됐다. 전체 흐름 원자료는 변경 전 5.89/5.97/6.00초, 변경 후 5.56/5.60/5.53초다. 중앙값의 합과 전체 시간 중앙값은 다를 수 있다.

재실행은 동일 입력을 다시 실행한 것으로 기존 분석 캐시의 효과가 포함된다. 신규 데이터의 반복 계산 성능을 입증하는 수치가 아니다. 이 실험은 MockShinySession 기반이며 브라우저 DOM 가시성, Electron 기동, 콜드 디스크 로딩을 직접 측정하지 않았다. 다른 분석의 첫 실행 성능은 이번 수치로 일반화하지 않는다.

## 검증

- 최종 3쌍의 전체 스냅샷이 `identical(...,num.eq=FALSE)`로 일치했다. 상관·KM 분석 객체, 결과 HTML/의존성, 경고 및 알림을 포함한다.
- 첫 실행과 동일 입력 재실행의 분석 객체가 각 프로세스 안에서도 정확히 일치했다.
- 분석 객체와 HTML은 기존 `current-auto-event-map-verified.rds` 검증본과도 일치했다. 알림은 이번 하네스가 추가한 KM 재실행으로 1건 늘어나므로 기존 검증본과 비교하지 않고 변경 전후 쌍끼리 비교했다.
- JIT 수준 0, 1, 2, 3 각각 정상 서버 초기화 및 의도적인 초기화 오류 후 원래 수준이 복원되는 8개 경로를 검증했다.
- 추가된 JIT 저장·복원 두 문장을 제외하면 서버 본문의 구문 객체가 이전과 동일함을 확인했다.
- 분석 및 출력 내용 변경이 없어 PDF/Word/HWPX/Excel을 재검증하지 않았다.

## 재현 자료
