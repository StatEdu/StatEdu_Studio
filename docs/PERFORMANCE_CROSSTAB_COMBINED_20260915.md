# 교차분석 네 가지 개선의 통합 검증

2026-09-15. Gamma 영역 합, 추세 점수 벡터, 백분율 문자열 일괄 생성, 표시 행 변환 개선을 모두 합친 현재 코드를 네 가지 개선 전 소스와 비교했다. 이번 작업에서는 제품 코드를 추가로 변경하지 않았다.

## 수치·진단·RNG 및 화면

7개 자료/경계 사례 × 한글·영문 × 간략/전체 옵션의 28개 조건을 비교했다. 기준/현재 모듈은 별도 환경에 로드했다. 매 실행을 동일한 seed에서 시작하여 반환 객체 전체, 조건 클래스/내용/순서, 표준 출력, 실행 후 RNG 및 시작 RNG를 `identical(..., num.eq=FALSE)`로 비교했고 모두 통과했다. 속성 제거·반올림·허용오차는 사용하지 않았다.

- Pearson 경로 12개: 충분한 기대빈도, 순서형 8×8, 결측 포함 자료.
- Fisher exact 경로 8개: 작은 2×2 및 4×4 희소표.
- Monte Carlo Fisher 경로 4개: 6×6 희소표. 실제로 시뮬레이션 경로에 진입하고 RNG가 시작 상태와 달라졌는지 확인한 뒤 기준/현재 최종 RNG가 같은지 검사했다. 기존 10,000회 설정은 변경하지 않았다.
- 제외 변수 경계 4개: 분석 제외 속성에 선택 행 변수를 지정했을 때의 오류 클래스와 내용도 일치했다. 이 검사는 실제 UI의 모든 사례 선택/분할 실행을 재현한 검사는 아니다.

성공한 24개 조건은 동일한 현재 렌더러에 기준/현재 결과를 전달하여 생성된 HTML 문자열도 정확히 비교했다. 이것은 과거 UI 버전과의 비교가 아니라 수치/표 생성 변경의 현재 UI 영향 검사다.

## 현재 결과와 누적 결과 저장

순서형 결과와 Monte Carlo Fisher 결과를 사용해 기준/현재 각각 현재 결과와 2개 누적 항목의 HTML·Excel 파일을 생성했다(총 8개 파일). 누적 항목의 title/saved_at은 동일한 고정값을 사용했다.

현재/누적 HTML은 UTF-8으로 읽은 전체 행 문자열이 일치했다. Excel은 모든 시트의 이름·순서와 빈 행/열을 유지해 읽은 전체 셀 내용/자료형/속성이 정확히 일치했다. 파일 바이트, ZIP 메타데이터, Excel 스타일/병합/인쇄 설정까지 비교한 것은 아니다. PDF/Word/HWPX의 새 검증이나 설치 파일 빌드는 수행하지 않았다.

## 누적 성능 직접 측정

과거 단계별 개선율을 더하지 않고, 네 가지 개선 전 소스와 현재 소스를 같은 실행에서 직접 측정했다. 번들 R 4.5.3, 각 셀 8명인 4·12·40·80수준 순서형 변수, 추세 켜짐, 백분율 모두 끔/모두 켬 조건이다. 80×80은 51,200행이고 충분한 기대빈도로 Monte Carlo를 사용하지 않는다. 위 희소표 검증의 시간과 혼동하지 않는다.

양쪽 모듈 함수를 동일하게 compiler::cmpfun으로 준비하고 독립 R 프로세스 3개를 순차 실행했다. 조건별 준비 비교 후 3회 측정했으며 두 번째 프로세스의 순서는 반대로 했다. 전체 R 분석과 같은 진단/출력 캡처까지 타이머에 포함하고 정확 비교는 타이머 밖에 둔다. 앱 시작·HTML 배치·파일 저장은 제외한다. 준비 및 측정 결과 비교는 모두 통과했다.

|80×80 옵션|기준 중앙값: 프로세스 1/2/3(초)|현재 중앙값: 프로세스 1/2/3(초)|
|---|---|---|
|빈도만|0.33 / 0.31 / 0.31|0.11 / 0.11 / 0.11|
|백분율 모두|0.67 / 0.63 / 0.66|0.16 / 0.17 / 0.16|

프로세스별 중앙값의 대표값은 빈도만 약 0.31→0.11초(약 65%), 백분율 모두 약 0.66→0.16초(약 76%)다. 해당 큰 합성표의 누적 개선이며 앱 전체나 모든 자료의 개선율이 아니다. 작은 표의 개별 측정은 0.00~0.03초에 가까워 이 측정만으로 정밀한 개선율을 주장하지 않는다.
