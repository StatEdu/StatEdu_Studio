# 연구별 제외 민감도 분석 정규화 재사용 — 2026-09-14

`meta_leave_one_study_out()`에서 최초 전체 적합의 정규화된 연구별 효과값을 재사용하도록 적용했다. 기존에는 연구 하나를 제외할 때마다 나머지 연구를 모두 `meta_normalize_effect()`로 다시 처리했다. 연구 수가 k이면 전체·제외 모형을 합쳐 k²개 행을 정규화하던 작업을 최초 k개 행으로 줄였다.

각 제외 모형은 여전히 별도로 적합한다. 연구별 집계, 효과값 변환, 분산 추정, 최적화 허용오차, 신뢰구간 계산은 변경하지 않았다. `base_fit$rows`에서 제외 연구를 제거하고 행 ID와 행 이름을 기존과 같이 다시 부여한다. 재사용 범위는 한 번의 함수 실행 내부이다. 앞서 적용한 3수준 연구 소속 행렬 재사용도 유지했다.

## 측정

번들 R 4.5.3, 새 프로세스 3개를 순차 실행했고 두 번째는 기존/후보 순서를 뒤집었다. 각 조건의 준비 실행 후 GC와 비프로파일 경과 시간 측정을 수행했다. 동시에 다른 R 작업을 실행하지 않았다.

| 연구 수 / 효과크기 수 | 기존 3회(초) | 후보 3회(초) | 중앙값 변화 |
|---|---|---|---|
| 20 / 40 | 1.06 / 1.04 / 1.07 | 0.09 / 0.11 / 0.08 | 1.06 → 0.09, 약 92% 감소 |
| 60 / 120 | 13.91 / 13.75 / 13.72 | 0.40 / 0.34 / 0.37 | 13.75 → 0.37, 약 97% 감소 |

시드 139로 정규 효과값과 양의 균등분포 표집분산을 생성하고 연구당 효과크기 2개를 사용했다. Hedges' g, 랜덤효과 REML, 신뢰수준 95%, 연구 내 상관 가정 0.5이다. 시간에는 연구별 집계·최초 적합·모든 연구 제외 적합·최종 결과 생성 및 조건 수집을 포함한다. 입력 생성·소스 로딩·화면·내보내기는 제외한다. **전체 앱이나 모든 메타분석 기능의 개선율이 아니다.** 메모리 사용량은 측정하지 않았다.

## 결과 및 회귀 검증

- 두 자료 크기 × 새 프로세스 3개에서 준비/측정 결과를 기존과 `identical(..., num.eq=FALSE)`로 비교해 모두 일치했다. 전체 반환값, 경고/메시지 문자열, 난수 상태를 비교했으며 수치 허용오차는 사용하지 않았다.
- 적용 후 실제 소스의 결과를 저장한 기존 결과 6개와 다시 비교해 모두 일치했다.
- 새 `scripts/validate_meta_leave_one_reuse.R`은 g/r/OR × 고정효과/REML/PM/DL × 단일 효과/혼합 연구 크기/별도 행 이름의 36개 조건과 5개 경계 조건을 검증한다. 경계 조건은 연구 수 부족, 잘못된 출판연도, 출판연도 결측, 분산 결측, 잘못된 rho이다. 총 41개 조건의 반환값·오류/경고/메시지 클래스 및 문자열·표준출력·난수 상태가 일치했다. 조건 객체의 호출 환경 자체는 비교하지 않는다.
- 36개 정상 조건에서는 최종 민감도 표뿐 아니라 각 제외 모형의 **전체 반환값과 정규화된 행·행 ID**도 비교했다. 한글·영문 결과표도 정확히 일치했다.
- 기존 `validate_meta_analysis_model.R`, `validate_meta_analysis_input.R`, `validate_meta_analysis_ui.R`, 앞선 `validate_meta_three_level_reuse.R` 모두 통과했다.

실험 코드의 최초 AST 변환에서 함수 인수 목록을 잘못 바꾸어 실패한 실행은 제외했다. 인수 목록을 변환하지 않도록 수정한 후 표의 세 프로세스를 새로 실행했다. 신규 검증 스크립트의 닫는 중괄호 누락도 수정 후 전체 검증을 다시 수행했다. 운영 코드에는 이 실험용 변환을 사용하지 않는다.
