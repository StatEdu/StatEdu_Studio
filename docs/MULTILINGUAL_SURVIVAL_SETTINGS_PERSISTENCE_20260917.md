# 생존 설정 파일 저장·복원 연결

후속 검사: 결과 추가 스모크 실패는 테스트의 `source()` 실행 시 정리 범위 문제로 확인·수정했다. 직접 실행과 source 실행 모두 통과했으며 `SURVIVAL_RESULT_ADD_SMOKE_FIX_20260917.md`에 기록했다. 아래 실패 설명은 최초 검증 당시 기록이다.

`.studio` 설정에 버전 1의 `survival` 항목을 추가했다. KM·Cox·경쟁위험의 변수 배정, 코드값, 자료 구조, 보고 시점, 표/그림 선택, 체크 상태와 고급 옵션을 수집한다. 실행 결과나 실행 버튼 상태는 저장하지 않는다.

앱 설정 수집/기본 복원 처리에 생존 모듈을 연결했다. 모듈이 아직 로딩되지 않았으면 복원 요청을 보관하고 최초 로딩 시 적용한다. 열린 모듈에도 다시 적용하며 이전 분석 결과와 추천 전송 상태는 비운다. 새 자료 로드 및 전체 초기화 경로에도 생존 기본값 초기화를 연결했다. 생존 항목이 없는 예전 파일은 기본값으로 처리한다. 사용자 변수명은 번역하지 않는다.

검증:

- `validate_survival_settings_persistence.R`: 실제 설정 수집 함수→파일 쓰기→파일 읽기→Shiny 서버 모듈 복원을 8언어로 검사했다. 모듈 초기/재복원, 복원 후 편집, 빈 배열, 체크 해제, 사용자 문자열, 기존 파일 기본값을 확인했다.
- `validate_survival_options_browser.cjs`: 현재 개발 소스의 Chrome에서 8언어 × 3화면 설정 유지, 대표 라벨, 조건부 표시/숨김을 다시 확인했다. 페이지 오류 없음.
- 변경한 R 소스 구문과 diff 공백 검사 통과.

한계 및 미해결:

- Windows 파일 선택 대화상자를 통한 실제 저장/열기 클릭은 이번 검사가 아니다. 파일 입출력과 복원 서버는 직접 검사했고 브라우저는 세션 언어 왕복을 검사했다.
- 기존 `validate_survival_ui_smoke.R`는 결과 생성과 저장 컨트롤 확인을 지나 `결과 추가` 후 result_store 파일 존재 검사에서 실패했다. 해당 결과 저장 검사는 미해결이며 성공으로 보고하지 않는다. 이번 설정 저장 검사와 별도다.
- 추천 설계/사건 매핑 화면의 설정 저장은 이번 KM·Cox·경쟁위험 스키마 범위가 아니다.
- 분석 출력/내보내기 코드를 변경하지 않았으며 새 설치본을 만들지 않았다.
