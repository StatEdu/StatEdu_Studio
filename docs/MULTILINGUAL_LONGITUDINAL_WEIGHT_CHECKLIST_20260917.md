# 종단 보고 점검표의 가중치 설명 — 2026-09-17

보고 점검표가 가중치 요약 표를 한 문장으로 연결한 뒤 한국어 전체 치환을 수행해 사용자 변수명 속 `None`과 `Not applied`도 바꾸는 문제를 재현했다. 다른 언어에서는 이 복합 문장의 번역이 누락될 수 있었다.

점검표 생성 시 원본 가중치 표와 원본 설명을 메타데이터로 보관한다. 표시할 때 원본 설명이 일치하는 경우에만 가중치 표를 기존 보조표 번역 경로로 처리한 뒤 항목과 값을 연결한다. 변수명 셀의 원문 보존 규칙을 그대로 사용한다. 기존 원본 설명이나 숫자 계산을 수정하지 않는다.

구조 정보가 없는 과거의 평탄화 문장은 원문으로 보존한다. 사용자 이름과 앱 문구의 경계를 추측해 치환하지 않으며 저장 스냅샷을 다시 쓰지 않는다.

`validate_longitudinal_weight_checklist_i18n.R`에서 앱 문구·마침표·한글·특수문자·줄바꿈·가짜 항목명이 포함된 변수명을 사용하는 실제 점검표 생성 함수를 검사했다. 8언어에서 변수명 원문과 번역된 가중치 표를 연결한 결과의 정확한 일치를 확인했다. 이는 점검표 생성 시험이며 해당 복잡한 변수명으로 모형을 적합한 시험은 아니다.

`validate_longitudinal_error_exports.R`에 점검표를 포함해 한국어/일본어 현재·누적 HTML/PDF/Word/직접 생성 HWPX/Excel 저장을 검사한다. 기존 실제 GEE/LMM/패널 결과의 구조화 번역 회귀 검사도 수행한다. PDF 캡처 텍스트는 `validate_longitudinal_error_pdf.py`로 확인한다.

전체 브라우저·모형 조합·페이지별 시각 검토는 별도 남아 있다. 메타분석은 제외하며 설치본은 만들지 않았다.

위 검사와 기존 실제 GEE/LMM/패널 결과의 8언어 회귀 검사, 현재·누적 5종 저장 검증이 모두 통과했다. PDF 네 개의 모든 캡처 텍스트를 확인했으며 각 언어 현재 21쪽, 누적 41쪽이다. 일본어 가운데점 U+30FB가 PDF에서 U+2027로 추출되는 글꼴 매핑 차이를 확인해 검사에서 정규화했다. 변경 파일의 `git diff --check`도 통과했다.
