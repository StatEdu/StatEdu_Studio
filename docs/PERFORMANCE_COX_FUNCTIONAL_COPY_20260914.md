# Cox 진단 자료의 완전 벡터 복사 생략 — 2026-09-14

> 검증 범위 정정 (2026-09-14): 아래의 경쟁위험/Fine–Gray 전체 결과 검증 표현은 당시 `integration.R`이 `regression`을 지정하지 않아 기본 CIF/Gray 경로만 실행한 것을 잘못 기술한 것이다. 그 검증은 원인별 Cox 또는 Fine–Gray 회귀 검증으로 볼 수 없다. 직접 함수 및 Cox 검증 결과는 별개다. 이후 `regression="both"`를 명시한 600행·20공변량 자료에서 초기 Cox 최적화 전과 현재 모듈 전체의 결과·진단·난수 상태를 비교해 통과했다. 상세 내용은 [원인별 Cox 저장·통합 검증](COMPETING_PH_EXPORT_VALIDATION_20260914.md)을 참고한다.

`survival_cox_functional_form_data`에서 선택 마스크가 모두 TRUE이고 벡터에 속성이 없으면 공변량 값과 마팅게일 잔차를 원본 벡터로 전달하도록 적용했다. 기존 `values[keep]`, `martingale[keep]`의 불필요한 복사를 줄인다. 제외할 값이나 이름·클래스 등 속성이 있으면 해당 벡터의 기존 부분 추출을 유지한다. 행 번호·변수 순서·값·표 구조·결측 제외 규칙은 변경하지 않았다.

## 시간 및 메모리

번들 R 4.5.3, 앱 설정 적용, 자동 설치 비활성화. 새 프로세스에서 변경 전후 3쌍을 순차 실행했고 두 번째 쌍은 순서를 반대로 했다. 각 프로세스는 1천 행 다음 10만 행, 숫자 공변량 10개와 유한 잔차 자료를 실행했다. 검증 및 메모리 계측을 시간 측정과 동시에 실행하지 않았다.

10만 행에서 약 29% 단축됐다. 시간은 진단용 자료 생성 함수 전체이며 Cox 적합·다른 진단·UI·내보내기·앱 로딩은 포함하지 않는다. 작은 조건의 중앙값은 같았다. 결측이 있는 대용량 자료의 성능은 이번 측정 대상이 아니다.

별도 Rprofmem 계측은 각 함수를 3회 준비 실행한 뒤 gc() 후 1회 호출했다. 10만 행·10공변량의 기록된 누적 할당량은 276,458,608→244,455,568바이트로 32,003,040바이트(약 32.00MB, 11.6%) 감소했다. 최대 메모리나 프로세스 RSS 감소를 뜻하지 않는다.
