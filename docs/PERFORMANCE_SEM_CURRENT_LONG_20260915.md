# 일반 SEM 및 제품지표 모형 5,000회 실제 작업 검증

2026-09-15. 제품 변경 없이 현재 실제 백그라운드 작업 경로의 5,000회 실행 기준을 확보했다. 네 조건을 새 부모 프로세스로 각각 두 번 순차 실행했다. 총 요청 재표집 40,000회이며, 같은 조건의 반환 결과는 `timings` 속성을 제외하고 정확히 일치했다. 새 최적화의 A/B 성능 개선율이 아니다.

## 조건

- 번들 Windows R 4.5.3, 부모·자식 모두 번들 라이브러리 사용. 기존 일반 SEM 200회 측정과 동일하게 작업자 4개, 청크 100개, ML/FIML, `std_lv=FALSE`, bias-corrected CI를 사용했다. 반복 수만 측정 옵션으로 5,000을 지정했다. 제품의 기본 반복 수나 수렴 기준은 변경하지 않았다.
- 일반 SEM: 기존 `benchmark_sem_complete_bootstrap_5000.R`의 240행·지표 9개·잠재변수 3개, A→B/A→C/B→C. 완전자료 및 변수마다 10% 결측인 216개 결측 셀 조건. 재표집 seed 20260826.
- 제품지표: 기존 `benchmark_sem_product_bootstrap_5000.R`의 안정적인 240행·관측 지표 9개·잠재변수 X/W/Y 합성 fixture. 짝별 DMC는 제품지표 3개와 seed 20260832, 전체 조합 DMC는 9개와 seed 20260833. 원모형의 수렴·허용 가능 여부와 제품지표 정의를 확인했다.
- 첫 실행 순서는 완전→결측→짝별→전체 조합, 두 번째는 역순이다. 측정끼리 동시에 실행하지 않았다.
- 원모형 적합과 모듈 로딩은 타이머 밖이다. 작업 시작 호출부터 준비·백그라운드 시작·재표집·검증·요약·결과 파일 읽기까지 포함한다. 진행 상태를 0.2초 간격으로 확인하므로 관측 지연이 포함된다. UI 렌더링과 내보내기는 제외한다.

최초 제한 환경에서는 `processx` 파이프 생성 접근 거부로 작업 시작이 실패했다. 허용된 실행 환경에서 다시 시작해 성공한 실행만 기록했다. 이 시작 실패를 수치 계산 실패나 성능 값으로 사용하지 않았다.

## 실측

| 조건 | 전체 실행 1(초) | 전체 실행 2(초) | 재표집 실행 1/2(초) | 최종 유효 반복, 매 실행 |
|---|---:|---:|---:|---:|
| 일반 완전자료 | 64.585 | 64.572 | 63.311 / 63.169 | 4,998/5,000 |
| 일반 10% 결측 | 155.104 | 154.894 | 153.888 / 153.673 | 4,999/5,000 |
| 짝별 제품지표 3개 | 147.060 | 145.543 | 145.576 / 143.944 | 5,000/5,000 |
| 전체 조합 제품지표 9개 | 204.320 | 204.999 | 202.621 / 203.395 | 5,000/5,000 |

재표집 구간이 전체 시간의 약 98~99%였다. 이 구간에는 엔진 내부 반복 준비·적합·취합 비용이 함께 들어가므로 모두 최적화 함수 자체의 시간이라고 해석하지 않는다. 제품지표의 별도 최종 검증은 약 0.22~0.35초, 요약은 모든 조건 약 0.04초였다. 일반 모형과 제품지표 모형은 자료·모형이 다르므로 전체 시간 차이를 제품지표 연산만의 추가 비용으로 단정하지 않는다.

제품지표의 진행 중 유효 수는 4,992회였지만 기존 최종 검증 후 5,000회가 됐다. 이를 오류나 표본 추가 생성으로 해석하지 않는다. 일반 완전자료의 2개, 결측자료의 1개 제외 반복은 그대로 유지했으며 유효 횟수를 맞추기 위해 추가 표본을 생성하지 않았다. 이 기록만으로 제외의 구체적인 원인을 단정하지 않는다.

## 동일성과 계산 경로

`verify_sem_current_long.R` 검사:

- 네 조건 각각 전체 반환 부트스트랩 결과에서 `timings` 속성만 제거한 뒤 두 실행을 `identical(..., num.eq=FALSE)`로 비교해 통과했다. 그 외 속성 제거·수치 반올림·환경 정규화는 하지 않았다.
- 각 조건의 부모 RNG 상태를 작업 시작 전/종료 후 한 쌍으로 보관하고 실행 간 정확 일치를 확인했다. 이것은 작업 전과 후가 서로 같다는 주장이 아니다.
- `timings`의 RNG 메타데이터도 실행 간 비교하고 seed를 명시적으로 확인했다. 작업자 4개·청크 100개, fixed-index 활성, fallback 0을 모든 실행에서 확인했다. 두 제품지표 조건에서는 `product_aware=TRUE`도 확인했다.
- 일반 결측 경로의 expected-information 활성은 두 번 모두 TRUE, 나머지는 FALSE였다.
- `verify_sem_current_long_fixtures.R`에서 두 원모형의 수렴·허용 가능 여부, DMC 방식 및 제품지표 개수 3/9를 별도로 확인했다.

실제 작업 경로는 개별 표본 인덱스·원계수 행렬을 반환하지 않는다. 따라서 이번 반복 비교는 반환 결과와 난수 상태의 재현성 검증이며, 개별 40,000개 표본의 원계수를 전부 대조한 검사가 아니다. `timings`에는 시간 외 실행 진단도 포함되므로 전체 속성까지 동일한 원본 객체라는 뜻도 아니다. 필요한 seed·작업자·경로 조건은 위와 같이 별도로 검사했다.

기존 기준 스크립트의 점추정 경고 억제 등을 유지했다. 진행 stdout 및 경고·메시지 전체의 동일성 검사는 수행하지 않았으며 이를 통과한 것으로 보고하지 않는다. 과거 경로와 현재 경로의 신규 A/B 정확성 검증도 아니다.

## 산출물과 남은 범위

- 실행: `scripts/benchmark_sem_current_long.R <mode> <1|2>`. mode는 `complete`, `missing`, `matched_pair_dmc`, `all_pairs_dmc`.
- 검증: `scripts/verify_sem_current_long.R`, `scripts/verify_sem_current_long_fixtures.R`.
- `output/sem-current-long-20260915/`: 조건별 결과 RDS, 전후 RNG RDS, CSV, 집계 `summary.csv`, `fixture-contracts.rds`. 완전자료 최초 실행 이외 7개 실행의 진행 로그도 보관했다.
- 실행 전 `LC_ALL`/`LANG=English_United States.utf8`, `R_LIBS_USER`를 번들 라이브러리로 지정했다. 기존 일반 SEM 기준 스크립트가 이후 자식 실행에 한국어 UTF-8 로케일을 설정하는 동작은 유지했다.
- 제품 `R/setup_custom_model_canvas_structural_bootstrap.R` 전후 SHA256: `63E1243A036200496E9D4FF0BDFC00D9FCCAB232D1A80611CED97FCC9A9651BC`.

75행 release DMC fixture, 제품지표 자체의 결측 조건, 작업자 12개·기본 청크 250 조건, 과거 two-stage 경로와 5,000개 원계수 전체 비교는 이번 범위에 포함하지 않는다. 기존 long A/B benchmark는 별도 도구로 유지하며 그 검증을 대체하지 않는다. 설치본 로딩·결과 렌더링·현재/누적 모든 형식의 내보내기도 새로 검사하지 않았다.

다음 후보 선정은 약 203초를 차지한 전체 조합 제품지표 재표집 구간의 내부 프로파일을 우선한다. 이미 이득이 없었던 일반 SEM 역행렬 캐시 후보를 새 근거 없이 재적용하지 않는다.
