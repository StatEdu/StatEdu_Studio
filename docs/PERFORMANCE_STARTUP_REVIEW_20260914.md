# 프로그램 초기화 재측정 — 2026-09-14

이번 작업은 측정과 병목 검토다. 애플리케이션 코드 및 기본 모듈 캐시 정책은 변경하지 않았고 설치 파일도 재빌드하지 않았다.

## 측정 조건

- 저장소의 번들 R 4.5.3, JIT 3, UTF-8 환경을 사용했다.
- 캐시 miss/hit/off 각각 새 R 프로세스에서 3회 순차 측정했다. miss는 회차별 새 캐시 디렉터리, hit는 첫 회 생성된 캐시를 사용했다.
- 운영체제 파일 캐시는 비우지 않았다. 설치된 Electron 앱의 콜드 스타트 측정이 아니다.
- 모듈 로딩과 초기 UI 생성 실험은 R 프로세스 실행, 브라우저 렌더링, 실제 서버 세션 초기화를 포함하지 않는다.

## 초기화 프로파일과 해석 한계

별도 1회 초기화 프로파일 실행의 경과 시간은 2.87초였다. 샘플 합계 1.095초 중 renderUI 포함 스택 0.465초(42.47%), compiler:::tryCmpfun 포함 스택 0.355초(32.42%), render_about_document 포함 스택 0.145초(13.24%)가 관측됐다. 포함 스택은 서로 겹칠 수 있으며 이 비율은 경과 시간의 비율이나 제거 가능한 비용이 아니다.

`verify_profile.R`에서 MockShinySession의 `output_lazy_about_overview_hidden`이 FALSE임을 확인했다. 실제 구현은 `register_visible_ui_output`에서 hidden이 FALSE일 때만 UI를 생성하고 `suspendWhenHidden=TRUE`를 설정한다. 따라서 모의 세션에서 관측된 도움말 생성 비용을 실제 초기 화면의 병목으로 단정할 수 없다.

다음 검토 우선순위는 실제 화면의 표시 상태를 반영한 초기화 측정이다. 그 결과를 바탕으로 UI 생성 및 첫 호출 컴파일 비용을 분리하고, 개선 후보를 기존 결과와 비교해야 한다. 이번 자료만으로 숨겨진 화면의 지연 로딩이나 JIT 정책을 변경하지 않았다.
