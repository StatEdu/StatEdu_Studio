# 주성분·요인분석 저장 병목 측정 — 2026-09-14

주성분분석(PCA)과 탐색적 요인분석(EFA)의 저장용 HTML 생성을 측정했다. 반복 저장에서는 PNG 생성, 첫 저장에서는 PNG 생성과 함수 컴파일이 주요 비용으로 관찰됐다. 이번 작업은 개선 우선순위를 정하는 측정이며 제품 소스는 변경하지 않았다.

## 방법과 범위

- 번들 R 4.5.3, Windows, 기본 그림 해상도 600 dpi.
- seed 714, 2,000행·20변수, 두 공통 요인과 잡음으로 만든 합성 자료.
- PCA: 상관행렬, 고정 2성분, 회전 없음, 스크리 그림·바이플롯 켜짐.
- EFA: 주축요인법, 고정 2요인, varimax, 하위요인 신뢰도 켜짐, 정규성 검사 꺼짐.
- 분석별 새 프로세스 3개에서 첫 저장·반복 저장을 측정했다. 2번째 회차는 분석 실행 순서를 바꿨다. 별도 새 프로세스 1개씩에서 `Rprof(interval=.01)`와 그림 함수 구간 계측을 실행했다. 모든 R 실행은 순차 수행했다.
- 측정 시작 전에 패키지 로딩 및 분석을 완료했다. 수치는 **저장용 HTML 생성**이며 앱 시작, 분석 실행, 저장 대화상자, PDF/Word/HWPX/Excel 변환 시간은 포함하지 않는다. 첫 저장도 앱 전체가 차가운 상태라는 의미가 아니다.

## 비용 위치

별도 프로파일 실행의 전체 시간은 PCA 1.38 / 0.78초, EFA 0.94 / 0.38초였다. 아래 시간은 이 계측 실행에서 관측한 값이다. 호출 관계가 중첩되므로 서로 더하지 않는다.

| 구간 | 첫 저장(초) | 반복 저장(초) |
|---|---:|---:|
| PCA 스크리 PNG URI 생성 전체 | 0.20 | 0.19 |
| PCA 바이플롯 PNG URI 생성 전체 | 0.47 | 0.41 |
| PCA 스크리 그리기 함수 | 0.01 | 0.01 |
| PCA 바이플롯 그리기 함수 | 0.13 | 0.06 |
| EFA 스크리 PNG URI 생성 전체 | 0.20 | 0.20 |
| EFA 스크리 그리기 함수 | 0.02 | 0.00* |

*표시 해상도 아래의 관측값이며 비용이 없다는 뜻이 아니다.

반복 PCA에서는 두 PNG 생성 합계 0.60초가 전체 0.78초 중 약 77%, EFA에서는 0.20초가 전체 0.38초 중 약 53%였다. `plot_data_uri`는 장치 생성·그리기·장치 종료·파일 읽기·base64 변환을 모두 포함한다.

`Rprof`에서 장치 종료 `grDevices::dev.off`의 총 샘플 비중은 PCA 첫 34.44% / 반복 60.78%, EFA 첫 18.03% / 반복 45.83%였다. `compiler:::tryCmpfun` 비중은 첫 PCA 33.33%, EFA 47.54%였다. 이 비율은 **채집된 프로파일 샘플 비율**이며 전체 경과 시간의 비율로 환산하면 안 된다. 특히 짧은 함수의 수치는 거칠다.

PNG는 PCA 스크리 4,500×3,100(65,890 bytes), 바이플롯 4,500×3,600(393,419 bytes), EFA 스크리 4,500×3,100(68,746 bytes)였다. 파일 용량이 작아도 렌더링 픽셀 수는 크다.

## 판단

1. **첫 저장 개선은 출력 UI 함수의 컴파일 구간부터 검토할 가치가 있다.** 단, 이번 측정만으로 컴파일을 끄면 해당 시간이 전부 사라진다고 볼 수 없다. 반복 호출 성능과 JIT 상태 복원, 출력 동일성을 함께 비교해야 한다.
2. **반복 저장은 동일 PNG 재사용이 후보**다. 앞서 상관분석에서 적용한 방식과 유사하지만, PCA/EFA 결과 객체와 서버 수명에 맞춘 캐시 키·보관 크기·초기화 검증이 필요하다. 이번에는 캐시 확장 구현이나 그 효과를 측정하지 않았다.
3. **바이플롯 라벨 위치 계산은 현재 자료에서 우선순위가 낮다.** 반복 샘플 시간은 약 0.03초였고 PNG 생성보다 작다. 이를 줄이기 위해 표시 위치나 배치 규칙을 바꾸는 것은 결과 보존 요구에 맞지 않는다.

## 동일성 확인

분석별 일반 실행 3개와 프로파일 실행 1개, 총 8개 프로세스의 HTML 전체(내장 PNG 포함), 경고·메시지, 표준 출력, 난수 상태가 같은 분석 내에서 `identical(..., num.eq=FALSE)`로 일치했다. 각 실행의 첫·반복 출력도 일치했고 분석 결과 직렬화 값은 저장 전후 동일했다. 소스 변경이 없어 5종 파일 변환은 이번에 재실행하지 않았다.
