## 통합 결과 검증

`scripts/validate_correlation_reader_combined.R`에서 전체 변수 정보와 범주 라벨 표를 각각 10,000행으로 구성했다. 연속·순서·이분·명목 변수와 상수 변수를 포함한 60행 자료에 완전/결측/범위 제외 조건, Pearson/Spearman/Kendall/auto, 정규성 표 켜기/끄기를 조합한 24개 조건을 비교했다.

전체 반환 객체와 속성, 진단, stdout, RNG가 `identical(..., num.eq=FALSE)`로 일치했다. 실제 쌍별 결과가 생성됐고 상수 변수 제외 안내가 존재함도 확인했다. 범위 제외 조건에서 해당 변수가 결과 변수 목록에서 제거되는지 확인했다. 한글/영문 현재 결과 HTML 2개도 일치했다. 환경 속성 제거 등 비교용 정규화는 하지 않았다.

## 결합 성능

`scripts/benchmark_correlation_reader_combined.R`로 실제 서버 환경설정을 초기화하고 두 버전의 상관 모듈 함수를 같은 방식으로 컴파일했다. 1,000행·선택 20변수·190쌍의 Pearson 분석 및 정규성 표 조건에서 전체 변수 정보와 라벨 표를 동시에 20/10,000행으로 설정했다. 결측 조건은 각 열에 서로 어긋난 일정 간격의 NA를 넣었다.

독립 프로세스 3개, 사전 호출 후 구/신 버전 순서를 교대해 조건별 3회 중앙값을 측정했다. 시간에는 전체 결과 준비와 진단/stdout 캡처가 포함되고 데이터 생성과 명시적 GC는 제외된다. 모든 측정 반환값도 정확히 비교했다.

## 작은 결측 조건 재확인

각 정보 표가 20행인 초기 결측 조건에서는 프로세스별 중앙값이 기존 0.0396/0.0517/0.0405초, 현재 0.0510/0.0396/0.0474초로 엇갈렸다. 이 차이를 숨기거나 일관된 개선으로 판단하지 않고 해당 조건만 추가 측정했다.

`small-missing` 옵션으로 새 프로세스 2개에서 순서를 교대하고 각각 15회 측정했다. 중앙값은 기존 0.056820/0.056916초, 현재 0.051202/0.052449초였다. 지속적인 성능 저하는 재현되지 않았다. 짧은 절대 시간과 실행별 변동이 있어 작은 조건에 큰 정보 표의 개선율을 일반화하지 않는다. 추가 측정에서도 모든 반환값·진단·stdout·RNG가 일치했다.

이는 현재 결과를 준비하는 서버 함수의 측정이며 전체 로딩, 실제 브라우저 반응, 파일 쓰기 또는 내보내기 시간은 아니다. 누적 결과와 PDF/Word/HWPX/Excel 내보내기를 이번 단계에서 새로 검증하지 않았다.
