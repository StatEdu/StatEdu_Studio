# 잠재 상관의 순서형 변환 재사용 — 2026-09-14

`R/analysis_correlation.R`에 한 분석 호출 안에서 순서형 변환 결과를 재사용하는 캐시를 적용했다. 기존 범주 순서 캐시와 별개로, polychoric/tetrachoric 및 polyserial 추정에 전달하는 `ordered()` 결과를 저장한다.

## 결과 보존 방식

- 쌍별 완전 관측치 선택과 범주 순서 결정은 기존 위치에서 수행한다. 그 이후의 벡터와 범주 목록이 이전 항목과 `identical(..., num.eq=FALSE)`일 때만 변환 결과를 재사용한다. 같은 변수라도 결측 패턴에 따라 벡터가 바뀌면 다시 변환한다.
- 속성 없는 숫자 벡터와 속성 없는 문자/숫자 범주 목록에만 캐시를 사용한다. 클래스·이름 등 속성이 있는 입력과 기본 직접 호출은 원래 `ordered()` 경로를 사용한다.
- 변환에서 경고나 메시지가 발생하면 이를 그대로 전달하고 캐시하지 않는다. 빈 범주를 제거하지 않으며 추정기·표준오차·최적화 설정을 바꾸지 않는다.
- 변수별 최근 항목 한 개만 저장하며 분석 호출이 끝나면 캐시가 더 이상 유지되지 않는다. 결과 객체에는 캐시를 포함하지 않는다. 호출 중 입력 벡터 참조와 변환 결과를 유지하는 메모리 비용이 있으며, 이번에는 최대 메모리 사용량을 측정하지 않았다.

## 시간 측정

번들 R 4.5.3, polycor 0.8.2, 새 프로세스에서 변경 전후 3쌍을 순차 측정했다. 두 번째 쌍은 실행 순서를 반대로 했다. 각 스냅샷의 모든 함수를 동일한 전역 환경에 연결했다. 다른 테스트나 프로파일링을 시간 측정과 동시에 실행하지 않았다.

1만 행·8변수, latent_correlations=TRUE, continuous_method=auto, normality=TRUE 조건이다. 각 프로세스에서 순서형 3범주, 이분형, 순서형 각 변수에 무작위 결측값 10% 조건을 순서대로 측정했다. 시간은 전체 `prepare_correlation_results` 호출이며 UI·내보내기·앱 로딩은 포함하지 않는다.

| 자료 | 변경 전 3회(초) | 변경 후 3회(초) | 중앙값 전→후 |
|---|---|---|---|
| 순서형 | 0.95 / 0.95 / 0.96 | 0.71 / 0.71 / 0.69 | 0.95→0.71 |
| 이분형 | 0.53 / 0.53 / 0.55 | 0.33 / 0.31 / 0.31 | 0.53→0.31 |
| 순서형, 변수별 결측 10% | 0.70 / 0.71 / 0.71 | 0.71 / 0.69 / 0.71 | 0.71→0.71 |

완전 자료의 순서형은 약 25%, 이분형은 약 42% 감소했다. 결측 조건에서는 유의미한 시간 개선을 관찰하지 못했다. 혼합 변수의 성능은 이번 측정에 포함하지 않았으며 모든 입력에 같은 단축률을 주장하지 않는다.

## 검증

- 전체 잠재 상관 24조건: 전체 결과, 쌍별 추정 정보, 경고·메시지 순서, 난수 상태가 정확히 일치했다. 정상 추정과 추정 불가 처리를 포함하며 HTML/의존성 3건도 일치했다.
- 직접 호출 12조건: 범주 설정, 특수 숫자 클래스, 결측·무한값·전부 결측·빈 입력이 일치했다. 변경 전후 모듈 전체를 교체해 비교했다.
- 변환 함수 계측 3조건: 정상 4변수 분석의 변환 호출은 12→4회였다. 메시지·경고 발생 조건은 각각 12→12회이며 전체 결과·진단·난수 상태가 일치했다.
- 캐시를 연속 사용하는 쌍별 검증 26조건: 벡터 변경, 범주 역순·추가, 서로 다른 결측 위치, 빈 범주, 상수, 이름 있는 벡터, factor 입력을 포함했다. 빈 범주의 polychoric 경고와 polyserial 추정 불가 처리도 기존과 일치했다.
- 위 65조건 및 시간 측정 9쌍 모두 `identical(..., num.eq=FALSE)` 비교를 통과했다. 초기 추가 검사의 “두 추정기 모두 빈 범주 경고 문구를 반환한다”는 커버리지 가정은 polyserial의 기존 추정 불가 처리와 달라 수정했다. 결과 동일성 비교 자체는 통과했으며 최종 검사에는 각 추정기의 실제 기존 동작을 명시했다.
- `git diff --check` 통과. 수정 전 스냅샷과의 diff에서 이번 캐시 변경만 확인했다.
