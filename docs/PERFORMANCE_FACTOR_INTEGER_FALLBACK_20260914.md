# 정수 입력 최적화의 작은 자료·혼합 자료 확인 — 2026-09-14

직전 정수 전용 변환 최적화가 작은 입력, 혼합 저장형, 속성 있는 정수에 불필요한 지연을 만드는지 비교했다. 이번에는 제품 코드를 변경하지 않았다.

## 전체 분석 시간

| 입력 / 분석 | 기존 3회 평균(ms/분석) | 현재 3회 평균(ms/분석) | 평균들의 중앙값 |
|---|---|---|---|
| 100행·6변수 일반 정수 PCA | 7.0 / 7.5 / 7.0 | 7.0 / 7.0 / 8.0 | 7.0 → 7.0 |
| 5,000행·12변수 혼합 PCA | 46.7 / 40.0 / 40.0 | 40.0 / 43.3 / 36.7 | 40.0 → 40.0 |
| 5,000행·12변수 라벨 속성 정수 PCA | 20.0 / 26.7 / 20.0 | 26.7 / 20.0 / 20.0 | 20.0 → 20.0 |
| 5,000행·12변수 혼합 요인분석 | 36.7 / 36.7 / 33.3 | 36.7 / 30.0 / 33.3 | 36.7 → 33.3 |

PCA 세 조건의 중앙값은 같았고 혼합 요인분석도 세 번 중 두 번은 같았다. 측정한 범위에서는 일관된 지연이 발견되지 않았으며, 작은 시간 차이를 추가 개선으로 주장하지 않는다. 자료나 환경에 관계없이 비용이 정확히 0이라는 의미는 아니다.

## 조건과 검증

- 번들 R 4.5.3의 새 프로세스 3개를 순차 실행했다. 양쪽 준비 실행 후 GC와 시간 측정을 수행했고 두 번째는 비교 순서를 뒤집었다. 다른 R 타이밍 작업은 동시에 실행하지 않았다.
- 100행 조건은 20회, 나머지는 3회 분석을 묶어 경과 시간을 반복 수로 나눴다. 표의 세 값은 세 프로세스에서 얻은 평균이다. 매우 짧은 분석이므로 시간 해상도와 실행 변동을 고려해야 한다.
- 시드 927의 공통 정규 잠재값과 독립 정규 오차를 사용했다. 작은 자료는 10배 후 반올림해 integer로 저장했다. 속성 자료는 100배 후 반올림한 모든 integer 열에 label 속성을 붙였다. 혼합 자료는 숫자 문자열 factor, 숫자 문자열 character, double, 일반 integer를 반복 배치하고 두 번째 열의 매 19번째 행을 결측 처리했다.
- 변수 메타데이터는 continuous, PCA는 Pearson·고정 3성분·회전 없음, 요인분석은 Pearson·주축요인·고정 1요인·회전 없음·정규성 검사 끔이다. 범주 이름이 숫자로 변환되는 factor를 사용했으며 모든 범주형 입력이 수치 분석에 적합하다는 의미는 아니다.
- 기준은 `output/factor-integer-input-20260914/baseline.R`의 이전 숫자 변환 함수, 비교 대상은 현재 제품 함수다. PCA 별칭과 요인분석의 공유 함수 바인딩을 함께 교체했다. 나머지 분석 코드는 동일한 현재 모듈이다.
- 네 입력 × 세 프로세스에서 준비 실행 및 시간 측정의 마지막 결과를 비교해 전체 반환 객체, 경고·메시지 클래스와 문자열·순서, 난수 상태가 `identical(..., num.eq=FALSE)`로 일치했다. 객체 정규화나 수치 허용오차는 적용하지 않았다. 묶음 측정의 중간 결과는 개별 비교하지 않았다.
- 시간은 분석·결과표 준비와 비교용 스냅샷 구성을 포함한다. 입력 생성·모듈 로딩·그림 렌더링·저장은 제외한다. 메모리는 측정하지 않았다.

현재 소스 스냅샷·측정 코드·세 시간 CSV는 `output/factor-integer-fallback-20260914/`에 보관했다. 제품과 출력 형식 변경이 없어 기존 회귀 검증·파일 변환·설치 파일 빌드는 재실행하지 않았다. 정수 입력 최적화는 유지한다.
