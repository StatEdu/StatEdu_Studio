# 최근 성능 개선의 결합 상태 검증 — 2026-09-14

서버 초기화 JIT 제어, KM 곡선 시작점 일괄 생성, 경쟁위험 표 집계, 상관분석 정규성 변환 재사용이 모두 적용된 현재 소스에서 기존 비교 검증을 다시 실행했다. 이번 작업은 검증과 재실행 도구 추가이며 애플리케이션 코드는 변경하지 않았다.

## 결과

8개 검증 스크립트가 각각 새 R 프로세스에서 성공했고, 이어 전체 서버 하네스 및 스냅샷 비교가 성공했다.

| 대상 | 확인 내용 |
|---|---|
| 초기화 JIT | 정상 종료·오류 시 수준 0~3 복원, 기존 서버 본문 유지 |
| KM 곡선 데이터 | 40개 일반 조건과 16개 경계 조건의 값·진단·난수 상태 동일 |
| KM 그래프 | 네 유형 × 컬러/흑백 PNG 8쌍 바이트 동일 |
| 경쟁위험 표 | 59조건의 데이터·팔레트·진단·난수 상태 동일, 사용자 정의 data.frame 접근 진단 동일 |
| 경쟁위험 그래프 | PNG 3쌍 바이트 동일 |
| 실제 경쟁위험 결과 | 실제 분석 결과를 입력한 표 집계 동일 |

| 전체 서버 | 상관·KM 결과 객체, HTML/의존성, 경고·알림이 이전 검증본과 정확히 동일 |

전체 서버 실행의 초기화는 0.73초, 업로드·설정·첫 상관/KM 분석·동일 입력 재실행을 포함한 전체 흐름은 5.55초였다. 이는 단일 검증 실행으로, 새로운 개선률을 산출하는 벤치마크가 아니다. 기존 그래프 좌표계 교체 안내 메시지는 관측됐으며 경고는 0건이었다.

## 재실행 및 근거

- 실행: 저장소에서 `./scripts/validate_recent_performance_20260914.ps1`.
- 번들 R 4.5.3, 기존 모듈 캐시, selected 가시성 모의 세션을 사용한다. 자동 패키지 설치는 비활성화한다.
- 도구는 각 검증을 별도 프로세스에서 순차 실행하고 실패 시 중단한다. 기존 output 디렉터리의 기준 파일과 검증 스크립트가 필요하므로 독립 배포용 테스트는 아니다.
- `output/recent-performance-validation-20260914/checks.csv`와 `check-1.log`~`check-8.log`, `server.log`, `server-compare.log`에 실행 결과를 보관했다.
- `source-hashes.csv`에 검증 완료 시점의 관련 런타임 파일 4개의 SHA256을 기록했다.
- 전체 서버 스냅샷: `output/startup-jit-20260914/current-recent-combined.rds`. 기준은 같은 디렉터리의 `current-final1.rds`이며 `identical(...,num.eq=FALSE)`로 비교했다.
