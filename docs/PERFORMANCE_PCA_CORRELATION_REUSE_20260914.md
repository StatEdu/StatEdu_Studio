# PCA 적합성 검사의 상관행렬 재사용 — 2026-09-14

PCA는 Pearson 상관행렬을 분석용으로 만든 뒤 적합성 검사에서 동일한 완전 사례 자료의 Pearson 상관을 다시 계산했다. 공분산 분석을 제외한 경로에서는 이미 계산한 `analysis_matrix`를 적합성 검사에 사용하도록 한 조건을 변경했다. 공분산 분석은 별도 Pearson 상관 계산이 필요하므로 그대로 유지한다. 순서형 상관 경로는 원래도 분석 행렬을 재사용했다.

고윳값·회전·적재량·점수·적합성 계산식과 출력 내용은 변경하지 않았다. 요청한 순서형 상관이 Pearson으로 전환된 경우에도 기존 Pearson 행렬을 재사용한다. 별도의 전역 캐시를 만들지 않았다.

## 전체 PCA 분석 측정

| 20,000행·60변수 | 기존 3회(초) | 변경 후 3회(초) | 중앙값 |
|---|---|---|---|
| 상관행렬 | 2.86 / 2.56 / 2.89 | 2.45 / 2.75 / 2.47 | 2.86 → 2.47, 약 14% 감소 |
| 공분산행렬 | 2.27 / 2.30 / 2.27 | 2.26 / 2.27 / 2.27 | 2.27 → 2.27 |

상관행렬은 세 번 중 두 번 빨라졌고, 두 번째는 0.19초 느렸다. 따라서 모든 실행에서 14% 개선된다는 의미가 아니다. 중복 계산 제거와 결과 동일성, 중앙값 감소를 근거로 범위가 작은 변경을 반영했다. 공분산 경로에서는 의미 있는 차이가 없었다.

번들 R 4.5.3의 새 프로세스 3개를 순차 실행했다. 각 입력에서 양쪽 준비 실행 후 GC 및 전체 분석을 측정했으며 두 번째는 비교 순서를 뒤집었다. 다른 R 타이밍 작업은 동시에 실행하지 않았다. 시드 920의 연속 정규 변수 60개, 완전 자료, 고정 3성분·회전 없음이다. 각 분석 전 시드 718로 초기화했다. 모듈 로딩·입력 생성·그림 렌더링·저장은 제외하고 분석 및 결과표 준비와 비교용 스냅샷 구성을 포함했다. 메모리는 측정하지 않았다.

## 검증

- 두 입력 × 세 프로세스의 준비/측정 실행에서 전체 반환 객체, 경고·메시지 클래스와 문자열·순서, 난수 상태가 `identical(..., num.eq=FALSE)`로 일치했다. 결과 객체를 정규화하거나 수치 허용오차를 적용하지 않았다.
- 24개 전체 PCA 비교 통과: 상관·공분산·순서형 상관·연속 변수에 따른 Pearson 전환 × 회전 없음/Varimax/Oblimin × 결측 유무. 240행·6변수에 상수 열을 추가해 제외 처리도 포함했다. 점수 저장 옵션도 켜서 순서형 상관의 관련 경고 내용까지 비교했다.
- 지속 검증 `scripts/validate_pca_correlation_reuse.R` 역시 24개 통과. 현재 함수의 적합성 행렬 선택 조건만 원래대로 복원한 참조와 비교한다. 변경 전 소스와 후보의 독립 비교도 보관했다.
- `scripts/validate_factor_pca.R` 통과: 기존 요인분석/PCA 옵션, 그림 및 내보내기 관련 검증 포함.
- `scripts/validate_pca_varimax_precision.R` 통과: 보관 50개 및 경계/대조 8개, psych 네임스페이스 유지. 이 기존 검증 일부는 1e-12 허용오차를 쓰며 위 24개 정확 비교와 구분한다.
- 변경 파일의 `git diff --check` 통과.

기준 소스·후보·측정 코드·시간 CSV·경계 검증 코드는 `output/pca-correlation-reuse-20260914/`에 보관했다. 출력 내용·형식 변경은 없으며 PDF/Word/HWPX/Excel 전체 파일 변환을 별도로 재생성하지 않았다. 설치 파일도 재빌드하지 않았다.
