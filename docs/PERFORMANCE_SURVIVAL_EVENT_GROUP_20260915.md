# 생존분석 사건·집단 전처리 계측

이번 작업은 병목 분리와 재현성 확인이다. 제품 코드는 변경하지 않았다. 직전 숫자 생존시간 개선이 적용된 현재 코드에서 사건 코드의 반복 문자열 처리를 다음 후보로 선정했다.

## 측정 조건

`scripts/profile_survival_event_group.R` 사용. 번들 R 4.5.3, 앱 모듈 및 실제 초기 환경설정 적용. 두 독립 프로세스에서 조건 순서를 반대로 실행했다. 각 조건 준비 1회, 타이밍 5회 중앙값, 별도 Rprof 10회(요청 간격 5ms). 타이밍은 전체 `survival_preflight`와 진단/stdout 수집을 포함하고 동일성 비교는 제외한다. Rprof 표본 시간은 벽시계 시간과 구분하며, 표본 비율은 대략적인 우선순위 판단에만 사용한다.

20,000/100,000행, 연속 공변량 6개, 집단 factor 3수준, 사건 확률 0.7. 사건 입력은 숫자/문자/factor와 자동/명시적 매핑으로 나누었다. 결측 조건은 사건 5%, 집단 5%를 서로 다른 행에 배치해 분석 행 90%를 확인했다. 집단은 모든 조건에서 factor이며 다른 집단 형식 전체를 포괄하는 검사는 아니다.

## 전처리 시간

각 칸은 독립 실행 1 / 2의 중앙값(ms)이다.

| 사건 조건 | 20,000행 | 100,000행 |
|---|---:|---:|
| 숫자·자동 매핑 | 9.35 / 11.90 | 43.64 / 52.74 |
| 숫자·명시적 매핑 | 15.01 / 15.13 | 64.83 / 67.65 |
| factor·자동 매핑 | 16.12 / 17.68 | 74.17 / 76.80 |
| 문자·자동 매핑 | 12.18 / 12.79 | 52.22 / 51.59 |
| 사건/집단 결측·자동 매핑 | 21.42 / 21.73 | 95.88 / 75.94 |

전체 Cox 모형 적합, 전체 앱 로딩, 렌더링·내보내기 시간이 아니다. 서로 다른 입력 조건 간 차이를 최적화 효과로 해석하지 않는다.

## 확인한 병목과 다음 후보

1. `survival_normalize_event_map`은 명시적 매핑을 반환하는 경우에도 함수 시작에서 전체 관측 코드의 문자 변환·공백 제거·unique를 실행한다. 해당 분기의 반환값에는 관측 코드 목록이 사용되지 않는다. 100,000행 명시적 매핑 프로파일에서 이 함수 경로는 약 18~33%, `trimws` 경로 전체는 약 56~72%의 표본 시간이었다. 중첩 경로이므로 비율을 합산할 수 없다.
2. 숫자·자동 매핑의 집단 `droplevels` 경로는 약 3%의 표본 시간이었다. 이 조건에서는 집단 수준 정리보다 사건 문자열 처리의 우선순위가 높다. factor 관련 스택에는 지연 평가 중인 다른 연산도 들어가므로 `is.factor` 비율을 집단 변환 비용으로 간주하지 않았다.
3. 결측 조건에서는 `add_reason` 경로가 약 36~57%로 나타났다. 이 경로는 호출 인자의 지연 평가와 행별 사유 기록을 함께 포함하므로 순수 기록 비용으로 단정하지 않는다. 사유 순서·중복 제거 계약을 보존하는 추가 계측이 필요하다.

다음 작업은 명시적 사건 매핑에서 사용하지 않는 관측 코드 준비를 생략하는 후보 검증이다. 반환값만 보고 계산을 무조건 이동하지 않는다. 특수 클래스 변환의 경고·오류·난수 소비와 기존 평가 순서를 보존할 수 있는 일반 입력 범위를 먼저 정하고, 직접 helper 및 전체 전처리/분석 비교와 전후 측정 후 적용 여부를 결정한다.
