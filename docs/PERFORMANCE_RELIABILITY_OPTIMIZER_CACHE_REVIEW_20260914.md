# 신뢰도 캐시의 중간값 재사용 검토 — 미채택 — 2026-09-14

현재 문항쌍 캐시보다 작은 중간값을 보관하는 후보를 시험했으나, 실제 최고 메모리가 줄지 않고 시간 이점도 없어 적용하지 않았다. 운영 `R/analysis_reliability.R`는 변경하지 않았다.

## 후보

기존 구현은 psych의 `polyc`에 전달되는 원자료 벡터·임계값·옵션과 그 추정 결과를 재사용한다. 후보는 재사용 위치를 내부 `optimize` 호출로 옮겼다. 교차 빈도표 구성과 정규화는 매번 기존 `polyc`가 수행하고, 동일한 목적 함수 `polyF`, 탐색 구간, 행/열 임계값과 정규화된 표의 최적화 결과만 재사용한다.

로컬 복제 함수의 환경에서만 조회를 변경한다. 목적 함수가 예상 함수와 다르면 기존 `stats::optimize`를 사용하도록 구성했다. 기존 패키지 버전·함수 본문 검사, 해시 후 실제 인수 동일성 검사, 경고/메시지·난수 변경 시 비저장, 128항목 제한, 분석별 캐시 및 결측 자료 우회는 유지했다. 통합 후보에 대한 추가 운영 변경이나 설치 패키지 수정은 하지 않았다.

## 시간

직전 통합과 같은 2,000건·8문항·5범주 자료, 문항 삭제 신뢰도와 문항-전체 상관 요청이다. 시드 719로 공통 정규 성분 0.6과 독립 성분 0.8을 생성하고, 분석 시드 941을 사용한다. 결측 조건은 문항별 독립 10% 결측이다. 번들 R 4.5.3의 새 프로세스 각 3개를 순차 실행하고 두 번째 쌍은 역순이다. 준비 실행 후 GC하고 전체 분석을 측정했으며 준비 캐시는 다음 호출로 전달하지 않는다.

| 조건 | 기존 3회(초) | 후보 3회(초) | 중앙값 |
| --- | --- | --- | --- |
| 완전 자료 | 0.37 / 0.39 / 0.37 | 0.37 / 0.37 / 0.37 | 0.37 → 0.37초 |
| 결측 자료 | 1.14 / 1.14 / 1.16 | 1.17 / 1.15 / 1.13 | 1.14 → 1.15초 |

캐시 설정·전체 결과·진단/표준출력 수집은 포함하고, 패키지/앱 로딩·자료 생성·UI·저장은 제외했다. 결측 조건은 양쪽 모두 캐시를 우회하므로 작은 시간 차이를 계산 알고리즘 변화로 해석하지 않는다.

## 별도 메모리

완전 자료를 새 프로세스에서 한 번 실행해 실제 R PID의 `PeakWorkingSet64`를 약 20ms 간격으로 관측했다. 버전별 3개 프로세스를 순차 실행했고 두 번째 쌍은 역순이다. 패키지/모듈 로딩·자료 생성·분석·결과 직렬화를 포함하며 시간 측정과 동시에 실행하지 않았다.

| 반복 | 기존(bytes) | 후보(bytes) |
| --- | ---: | ---: |
| 1 | 310,079,488 | 311,259,136 |
| 2 | 311,623,680 | 313,094,144 |
| 3 | 311,832,576 | 313,663,488 |
| 중앙값 | 311,623,680 | 313,094,144 |

후보 중앙값은 **1,470,464 bytes(1.47 MB), 약 0.47% 높았다**. 작은 차이이지만 세 쌍 모두 감소하지 않았다. 저장 키가 작은 형태라고 해서 전체 프로세스의 관측 최고 메모리가 감소한다고 가정할 수 없다. 이번 측정은 별도 캐시 객체 크기나 Electron 전체 메모리의 측정이 아니다. 앞선 통합 보고서의 다른 프로세스 측정값과 섞어 개선율을 계산하지 않았다.
