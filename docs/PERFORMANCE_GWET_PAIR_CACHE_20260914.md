# Gwet AC1/AC2 쌍 인덱스 재사용 확대

## 적용

기존 interrater_gwet_ac는 바로 이전 행의 유효 평가자 수에 해당하는 쌍 인덱스만 재사용했다. 결측으로 평가자 수가 번갈아 바뀌면 이미 만들었던 조합을 다시 만들었다. 유효 평가자 수별 지역 캐시를 추가해 같은 수의 조합을 다시 사용할 수 있도록 했다.

캐시는 한 번의 함수 호출에서만 존재하며 32명 이하의 평가자 수에 대해서만 저장한다. 그보다 큰 수는 기존처럼 직전 크기만 재사용한다. 캐시를 채우는 것도 실제로 해당 크기가 나타났을 때뿐이다. 원래 combn의 쌍 순서, 합산 순서, 가중치와 분모 계산은 유지한다. 입력값이나 계산 결과를 전역에 보관하지 않는다.

처음 검토한 연속형 Krippendorff alpha의 pooled combn 경로는 현재 일반 분석 진입점에서 사용되지 않았다. 연속형 자료는 ICC로 반환되고 Krippendorff 호출은 nominal/ordinal에 있으므로, 실제 호출되는 Gwet 경로로 검토 범위를 옮겼다. 연속형 alpha 헬퍼는 변경하지 않았다.

## 전체 분석 성능

번들 R 4.5.3, 자료 seed 939, 5,000행·8평가자, A–E 및 NA를 같은 확률로 표집했다. 명목형(category) 및 순서형(ordered)의 prepare_interrater_agreement_results 전체 실행을 비교했다. Gwet 외에 해당 유형의 다른 일치도 계수와 결과 표 생성도 포함한다.

독립 프로세스 3개를 순차 실행했고 워밍업 후 두 번째는 후보부터 측정했다. 로딩을 제외하고 결과 캡처를 포함한다.

| 유형 | 기존 1 / 2 / 3 (초) | 변경 1 / 2 / 3 (초) | 중앙값 |
|---|---|---|---|
| 명목형 | 0.30 / 0.23 / 0.30 | 0.20 / 0.26 / 0.20 | 0.30 → 0.20초 |
| 순서형 | 0.20 / 0.22 / 0.19 | 0.18 / 0.16 / 0.19 | 0.20 → 0.18초 |

명목형은 두 번 개선·한 번 증가, 순서형은 두 번 개선·한 번 같은 표시 시간이었다. 중앙값 기준 약 33%와 10% 감소이며 짧은 실행의 측정 편차가 있다. 결측이 없거나 평가자 수가 연속해서 같으면 기존 캐시도 효과가 있으므로 같은 개선율을 기대할 근거는 없다.

별도 계측에서 Gwet의 combn 호출은 AC1/AC2 모두 3,641→7회로 줄었다. 이는 같은 자료의 Gwet 함수만 측정한 횟수이며 전체 분석의 다른 함수 호출까지 합친 수치는 아니다. 원시 계수와 RNG도 일치했다. trace는 별도 검증 프로세스에서만 사용하고 해제했다.

## 검증

각 워밍업·측정에서 전체 반환 결과, 조건 클래스·본문·순서, 표준 출력과 RNG가 `identical(..., num.eq=FALSE)`로 일치했다. 수치 반올림이나 정규화를 사용하지 않았다.

`scripts/validate_gwet_pair_reuse.R`를 32/33/40평가자까지 확장해 캐시 경계 양쪽을 검사했다. 총 8개 평가자 수(1/2/3/10/30/32/33/40), 완전·결측·희소·미등록 값·빈 자료·factor 자료, AC1/AC2와 linear/quadratic 조합 192건이 통과했다.

변경 직전 실제 소스와의 비교 및 파일 인수 없는 독립 참조 비교를 각각 수행했다. 같은 192개 조건을 두 방식으로 확인한 것이며 별개 자료 384종으로 집계하지 않는다. 독립 참조는 각 행마다 원래 combn(values, 2L)를 계산한다. 원시 계수·경고·메시지·오류·RNG를 비교했다.

기존 `scripts/validate_interrater.R`도 통과했고, 제품 Gwet 함수 본문이 측정한 후보와 동일함을 확인했다. 모든 사용자 정의 클래스에 대한 불변 증명은 아니다.
