# 일반 대응분석의 Wilcoxon 엔진 재사용 — 2026-09-14

## 적용 내용

`R/analysis_paired.R`의 `paired_analyze_pair()`에서 Wilcoxon 호출 두 곳을 기존 `paired_rm_wilcox_engine()`으로 연결했다. 연속형에서 가정검사 결과 Wilcoxon을 선택한 경우와 순서형 경로가 대상이다. 정규성 검사, 검정 선택, 대응 t 검정, 경고 억제, 제외 조건, 효과크기, 요약표 및 안내 문구는 변경하지 않았다. 엔진 자체와 코드 서명 불일치 시 원래 stats 함수로 돌아가는 동작도 그대로다.

변경 직전 소스와 diff하여 제품 변경이 두 호출 줄뿐임을 확인했다. 새 수치 계산 구현을 추가하지 않았다.

## 전체 실행 시간

번들 R 4.5.3, 데이터 seed 939, capture seed 718. 20,000행 × 16열의 8개 대응쌍을 분석했다. 연속형은 로그정규 난수, 순서형은 1~5 균등 표본이다. 셀별 독립 결측 확률은 0 또는 10%이며 기존의 쌍별 완전 사례 처리를 유지한다.

`prepare_paired_results()`를 `assumption_check=TRUE`, `median_iqr=TRUE`로 호출했다. 정규성 검사·검정 선택·효과크기·요약표·안내 생성까지 포함한 전체 시간이다. 모든 측정에서 실제 8쌍이 Wilcoxon으로 선택됐는지도 명시적으로 검사했다. 연속형을 강제로 Wilcoxon으로 고정한 모의 측정이 아니다.

3개의 새 R 프로세스를 순차 실행하고 각 조건에서 기존/현재를 예열한 후 측정했다. 두 번째 프로세스는 수준 및 기존/현재 실행 순서를 뒤집었다. 다음은 실제 제품 경로 측정이며 단위는 초다.

| 수준 | 셀별 결측률 | 기존 1/2/3 | 현재 1/2/3 | 중앙값 기존→현재 |
|---|---|---|---|---|
| 연속형 | 0% | 0.44 / 0.44 / 0.44 | 0.08 / 0.10 / 0.06 | 0.44→0.08 |
| 연속형 | 10% | 0.34 / 0.35 / 0.36 | 0.07 / 0.08 / 0.06 | 0.35→0.07 |
| 순서형 | 0% | 0.17 / 0.17 / 0.17 | 0.05 / 0.06 / 0.05 | 0.17→0.05 |
| 순서형 | 10% | 0.14 / 0.14 / 0.16 | 0.04 / 0.03 / 0.04 | 0.14→0.04 |

12회 모두 단축됐다. 결측 없는 조건의 중앙값 기준 연속형 약 82%, 순서형 약 71% 단축이다. 짧은 실행 시간은 타이머 해상도와 환경 변동의 영향을 받으며 다른 자료에서도 같은 비율을 보장하지 않는다. 메모리·앱 로딩 시간 및 대응 t 검정의 속도 향상을 주장하는 측정은 아니다.

초기 후보도 별도 3개 프로세스로 검증했고 12회 모두 단축됐다. 초기 측정값은 `timing-*.csv`, 실제 적용은 `product-timing-*.csv`에 보관했다. 두 세트의 시간을 섞어 중앙값을 계산하지 않았다.

## 동일성 확인

`scripts/validate_paired_engine.R`은 현재 함수의 엔진 호출 두 곳을 원래 stats 호출로 복원해 기준본을 만든다. 복원 개수도 검사한다.

- 전체·통합 결과 **112조건**: 연속형/순서형 × 로그정규 기반 일반/정규 기반 자료/결측/0 차이/Inf/일정 차이/factor × 평균·표준편차 또는 중앙값·IQR × 일반/통합 결과 × 가정검사 켬/끔. `add_mean_sd=TRUE`, `effect_size=TRUE`도 포함한다.
- 정상·정규·결측 입력은 오류 반환이 아님을 확인했다. 기존 제외 결과와 진단은 기준본과 비교했다. 테스트 집합에 대응 t 검정 및 Wilcoxon 경로가 실제 포함됐는지도 검사했다.
- 대규모 원시 검정 **32개**: 측정 자료의 두 수준 × 두 결측률 × 8쌍에서 원시 `htest` 전체를 비교했다.
- 모든 비교는 `identical(..., num.eq=FALSE)`로 수행했다. 전체 반환값, 원시 통계량·p값·데이터 이름·클래스와 경고/메시지·오류의 클래스 및 문구, 표준출력, RNG 상태가 일치했다. 반환 객체 정규화나 수치 허용 오차를 사용하지 않았다.
- 초기 후보·실제 제품 경로의 예열/실측 전체 결과도 정확히 일치했다. 실제 수정 함수와 후보의 실행 코드 텍스트가 같음을 확인했다.
- 수정 파일의 `git diff --check` 통과. 엔진 구현은 변경하지 않아 엔진 자체 경계 검사를 불필요하게 반복하지 않았다.

UI·내보내기 코드나 결과 구조는 변경하지 않았으며 문서 변환 및 설치 파일 빌드는 수행하지 않았다.
