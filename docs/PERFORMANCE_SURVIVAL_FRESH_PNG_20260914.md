# 생존분석 저장용 PNG의 중복 초기화 생략

2026-09-14. 새 PNG 장치에 저장하는 생존분석 그림에만 적용했다. 기존 Windows PNG 장치, 해상도, 픽셀 및 통계 결과를 유지했다.

## 변경 범위

`survival_draw_plot_with_risk_table`에 `newpage = TRUE` 인수를 추가했다. 기존 호출은 이전처럼 `grid::grid.newpage()`로 화면을 지운다. `survival_saved_plot_specs`의 KM 및 경쟁위험 저장용 콜백에서만 `newpage = FALSE`를 전달한다.

이 콜백은 `survival_inline_saved_plots`에서 `plot_data_uri`를 통해 실행되고, 해당 함수는 매번 새 PNG 장치를 연 뒤 콜백을 호출하고 파일을 닫는다. 이 경로에서는 페이지 초기화를 한 번 생략해도 출력이 동일했다. 화면 재출력, 기존 장치의 페이지 정리, 개별 PNG 폴더 저장 등 다른 호출 경로의 기본 동작은 유지한다. 위험집단 표가 없는 빠른 반환 경로는 기존 `print(main_plot)`을 유지한다.

기존 JIT 설정 저장·복원, 그래프 빌드, 좌표 정렬, 캡션, 곡선 및 위험집단 표 생성 코드는 그대로 사용한다. 분석 데이터나 모형을 다시 계산하는 최적화가 아니다.

## 성능

번들 R 4.5.3/JIT 3, 모듈 표현식 캐시, 패키지 설치 검사 생략. seed 714의 2,000행/4그룹 KM 자료, 평가 시점 5/10/20/40, 생존·사건·누적위험·로그생존 × 컬러/흑백의 **8개 그림**을 포함한 저장 HTML 생성을 측정했다. 각 PNG는 600 dpi, 5455×3927픽셀이다. 분석 준비와 모듈 로딩은 시간 측정 밖이다.

먼저 기존/실험 후보를 각각 새 프로세스 3개에서 순차 측정하고, 두 번째 세트의 실행 순서를 뒤집었다. 이후 새 파일 경로에만 한정한 실제 적용 코드를 별도 새 프로세스 3개에서 확인했다.

| 중앙값 | 첫 저장(초) | 같은 결과 반복 저장(초) |
|---|---:|---:|
| 기존 | 11.86 | 10.78 |
| 실험 후보 | 10.87 | 9.75 |
| 실제 적용 코드 | **10.80** | **9.72** |

기존 대비 최종 적용 코드의 단축은 첫 저장 **1.06초(약 8.9%)**, 반복 저장 **1.06초(약 9.8%)**다. 실제 적용 코드의 첫 저장 원시 값은 10.92/10.80/10.80초, 반복은 9.72/9.70/9.75초였다. 최종 적용 확인은 기존/후보 교차 측정 이후 별도로 진행했다.

최종 확인의 첫 시도는 출력 내용 검증 프로세스와 겹칠 가능성이 있어 제외하고, 다른 R 작업이 끝난 뒤 해당 실행을 다시 측정했다. 제외된 타이밍은 `integration/excluded-overlap-1.csv`에 보관했고 최종 중앙값에 포함하지 않았다.

이 수치는 첫 KM 분석이나 프로그램 시작 시간이 아니라 **그림을 포함한 저장 HTML 생성 시간**이다. PDF/Word/HWPX 변환 시간 및 메모리 최고점 개선은 주장하지 않는다.

## 동일성 및 기존 동작 검증

- 기존/후보 3쌍과 기존/최종 적용 3쌍에서 8개 고해상도 PNG가 포함된 전체 HTML, 경고·메시지, 표준 출력, RNG 상태가 `identical(..., num.eq=FALSE)`로 같았다.
- 각 프로세스에서 첫/반복 HTML도 같았으며 원래 분석 결과의 직렬화 바이트가 저장 전후 유지됐다.
- 최종 함수에서 생존/사건/누적위험/로그생존 × 컬러/흑백, CI·중도절단 표시 끔, 위험집단 표 없음, 캡션 없음, 경쟁위험의 **12개 PNG/조건/출력/RNG 쌍**이 기본 초기화 경로와 같았다.
- 기존 페이지를 빨간색으로 채운 뒤 기본 호출로 다시 그린 PNG가 새 장치에서 기본 호출로 그린 PNG와 같았다. 따라서 기본 호출의 화면 정리 기능이 유지됨을 확인했다.
- 기존 JIT 검증의 12개 그림 경우와 호출자 JIT 0/1/2/3의 정상·오류 복원 8개 시험도 통과했다. 해당 검증의 stub 인수만 새 선택 인수에 맞춰 조정했다.
- 변경 전 원본 소스와 최종 적용 코드의 KM·경쟁위험 패널, 저장 PNG HTML, 조건/출력/RNG 및 원래 결과 객체가 같았다. 현재/누적 HTML은 바이트 단위, Excel은 시트 값과 압축 내부 파일 단위로 같았다. Excel 문서 생성·수정 시각만 정규화했다.

## 현재·누적 결과 내보내기

KM와 경쟁위험을 함께 저장한 현재 결과와 두 결과를 한 번 더 추가한 누적 결과에서 HTML/PDF/Word/HWPX/Excel **10개 파일**을 생성했다.

| 검증 항목 | 현재 | 누적 |
|---|---:|---:|
| HTML 비어 있지 않은 표 셀 | 482 | 964 |
| Word/HWPX에서 일치하는 셀 내용·개수 | 482 | 964 |
| HTML/Word/HWPX 그림 수 | 2 | 4 |
| PDF 페이지 수 | 18 | 36 |
| PDF 그림 수 | 2 | 4 |

Word/HWPX 셀 내용은 공백 정규화 후 다중집합으로 비교했다. PDF 현재 결과의 7쪽(KM)과 18쪽(경쟁위험)을 렌더링하여 곡선·축·범례·위험집단 표·캡션을 확인했다. 모든 PDF 페이지의 픽셀 비교를 수행한 것은 아니다. 설치 파일은 재빌드하지 않았다.
