Short purpose statement (App Store Connect, under 300 characters)
StatEdu Studio is a local statistical analysis app for macOS. Bundled R analyzes user-selected files and exports results locally. HTTPS reads a public version-policy JSON. A random token protects its localhost Shiny service. No custom cryptographic algorithm or encrypted-data product is offered.

Application operations
1. HTTPS reads https://studio.statedu.com/releases/latest.json at startup or when the user checks for updates. The request reads a public version policy and does not attach analysis data or analysis results. R/update_check.R calls jsonlite::fromJSON on the HTTPS URL. The prepared R curl runtime reports libcurl 8.14.1 and LibreSSL/3.3.6 (SecureTransport). This identifies that transport backend; it does not establish the negotiated TLS version/cipher of every request. Other cryptographic capabilities remain included in Electron and R openssl.
2. packaging/macos/main.js uses Node crypto.randomBytes(32) to produce a random token for access to the local Shiny service on 127.0.0.1. The token is generated for local runtime access. It is not an encryption key for analysis files. Do not include live tokens in a regulatory submission.
3. Analysis modules use digest SHA-256 for code/content checks and cache signatures. SHA-256 is a hash function, not reversible encryption of analysis data.
4. The normal product workflow processes data locally and exports ordinary report/project files. The application does not expose a user-configurable cryptographic algorithm or an encrypted-file feature. No proprietary algorithm was identified in these application paths.

Included cryptographic components
- Electron 43.4.0: a local MAS fixture reports Node 24.18.1 and Chromium 150.0.7871.224. Node crypto enumerates 28 cipher entries, four EC curves (224, 256, 384 and 521 bits) and nine hash entries. AES fixed-length entries use 128, 192 or 256-bit keys. Blowfish, DES/3DES, RC2 and RC4 entries are included runtime capabilities, not Studio feature choices. getCipherInfo reports expected/default key length; its defaults must not be presented as maximum lengths for variable-length algorithms.
- R openssl package 2.4.2: the actual build-2 payload includes Resources/library/openssl/libs/openssl.so. Its package description lists standard RSA, DSA, EC, AES, signatures, hash functions and random generation capabilities. This describes included library capabilities; it does not mean the Studio UI exposes all of them.
- OpenSSL 3.5.4 (30 Sep 2025): the version string was observed in the above openssl.so. nm confirms compiled AES and EVP encryption symbols. otool -L does not show a separate system libssl/libcrypto dependency for this file. Thus this submission cannot be described as containing only encryption supplied by Apple's operating system.
- The native OpenSSL EVP registry contains 136 cipher definitions, including AES, ARIA, Camellia, ChaCha20, DES/3DES, Blowfish, CAST5, IDEA, RC2, RC4, SEED and SM4. Registered definitions do not prove that every legacy provider is active. R's exposed AES CBC/CTR/GCM functions passed nine synthetic encrypt/decrypt roundtrips with 128, 192 and 256-bit keys; EC key generation passed for P-256, P-384 and P-521. RSA key generation defaults to 2048 bits. A build-specific RSA maximum and variable-length cipher maxima have not been certified; do not substitute defaults for those maxima.
- Probes used the prepared R runtime and Developer-ID-signed local MAS fixture. The R openssl.so, R curl.so and Electron Framework executable __text section hashes each match the submitted build-2 payload. This checks executable-code equivalence, not full signed-binary equivalence or TestFlight execution. Direct standalone probes of the store-signed binaries did not run, so they are not reported as successful store installs.
- Sanitized measured evidence is in docs/validation/macos-1.3.1/crypto-inventory-summary.json and crypto-cipher-inventory.csv. These files contain no generated keys, local access tokens or applicant address.

Observed Apple requirement
App Store Connect's encryption-document wizard, with standard encryption outside Apple's operating system and France selected, requests a copy of the French encryption declaration approval. No approval file has been supplied. The wizard was cancelled without submitting a document. Build 2 remains marked as missing export-compliance documentation.
This technical draft is supporting information, not that approval. No ITSAppUsesNonExemptEncryption=false setting or exemption claim has been applied to bypass the document requirement. No final ECCN, exemption, mass-market classification or regulatory approval is asserted here.

Official French form preparation
ANSSI publishes an official interactive PDF form for cryptology declarations and authorization requests. The downloaded file uses dynamic XFA; ordinary PDF extraction shows a viewer-upgrade notice. It needs a compatible viewer for completion and visual verification. The original remains unchanged in local temporary storage.
Known product and technical details above can support the product-description sections. The operator supplied a name, nationality, postal address and postal code on 2026-10-03 and confirmed the address correction; they are preserved only in local private preparation files, not in this public repository. The private French worksheet maps the supplied details and measured evidence to the official form's A.2 and B sections, with C-F items marked for finalization. Applicant signing capacity, applicable operation/classification, build-specific algorithm/key-length maxima and the applicant's signature must still be verified before filing. An organization may need registration evidence as described by the official form. No signature or applicant address has been invented.
The three-page English preparation PDF was updated and a four-page French worksheet was created under local output/pdf. All seven pages were rendered and visually checked. The worksheet is not a completed official XFA form or an approval document; the original official form remains unmodified. Both PDFs contain personal details and are excluded from the public repository.
ANSSI's official electronic procedure requests a completed electronic form, a signed scan and supporting documentation. No email has been sent and no filing has been made.
